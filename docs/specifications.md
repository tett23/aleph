# Aleph 仕様書

Aleph は、Golem（https://github.com/tett23/golem ）の原稿を書き、組まれた姿を確かめ、作品の構成を管理するためのデスクトップアプリである（[ADR 0002](adr/0002-purpose-scope-and-name.md)）。
Tauri 2 で作り、画面を TypeScript、ファイルとプロセスを Rust で扱う（[ADR 0003](adr/0003-application-architecture.md)）。
リポジトリの名前は `aleph` とする。

この文書は、Aleph の今の振る舞いを定める。
設計の決定は `docs/adr/` に連番の ADR として置く。

## アプリの構成

Aleph は Tauri 2 のアプリで、画面を TypeScript（`app/`）、ファイルと外部のプロセスを Rust（`src-tauri/`）で扱う（[ADR 0003](adr/0003-application-architecture.md)）。

- 画面の状態（ワークスペース、開いているシートの並び、選択、パネルの表示）は一つの値で持ち、操作を受けて新しい状態を返す関数（リデューサー）だけで変える。開いているシートは、一つでも配列で持つ。
- Rust の側は、ファイルの読み書き、ディレクトリの一覧、外部のプロセスの実行を受け持つ。外部のプロセスは引数を配列で渡し、シェルを通さない。
- git は、設定の値、`/usr/bin`、Homebrew（`/opt/homebrew/bin`）、PATH の順に探す。設定の値があれば、ほかの場所は探さない。macOS の GUI アプリはログインシェルの PATH を受け継がないためである。
- アイコンは、使うものだけを `app/icons/` に SVG で置く（lucide、ISC ライセンス）。
- テストは、TypeScript は `node --test`（Node が型を取り除いて実行する）、Rust は `cargo test` で書く。CI の `app` のジョブが macOS で、型検査、`node --test`、Vite のビルド、rustfmt、clippy、`cargo test` を実行する。

## 画面の構成

画面は、左から次の順に並ぶ（[ADR 0005](adr/0005-layout-and-appearance.md)）。

- **リボン**：左のサイドバーに出すもの（ファイル、検索、Git、診断、共有ライブラリ）を切り替えるアイコンと、プロットを開くアイコン、設定を開くアイコン。同じアイコンをもう一度押すと、サイドバーを畳む。
- **左のサイドバー**：上にワークスペースの名前があり、押すとワークスペースを切り替えるメニューが出る。その下に、リボンで選んだものを出す。
- **中央**：上にツールバー、その下にエディタとプレビューを左右に並べ、下にステータスバーを置く。ツールバーは、エディタに効く「縦」「横」を左に、プレビューを選ぶ「原稿のみ」「本文」「ページ」を右に置く。形式が持たない切り替えは出さない。
- **右のパネル**：添付、アウトライン、そのプロジェクトの共有ライブラリを、上のアイコンで切り替える。ツールバーの右端のアイコンで畳む。

外観はライト、ダーク、OS に合わせる（既定）のどれかを設定で選ぶ。
アクセントの色は彩度を落とした黄土色とし、選択の背景は無彩色とする。
パネルの表示の状態（どのパネルか、畳んだか、縦と横、プレビュー）は、次に起動したときに戻す。

## ワークスペースとプロジェクト

**ワークスペース** は、設定で登録したディレクトリである（[ADR 0004](adr/0004-workspaces-and-projects.md)）。
複数を登録でき、左のサイドバーの上の名前から切り替える。
ワークスペースの中で `manifest.toml` を持つディレクトリを、深さによらず **プロジェクト** とする。
プロジェクトの中の `manifest.toml` は無視する。

左のサイドバーの「ファイル」には、ワークスペースのツリーを出す。

- `.` で始まるもの、`build/`、`node_modules/`、`target/`、`dist/` は出さない。Aleph が開けない形式のファイルも出さない。
- プロジェクトの中は、`manifest.toml` の `chapters` に並んだ章をその順で先に出し、次に `plot.csv` を「プロット」として、そのあとにほかのファイルとディレクトリを出す。`chapters` の項目は、文字列、`file` を持つ表、入れ子の配列のどれでもよい。
- `.gm` と `.md` は最初の見出しを名前として出し、ファイル名を小さく添える。
- 新しいシートは、プロジェクトの中なら `chapters/NN.gm` として作り、`chapters` の末尾に足す。足すときは配列の書き方（一行か、一行に一項目か）を保つ。プロジェクトの外では、開いているシートと同じディレクトリに作る。
- ファイルの名前は、ダブルクリックで変える。消す操作は持たない。
- 新しいプロジェクトは `golem new` で作る。共有ライブラリを設定していれば `--no-fonts` を付け、フォントは共有ライブラリからコピーする（[ADR 0014](adr/0014-shared-library-and-assets.md)）。

アプリの設定は、アプリの設定のディレクトリ（macOS では `~/Library/Application Support/dev.tett23.aleph/`）の `config.json` に置く。
読み込むとき、形の違う値は既定に戻し、範囲のある値（文字サイズ、行間、自動保存の間隔など）は上限と下限に丸める。

メインのウィンドウの位置と大きさは、動かしたとき、大きさを変えたとき、閉じるとき、アプリを終えるときに `window.json` に記録する。
起動したとき、記録した矩形がどれかのディスプレイに収まり、幅 400、高さ 300 の画素より大きければ戻し、そうでなければ既定の大きさで中央に置く。

## Golem と shem

Aleph は、組版、診断、整形、LSP を golem に、PDF のラスタライズを shem に任せる（[ADR 0008](adr/0008-golem-and-shem-binaries.md)）。
それぞれ、次の順に探して最初に見つかったものを使う。

1. 設定の値（絶対パス）。設定した場所になければ、ほかの場所は探さない。
2. アプリに同梱したもの（アプリのリソースの `resources/golem`、`resources/shem`）
3. `~/.local/bin`
4. Homebrew（`/opt/homebrew/bin`）
5. PATH

設定の「Golem と shem」に、使っているバイナリのパスと `--version` の出力を出し、同梱の版と違えば同梱の版も出す。
見つからないときは、探した場所を出す。

同梱する版は、リポジトリの根の `tools.versions` に書く。
`scripts/bundle-tools.sh` が、GitHub Releases から配布物と `SHA256SUMS` を取り、照合してから、バイナリとライセンスを `src-tauri/resources/` に入れる。
照合に失敗すれば止まり、何も入れない。

## 横書きのエディタ

シートは CodeMirror 6 のエディタで書く（[ADR 0006](adr/0006-horizontal-editor.md)）。

- 本文（`.gm`、`.md`、`.txt`）の列の幅は、`style.toml` の `[page.grid] characters` の字数にする。設定の「1 行の字数」があればそれを使う。ほかの形式は 110 字まで広げる。
- 本文は明朝、それ以外（`.emet`、`.toml` など）は等幅で書く。`.gm` の中の命令の頭と引数、式は等幅にし、散文スロットは本文のフォントのままにする。文字サイズは本文とコードで別に、行間は本文に設定する。
- 溝には、左から、HEAD からの変更の印（追加、変更、削除）、行番号、診断の印を並べる。折り返した行では、行番号を 1 行目の高さにそろえる。HEAD にないファイルは、すべての行を追加とする。
- `.gm` には、改ページが入る位置の見積もりの印（「改ページ（見積もり） 2 → 3」）を出す。段落の字数を字詰めで割った行数と、見出しの行数（第 1 階層は 3 行、ほかは 2 行）から数え、`@page-break` と `@column-break` の後では必ずページを改める。禁則、ルビ、行アキは数えない。
- 設定で、半角スペース（·）、全角スペース（□）、タブ（→）、改行（↵）を出せる。ゼロ幅の文字と制御文字は、設定によらず出す。
- ツリーで `.gm` を選び、shift を押して別の `.gm` を押すとその間の章を、⌘ を押して押すと 1 章ずつ足し引きして、まとめて開く。エディタは章ごとに縦に並び、見出しを上に貼り付ける。まとめて開いたあいだは横書きで書く。
- サーバー（[ADR 0009](adr/0009-lsp-and-formatting.md)）が応えるまでのあいだの `.gm` の色付けは、角括弧の入れ子を追う簡単な字句の読み方で行う。
- ステータスバーに、字詰め（「38 字 × 16 行」）とカーソルの位置を出す。

改ページの位置を正確に出すため、Golem に、PDF の各ページが原稿のどこから始まるかを出す機能を依頼する。
その機能が入るまでは、上の見積もりを使う。

## 縦書きのエディタ

ツールバーの「縦」で、本文（`.gm`、`.md`、`.txt`）を縦書きで書く（[ADR 0007](adr/0007-vertical-editor.md)）。

- テキストエリアを `writing-mode: vertical-rl` にし、その裏に同じ字詰めの影の層を重ねる。影の層は原稿の各行を一つのブロックとして置き、各行の上に行番号を、その上に HEAD からの変更の印を出す。折り返した行では、1 列目の上にだけ番号を出す。
- 列の高さは字詰めの字数に合わせる。テキストエリアは中でスクロールさせず、文字の量に合わせて横に伸ばし、外側の枠を右端からスクロールさせる。開いたときは冒頭を出す。
- 縦書きでは色付けをせず、LSP の波線、溝の印、ホバー、補完も出さない。⌘S は整形せずに保存する。
- 複数の章をまとめて開いたときは、縦書きにしない。

## LSP と整形

`.gm` と `.emet` は `golem lsp` とつなぐ（[ADR 0009](adr/0009-lsp-and-formatting.md)）。

- プロジェクトごとに一つ `golem lsp` を起動し、そのプロジェクトのシートを開いたすべてのエディタで共有する。そのプロジェクトのシートをすべて閉じて 10 分たったときと、アプリを終えるときに止める。起動に失敗するか途中で終わったときは、1 分たってから、次に開くか書いたときに起動し直す。
- `initialize` で位置の単位に UTF-16 を申し出る。サーバーからの要求には空の応答を返す。文書の URI は、パスの各部分をパーセントエンコードして作る。
- 開く、変える、保存する、閉じるを `didOpen`、`didChange`（入力が止まって 250 ミリ秒後に全文）、`didSave`、`didClose` で伝える。これは画面の状態から送るので、縦書きで書いているあいだも伝わる。
- 診断は、重大度の色の波線と溝の印で出す。ステータスバーに、開いているシートの「エラー n　警告 m」と、サーバーの状態（「● LSP」「LSP 起動中」「LSP 停止」）を出す。数を押すと、エディタの下に **エディタの診断の一覧** を開き、項目を選ぶとその位置に移る。縦書きでは一覧を開かず、横書きで開くよう知らせる。
- 色付けは、サーバーの semantic tokens を使う。型は Golem の `tools/editors/README.md` の表に合わせ、命令の部品（keyword、function、decorator、operator）を命令の色、値（string、number、variable など）を式の色、comment と `.gm` の macro（エスケープ）を薄い色、見出しの `#` を薄い色、見出しの文字（namespace）を太字にする。届くまでのあいだと、サーバーが使えないときは、簡単な字句の読み方の色を使う。
- 命令と式を等幅にする範囲は、semantic tokens の型の付いた部分と、簡単な字句の読み方で命令と式とした部分を合わせたものにする。今の Golem は、命令の角括弧や式の中の `.`、`(`、`)` などに型を付けないため、型だけでは範囲が決まらない。Golem に、これらの記号への型か修飾子を依頼する。
- ホバーはサーバーの文言を出す。補完は `[` と空白の後で始める。
- 整形は、⌥⇧F とツールバーのメニューの「整形（⌥⇧F）」で、`textDocument/formatting` の結果を一回の変更として当てる。⌘Z で一度に戻せる。変わったときは「整形しました」、変わらなかったときは「変更はありません」と知らせる。サーバーが応えるのを待つあいだに書き足したときは、当てない。
- ⌘S は、設定の「⌘S で整形する」（既定はオン）がオンなら、整形してから保存する。変わったときだけ「整形しました」と知らせる。自動保存と縦書きでは整形しない。
- サーバーが使えないときは、保存したファイルに `golem fmt` を実行し、結果をエディタに読み直す。

## プレビュー

ツールバーの右の「原稿のみ」「本文」（`.md`、`.svg`、Mermaid では「プレビュー」）「ページ」で、エディタの右に出すものを選ぶ（[ADR 0010](adr/0010-previews.md)）。
描く処理は、スクロールする枠の中の要素に描き、枠そのもののクラスは変えない。

- **本文**：`.gm` を開いたときと保存したときに `golem build --target html` を実行し、章の XHTML の `body` の中身を出す。`script`、`style`、`link` の要素、イベントの属性、`javascript:` の参照は除き、画像は `build/html` から読む。組んでいるあいだと組めなかったときは、前の結果を出したまま見出しに小さく示す。前の結果がないときは、記号を取り除いた本文を出す。縦と横の切り替えに従い、まとめて開いた章は並べて出す。
- **ページ**：`golem build --target pdf` のあと `shem render --dpi N` で各ページを PNG にし、縦に並べる。「ページ」を選んでいて組んだ結果がなければ、すぐ組む。保存したあとは、設定の「保存したらページを組みなおす」（既定はオン）に従って組み直す。見出しのボタンで組み直せる。
- **解像度**：設定の「ページの解像度」が空なら自動とし、`(枠の幅 − 36) × 画面の倍率 × max(1, 拡大率) ÷ ページの幅（インチ）` を切り上げ、72 から 1200 のあいだに収める。ページの幅は `style.toml` の `[page]` の `size`（Golem の判型の名前か `width`）に、`bleed` の 2 倍を足したものとする（Golem の PDF のページは塗り足しを含む）。書かれていなければ A5 とする。拡大や枠の広がりで足りなくなったら、PDF を組み直さず、shem で描き直す。
- **拡大縮小**：見出しのボタン、ピンチ、⌘ を押しながらのスクロールで、30% から 400% まで変える。100% は枠の幅とする。拡大率は見る人ごとに覚える。
- **Markdown**：自前の読み方（見出し、段落、強制改行、箇条書きと番号付きリストの入れ子、引用、コードブロック、表、区切り線、強調、斜体、インラインのコード、リンク、画像）で HTML にする。HTML のタグは文字として出し、`javascript:` などの参照は無効にする。
- **SVG** は画像として出し、スクリプトは動かさない。**Mermaid** は Mermaid で描き、誤りは文言で出す。
- **PDF** と **画像** はエディタの代わりに出す。PDF は shem で描き、描けないものは WebView の表示に任せる。
- **別ウィンドウ**：本文とページの見出しのボタンで、別のウィンドウに出す。メインのウィンドウが組んだ結果をイベントで送り、ページのウィンドウは自分の幅と拡大率で足りなくなると、合う dpi で描き直すよう頼む。
