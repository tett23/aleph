# Aleph 仕様書

Aleph は、Golem（https://github.com/tett23/golem ）の原稿を書き、組まれた姿を確かめ、作品の構成を管理するためのデスクトップアプリである（[ADR 0002](adr/0002-purpose-scope-and-name.md)）。
Tauri 2 で作り、画面を TypeScript、ファイルとプロセスを Rust で扱う（[ADR 0003](adr/0003-application-architecture.md)）。
リポジトリの名前は `aleph` とする。

この文書は、Aleph の今の振る舞いを定める。
設計の決定は `docs/adr/` に連番の ADR として置く。

## アプリの構成

Aleph は Tauri 2 のアプリで、画面を TypeScript（`app/`）、ファイルと外部のプロセスを Rust（`src-tauri/`）で扱う（[ADR 0003](adr/0003-application-architecture.md)）。

- 画面の状態（ワークスペース、開いているシートの並び、選択、パネルの表示）は一つの値で持ち、操作を受けて新しい状態を返す関数（リデューサー）だけで変える。開いているシートは、一つでも配列で持つ。
- Rust の側は、ファイルの読み書き、ディレクトリの一覧、外部のプロセスの実行を受け持つ。外部のプロセスは引数を配列で渡し、シェルを通さない。
- 外部のプログラム（golem、shem、git）を走らせて待つコマンドと、ワークスペースの木を辿るコマンドは、メインスレッドの外で動かす（[ADR 0062](adr/0062-run-programs-off-the-main-thread.md)）。組版のあいだも、入力と描画は止まらない。そのため種類の違うプログラムが同時に走るので、同じワークスペースの git の書き込み（`add`、`commit`、`init`、`pull`、`push`）と、同じプロジェクトの `build/` に書く組版と `golem fmt` は、画面の側で一つずつ走らせる。
- git は、設定の値、`/usr/bin`、Homebrew（`/opt/homebrew/bin`）、PATH の順に探す。設定の値があれば、ほかの場所は探さない。macOS の GUI アプリはログインシェルの PATH を受け継がないためである。
- アイコンは、使うものだけを `app/icons/` に SVG で置く（lucide、ISC ライセンス）。
- テストは、TypeScript は `node --test`（Node が型を取り除いて実行する）、Rust は `cargo test` で書く。CI の `app` のジョブが macOS で、型検査、`node --test`、Vite のビルド、rustfmt、clippy、`cargo test` を実行する。
- CI の `audit` のジョブ（`.github/workflows/audit.yml`）が、プルリクエスト、main、週に一度の定期の実行で、`npm audit --omit=dev --audit-level=high` と、版を固定した `cargo audit` を走らせる（[ADR 0049](adr/0049-dependency-audit-in-ci.md)）。既知の脆弱性を一時的に許すときは、advisory の ID、理由、見直す日を書く（cargo は `src-tauri/.cargo/audit.toml`）。理由のない許可は置かない。

## 画面と Rust の信頼の境界

Rust の側は、画面（webview）からの呼び出しを信じきらない（[ADR 0042](adr/0042-ipc-trust-boundary.md)、[ADR 0050](adr/0050-paths-the-writer-chooses.md)）。プレビューなどに HTML が一か所注入されても、任意のコマンドの実行や居座りに届かないようにするためである。

- CSP で、読み込めるスクリプトを自分のものと blob（プラグイン）に、接続を IPC に限る。`object`、`base`、フォームの送り先は使わない。
- 画面からファイルを読み書きできるのは、ワークスペース、共有ライブラリ、アプリの一時のディレクトリの下に限る。アプリの設定のディレクトリ（`config.json`、`plugins/`、`trash/`）は読めるが、書けるのはゴミ箱だけである。パスは `canonicalize` してから確かめるので、`..` やシンボリックリンクで外へ出るものも拒む。範囲の外は誤りを返し、`exists` は偽を、ツリーと一覧は空を返す。
- Finder から落としたファイルとフォルダは、アプリが動いているあいだだけ、コピーの元として読める。
- git、golem、shem の実行ファイルは、Rust の側が設定から決める。画面からは渡せない。サブコマンドは Aleph が使うものに限る（git は `add`、`branch`、`commit`、`diff`、`init`、`log`、`pull`、`push`、`rev-parse`、`show`、`status`、golem は `build`、`check`、`fmt`、`lint`、`new`、`preflight`、`lsp`、`--version`、shem は `render`、`--version`）。git の `init` は [ADR 0051](adr/0051-git-init-and-the-pages-window.md) で足した。作業のディレクトリも上の範囲に限る。
- 設定のうち、`workspaces`、`libraryDir`、`gitPath`、`golemPath`、`shemPath` は Rust の側だけが足し、変える。画面からの保存では、ワークスペースを外すことと、パスを空にすることだけを受け付ける。ワークスペースを足す、共有ライブラリを選ぶか作る、バイナリを選ぶときは、Rust の側がネイティブのダイアログを開く。バイナリのパスを欄に打ったときは、Rust の側がネイティブの確認のダイアログを出し、はいのときだけ使う。
- 権限は、Aleph が開くウィンドウ（`main`、`plain-*`、`pages-*`、`plot-*`、`imelog-*`）に限って与える。`pages-*` は [ADR 0051](adr/0051-git-init-and-the-pages-window.md) で決めた。
- ウィンドウは、アプリのページ（開発のときは開発のサーバー）から外へ移らない（[ADR 0044](adr/0044-navigation-from-the-preview.md)）。プレビューのリンクを押しても、ウィンドウは移らない。`#…` はプレビューの中のその要素へ送り、`http` と `https` は URL を示して確かめてから既定のブラウザで開く。ウィキリンクと埋め込みの見出しは Aleph の中で開き、ほかのリンク（`file:`、相対のパスなど）は何もしない。`target="_blank"` と `window.open` も新しいウィンドウを開かない。

## 画面の構成

画面は、左から次の順に並ぶ（[ADR 0005](adr/0005-layout-and-appearance.md)）。

- **リボン**：左のサイドバーに出すもの（ファイル、ブックマーク、キーワード、検索、Git、診断、共有ライブラリ、ゴミ箱）を切り替えるアイコンと、プロットを開くアイコン、設定を開くアイコン。同じアイコンをもう一度押すと、サイドバーを畳む。
- **左のサイドバー**：上にワークスペースの名前があり、押すとワークスペースを切り替えるメニューが出る。その下に、リボンで選んだものを出す。
- **中央**：上にツールバー、その下にエディタとプレビューを左右に並べ、下にステータスバーを置く。ツールバーは、エディタに効く「縦」「横」を左に、プレビューを選ぶ「原稿のみ」「本文」「ページ」を右に置き、その右に Golem のプロジェクトのシートならビルドのボタンを置く（[ADR 0058](adr/0058-build-from-aleph.md)）。形式が持たない切り替えは出さない。
  デバッグのビルド（`tauri dev` と `tauri build --debug`）では、ツールバーのタイトルの左に「dev」の印を出し、設定の見出しの版に「(dev)」を添える（[ADR 0052](adr/0052-show-the-debug-build.md)）。判定は Rust の `cfg!(debug_assertions)` による。リリースのビルドでは出さない。
- **右のパネル**：添付、アウトライン、リンク、そのプロジェクトの共有ライブラリを、上のアイコンで切り替える。ツールバーの右端のアイコンで畳む。

知らせは、一つの **通知** の仕組みで出す（[ADR 0064](adr/0064-unified-notifications.md)）。

- 通知は、ウィンドウの右下、ステータスバーの上に、下から上へ積む。幅は 360 ピクセル（狭いウィンドウではウィンドウの幅から余白を引いた幅）とする。
- 一つの通知は、重大さ（情報、警告、エラー）のアイコン、文（複数行でよく、選んでコピーできる）、0 個から 3 個のボタン、閉じるボタン（×）を持つ。ボタンを押すと、その操作を行い、通知を閉じる（閉じない指定のボタンもある）。
- **時間で消える通知** は 5 秒で消える。ポインタが上にあるあいだは数えるのを止め、離れてから 5 秒を数えなおす。**消えない通知** は、× を押すか、ボタンで閉じるか、それを出した機能が閉じるまで残る。失敗の知らせ（Git の add とコミットと pull と push の失敗、ビルドの失敗とエラー、`golem fmt` と `golem new` の失敗、プラグインの誤り、Finder で表示できない、画像を書けない、ウィンドウを開けない、ブックマークの行き先がない、ゴミ箱から戻せない）は、エラーの消えない通知とする。ほかは、情報の時間で消える通知とする。
- 同じ鍵の通知を出すと、前のものを置き換える。一度に見せるのは 4 つまでとし、超えたときは古い時間で消える通知から閉じる。消えない通知は閉じず、新しい 4 つを見せ、上に「ほか n 件の通知」を出す。押すと全部を見せる。
- ページのプレビューとプロットの別のウィンドウも、同じ通知を出す。それらの通知は、メインのウィンドウの履歴にも入る。

外観はライト、ダーク、OS に合わせる（既定）のどれかを設定で選ぶ。
アクセントの色は彩度を落とした黄土色とし、選択の背景は無彩色とする。
パネルの表示の状態（どのパネルか、畳んだか、縦と横、プレビュー、開いたフォルダ、ワークスペース）と、ページとガントの拡大率は、アプリの設定の `config.json` の `ui` に置き、次に起動したときに戻す（[ADR 0004](adr/0004-workspaces-and-projects.md)）。書くのはメインのウィンドウで、変わってから 0.5 秒後に、変わったときだけ書く。プレビューとプロットのウィンドウは、自分の拡大率の変更をメインのウィンドウに送る。

## ワークスペースとプロジェクト

**ワークスペース** は、設定で登録したディレクトリである（[ADR 0004](adr/0004-workspaces-and-projects.md)）。
複数を登録でき、左のサイドバーの上の名前から切り替える。
ワークスペースの中で `manifest.toml` を持つディレクトリを、深さによらず **プロジェクト** とする。ワークスペースのルートが `manifest.toml` を持つときは、ルートそのものがプロジェクトで、ツリーの先頭にその行を開いたまま出す。
プロジェクトの中の `manifest.toml` は無視する。

左のサイドバーの「ファイル」には、ワークスペースのツリーを出す。

- `.` で始まるファイルとフォルダは既定では表示しない。「隠しファイルを表示」をオンにすると表示する。`.gitignore` の対象ファイルは既定では表示し、設定の「.gitignore 対象のファイルを表示」をオフにすると配下の規則、ディレクトリ指定、否定パターンに従って隠す。両方に該当する項目は両方の表示設定がオンのときだけ表示する。設定が欠けているか真偽値以外なら既定値を使い、変更は直ちに反映する（[ADR 0067](adr/0067-tree-visibility-and-directories.md)）。
- `build/`、`node_modules/`、`target/`、`dist/` は表示しない。Aleph が開けない形式のファイルも表示しない。
- シンボリックリンクは、ファイルもフォルダも出さず、辿らない。ツリーは 64 段までとする。書き先がシンボリックリンクなら、保存、コピー、移動を拒む（[ADR 0045](adr/0045-symlinks.md)）。
- プロジェクトの中は、登録した章を実際の親フォルダの下に一度だけ表示する。同じ親の章は `manifest.toml` の `chapters` の順に先に出し、プロジェクト直下ではその次に `plot.csv` を「プロット」として、そのあとにほかのファイルとディレクトリを出す。`chapters` フォルダは空でも表示し、展開と折り畳みができる。`chapters` の項目は、文字列、`file` を持つ表、入れ子の配列のどれでもよい（[ADR 0067](adr/0067-tree-visibility-and-directories.md)）。
- `.gm` と `.md` は最初の見出しを名前として出し、ファイル名を小さく添える。
- プロジェクトの行は、ほかの行（27 ピクセル）より高い 34 ピクセルにし、名前を太字の 13.5 ピクセルで出す（[ADR 0020](adr/0020-project-rows-in-the-tree.md)）。最初の行でないプロジェクトの行は、上に 6 ピクセルの間と区切りの線を置く。
- 新しいシートは、プロジェクトの中なら `chapters/NN.gm` として作り、`chapters` の末尾に足す。足すときは配列の書き方（一行か、一行に一項目か）を保つ。プロジェクトの外では、開いているシートと同じディレクトリに作る。
- プロジェクトまたはフォルダの行の右クリックから、指定した場所にフォルダか空のシートを一つ作る。シートの種類は gm、md、emet、txt、toml、csv、tsv、svg、mmd、json、jsonc、json5、jsonl から選び、拡張子は一度だけ付ける。右クリックで作った gm は章に登録しない。空の名前、パス区切りを含む名前、同名の項目、取消では作らない（[ADR 0065](adr/0065-tree-create-and-convert.md)）。
- プロジェクト内の gm は右クリックで `chapters` に追加または削除する。削除すると同じ参照を入れ子も含めてすべて外し、残る章の順序と書式を保つ。ツリーで選んだ gm は、表示順に本文を結合して一つの gm に書き出す。開いている章は編集中の本文を用い、章の間には LF を二つ入れる。保存先はネイティブのダイアログで選び、元の章への上書きは拒む（[ADR 0066](adr/0066-chapter-membership-and-export.md)）。
- シート、フォルダ、プロジェクトの行を右クリックし、「名前を変える」を選ぶと、その一件を同じフォルダ内で改名する。シートはダブルクリックでも改名できる。既存の名前、パス区切りを含む名前、空の名前、`.`、`..` は受け付けない。登録済みワークスペースと、プロジェクト直下の `plot.csv`、`manifest.toml`、`style.toml` は改名の対象から外す（[ADR 0070](adr/0070-rename-sheets-and-folders-from-tree.md)）。
- フォルダを改名すると、開いている子孫シートは同じタブで編集を続けられ、ノートも引き継ぐ。プロジェクトを改名すると、開いているプロットとノートは新しいルートに保存する。
- プロジェクト内のシートまたはフォルダの改名では、Golem LSP に改名前の参照編集を問い合わせ、開いているシートはエディターで、閉じたシートはファイルで編集してから改名する（[Golem ADR 0338](https://github.com/tett23/golem/blob/main/docs/adr/0338-update-references-on-file-and-folder-renames.md)）。
- Golem LSP が応答しない場合や編集を検査できない場合は、「中止」と「参照を更新せず改名」を区別して選ぶ。編集またはディスクの改名が失敗した場合は、適用した編集を逆順に戻す。
- ファイルを消すときはゴミ箱に移す（[ゴミ箱](#ゴミ箱)）。
- ファイル、フォルダ、プロジェクトの行の右クリックのメニューの「Finder で表示」で、その行を Finder で選んだ状態で表示する（[ADR 0053](adr/0053-reveal-in-finder.md)）。パスは Rust の側で範囲を確かめてから `/usr/bin/open -R` に渡す。
- 新しいプロジェクトは `golem new --no-fonts` で作り、フォントは共有ライブラリからコピーする（[ADR 0014](adr/0014-shared-library-and-assets.md)）。共有ライブラリを設定していなければフォントは入らないので、そのことを知らせる。

アプリの設定は、アプリの設定のディレクトリ（macOS では `~/Library/Application Support/dev.tett23.aleph/`）の `config.json` に置く。
読み込むとき、形の違う値は既定に戻し、範囲のある値（文字サイズ、行間、自動保存の間隔など）は上限と下限に丸める。

メインのウィンドウの位置と大きさは、動かしたとき、大きさを変えたとき、閉じるとき、アプリを終えるときに `window.json` に記録する。
起動したとき、記録した矩形がどれかのディスプレイに収まり、幅 400、高さ 300 の画素より大きければ戻し、そうでなければ既定の大きさで中央に置く。

## Golem と shem

Aleph は、組版、診断、整形、LSP を golem に、PDF のラスタライズを shem に任せる（[ADR 0008](adr/0008-golem-and-shem-binaries.md)）。
それぞれ、次の順に探して最初に見つかったものを使う。

1. 設定の値（絶対パス）。設定した場所になければ、ほかの場所は探さない。
2. アプリに同梱したもの（アプリのリソースの `resources/golem`、`resources/shem`）
3. `~/.local/bin`
4. Homebrew（`/opt/homebrew/bin`）
5. PATH

設定の「Golem と shem」に、使っているバイナリのパスと `--version` の出力を出し、同梱の版と違えば同梱の版も出す。
golem と shem に渡す相対のパスには `./` を付け、オプションとして読まれないようにする。`-` で始まる名前のプロジェクトは作らない（[ADR 0048](adr/0048-paths-in-arguments-and-data-files.md)）。
見つからないときは、探した場所を出す。

同梱する版は、リポジトリの根の `tools.versions` に書く。
`scripts/bundle-tools.sh` が、GitHub Releases から配布物と `SHA256SUMS` を取り、照合してから、バイナリとライセンスを `src-tauri/resources/` に入れる。
すべてのアーカイブを取ってきて照合してから、まとめて入れる。どれかの照合に失敗すれば止まり、何も入れない。

## ブックマーク

シートと、シートの中の一行をブックマークできる（[ADR 0025](adr/0025-bookmarks.md)）。

- ⌘D（`bookmark.toggle`）でエディタのカーソルの行を、ツリーの行の右クリックのメニューと `bookmark.toggleSheet` でシートをブックマークする。すでにあれば外す。
- ブックマークは、ワークスペースのルートの `.aleph/bookmarks.json` に、ルートからの相対パスで置く（行のブックマークは行の番号とその行の文字も持つ）。Git で同期すれば、ほかの機械でも同じになる。
- 左のサイドバーの「ブックマーク」（リボンのピンのアイコン）に並べる。各行にシートの名前と、行のブックマークなら行の番号と文字の初めの 40 字を出す。押すと開き、つまみのドラッグで並べ替え、× で外す。見つからないファイルと、パスがワークスペースの外を指すもの（`..` で外へ出る、絶対パス、`~` で始まる、[ADR 0048](adr/0048-paths-in-arguments-and-data-files.md)）は薄く出し、押すと知らせる。
- 行のブックマークで移るときは、残した番号の行の文字が残した文字と同じならその行に、違えば近い順に同じ文字の行（前後で同じ距離なら前）に、見つからなければ残した番号の行に移り、番号を残し直す。
- Aleph でファイルやフォルダの名前を変えると、その上とその下のブックマークのパスも変わる。

## 最近開いたシート

開いたシートを、ワークスペースごとに新しい順に覚える（[ADR 0026](adr/0026-recent-files.md)）。

- シートを開くと（どこから開いても）、そのパスを並びの先頭に置き、すでにあれば先頭へ移す。まとめて開いた章は、右のパネルが従う章を先頭に、すべて置く。並びはワークスペースごとに 50 件までで、機械ごとの履歴として `config.json` の `ui` の `recent` に置く。
- 左のサイドバーの「ブックマーク」のパネルの下に「最近開いたシート」として出し、押すと開く。見つからないシートは出さず、次に並びを書き直すときに並びから落とす。「消去」で今のワークスペースの並びを空にする。
- Aleph でファイルやフォルダの名前を変えると、並びのパスも変わる。
- 起動したときは、残したタブを開き直す（[タブと分割](#タブと分割)）。開き直すタブがなければ、並びの先頭の、まだあるシートを開く。

## シートを名前で開く

⌘P（コマンド `file.quickOpen`）で、パレットと同じ入力欄を出し、今のワークスペースのシートを名前で探して開く（[ADR 0022](adr/0022-quick-open.md)）。

- 候補は、ツリーに出すファイルすべてで、畳んだフォルダの中のものも含む。
- 入力が空のときは、最近開いたシート（[ADR 0026](adr/0026-recent-files.md)）を新しい順に出す。
- 入力があるときは、見出しから取った名前と、ワークスペースのルートからのパスの両方と照らし、高いほうの点数を取る。照らし方はコマンドの一覧と同じで、最近開いたシートには新しいものほど大きく加点する。上位 50 件を出し、一致した文字を太字にする。
- 各行に、名前（見出しがなければファイル名）と、薄くパスを出す。↑↓ で選び、↩ で選んでいるタブの中身と入れ替えて開き、⌘↩ で新しいタブに開く（[タブと分割](#タブと分割)）。Esc か一覧の外を押すと閉じる。
- 入力欄の先頭に `>` を打つと、コマンドの一覧に変わる。

## タブと分割

エディタの枠は、一つか、左右に並べた二つの **ペイン** に分かれる（[ADR 0024](adr/0024-tabs-and-split.md)）。
ペインは **タブ** の並びを持つ。タブは、一つのシート、まとめて開いた複数の章、プロジェクトのプロットのどれかを持つ。
右のパネル、ステータスバー、プレビュー、ツールバーは、選んでいるペインの選んでいるタブに従う。

- 同じシートは、すべてのペインとタブを通して一度だけ開く。開いているシートを開こうとすると、そのタブとペインを選び、まとめて開いた章の一つならその章に移る。
- ツリー、検索、診断、⌘P の ↩ は、選んでいるタブの中身を入れ替える。⌥ を押しながらツリーの行を押したとき、⌘P で ⌘↩ を押したとき、タブの並びの「＋」（⌘P を出す）から選んだときは、新しいタブとして開く。
- ⌘W（`file.closeTab`）とタブの × で、変更のあるシートを保存してからタブを閉じる。閉じたあとは右隣、なければ左隣のタブを選ぶ。最後のタブを閉じると空のペインになる。ウインドウを閉じるキーは ⇧⌘W とする。
- ⌃Tab と ⌃⇧Tab（`view.nextTab`、`view.prevTab`）で選んでいるペインのタブを巡り、⌘1 から ⌘9（`view.tab1` から `view.tab9`）でその番号のタブを選ぶ。タブはドラッグで並べ替え、ほかのペインへ移せる。
- `view.split`（「右に分ける」）で、選んでいるタブを右のペインに移す（[ADR 0037](adr/0037-split-conditions.md)）。タブが一つのペインは分けず、コマンドの一覧にも出さない。分けたあとは、選んでいるタブをもう一方のペインの末尾に移し、そのペインを選ぶ。左右のどちらのペインでも、タブを閉じるか移すかしてタブがなくなると、分割をやめ、残ったペインを選ぶ。ペインを押すとそのペインを選び、選んでいるペインのタブに印を付ける。ペインの幅はあいだの境目のドラッグで変え、`ui` の `splitRatio` に残す。
- 縦と横は画面全体で一つとし、各タブの本文がすべて縦書きにできる形式のときだけ縦にする。
- タブの右クリックのメニューの「Finder で表示」で、そのタブの焦点のあるシートを、プロットのタブではプロジェクトの `plot.csv` を Finder で表示する（[ADR 0053](adr/0053-reveal-in-finder.md)）。何も開いていないタブでは、メニューを出さない。
- タブを切り替えても、エディタは捨てずに隠しておくので、カーソル、スクロールの位置、取り消しの履歴は保たれる。タブは id を持ち、シートの名前を変えても同じエディタを使う。
- ワークスペースごとのタブの並び、選んでいるタブ、分割を `ui` の `tabs` に残し、起動したときに開き直す。開けないシートは飛ばし、残せるタブがなければ最近開いたシートの先頭を開く（[ADR 0026](adr/0026-recent-files.md)）。ワークスペースを切り替えると、タブは空になる。

## ウィキリンク

`.md` のシートの中で、`[[行き先]]`、`[[行き先|表示する文字]]`、`[[行き先#見出し]]`、`[[#見出し]]` をウィキリンクとする（[ADR 0027](adr/0027-wikilinks-in-markdown.md)）。
コードのスパンとコードブロックの中と、`\[[` は読まない。`.gm` の中には入れないが、`.gm` は行き先になれる。

- 行き先は、ワークスペースのテキストの形式のファイルから、パス（`/` か拡張子を含むとき。書いたシートのディレクトリから、次にワークスペースのルートから。拡張子がなければ `.md`）、拡張子を除いたファイル名（`.md`、`.gm`、ほかの順）、シートの名前（最初の見出し）の順に探す。NFC にそろえ、大文字と小文字は区別する。候補が複数あれば、同じディレクトリ、次にパスの近いもの、それでも決まらなければパスの順の最初を選び、情報の診断を出す。
- `#見出し` は、行き先の見出しの行を上から探す。見つからなければ先頭を開き、警告の診断を出す。見つからない行き先は、点線の下線を引き、警告の診断を出す。プレビューでは、見つからない行き先へのリンクを薄い色で出す。
- エディタでは、`[[`、`]]`、`#`、`|` を記号の色、行き先を別の色にする。⌘ を押しながらリンクを押すと行き先を開き、見つからない行き先では、書いたシートと同じディレクトリに `# 行き先` だけのシートを作るかを確かめる。`[[` の後ではシートのファイル名と名前を、`#` の後では行き先の見出しを補完する。
- 右のパネルの「リンク」に、開いているシートを指すリンクを、リンクを持つシートごとの見出し（名前とリンクの数、押すとそのシートを開く）の下に、行の番号と行の文字でまとめて出し（一つの行は一度だけ。シートはパスの順、行は番号の順。節の見出しにシートの数とリンクの数を出す、[ADR 0038](adr/0038-backlinks-by-sheet.md)）、`.md` ではそのシートから出るリンクも出す。押すとその行か行き先を開く。リンクの索引は、ツリーを読み直すときに作り、編集が 500 ミリ秒止まったときと保存したときに直す。
- プレビューでは、表示する文字（なければ行き先、見出しがあれば `行き先 > 見出し`）のリンクとして出し、押すと行き先を開く。gm への変換と字数では、表示する文字だけを残す。
- Aleph でファイルの名前を変えると、そのファイルをパスかファイル名で指していたリンクの件数を示して、書き換えるかを確かめる。開いているシートはエディタの一回の変更として書き換える。

## キーワード

シートに、書き手がキーワードを付けられる（[ADR 0028](adr/0028-keywords.md)）。
キーワードは、シートのメタデータ（`.aleph/notes.json`、[ADR 0012](adr/0012-sheet-goals-and-notes.md)）の `keywords` に、付けた順に置く。前後の空白を除き、NFC にそろえて比べ、同じものは一つにする。空の並びは書き出さない。

- 右のパネルの「添付」の「キーワード」に、このシートのキーワードを × つきで並べ、末尾の欄で ↩ を押すと足す。欄の候補は、同じルートのシートに付いているキーワードを、使われている数の多い順に出す。その下の「プロットから」に、プロットの行の視点人物、登場人物、場所、サブプロットを今までどおり出す（書き換えられない）。
- 左のサイドバーの「キーワード」のパネルに、今のワークスペースのすべてのルートのキーワードを、件数とともに名前の順に出す。プロットから読んだ名前も、列ごとの見出しの下に出す。押すと、そのキーワードを持つシート（プロットの名前なら、その名前を持つ行のシート）を出し、押すと開く。⌘ を押しながら押すと、選んだキーワードをすべて持つシートに絞る。
- キーワードの行の右クリックのメニューから、名前を変える（同じ名前があれば一つにまとめるかを確かめる）、すべてのシートから外す、ができる。
- ファイルの名前を変えると、メタデータのキーと一緒にキーワードも移る。

## 埋め込み

`.md` のシートで、行の全体が `![[行き先]]`、`![[行き先#見出し]]`、`![[画像のパス]]` のものを埋め込みとする（[ADR 0029](adr/0029-embeds.md)）。行き先の決め方はウィキリンクと同じで、行の途中の `![[…]]` はウィキリンクとして扱う。

- プレビューでは、埋め込みの行き先を先に読み（開いているシートはエディタの今の文字）、枠で囲んだ中身に置き換えて描く。枠の見出しに行き先のシートの名前（最初の見出し、なければファイル名。見出しがあれば `名前 > 見出し`）を出し、書いた行き先が名前と違うときは薄く添える（[ADR 0039](adr/0039-embed-frame-titles.md)）。見つからない行き先は書いた行き先を、画像はファイル名を出す。見出しを押すと行き先（見出しの行）を開く。
- 中身は、`.md` なら Markdown として描き、その中の埋め込みも置き換える。`.gm` は記号を取り除いた本文、そのほかのテキストは `<pre>`、PNG、JPEG、GIF、WebP、SVG は画像として出す。`#見出し` は、その見出しの行から、同じかより上の階層の次の見出しの前までとする。
- 入れ子は 3 段まで。それより深いものと、自分や祖先を埋め込むものは、「（入れ子が深すぎるため埋め込みません）」「（循環のため埋め込みません）」とだけ出す。一つのプレビューで埋め込む中身は合計 20 万字までとし、超えた分は「（長すぎるため省きました）」と出す。見つからない行き先と見出しは、その旨を枠の中に出す。
- 埋め込んだシートを保存すると、開いている Markdown のプレビューを描き直す。
- エディタでは、埋め込みの `!` も記号の色にし、行き先はウィキリンクと同じに出す。⌘ を押しながらの押下で行き先を開く。
- gm への変換では、画像の埋め込みを `@figure` に、シートの埋め込みを行き先の名前だけの段落にする。字数には埋め込みの中身を数えない。

## 文章の検査

`.gm`、`.md`、`.txt` の本文を、形態素の解析なしに判断できる規則で検査し、診断として出す（[ADR 0030](adr/0030-spelling-and-grammar.md)）。

- `.gm` は、命令の頭と引数、式、コメント、エスケープ、コードブロックを除いた文字（散文スロット、地の文、見出し）を、`.md` は、コード、リンクと画像の URL、ウィキリンクの行き先を除いた文字を、`.txt` は全体を検査する。除いた範囲をまたいで規則を当てない。
- 規則と重さ：ら抜き言葉（決まった一覧の動詞、情報）、表記ゆれ（「出来る」と「できる」などの組と、片仮名の末尾の長音の有無。少ないほうの書き方に、多いほうの数を添える。情報）、句読点の連続（警告）、全角の英数字（情報。縦組みのシート、つまりプロジェクトの `style.toml` が `writing-mode = "vertical"` のシートでは検査しない。`style.toml` を保存したら、そのプロジェクトの開いているシートを検査し直す。[ADR 0057](adr/0057-no-fullwidth-check-in-vertical.md)）、半角の片仮名（警告）、英語の綴り（macOS の `NSSpellChecker` に語の一覧を渡し、誤った語を返す。語ごとに覚える。情報）。
- 診断は出どころを分けて重ねる（`setDiagnostics(一覧, 出どころ)`）。LSP、ウィキリンク、検査の診断は互いに置き換えない。どれもステータスバーの「エラー n　警告 m」に数え、問題のパネルに出す（[ADR 0055](adr/0055-problems-panel.md)）。
- シートを開いたときと、入力が 700 ミリ秒止まったときに、文書の全体を検査する。30 万字を超えるシートは検査せず、ステータスバーに「長いため文章の検査をしていません」と出す。
- 設定の「文章の検査」で、全体と規則ごとのオンとオフ（既定はすべてオン）、英語の綴りで無視する語（1 行に 1 語、大文字と小文字は区別しない）を変える。値は `config.json` の `proofread` に置き、変えたら開いているエディタの検査をやり直す。形態素の解析が要る検査は [ロードマップ](roadmap.md) に載せた。

## 画像の貼り付け

クリップボードの画像を、エディタに ⌘V で貼り付けると、ファイルに書いてその参照を差し込む（[ADR 0031](adr/0031-paste-images.md)）。

- クリップボードに文字があれば、今までどおり文字だけを貼り付ける。文字がなく画像があるときだけ、画像として扱う。
- PNG と JPEG はそのまま、ほかの形式は PNG に直して、`pasted-YYYYMMDD-HHMMSS.png`（JPEG は `.jpg`）の名前で書く。同じ名前があれば `-2`、`-3` を付ける。
- `.gm` は、プロジェクトの章なら、プロジェクトの `images/` に書き、カーソルの行の後に `@figure` とキャプションの行を差し込む。プロジェクトの外の `.gm` には差し込まず、そのことを知らせる。`.md` は、シートのディレクトリの `images/` に書き、カーソルの行の後に `![名前](images/名前)` を、前後を空行で区切って差し込む。ほかの形式では何もせず、知らせる。
- 差し込みは一回の変更として当て、⌘Z で一度に戻せる。書いた画像は消さない。書いたあとはツリーを読み直す。
- 画像のバイト列は、生の本文として Rust に送って書く（JSON にしない）。

## ワークスペース全体の置換

左のサイドバーの「検索」に、置換の欄と「選んだものを置換」「すべて置換」を置く（[ADR 0032](adr/0032-replace-across-workspace.md)）。

- 置換の欄が空でないあいだは、各一致の行に、一致した文字を取り消し線で、置換の後の文字を強調で並べる。一致ごととファイルごとに、置換するかを選ぶ印を付ける（初めはすべて選ぶ）。
- 置換は検索と同じ Rust の `regex` で行う。正規表現では `$1`、`${1}`、`$name`、`${name}` を捕獲した文字に、`$$` を `$` にし、正規表現でない検索では置換の欄を文字のまま使う。開いているシートもディスクの上のファイルも、同じ処理で置換の後の文字を作る。
- 置換を始める前に、範囲の中の開いているシートを保存し、検索をし直す。選んだ一致は、ファイル、行、列、一致した文字で指し、位置の文字が変わっていれば飛ばして数える。「すべて置換」は、検索の 2000 件の打ち切りによらず、すべての一致を置換する。
- 置換の前に、ファイルと一致の数を示して確かめる。ワークスペースが Git のリポジトリなら「Git の変更から戻せます」、そうでなければ「ディスクの上のファイルの置換は元に戻せません」と添える。
- 開いているシートはエディタの一回の変更として当て（⌘Z で一度に戻せる）、保存する。開いていないファイルは Rust の側で置換して書き戻す。終わったら、置換したファイルと一致と飛ばした数を知らせ、ツリーと検索の結果を読み直し、置換した `.gm`、`.emet`、`.toml`、`.json` を含むプロジェクトごとに lint と preflight を一度ずつ走らせる（保存のあとの待ちは取り消す、[ADR 0041](adr/0041-checks-after-replacing.md)）。

## ゴミ箱

ツリーのシートとフォルダを、Aleph のゴミ箱に移し、あとから戻せる（[ADR 0033](adr/0033-trash.md)）。

- ゴミ箱はアプリの設定のディレクトリの `trash/` に置き、ワークスペースの中には置かない。移すたびに `trash/<日時と連番>/` を作り、消したものと `entry.json`（元のパス、日時、ワークスペース、種類、`manifest.toml` から外した章の項目と位置、`notes.json` から外したキーと値）を置く。
- ツリーの行の右クリックの「ゴミ箱に移す」か、ツリーで選んだシートで、ツールバーのメニューの「ゴミ箱に移す」または ⌘⌫（`file.trash`、エディタや入力欄に焦点があるときは引かない）で移す。ワークスペースそのものとプロットは移さない。フォルダは中のファイルの数を、プロジェクトはプロジェクトであることを示して確かめる。開いているシートは保存してからタブを閉じる。
- 章を移すときは、そのプロジェクトの `chapters` から項目を外し（入れ子の配列の中のものも。空になった入れ子は丸ごと）、書き方を保つ。シートのノートのキーも外す。移したあとは、ツリーを読み直し、通知の「戻す」でそのまま戻せる。
- 左のサイドバーの「ゴミ箱」に、新しい順に元の場所、種類、日時を出し、項目ごとに「戻す」と「完全に消す」、全体に「空にする」を置く。完全に消すときは、元に戻せないことを示して確かめる。
- 戻すときは元の場所に移し戻し、同じ名前があれば `-2` を付けて戻す。元の場所が登録したワークスペースの外なら戻さない（[ADR 0048](adr/0048-paths-in-arguments-and-data-files.md)）。章は記録した位置（並びが短くなっていれば末尾）に、名前を変えたときは新しいパスで戻す。ノートは、同じキーがなければ戻す。
- 起動のときに、消してから 30 日を過ぎた項目を消す。ボリュームをまたぐ移動は、複製してから元を消す。

## Markdown の改行と GFM

Markdown のプレビューの改行の扱いを設定で選び、GFM の拡張を読む（[ADR 0035](adr/0035-markdown-line-breaks-and-gfm.md)）。

- 設定の「エディタ」の「Markdown の改行」で、「改行をそのまま改行」（`config.json` の `markdownBreaks` が `"newline"`、既定）か「空行で改行」（`"blank-line"`、CommonMark。行末の空白 2 つか `\` だけが強制改行）を選ぶ。プレビュー（埋め込みの中身を含む）にだけ効き、どちらでも空行は段落を区切る。空行で改行するとき、前後のどちらかが日本語の文字の柔らかい改行は、空白を挟まずにつなぐ。gm への変換と字数は、この設定を見ない。
- GFM の取り消し線（`~~文~~`、`~` 1 つは文字のまま）、タスクリスト（項目の先頭の `[ ]`、`[x]`、`[X]` の後に空白。押せないチェックボックスで出す）、自動リンク（`<https://…>`、`<mailto:…>` と、文の中の `https://`、`http://`、`www.` で始まる URL。末尾の句読点と対のない閉じ括弧は含めない）、表の列の揃え（`:--`、`:-:`、`--:`）を読む。脚注は読まない。
- エディタでは、取り消し線を `t-del`、タスクリストの印をリストの印と同じ色、自動リンクをリンクの色にする。
- gm への変換では、取り消し線は中身の文字だけを、タスクリストの印は `☐` と `☑` を項目の先頭に、自動リンクは URL の文字を残す。字数では、取り消し線の中身を数え、タスクリストの印は数えない。

## コマンドとコマンドパレット

操作はコマンドとして一か所に登録する（[ADR 0023](adr/0023-command-palette.md)）。
コマンドは、`<領域>.<操作>` の形の ID（`file.save`、`view.left.search`、`editor.format` など）、名前、使えるかどうかの判定、実行の処理、既定のキー、ツールバーのメニューに出すかどうかを持つ。
ツールバーのメニュー（「…」）は、メニューに出すコマンドのうち使えるものを、名前と今の割り当ての初めのキー（⌃⌥⇧⌘ の順の記号、[キーの割り当て](#キーの割り当て)）で並べる。
設定の画面の各節も `settings.<節の ID>` のコマンドとして登録し、Aleph のプラグインのコマンドは `plugin.<名前>.<連番>` の ID で登録する。

- ⇧⌘P で、画面の上の中央に入力欄を出し、先頭に `>` を入れてコマンドを一覧にする。入力欄の先頭が `>` のあいだはコマンドを、そうでないときはシートを絞り込む（シートは [ADR 0022](adr/0022-quick-open.md)）。`>` の後の空白は読み飛ばす。
- コマンドの一覧には、今使えるものだけを出す。各行に、名前、ID、今の割り当ての初めのキーを出す。名前と ID のどちらとも、文字が同じ順に現れるかで照らし（大文字と小文字は区別しない）、続けて一致した文字、単語の先頭、ファイル名の部分での一致を高く数える。入力が空のときは、最近実行したもの（20 件まで、設定の `ui` に残す）を先に、残りを名前の順に出す。
- ↑↓ で選び、↩ で実行し、Esc か一覧の外を押すと閉じる。
- キーを押したときは、エディタの補完の一覧が開いていればそれが先に引き、残りを今の割り当て（[キーの割り当て](#キーの割り当て)）から引く。エディタのコマンド（`editor.*`）は、エディタに焦点があるときだけ引く。日本語の入力の変換中は引かない。
- エディタのコマンド（`editor.*`）は、パレットやメニューから実行すると、開いているシートのエディタにフォーカスを戻してから実行する。

## キーの割り当て

キーの割り当ては、コマンドの ID に結びつき、設定の「キーの割り当て」で変えられる（[ADR 0034](adr/0034-key-bindings.md)）。

- 割り当ては、一つ以上の打鍵の並びとする。打鍵は修飾キーとキーの組で、`Mod-Shift-k` のように Mod、Ctrl、Shift、Alt の順に書き、並びは空白で区切る（`Leader g c`）。文字のキーは、キーの位置（`KeyboardEvent.code`）から読むので、⌥ で文字が変わっても同じ打鍵になる。
- 並びの 1 打目は、⌘、⌃、⌥ のどれかを含む打鍵か、ファンクションキーでなくてはならない。2 打目からは、修飾キーのない文字のキーも使える。アプリのメニューのキー（⌘Q、⇧⌘W、⌘C、⌘V、⌘X、⌘M、⌘H、⌥⌘H、⌃⌘F）は割り当てられない。⌘W はタブを閉じるコマンド（`file.closeTab`）の既定のキーで、ほかの既定のキーと同じく変えられる（[ADR 0036](adr/0036-cmd-w-closes-a-tab.md)）。
- 割り当ての中の `Leader` は、設定のリーダーキー（既定は ⌘;）に読み替える。リーダーキーを変えると、`Leader` を含む割り当てはすべて新しいキーで呼ばれる。
- 押した並びがある割り当ての途中にあるあいだは、押したキーをエディタに渡さず、ステータスバーに押した並びを出して次の打鍵を待つ。待つ時間は設定の「続けて押すキーを待つ時間」（既定 1000 ミリ秒、200 から 5000）とする。時間が過ぎたら、そこまでの並びにちょうど当たる割り当てを実行し、当たらなければ何もしない。続きのどれにも当たらない打鍵を押したら、並びを捨て、その打鍵を改めて引く（文字のキーなら入力になる）。Esc は待つのをやめるだけである。短い割り当てが長い割り当ての先頭でもあるときは、時間が過ぎるまで実行しない。変換中は並びを始めず、待つあいだに変換が始まったら待つのをやめる。
- 設定の節では、コマンドの名前、ID、今の割り当てを一覧にし、名前で絞り込める。＋で続けて押した打鍵を記録し（待つ時間が過ぎるか ↩ で終わり、Esc でやめる）、× で外す。ほかのコマンドに割り当て済みのときは、置き換えるかを尋ねる。先頭が重なるときは、その旨を知らせ、一覧でもほかの割り当ての先頭と重なる割り当てに印（説明に相手の操作の名前）を出し、一覧の上に重なりの数を出す（[ADR 0040](adr/0040-key-overlap-marks.md)）。コマンドごとの「既定に戻す」と、全体の「すべて既定に戻す」（リーダーキーも戻す）を持つ。
- 利用者の割り当ては、`config.json` の `keyBindings` に、既定と違うコマンドだけを置く。リーダーキーは `leaderKey`、待つ時間は `keySequenceTimeout` に置く。読み込むとき、知らない ID と使えない割り当ては捨て、使えないリーダーキーは既定に戻す。
- ツールバーのメニューとパレットに出すキーは、今の割り当てから作る。

## エディタ

シートは、縦書きと横書きの両方を書ける一つのエディタで書く（[ADR 0019](adr/0019-one-editor-for-both-writing-modes.md)）。
エディタは CodeMirror などの部品を使わずに作り、`@codemirror/*` と `@lezer/*` には依存しない。

- 編集する部分は `contenteditable` の一つの要素で、原稿の 1 行を一つのブロックに描く。ツールバーの「縦」「横」で、本文（`.gm`、`.md`、`.txt`）の `writing-mode` を `vertical-rl` と `horizontal-tb` で切り替える。切り替えてもエディタは作り直さず、内容、カーソル、取り消しの履歴を保つ。
- 表示は仮想化する。見えている行と前後の余白の行だけを描き、ほかの行は大きさの合計を持つ空きの要素にする。行の大きさ（横書きでは高さ、縦書きでは幅）は描いたときに測り、まだ測っていない行は字数と 1 行の字数から見積もる。選択の両端と変換中の行は、見えていなくても描く。縦書きではスクロールが横の向きになり、開いたときは冒頭（右端）を出す。
- 本文の列の長さ（横書きでは幅、縦書きでは高さ）は、`style.toml` の `[page.grid] characters` の字数にする。設定の「1 行の字数」があればそれを使う。ほかの形式は 110 字まで広げる。
- 本文は明朝、それ以外（`.emet`、`.toml` など）は等幅で書く。`.gm` の中の命令の頭と引数、式は等幅にし、散文スロットは本文のフォントのままにする。文字サイズは本文とコードで別に、行間は本文に設定する。
- 溝には、HEAD からの変更の印（追加、変更、削除）、行番号、診断の印を並べる。横書きでは行の左に、縦書きでは行の上に出す。折り返した行では、最初の折り返しにそろえる。HEAD にないファイルは、すべての行を追加とする。
- `.gm` には、縦書きでも横書きでも、改ページが入る位置の見積もりの印（「改ページ（見積もり） 2 → 3」）を行のあいだに出す。段落の字数を字詰めで割った行数と、見出しの行数（第 1 階層は 3 行、ほかは 2 行）から数え、`@page-break` と `@column-break` の後では必ずページを改める。禁則、ルビ、行アキは数えない。
- 設定で、半角スペース（·）、全角スペース（□）、タブ（→）、改行（↵）を出せる。ゼロ幅の文字と制御文字は、設定によらず出す。
- `.gm`、`.emet`、`.md`、`.toml`、`.svg`、Mermaid に色付けを持つ。字句の読み方は形式ごとに行の状態を引き継ぎ、変わった行から状態が元と同じになる行まで読み直す。サーバー（[ADR 0009](adr/0009-lsp-and-formatting.md)）が応えるまでのあいだの `.gm` の色付けは、角括弧の入れ子を追う簡単な字句の読み方で行う。
- 文字の入力、削除、改行、貼り付け、⌘Z、⇧⌘Z は `beforeinput` などで受け、ブラウザに DOM を変えさせずに文書へ当てる。続けて打った文字は、入力が 500 ミリ秒止まるまで一つの取り消しにまとめる。整形、置換、`@figure` の差し込みは、それぞれ一つの取り消しとする。
- カーソルの移動と範囲の選択は、ブラウザに任せる。ただし縦書きの矢印キーは、エディタが受け持ち、見た目の向きに合わせる（[ADR 0059](adr/0059-arrow-keys-in-vertical-writing.md)）。↓↑ で行の中を次の字と前の字へ、←→ で次の行と前の行へ動く。⌥ を足すと ↓↑ は語、←→ は段落の端へ、⌘ を足すと ↓↑ は行の端、← は文書の末尾、→ は文書の頭へ動く。⇧ を足すと選択を伸ばす。変換中のキーと、補完のウィンドウが開いているあいだの ↑↓、⌃ を含むキーは、これまでどおりに扱う。
- 日本語の入力（IME）では、変換のあいだはブラウザに DOM を変えさせ、その行を描き直さない。ほかの描き直しは変換が終わるまで待たせ、選択も書き直さない（WebKit では、変換中に選択を書き直すと変換が終わる）。確定のとき、変換を始めたときの行の文字と、確定のあとの DOM の行の文字の差を一つの変更にする。選択した範囲の変換、取り消し、Enter での確定、変換中のフォーカスの移動も扱う。
- カーソルの移動と範囲の選択はブラウザに任せ、選択を文書の位置に直して持つ。列の外（字詰めの幅の右や、最後の行の後）を押したときは、エディタがいちばん近い行にカーソルを置く。描いていない行をまたぐ選択のコピー、切り取り、削除は、文書から行う。
- キーの割り当て（⌘S、⌥⇧F、⌘Z、⇧⌘Z、⌘A、⌘F、Tab、⇧Tab）は、文字に加えてキーの位置（`KeyboardEvent.code`）でも引く。Tab と ⇧Tab は、選択した行を 2 字の空白で字下げし、また戻す。
- ⌘F で検索と置換のパネルを出す。大文字と小文字の区別と正規表現を選べ、一致に印を付け、Enter で次へ、⇧Enter で前へ移る。「置換」は今の一致を、「すべて置換」はすべての一致を一回の変更で置き換える。選んだ短い文字列と同じ文字列にも印を付ける。
- ツリーで `.gm` を選び、shift を押して別の `.gm` を押すとその間の章を、⌘ を押して押すと 1 章ずつ足し引きして、まとめて開く。横書きでは章を上から下へ並べ、見出しを上に貼り付ける。縦書きでは縦書きのまま、章を右から左へ並べ、見出しを各章の右端に貼り付ける。「縦」「横」は、開いているシートがすべて本文のときに出す。
- 選択の背景と、入力欄、表のセル、検索の一致などの印は無彩色にし、アクセントの色は目標の円とオンのトグルにだけ使い（ADR の認める選択の文字には今は使っていない）、命令の色とも分ける（[ADR 0005](adr/0005-layout-and-appearance.md)）。
- ステータスバーに、字詰め（「38 字 × 16 行」）とカーソルの位置を出す。
- ツールバーのメニューの「IME のイベントを記録（開発用）」で、入力のイベント（`keydown`、`beforeinput`、`input`、変換のイベント、選択）を記録する画面を開く。「JSON を書き出す」で `/tmp/aleph-ime-log.json` に書き、その JSON を `app/ed/fixtures/` に置くと、エディタのテストがその列を再生して確かめる。

改ページの位置を正確に出すため、Golem に、PDF の各ページが原稿のどこから始まるかを出す機能を依頼する。
その機能が入るまでは、上の見積もりを使う。

## JSON の仲間

`.json`、`.jsonc`、`.json5`、`.jsonl` を、テキストとして開く形式として扱う（[ADR 0021](adr/0021-json-files.md)）。
ツリーに出し、エディタで開き、検索の対象にする。
形式は拡張子で決める。
エディタではコードとして等幅で書き、縦書きにはしない。

- **色付け**：キーの文字列、値の文字列、数、`true`・`false`・`null`、記号（`{ } [ ] : ,`）、コメントを分けて色を付ける。JSON5 の引用符のないキーはキーの色にし、`Infinity` と `NaN` は数の色にする。JSONC と JSON5 の行をまたぐ `/* */` のコメントと、JSON5 の `\` で続く文字列は、次の行に引き継ぐ。
- **文法の検査**：形式ごとの自前の読み方で、最初の誤りをエラーの診断として、位置（UTF-16）と理由とともに出す。JSON は RFC 8259、JSON5 は JSON5 1.0.0 に従う。JSONC はコメントを許し、末尾のカンマを警告にする。JSON Lines は行ごとに JSON として読み、行ごとに最初の誤りを出し、途中の空の行を誤りとする（末尾の改行は誤りにしない）。同じオブジェクトの中でキーが重なるときは、二つ目のキーに警告を出す。検査は入力が 300 ミリ秒止まったときに行う。ステータスバーには「エラー n　警告 m」を出し、診断は問題のパネルに出す（[ADR 0055](adr/0055-problems-panel.md)）。
- **整形**：字句の並びを読み直し、空白と改行だけを組み直す。数、文字列とその引用符、引用符のないキー、コメント、末尾のカンマは書かれたまま残し、キーの順も変えない。空白 2 つの字下げで、オブジェクトと配列の要素を 1 行に一つ置き、空のものは `{}` と `[]` にする。自分の行のコメントは自分の行に、行末のコメントは行末に残し、要素のあいだの空の行は一つにまとめて残す。JSON Lines は行ごとに、コロンとカンマの後に空白を一つ置いた 1 行の形にする。文書の末尾には改行を一つ置く。
- 整形は、⌥⇧F、ツールバーのメニューの「整形（⌥⇧F）」、⌘S（設定の「⌘S で整形する」がオンのとき）で、一回の変更として当てる。誤りがあるときは整形せず「JSON に誤りがあるため整形しません」と知らせ、⌘S では整形せずに保存する。自動保存では整形しない。
- プロジェクトの中の `.json` を保存したときは、`.toml` と同じく、2.5 秒たってから lint と preflight を実行する。

## LSP と整形

`.gm` と `.emet` は `golem lsp` とつなぐ（[ADR 0009](adr/0009-lsp-and-formatting.md)）。

- プロジェクトごとに一つ `golem lsp` を起動し、そのプロジェクトのシートを開いたすべてのエディタで共有する。そのプロジェクトのシートをすべて閉じて 10 分たったときと、アプリを終えるときに止める。起動に失敗するか途中で終わったときは、1 分たってから、次に開くか書いたときに起動し直す。
- `initialize` で位置の単位に UTF-16 を申し出る。サーバーからの要求には空の応答を返す。文書の URI は、パスの各部分をパーセントエンコードして作る。
- 開く、変える、保存する、閉じるを `didOpen`、`didChange`（入力が止まって 250 ミリ秒後に全文）、`didSave`、`didClose` で伝える。
- 診断は、縦書きでも横書きでも、重大度の色の波線と溝の印で出す。波線の上にポインタを置くと、その文言を出す。溝の診断の印にポインタを置くか印を押すと、範囲の始まりがその行にある診断を、出どころを問わず重大度の順にポップアップに出す（[ADR 0054](adr/0054-diagnostics-from-the-gutter-mark.md)）。範囲が改行だけの診断や幅のない診断も、ここで読める。印を押してもカーソルは動かない。ポップアップは、ポインタが印からもポップアップからも離れたとき、Esc、エディタの変更で閉じ、中の文字は選んでコピーできる。ステータスバーに、サーバーの状態（「● LSP」「LSP 起動中」「LSP 停止」）を出す。その左に、開いているシートの「エラー n　警告 m」を、LSP を持たない形式でも出どころを問わず数えて出す。数を押すと問題のパネルを開く（[ADR 0055](adr/0055-problems-panel.md)）。
- 色付けは、サーバーの semantic tokens を使う。型は Golem の `tools/editors/README.md` の表に合わせ、命令の部品（keyword、function、decorator、operator）を命令の色、値（string、number、variable など）を式の色、comment と `.gm` の macro（エスケープ）を薄い色、見出しの `#` を薄い色、見出しの文字（namespace）を太字にする。届くまでのあいだと、サーバーが使えないときは、簡単な字句の読み方の色を使う。
- 命令と式を等幅にする範囲は、semantic tokens の型の付いた部分と、簡単な字句の読み方で命令と式とした部分を合わせたものにする。今の Golem は、命令の角括弧や式の中の `.`、`(`、`)` などに型を付けないため、型だけでは範囲が決まらない。Golem に、これらの記号への型か修飾子を依頼する。
- ホバーはサーバーの文言を出す。補完は `[` と空白の後で始め、↑↓で選び、Enter か Tab で入れ、Esc で閉じる。Ctrl-Space で、どこでも始める。ホバーと補完の窓は、縦書きでも横書きで出す。
- 整形は、⌥⇧F とツールバーのメニューの「整形（⌥⇧F）」で、`textDocument/formatting` の結果を一回の変更として当てる。⌘Z で一度に戻せる。変わったときは「整形しました」、変わらなかったときは「変更はありません」と知らせる。サーバーが応えるのを待つあいだに書き足したときは、当てない。
- ⌘S は、設定の「⌘S で整形する」（既定はオン）がオンなら、整形してから保存する（JSON の仲間も同じ設定に従う）。⌥⇧F と同じく、変わったときは「整形しました」、変わらなかったときは「変更はありません」と知らせる。自動保存では整形しない。縦書きでも整形する。
- サーバーが使えないときは、保存したファイルに `golem fmt` を実行し、結果をエディタに読み直す。

## プレビュー

ツールバーの右の「原稿のみ」「本文」（`.md`、`.svg`、Mermaid では「プレビュー」）「ページ」で、エディタの右に出すものを選ぶ（[ADR 0010](adr/0010-previews.md)）。
描く処理は、スクロールする枠の中の要素に描き、枠そのもののクラスは変えない。

- **本文**：`.gm` を開いたときと保存したときに `golem build --target html` を実行し、章の XHTML の `body` の中身を出す。本文は、Golem が書く要素（見出し、段落、ルビ、強調、リスト、引用、表、図、`details` と `summary` の折りたたみなど）と属性（`class`、`id`、`lang`、`title`、`alt` など）だけで組み立て直し、ほかの要素は中の文字だけを、`script` や `iframe` などは中身ごと捨てる（[ADR 0043](adr/0043-golem-html-sanitizer.md)）。リンクは `#`、相対のパス、`http`、`https` だけを残す。画像は `build/html` の下を指すものだけを読み、外を指すものは代替テキストを出す。組んでいるあいだと組めなかったときは、前の結果を出したまま見出しに小さく示す。前の結果がないときは、記号を取り除いた本文を出す。縦と横の切り替えに従い、まとめて開いた章は並べて出す。
- **ページ**：`golem build --target pdf` のあと `shem render --dpi N` で各ページを PNG にし、縦に並べる。「ページ」を選んでいて組んだ結果がなければ、すぐ組む。保存したあとは、設定の「保存したらページを組みなおす」（既定はオン）に従って組み直す。ただし、そのプロジェクトのシートの最後の編集から 5 秒たつまで待ち、待っているあいだに編集があれば数え直し、重なった保存は一回の組み直しにまとめる（[ADR 0056](adr/0056-wait-before-building-pages.md)）。待っているあいだは、見出しに「入力が止まったら組みなおします」と出す。見出しのボタンと、組んだ結果がないときの最初の組み立て、解像度の変更による描き直しは待たない。見出しのボタンで組み直せる。
- **解像度**：設定の「ページの解像度」が空なら自動とし、`(枠の幅 − 36) × 画面の倍率 × max(1, 拡大率) ÷ ページの幅（インチ）` を切り上げ、72 から 1200 のあいだに収める。ページの幅は `style.toml` の `[page]` の `size`（Golem の判型の名前か `width`）に、`bleed` の 2 倍を足したものとする（Golem の PDF のページは塗り足しを含む）。書かれていなければ A5 とする。拡大や枠の広がりで足りなくなったら、PDF を組み直さず、shem で描き直す。
- **拡大縮小**：見出しのボタン、ピンチ、⌘ を押しながらのスクロールで、30% から 400% まで変える。100% は枠の幅とする。拡大率は見る人ごとに覚える。
- **Markdown**：自前の読み方（見出し、段落、強制改行、箇条書きと番号付きリストの入れ子、引用、コードブロック、表、区切り線、強調、斜体、インラインのコード、リンク、画像と、GFM の取り消し線、タスクリスト、自動リンク、表の列の揃え）で HTML にする（[Markdown の改行と GFM](#markdown-の改行と-gfm)）。HTML のタグは文字として出し、`javascript:` などの参照は無効にする。画像は、シートのフォルダからの相対のパスで、ワークスペースの中にあるものだけを読む。`http`、`https` などの外部の画像は読み込まず、代替テキストと URL を文字で出す（[ADR 0047](adr/0047-no-remote-images-in-previews.md)）。
- **SVG** は画像として出し、スクリプトは動かさない。**Mermaid** は Mermaid で描き、描いた図から外部の画像を取り除く。誤りは文言で出す。
- **PDF** と **画像** はエディタの代わりに出す。PDF は shem で描き、描けないものは WebView の表示に任せる。
- **別ウィンドウ**：本文とページの見出しのボタンで、別のウィンドウに出す。メインのウィンドウが組んだ結果をイベントで送り、ページのウィンドウは自分の幅と拡大率で足りなくなると、合う dpi で描き直すよう頼む。

## 保存と Git

シートの保存と Git は [ADR 0011](adr/0011-saving-and-git.md) に従う。

- 変更のあるシートを、設定の「自動保存の間隔」（既定 10 秒）ごとに保存する。⌘S ですぐに保存する（`.gm` と `.emet` の横書きでは、設定に従って整形してから保存する、[ADR 0009](adr/0009-lsp-and-formatting.md)）。
- シートを閉じたときと、ほかのシートを開いて入れ替わったときに、変更があれば保存する。ウィンドウを閉じるときと、メニューの「Aleph を終了」（⌘Q）では、画面の側が保存してから終える。画面の側が 5 秒のうちに応えなければ、そのまま終える。ほかのアプリから終了を求められたとき（Apple イベント）は、保存を待たずに終わる。
- 保存していない変更があるあいだは、ツールバーの題名の横に「●」を出す。
- 外部で変わったファイルに追従する（[ADR 0063](adr/0063-watch-files-changed-outside.md)）。
  - 保存の前に、そのファイルをディスクから読み、最後に読むか書いた中身と比べる。違えば書かず、下の「外部で変わったとき」に回す。ファイルがなければ書かず、「消えた」とする。自動保存、⌘S、整形してからの保存、シートを閉じるときの保存のどれも、この確かめを通す。比べるのは中身である。
  - 登録したワークスペースと共有ライブラリのフォルダを、macOS の FSEvents で見張る（FSEvents の C の API を Rust から直接呼ぶ自前のモジュール。外部のライブラリは使わない）。通知は専用のディスパッチキューで受け、0.2 秒のあいだのパスをまとめて画面に送る。プロジェクトの `build/` の下と `.git/` の下は送らず、`.git/HEAD`、`.git/index`、`.git/refs/` の下が変わったときは「Git の状態が変わった」として送る。見張りを始められなかったときは通知で知らせ、ウィンドウが前面に戻ったときに開いているシートを確かめる。
  - 外部で変わったとき、Aleph での変更がないシートは、ディスクの中身を一つの編集として読み込み（カーソルは同じ行と列）、「ほかのアプリで変更されたので読み込みなおしました」と通知する。Aleph での変更があるシートは、最後に読むか書いた中身、Aleph での変更、ほかのアプリでの変更の三つから、行を単位に合わせる（diff3）。食い違いがなければ、合わせた内容を入れ、「元に戻す」付きの通知を出す。食い違いがあれば、そのシートの保存を止め、消えない通知に「ほかのアプリの内容にする」「Aleph の内容で上書きする」「食い違いを直す」を置く。保存を止めているあいだの ⌘S は、同じ三つを選ぶダイアログを出す。
  - 「食い違いを直す」は、食い違いの箇所ごとに、前の 2 行と、「ほかのアプリでの変更」（左）と「Aleph での変更」（右）を並べ、元の内容から変わった字に色を付ける。箇所ごとに「左を使う」「右を使う」「両方残す」（Aleph、ほかのアプリの順）を選び（初めは右）、下に決まる全文を出す。「これで決める」で、決めた内容を一つの編集としてエディタに入れる。画面の文言に Git の言葉は使わない。
  - 開いているシートのファイルが消えたときは、エディタを閉じず、保存を止め、消えない通知に「閉じる」と「この内容で作りなおす」を置く。PDF と画像のシートは、ファイルが変わったら描きなおす。
  - 見張りの通知でワークスペースのファイルが変わったときは、0.5 秒のあいだの通知をまとめて、ツリーを読み直す。Git の状態が変わったときは、Git のパネルの状態とブランチ、変更の印を読み直す。
- 変更の印は、エディタの今の文書と HEAD の版を比べて出す。コミットと pull のあとは、比べる相手を新しい HEAD に取り直す。
- 1 日 1 回の自動コミット：起動時と 1 時間ごとに、登録したワークスペースごとに、その日にまだ自動でコミットしておらず、変更（未コミットのファイルか、保存していないシート）があれば、開いているシートを保存してから `git add -A` し、`Autosave YYYY-MM-DD`（その日の日付）でコミットする。コミットした日は設定に記録する。設定の「1 日 1 回自動でコミットする」で切れる（既定はオン）。Git のリポジトリでないワークスペースは飛ばす。
- 手動のコミット：左のサイドバーの Git のパネル、ツールバーのメニューの「コミット（⌘⇧K）」、⌘⇧K で、Git のパネルのメッセージ欄に移る。メッセージを書いてコミットのボタンか ⌘↩ を押すと、開いているシートを保存してから `git add -A` してコミットする。
- Git のパネル：現在のワークスペースの、変更のあるファイル（`git status --porcelain=v1 -z -uall`）、選んだファイルの `git diff HEAD`、コミットメッセージ、コミット、push、pull（`--no-rebase`）、直近 20 件の履歴を出す。ファイルを二度押すと開く。Git のリポジトリでなければ、`git init` のボタンを出す。
- ツリーでは、コミットしていない変更のあるファイルに点を出す。ツリーの上のワークスペースの名前の横に、現在のブランチを出す。
- git が使えるかは、起動したときに一度、見つけた git で `git --version` を走らせて確かめる（[ADR 0060](adr/0060-when-git-is-missing.md)）。終了コードが 0 で、出力が `git version` で始まれば使えるとする。macOS の `/usr/bin/git` は、Xcode のコマンドラインツールがなければ失敗するので、見つかっても使えるとは限らない。確かめなおすのは、設定で git のパスを変えたときと、Git のパネルの「確かめなおす」を押したときに限る。
- git が使えないときは、git を走らせない。Git のパネルには「git が使えません」と理由、入れ方の案内（`xcode-select --install` か Homebrew）、「確かめなおす」と「設定を開く」を出し、`git init` のボタンは出さない。自動コミットはせず、設定で自動コミットがオンなら、起動したときに一度だけそれを知らせる。溝の変更の印は出さない。置換の確認は、Git のリポジトリでないときと同じく「元に戻せません」とする。設定の「git のバイナリ」の説明に、使っている git のパスと版、使えないときは理由を出す。
- Aleph が走らせる git には、いつも `-c core.fsmonitor=false -c core.hooksPath=/dev/null` を付け、リポジトリの fsmonitor と hook を使わない（[ADR 0046](adr/0046-safe-automatic-git.md)）。状態を読むだけのもの（`status`、`diff`、`log`、`show`、`rev-parse`）には `--no-optional-locks` を、`diff` には `--no-ext-diff` も付ける。hook を使いたいときは、ターミナルからコミットする。

## プロットとガントチャート

プロットはプロジェクトの `plot.csv` に置き、表とガントチャートで編集する（[ADR 0013](adr/0013-plot-and-gantt-chart.md)）。
リボンの「プロット」と、ツリーの「プロット」の行（`plot.csv`）で、エディタの代わりに開く。

- CSV は RFC 4180 の引用の規則で読み書きする。1 行が 1 シーンで、空の行は読み飛ばす。
- 決まった列は `scene`（シーン）、`file`（ファイル）、`subplots`（サブプロット）、`pov`（視点人物）、`characters`（登場人物）、`place`（場所）、`must`（書かなくてはいけないこと）、`flavor`（フレーバー）、`target`（予定字数）、`memo`（メモ）、`fragments`（本文の断片）、`start`（開始）、`end`（終了）とする。見出しは英語で書き、画面には日本語の名前を出す。そのほかの見出しは足した列として、決まった列の後ろに見出しの順で並べる。書き出すときは、決まった列、足した列の順にする。
- 名前の並びの列（サブプロット、視点人物、登場人物、場所）は `;`、`；`、`、`、`,` と改行で、文の並びの列（書かなくてはいけないこと、フレーバー、本文の断片）は `;`、`；` と改行で区切る。
- 表のセルはその場で書き換え、0.4 秒後に保存する。列の幅は列ごとに決め、書き込む欄はセルいっぱいに広げる。メモと本文の断片の列をいちばん広くし、メモ、本文の断片、書かなくてはいけないこと、フレーバーの欄は、書いているあいだ 9 行ぶんの高さに広げる。「＋列」で列を足し（決まった列の英語と日本語の名前、足した列と重なる名前は使えない）、見出しの × で確かめてから消す。シーンは表の下の「シーンを足す」か、行の境目に近づくと出る「＋」で足し、左端のつまみのドラッグで並べ替える。行の × で確かめてから消す。サブプロットで絞り込み、絞り込んだまま足したシーンにはそのサブプロットを入れる。`file` のセルの矢印で開く（プロジェクトの外を指す `file` は開かない、[ADR 0048](adr/0048-paths-in-arguments-and-data-files.md)）。
- **暦**：`start` と `end` は任意の文字列とする。ガントの横軸の並びは `plot-calendar.txt` に早い順に 1 行に 1 つ書き、ガントの「暦」から編集する。暦のファイルがなければ、すべての時が日付（`YYYY`、`YYYY-MM`、`YYYY-MM-DD`）のときは日付の順に、すべてが数のときは値の順に並べる（4 桁の数は年として日付に数える）。それ以外（数と日付が混ざっているときや、どちらでもない文字列があるとき）は、表に出てくる順に並べる。暦のファイルにない時は、末尾に表に出てくる順で足す。
- **ガントチャート**：サブプロットごとの帯に、シーンを `start` から `end`（`end` を含む。なければ `start` の 1 つ分）までの棒で描く。同じ帯で時期の重なる棒は、始まりの早いものから順に、空いている最初の段に置く。収まらない名前は「…」で切り、マウスを乗せると名前と時期を出す。棒を押すとそのシーンのファイルを開く。右上のボタン、ピンチ、⌘ を押しながらのスクロールで、40% から 400% まで拡大縮小する。
- 表とガントはそれぞれ出し入れでき、少なくとも一方は出す。
- 見出しの矢印で、プロットを別のウィンドウに出す。保存するとイベントで知らせ、ほかのウィンドウのプロットを読み直し、メインのウィンドウの右のパネルとツリーを描き直す。別のウィンドウでファイルを開くと、メインのウィンドウで開く。

## シートの目標とノート

シートごとの目標、ノート、書くことのチェックは [ADR 0012](adr/0012-sheet-goals-and-notes.md) に従う。

- メタデータは、シートのプロジェクトの `.aleph/notes.json` に、プロジェクトの外のシートはワークスペースの `.aleph/notes.json` に、そのルートからのパスをキーとして置く。中身は、目標の字数（`goal`）、ノート（`note`）、チェックした書くこと（`done`）、キーワード（`keywords`、[キーワード](#キーワード)）である。中身のない項目は書き出さない。プロトタイプの複数のノート（`notes`）は、空行でつないで一つのノートとして読む。Aleph でファイルの名前を変えたら、キーも変える。
- 右のパネルの「添付」に、上から次のものを出す。
  - **目標**（本文のシートだけ）：今の字数と目標の字数を円で示し、残りと原稿用紙の枚数を添える。目標は欄に手で書くか、書かなければプロットのそのシートの行の予定字数の合計を使う。
  - **キーワード**：プロットのそのシートの行の、視点人物、登場人物、場所、サブプロット。
  - **書くこと**：「書かなくてはいけないこと」のチェックの一覧と、フレーバー。チェックの状態はメタデータに残す。
  - **プロットのメモと断片**。
  - **ノート**：一つのテキストエリアで、パネルの残りの高さを使う。
- 右のパネルの「アウトライン」に、`.gm` と `.md` の見出しを出し、押すとその行に移る。
- **数え方**：字数は、本文（`.gm` は命令、式、コメントを除いたもの、`.md` は記号を除いたもの）の空白を除いた文字の数とする。ワード数は `Intl.Segmenter` の単語とみなすものの数とする。原稿用紙の枚数は、段落ごとに字数を 1 行の字数で割って切り上げた行数を足し、1 枚の行数で割って小数第 1 位に丸める。既定は 20 字 20 行で、設定の「原稿用紙の換算」で変える。`.gm` の段落は、Golem の `paragraph-separator`（ファイルの `@manifest`、`chapters` の項目、`[source]`、既定の `blank-line` の順）に従って区切る。
- ステータスバーに、本文（`.gm`、`.md`、`.txt`）の字数、ワード数、原稿用紙の枚数を出す。
- ツリーの `.gm` に字数を添え、目標のあるシートには進み具合の小さな円を付ける。

## 共有ライブラリとアセット

フォント、プラグイン、関数の共有と、画像のアセットは [ADR 0014](adr/0014-shared-library-and-assets.md) に従う。

- **共有ライブラリ** は、設定の「共有ライブラリ」で選ぶ一つのフォルダで、`fonts/`、`plugins/`（`.wasm`）、`functions/`（`.emet`）を置く。設定の「作る」で、選んだ場所に `Aleph Library` と三つのフォルダを作る。
- プロジェクトにはコピーして入れる。プラグインを入れると、`manifest.toml` に `[plugins.<名前>]` と `path = "plugins/<名前>.wasm"` の宣言がなければ足す。関数の `@import` は書き手が書く。
- **フォント**：プロジェクトのシートを初めて開いたときと、`golem new --no-fonts` で作ったときに、`style.toml` が指すフォントのうちプロジェクトにないものを、共有ライブラリから同じ名前のものを探してコピーする。コピーしたときは、`LICENSE` で始まるファイルも `fonts/` にコピーする。メニューの「共有ライブラリのフォントをコピー」でも行う。
- 左のサイドバーの「共有ライブラリ」に、ファイルごとに、すべてのプロジェクトでの状態（同じものが入っている、中身が違う、入っていない）を出す。中身はバイトの列で比べ、どちらが新しいかは判断しない。プロジェクトの名前を押すとそこに、「すべてに入れる」で同じでないすべてのプロジェクトに入れる。中身が違うプロジェクトに入れるときは、上書きすることを確かめる。
- 右のパネルの「共有ライブラリ」には、開いているプロジェクトでの状態だけを出す。
- 共有ライブラリのパネル（左と右）にファイルを落とすと、拡張子で振り分けて共有ライブラリにコピーする（`.wasm` は `plugins/`、`.emet` は `functions/`、フォントと `LICENSE` で始まるファイルは `fonts/`）。扱えないファイルは通知で知らせる。
- `.gm` のエディタに画像（PNG、JPEG、SVG、PDF）を落とすと、プロジェクトの `images/` にコピーし、落とした行の後に `@figure images/<名前> alt="<名前>"` と字下げした「キャプション」の行を差し込む。ツリーのフォルダ（ファイルならそのフォルダ）に落とすと、そこにコピーする。同じ名前があれば、`-2`、`-3` を付けて上書きしない。
- ツリーの画像（PNG、JPEG、SVG、PDF）の行を押したまま 4 ピクセル以上動かすと、ドラッグになる（[ADR 0018](adr/0018-drag-image-from-tree.md)）。`.gm` のエディタの上では差し込む位置に線（縦書きでは行の左の縦の線）を出し、離すとポインタの下の行の後に `@figure` と字下げしたキャプションの行を一回の変更として差し込む。その章と同じプロジェクトの画像はコピーせずにプロジェクトのルートからのパスを書き、ほかの画像は `images/` に名前の衝突を避けてコピーしてから書く。`.gm` でないエディタとプロジェクトの外の `.gm` では差し込まず、理由を知らせる。縦書きのエディタにも差し込める（[ADR 0019](adr/0019-one-editor-for-both-writing-modes.md)）。Esc で取り消す。動かさずに離せば、今までどおり画像を開く。
- `@figure` を差し込むとき、文字のある行の後なら前に空行を置き、続く行が空行でなければ後にも空行を置く。

## ビルド

選んでいるシートの Golem のプロジェクトを、Aleph から `golem build` でビルドする（[ADR 0058](adr/0058-build-from-aleph.md)）。

- ツールバーのビルドのボタン（金槌）か `project.buildOptions`（「ビルドの設定」）で、ポップアップを開く。ターゲット（すべて、pdf、html、epub、text、既定はすべて）、プロファイル（dev、prod、既定は dev）、トンボ（なし、日本式、西洋式、既定はなし。ターゲットがすべてか pdf のときだけ出す）を選び、「ビルド」で走らせる。「build/ を Finder で表示」で出力のフォルダを開く。Esc かポップアップの外を押すと閉じる。
- 選んだものは `ui` の `buildOptions` に残し、形の違う値は既定に戻す。`project.build`（「ビルド」、⇧⌘B）は、ポップアップを開かずに残した選択でビルドする。
- 引数は `golem build --format json --no-notices --profile <p>` に、すべて以外なら `--target <t>`、トンボがなし以外でターゲットがすべてか pdf なら `--marks <m>` を足す。
- 同じプロジェクトのビルドは一つずつ走らせ、走っているあいだの頼みは、終わったあとの一回にまとめる。プレビューの `golem build`（本文とページ）を含め、プロジェクトの `build/` に書く golem は一つずつ走らせる。
- ステータスバーの lint と preflight の右に「● build」を出す。走っているあいだは薄く、終わったらエラーか失敗で赤、警告で黄、それ以外は緑とし、かかった秒数を添える。押すと下部パネルにそのプロジェクトの最新の手動ビルドのログを開く。実行中は引数と実行中の表示を出し、終了後は終了コード、標準出力、標準エラー出力を分けて表示する。起動に失敗した場合は理由を表示する（[ADR 0069](adr/0069-build-log-and-reveal.md)）。一度もビルドしていなければ出さない。
- 診断は出どころ `build` として問題のパネルに出す。標準エラー出力が JSON の配列として読めないときは失敗とし、出力の先頭の 20 行を位置のない診断にする。成功したら「ビルドしました（n 秒）」、エラーがあれば「ビルドでエラーが n 件あります」、失敗したら「ビルドできませんでした」と通知し、エラーか失敗のときは問題のパネルを開く。成功通知の「Finder で表示」は、そのビルドの出力先 `build/` を Finder で選択する。

## 診断と検索

check、lint、preflight の診断と検索は [ADR 0015](adr/0015-diagnostics-and-search.md) に従う。

- 左のサイドバーの「診断」で、プロジェクトを選び、check、lint、preflight のどれかを実行する。`golem <種類> --format json` の JSON を標準エラー出力から読み、check と lint には `-v` を付ける（preflight には付けない）。JSON の配列として読めないときは、出力をそのまま出す。
- 結果はファイルごとにまとめ、重大度（error、warning、notice、info）、ファイル、行、列の順に並べる。各項目に重大度の印、文言、コード、行と列、`facts`、関連の情報を出し、押すとその位置を開く。
- ステータスバーの LSP の隣に lint と preflight を出す。色は、エラーがあれば赤、警告があれば黄、notice があれば青、それ以外は緑とし、実行できなかったときは赤とする。件数は error、warning、notice の合計で、info は数えない。実行していないときは色を付けず、実行中は薄くする。押すと、問題のパネルを開く（[ADR 0055](adr/0055-problems-panel.md)）。左のサイドバーの「診断」は、プロジェクトを選んで実行し、結果を読む場所として残す。
- プロジェクトのシートを初めて開いたときと、`.gm`、`.emet`、`.toml`、`.json` を保存して 2.5 秒たったときに、lint、preflight の順に裏で実行する。check はパネルからだけ実行する。
- 左のサイドバーの「検索」（⌘⇧F）で、このプロジェクト、このワークスペース、すべてのワークスペースのどれかを範囲に、正規表現と大文字と小文字の区別を切り替えて検索する。検索は Rust の側で、`.gitignore` に従い、Aleph がテキストとして開く形式のファイルだけを読み、2000 件で打ち切る。結果はファイルごとに、一致した部分の前後 40 字とともに出し、押すとその位置を開く。入力欄は描き直さず、結果だけを描き直す。


### 問題のパネル

エディタのペインの下、ステータスバーの上に **問題のパネル** を置き、診断をまとめて読む（[ADR 0055](adr/0055-problems-panel.md)）。

- 開いているすべてのシートのエディタの診断（LSP、ウィキリンク、文章の検査、JSON の検査）と、選んでいるシートのプロジェクトの最後の `check`、`lint`、`preflight` の結果を、ファイルごとにまとめて出す。選んでいるシートのファイルを先に、ほかはワークスペースからの相対パスの順に並べ、位置のない診断は「（位置のない診断）」にまとめる。ファイルの中は行、列の順とし、同じファイルの同じ位置の同じ文言は一つにまとめる。実行できなかった結果は出さない。
- 各行に、重大度の印、文言、出どころとコード、行と列を出す。行を押すと、そのファイルを開いてその位置に移る。
- 見出しに、「問題」と「通知」の二つのタブを置く（[ADR 0064](adr/0064-unified-notifications.md)）。「問題」の横に、エラー、警告、そのほかの数を出す。右端の × で閉じる。ステータスバーの「エラー n　警告 m」、lint、preflight を押すと開く。`view.problems`（「問題のパネル」、⇧⌘M）で開け閉めする。パネルに焦点があるときは Esc で閉じる。最後に選んだタブを `ui` の `problemsTab` に残す。
- 「通知」のタブは、出した通知の履歴を、消えたものも閉じたものも含めて新しい順に一行ずつ出す。各行は、重大さのアイコン、時刻（時、分、秒）、文（選んでコピーできる）を持つ。画面に出ている消えない通知の行には、その通知と同じボタンを出す。同じ鍵で置き換えられた通知は一行にまとめ、回数（×2 など）を添える。タブの名前の横に、最後に見てから出た通知の数を出し、エラーがあれば数をエラーの色にする。タブを見ると数を消す。「履歴を消す」で、画面に出ている通知のほかを消す。履歴は起動のあいだだけ持ち、500 件までとする。`view.notifications`（「通知の履歴を表示」）で、パネルを開いて「通知」のタブを選ぶ。
- 上の境目のドラッグで高さを変える。高さ（既定 220 ピクセル、80 ピクセルから中央の列の 70% まで）と開いているかを `ui` の `problemsHeight`、`showProblems` に残す。
- エディタの下に開いていた「エディタの診断の一覧」と、そのコマンド（`editor.diagnostics`）はなくした。

## Markdown から gm への変換

`.md` のシートで、ツールバーのメニューかツリーの右クリックの「gm に変換」を選ぶと、同じディレクトリに同じ名前の `.gm` を作る（[ADR 0016](adr/0016-markdown-to-gm.md)、[ADR 0065](adr/0065-tree-create-and-convert.md)）。右クリックではその行の md を使い、開いているなら編集中の本文から変換する。

- 同じ名前の `.gm` があれば、上書きするかを確かめる。プロジェクトの中なら、作った `.gm` を `manifest.toml` の `chapters` の末尾に足し、`golem check` を実行して、作った章にエラーがあるか実行できなかったときは診断のパネルに出す。
- 読み方は Markdown のプレビューと同じ自前の読み方を使う。
- 見出しはそのまま（末尾の `#` は除く）、箇条書きは `- `（入れ子は空白 2 つの字下げ）、番号付きリストは `+ `、強調は `[strong: …]`、斜体は `[italic: …]`、インラインのコードは `[code: …]` にする。リンクは文字だけを残し、画像だけの行は `@figure パス alt="…"` にする。引用は記号を除いて段落にし、区切り線は空行にする。表とコードブロックはそのまま残す。行末の空白 2 つ（と `\`）の強制改行は行末の `\` にする。
- エスケープ：地の文の `[` と `\` の前に `\` を付け、`%%` は `\%%`、`##` の直後に ASCII の数字が続くときは `\##` にする。強調、斜体、コードの中身では、`]` と `|` にも `\` を付ける。段落の行頭が `#`、`-`、`+`、`=`、`@`、`|` になるときは、最初の文字の前に `\` を付ける。
- 段落：作る `.gm` を読む様式（プロジェクトの `paragraph-separator`。プロジェクトの外では空行の様式）が改行の様式なら、一つの段落の行をつないで一行にする（強制改行の行の終わりは残す）。空行の様式なら、行をそのまま残す。

## Aleph のプラグイン

Aleph の画面に機能を足すプラグインは [ADR 0017](adr/0017-aleph-plugins.md) に従う（Golem の `.wasm` のプラグインは共有ライブラリで扱う）。

- アプリの設定のディレクトリの `plugins/` にある `.js`（ES モジュール）を、起動して画面を描いたあとに名前の順で読み込み、書き出した `activate(aleph)` を呼ぶ。
- `aleph` は、`version`（API の版、今は 1）、`registerCommand(名前, 処理)`（ツールバーのメニューに項目を足す）、`registerStatus(処理)`（ステータスバーに文字を足す）、`onSave(処理)`（保存したあとに呼ぶ）、`toast(文言)` を持つ。処理には、開いているシートのパス、形式、本文、プロジェクトを渡す。本文を書き換える API はない。互換を壊す変更をするときは版を上げる。
- 読み込みか `activate` が失敗したプラグイン（例外、`activate` のないモジュール、構文の誤り）は、それが登録したものを外して無効にし、通知と設定の画面に理由を出す。ほかのプラグインは読み続ける。プラグインの処理が例外を投げたときは、通知を出すかその項目を出さずに続ける。
- 設定の「Aleph のプラグイン」に、フォルダの場所、プラグインが Aleph と同じ権限で動く旨の注意、読み込んだプラグインの一覧と状態を出す。プラグインごとに有効と無効を切り替えられ（設定の `disabledPlugins` に残す）、「読みなおす」でフォルダを読み直す。
- 「追加…」を押すと、Rust の側がネイティブのダイアログで `.js` を一つ選ばせ、ファイル名と注意を出して確かめてから、プラグインのフォルダに写して読み直す（[ADR 0042](adr/0042-ipc-trust-boundary.md)）。同じ名前があれば、置き換えるかを確かめる。画面からプラグインのフォルダには書けないので、確かめずに入ることはない。
- 各プラグインの「外す」は、Rust の側の確認のあとでフォルダから消す。「フォルダを開く」は、フォルダを Finder で開く。フォルダに直に置いたファイルも、読み直すと読む。Aleph の中でプラグインを編集する機能はない。

## 破棄した ADR

なし。
