# Aleph 仕様書

Aleph は、Golem（https://github.com/tett23/golem ）の原稿を書き、組まれた姿を確かめ、作品の構成を管理するためのデスクトップアプリである（[ADR 0002](adr/0002-purpose-scope-and-name.md)）。
Tauri 2 で作り、画面を TypeScript、ファイルとプロセスを Rust で扱う（[ADR 0003](adr/0003-application-architecture.md)）。
リポジトリの名前は `aleph` とする。

この文書は、Aleph の今の振る舞いを定める。
設計の決定は `docs/adr/` に連番の ADR として置く。

## アプリの構成

Aleph は Tauri 2 のアプリで、画面を TypeScript（`app/`）、ファイルと外部のプロセスを Rust（`src-tauri/`）で扱う（[ADR 0003](adr/0003-application-architecture.md)）。

- 画面の状態（ワークスペース、開いているシートの並び、選択、パネルの表示）は一つの値で持ち、操作を受けて新しい状態を返す関数（リデューサー）だけで変える。開いているシートは、一つでも配列で持つ。
- Rust の側は、ファイルの読み書き、ディレクトリの一覧、外部のプロセスの実行を受け持つ。外部のプロセスは引数を配列で渡し、シェルを通さない。
- git は、設定の値、`/usr/bin`、Homebrew（`/opt/homebrew/bin`）、PATH の順に探す。設定の値があれば、ほかの場所は探さない。macOS の GUI アプリはログインシェルの PATH を受け継がないためである。
- アイコンは、使うものだけを `app/icons/` に SVG で置く（lucide、ISC ライセンス）。
- テストは、TypeScript は `node --test`（Node が型を取り除いて実行する）、Rust は `cargo test` で書く。CI の `app` のジョブが macOS で、型検査、`node --test`、Vite のビルド、rustfmt、clippy、`cargo test` を実行する。

## 画面の構成

画面は、左から次の順に並ぶ（[ADR 0005](adr/0005-layout-and-appearance.md)）。

- **リボン**：左のサイドバーに出すもの（ファイル、検索、Git、診断、共有ライブラリ）を切り替えるアイコンと、プロットを開くアイコン、設定を開くアイコン。同じアイコンをもう一度押すと、サイドバーを畳む。
- **左のサイドバー**：上にワークスペースの名前があり、押すとワークスペースを切り替えるメニューが出る。その下に、リボンで選んだものを出す。
- **中央**：上にツールバー、その下にエディタとプレビューを左右に並べ、下にステータスバーを置く。ツールバーは、エディタに効く「縦」「横」を左に、プレビューを選ぶ「原稿のみ」「本文」「ページ」を右に置く。形式が持たない切り替えは出さない。
- **右のパネル**：添付、アウトライン、そのプロジェクトの共有ライブラリを、上のアイコンで切り替える。ツールバーの右端のアイコンで畳む。

外観はライト、ダーク、OS に合わせる（既定）のどれかを設定で選ぶ。
アクセントの色は彩度を落とした黄土色とし、選択の背景は無彩色とする。
パネルの表示の状態（どのパネルか、畳んだか、縦と横、プレビュー）は、次に起動したときに戻す。

## ワークスペースとプロジェクト

**ワークスペース** は、設定で登録したディレクトリである（[ADR 0004](adr/0004-workspaces-and-projects.md)）。
複数を登録でき、左のサイドバーの上の名前から切り替える。
ワークスペースの中で `manifest.toml` を持つディレクトリを、深さによらず **プロジェクト** とする。
プロジェクトの中の `manifest.toml` は無視する。

左のサイドバーの「ファイル」には、ワークスペースのツリーを出す。

- `.` で始まるもの、`build/`、`node_modules/`、`target/`、`dist/` は出さない。Aleph が開けない形式のファイルも出さない。
- プロジェクトの中は、`manifest.toml` の `chapters` に並んだ章をその順で先に出し、次に `plot.csv` を「プロット」として、そのあとにほかのファイルとディレクトリを出す。`chapters` の項目は、文字列、`file` を持つ表、入れ子の配列のどれでもよい。
- `.gm` と `.md` は最初の見出しを名前として出し、ファイル名を小さく添える。
- 新しいシートは、プロジェクトの中なら `chapters/NN.gm` として作り、`chapters` の末尾に足す。足すときは配列の書き方（一行か、一行に一項目か）を保つ。プロジェクトの外では、開いているシートと同じディレクトリに作る。
- ファイルの名前は、ダブルクリックで変える。消す操作は持たない。
- 新しいプロジェクトは `golem new` で作る。共有ライブラリを設定していれば `--no-fonts` を付け、フォントは共有ライブラリからコピーする（[ADR 0014](adr/0014-shared-library-and-assets.md)）。

アプリの設定は、アプリの設定のディレクトリ（macOS では `~/Library/Application Support/dev.tett23.aleph/`）の `config.json` に置く。
読み込むとき、形の違う値は既定に戻し、範囲のある値（文字サイズ、行間、自動保存の間隔など）は上限と下限に丸める。

メインのウィンドウの位置と大きさは、動かしたとき、大きさを変えたとき、閉じるとき、アプリを終えるときに `window.json` に記録する。
起動したとき、記録した矩形がどれかのディスプレイに収まり、幅 400、高さ 300 の画素より大きければ戻し、そうでなければ既定の大きさで中央に置く。

## Golem と shem

Aleph は、組版、診断、整形、LSP を golem に、PDF のラスタライズを shem に任せる（[ADR 0008](adr/0008-golem-and-shem-binaries.md)）。
それぞれ、次の順に探して最初に見つかったものを使う。

1. 設定の値（絶対パス）。設定した場所になければ、ほかの場所は探さない。
2. アプリに同梱したもの（アプリのリソースの `resources/golem`、`resources/shem`）
3. `~/.local/bin`
4. Homebrew（`/opt/homebrew/bin`）
5. PATH

設定の「Golem と shem」に、使っているバイナリのパスと `--version` の出力を出し、同梱の版と違えば同梱の版も出す。
見つからないときは、探した場所を出す。

同梱する版は、リポジトリの根の `tools.versions` に書く。
`scripts/bundle-tools.sh` が、GitHub Releases から配布物と `SHA256SUMS` を取り、照合してから、バイナリとライセンスを `src-tauri/resources/` に入れる。
照合に失敗すれば止まり、何も入れない。

## 横書きのエディタ

シートは CodeMirror 6 のエディタで書く（[ADR 0006](adr/0006-horizontal-editor.md)）。

- 本文（`.gm`、`.md`、`.txt`）の列の幅は、`style.toml` の `[page.grid] characters` の字数にする。設定の「1 行の字数」があればそれを使う。ほかの形式は 110 字まで広げる。
- 本文は明朝、それ以外（`.emet`、`.toml` など）は等幅で書く。`.gm` の中の命令の頭と引数、式は等幅にし、散文スロットは本文のフォントのままにする。文字サイズは本文とコードで別に、行間は本文に設定する。
- 溝には、左から、HEAD からの変更の印（追加、変更、削除）、行番号、診断の印を並べる。折り返した行では、行番号を 1 行目の高さにそろえる。HEAD にないファイルは、すべての行を追加とする。
- `.gm` には、改ページが入る位置の見積もりの印（「改ページ（見積もり） 2 → 3」）を出す。段落の字数を字詰めで割った行数と、見出しの行数（第 1 階層は 3 行、ほかは 2 行）から数え、`@page-break` と `@column-break` の後では必ずページを改める。禁則、ルビ、行アキは数えない。
- 設定で、半角スペース（·）、全角スペース（□）、タブ（→）、改行（↵）を出せる。ゼロ幅の文字と制御文字は、設定によらず出す。
- ツリーで `.gm` を選び、shift を押して別の `.gm` を押すとその間の章を、⌘ を押して押すと 1 章ずつ足し引きして、まとめて開く。エディタは章ごとに縦に並び、見出しを上に貼り付ける。まとめて開いたあいだは横書きで書く。
- サーバー（[ADR 0009](adr/0009-lsp-and-formatting.md)）が応えるまでのあいだの `.gm` の色付けは、角括弧の入れ子を追う簡単な字句の読み方で行う。
- ステータスバーに、字詰め（「38 字 × 16 行」）とカーソルの位置を出す。

改ページの位置を正確に出すため、Golem に、PDF の各ページが原稿のどこから始まるかを出す機能を依頼する。
その機能が入るまでは、上の見積もりを使う。

## 縦書きのエディタ

ツールバーの「縦」で、本文（`.gm`、`.md`、`.txt`）を縦書きで書く（[ADR 0007](adr/0007-vertical-editor.md)）。

- テキストエリアを `writing-mode: vertical-rl` にし、その裏に同じ字詰めの影の層を重ねる。影の層は原稿の各行を一つのブロックとして置き、各行の上に行番号を、その上に HEAD からの変更の印を出す。折り返した行では、1 列目の上にだけ番号を出す。
- 列の高さは字詰めの字数に合わせる。テキストエリアは中でスクロールさせず、文字の量に合わせて横に伸ばし、外側の枠を右端からスクロールさせる。開いたときは冒頭を出す。
- 縦書きでは色付けをせず、LSP の波線、溝の印、ホバー、補完も出さない。⌘S は整形せずに保存する。
- 複数の章をまとめて開いたときは、縦書きにしない。

## LSP と整形

`.gm` と `.emet` は `golem lsp` とつなぐ（[ADR 0009](adr/0009-lsp-and-formatting.md)）。

- プロジェクトごとに一つ `golem lsp` を起動し、そのプロジェクトのシートを開いたすべてのエディタで共有する。そのプロジェクトのシートをすべて閉じて 10 分たったときと、アプリを終えるときに止める。起動に失敗するか途中で終わったときは、1 分たってから、次に開くか書いたときに起動し直す。
- `initialize` で位置の単位に UTF-16 を申し出る。サーバーからの要求には空の応答を返す。文書の URI は、パスの各部分をパーセントエンコードして作る。
- 開く、変える、保存する、閉じるを `didOpen`、`didChange`（入力が止まって 250 ミリ秒後に全文）、`didSave`、`didClose` で伝える。これは画面の状態から送るので、縦書きで書いているあいだも伝わる。
- 診断は、重大度の色の波線と溝の印で出す。ステータスバーに、開いているシートの「エラー n　警告 m」と、サーバーの状態（「● LSP」「LSP 起動中」「LSP 停止」）を出す。数を押すと、エディタの下に **エディタの診断の一覧** を開き、項目を選ぶとその位置に移る。縦書きでは一覧を開かず、横書きで開くよう知らせる。
- 色付けは、サーバーの semantic tokens を使う。型は Golem の `tools/editors/README.md` の表に合わせ、命令の部品（keyword、function、decorator、operator）を命令の色、値（string、number、variable など）を式の色、comment と `.gm` の macro（エスケープ）を薄い色、見出しの `#` を薄い色、見出しの文字（namespace）を太字にする。届くまでのあいだと、サーバーが使えないときは、簡単な字句の読み方の色を使う。
- 命令と式を等幅にする範囲は、semantic tokens の型の付いた部分と、簡単な字句の読み方で命令と式とした部分を合わせたものにする。今の Golem は、命令の角括弧や式の中の `.`、`(`、`)` などに型を付けないため、型だけでは範囲が決まらない。Golem に、これらの記号への型か修飾子を依頼する。
- ホバーはサーバーの文言を出す。補完は `[` と空白の後で始める。
- 整形は、⌥⇧F とツールバーのメニューの「整形（⌥⇧F）」で、`textDocument/formatting` の結果を一回の変更として当てる。⌘Z で一度に戻せる。変わったときは「整形しました」、変わらなかったときは「変更はありません」と知らせる。サーバーが応えるのを待つあいだに書き足したときは、当てない。
- ⌘S は、設定の「⌘S で整形する」（既定はオン）がオンなら、整形してから保存する。変わったときだけ「整形しました」と知らせる。自動保存と縦書きでは整形しない。
- サーバーが使えないときは、保存したファイルに `golem fmt` を実行し、結果をエディタに読み直す。

## プレビュー

ツールバーの右の「原稿のみ」「本文」（`.md`、`.svg`、Mermaid では「プレビュー」）「ページ」で、エディタの右に出すものを選ぶ（[ADR 0010](adr/0010-previews.md)）。
描く処理は、スクロールする枠の中の要素に描き、枠そのもののクラスは変えない。

- **本文**：`.gm` を開いたときと保存したときに `golem build --target html` を実行し、章の XHTML の `body` の中身を出す。`script`、`style`、`link` の要素、イベントの属性、`javascript:` の参照は除き、画像は `build/html` から読む。組んでいるあいだと組めなかったときは、前の結果を出したまま見出しに小さく示す。前の結果がないときは、記号を取り除いた本文を出す。縦と横の切り替えに従い、まとめて開いた章は並べて出す。
- **ページ**：`golem build --target pdf` のあと `shem render --dpi N` で各ページを PNG にし、縦に並べる。「ページ」を選んでいて組んだ結果がなければ、すぐ組む。保存したあとは、設定の「保存したらページを組みなおす」（既定はオン）に従って組み直す。見出しのボタンで組み直せる。
- **解像度**：設定の「ページの解像度」が空なら自動とし、`(枠の幅 − 36) × 画面の倍率 × max(1, 拡大率) ÷ ページの幅（インチ）` を切り上げ、72 から 1200 のあいだに収める。ページの幅は `style.toml` の `[page]` の `size`（Golem の判型の名前か `width`）に、`bleed` の 2 倍を足したものとする（Golem の PDF のページは塗り足しを含む）。書かれていなければ A5 とする。拡大や枠の広がりで足りなくなったら、PDF を組み直さず、shem で描き直す。
- **拡大縮小**：見出しのボタン、ピンチ、⌘ を押しながらのスクロールで、30% から 400% まで変える。100% は枠の幅とする。拡大率は見る人ごとに覚える。
- **Markdown**：自前の読み方（見出し、段落、強制改行、箇条書きと番号付きリストの入れ子、引用、コードブロック、表、区切り線、強調、斜体、インラインのコード、リンク、画像）で HTML にする。HTML のタグは文字として出し、`javascript:` などの参照は無効にする。
- **SVG** は画像として出し、スクリプトは動かさない。**Mermaid** は Mermaid で描き、誤りは文言で出す。
- **PDF** と **画像** はエディタの代わりに出す。PDF は shem で描き、描けないものは WebView の表示に任せる。
- **別ウィンドウ**：本文とページの見出しのボタンで、別のウィンドウに出す。メインのウィンドウが組んだ結果をイベントで送り、ページのウィンドウは自分の幅と拡大率で足りなくなると、合う dpi で描き直すよう頼む。

## 保存と Git

シートの保存と Git は [ADR 0011](adr/0011-saving-and-git.md) に従う。

- 変更のあるシートを、設定の「自動保存の間隔」（既定 10 秒）ごとに保存する。⌘S ですぐに保存する（`.gm` と `.emet` の横書きでは、設定に従って整形してから保存する、[ADR 0009](adr/0009-lsp-and-formatting.md)）。
- シートを閉じたときと、ほかのシートを開いて入れ替わったときに、変更があれば保存する。ウィンドウを閉じるときと、メニューの「Aleph を終了」（⌘Q）では、画面の側が保存してから終える。画面の側が 5 秒のうちに応えなければ、そのまま終える。ほかのアプリから終了を求められたとき（Apple イベント）は、保存を待たずに終わる。
- 保存していない変更があるあいだは、ツールバーの題名の横に「●」を出す。
- 変更の印は、エディタの今の文書と HEAD の版を比べて出す。コミットと pull のあとは、比べる相手を新しい HEAD に取り直す。
- 1 日 1 回の自動コミット：起動時と 1 時間ごとに、登録したワークスペースごとに、その日にまだ自動でコミットしておらず、変更（未コミットのファイルか、保存していないシート）があれば、開いているシートを保存してから `git add -A` し、`Autosave YYYY-MM-DD`（その日の日付）でコミットする。コミットした日は設定に記録する。設定の「1 日 1 回自動でコミットする」で切れる（既定はオン）。Git のリポジトリでないワークスペースは飛ばす。
- 手動のコミット：左のサイドバーの Git のパネル、ツールバーのメニューの「コミット（⌘⇧K）」、⌘⇧K で、Git のパネルのメッセージ欄に移る。メッセージを書いてコミットのボタンか ⌘↩ を押すと、開いているシートを保存してから `git add -A` してコミットする。
- Git のパネル：現在のワークスペースの、変更のあるファイル（`git status --porcelain=v1 -z -uall`）、選んだファイルの `git diff HEAD`、コミットメッセージ、コミット、push、pull（`--no-rebase`）、直近 20 件の履歴を出す。ファイルを二度押すと開く。Git のリポジトリでなければ、`git init` のボタンを出す。
- ツリーでは、コミットしていない変更のあるファイルに点を出す。ツリーの上のワークスペースの名前の横に、現在のブランチを出す。

## プロットとガントチャート

プロットはプロジェクトの `plot.csv` に置き、表とガントチャートで編集する（[ADR 0013](adr/0013-plot-and-gantt-chart.md)）。
リボンの「プロット」と、ツリーの「プロット」の行（`plot.csv`）で、エディタの代わりに開く。

- CSV は RFC 4180 の引用の規則で読み書きする。1 行が 1 シーンで、空の行は読み飛ばす。
- 決まった列は `scene`（シーン）、`file`（ファイル）、`subplots`（サブプロット）、`pov`（視点人物）、`characters`（登場人物）、`place`（場所）、`must`（書かなくてはいけないこと）、`flavor`（フレーバー）、`target`（予定字数）、`memo`（メモ）、`fragments`（本文の断片）、`start`（開始）、`end`（終了）とする。見出しは英語で書き、画面には日本語の名前を出す。そのほかの見出しは足した列として、決まった列の後ろに見出しの順で並べる。書き出すときは、決まった列、足した列の順にする。
- 名前の並びの列（サブプロット、視点人物、登場人物、場所）は `;`、`；`、`、`、`,` と改行で、文の並びの列（書かなくてはいけないこと、フレーバー、本文の断片）は `;`、`；` と改行で区切る。
- 表のセルはその場で書き換え、0.4 秒後に保存する。「＋列」で列を足し（決まった列の英語と日本語の名前、足した列と重なる名前は使えない）、見出しの × で確かめてから消す。シーンは表の下の「シーンを足す」か、行の境目に近づくと出る「＋」で足し、左端のつまみのドラッグで並べ替える。行の × で確かめてから消す。サブプロットで絞り込み、絞り込んだまま足したシーンにはそのサブプロットを入れる。`file` のセルの矢印で開く。
- **暦**：`start` と `end` は任意の文字列とする。ガントの横軸の並びは `plot-calendar.txt` に早い順に 1 行に 1 つ書き、ガントの「暦」から編集する。暦のファイルがなければ、すべての時が数か日付（`YYYY`、`YYYY-MM`、`YYYY-MM-DD`）のときは値の順に、そうでなければ表に出てくる順に並べる。暦のファイルにない時は、末尾に表に出てくる順で足す。
- **ガントチャート**：サブプロットごとの帯に、シーンを `start` から `end`（`end` を含む。なければ `start` の 1 つ分）までの棒で描く。同じ帯で時期の重なる棒は、始まりの早いものから順に、空いている最初の段に置く。収まらない名前は「…」で切り、マウスを乗せると名前と時期を出す。棒を押すとそのシーンのファイルを開く。右上のボタン、ピンチ、⌘ を押しながらのスクロールで、40% から 400% まで拡大縮小する。
- 表とガントはそれぞれ出し入れでき、少なくとも一方は出す。
- 見出しの矢印で、プロットを別のウィンドウに出す。保存するとイベントで知らせ、ほかのウィンドウのプロットを読み直し、メインのウィンドウの右のパネルとツリーを描き直す。別のウィンドウでファイルを開くと、メインのウィンドウで開く。

## シートの目標とノート

シートごとの目標、ノート、書くことのチェックは [ADR 0012](adr/0012-sheet-goals-and-notes.md) に従う。

- メタデータは、シートのプロジェクトの `.aleph/notes.json` に、プロジェクトの外のシートはワークスペースの `.aleph/notes.json` に、そのルートからのパスをキーとして置く。中身は、目標の字数（`goal`）、ノート（`note`）、チェックした書くこと（`done`）である。中身のない項目は書き出さない。プロトタイプの複数のノート（`notes`）は、空行でつないで一つのノートとして読む。Aleph でファイルの名前を変えたら、キーも変える。
- 右のパネルの「添付」に、上から次のものを出す。
  - **目標**（本文のシートだけ）：今の字数と目標の字数を円で示し、残りと原稿用紙の枚数を添える。目標は欄に手で書くか、書かなければプロットのそのシートの行の予定字数の合計を使う。
  - **キーワード**：プロットのそのシートの行の、視点人物、登場人物、場所、サブプロット。
  - **書くこと**：「書かなくてはいけないこと」のチェックの一覧と、フレーバー。チェックの状態はメタデータに残す。
  - **プロットのメモと断片**。
  - **ノート**：一つのテキストエリアで、パネルの残りの高さを使う。
- 右のパネルの「アウトライン」に、`.gm` と `.md` の見出しを出し、押すとその行に移る。
- **数え方**：字数は、本文（`.gm` は命令、式、コメントを除いたもの、`.md` は記号を除いたもの）の空白を除いた文字の数とする。ワード数は `Intl.Segmenter` の単語とみなすものの数とする。原稿用紙の枚数は、段落ごとに字数を 1 行の字数で割って切り上げた行数を足し、1 枚の行数で割って小数第 1 位に丸める。既定は 20 字 20 行で、設定の「原稿用紙の換算」で変える。`.gm` の段落は、Golem の `paragraph-separator`（ファイルの `@manifest`、`chapters` の項目、`[source]`、既定の `blank-line` の順）に従って区切る。
- ステータスバーに、本文（`.gm`、`.md`、`.txt`）の字数、ワード数、原稿用紙の枚数を出す。
- ツリーの `.gm` に字数を添え、目標のあるシートには進み具合の小さな円を付ける。

## 共有ライブラリとアセット

フォント、プラグイン、関数の共有と、画像のアセットは [ADR 0014](adr/0014-shared-library-and-assets.md) に従う。

- **共有ライブラリ** は、設定の「共有ライブラリ」で選ぶ一つのフォルダで、`fonts/`、`plugins/`（`.wasm`）、`functions/`（`.emet`）を置く。設定の「作る」で、選んだ場所に `Aleph Library` と三つのフォルダを作る。
- プロジェクトにはコピーして入れる。プラグインを入れると、`manifest.toml` に `[plugins.<名前>]` と `path = "plugins/<名前>.wasm"` の宣言がなければ足す。関数の `@import` は書き手が書く。
- **フォント**：プロジェクトのシートを初めて開いたときと、`golem new --no-fonts` で作ったときに、`style.toml` が指すフォントのうちプロジェクトにないものを、共有ライブラリから同じ名前のものを探してコピーする。コピーしたときは、`LICENSE` で始まるファイルも `fonts/` にコピーする。メニューの「共有ライブラリのフォントをコピー」でも行う。
- 左のサイドバーの「共有ライブラリ」に、ファイルごとに、すべてのプロジェクトでの状態（同じものが入っている、中身が違う、入っていない）を出す。中身はバイトの列で比べ、どちらが新しいかは判断しない。プロジェクトの名前を押すとそこに、「すべてに入れる」で同じでないすべてのプロジェクトに入れる。中身が違うプロジェクトに入れるときは、上書きすることを確かめる。
- 右のパネルの「共有ライブラリ」には、開いているプロジェクトでの状態だけを出す（フォントは入っているものだけ）。
- 共有ライブラリのパネル（左と右）にファイルを落とすと、拡張子で振り分けて共有ライブラリにコピーする（`.wasm` は `plugins/`、`.emet` は `functions/`、フォントと `LICENSE` で始まるファイルは `fonts/`）。扱えないファイルは通知で知らせる。
- `.gm` のエディタに画像（PNG、JPEG、SVG、PDF）を落とすと、プロジェクトの `images/` にコピーし、落とした行の後に `@figure images/<名前> alt="<名前>"` と字下げした「キャプション」の行を差し込む。ツリーのフォルダ（ファイルならそのフォルダ）に落とすと、そこにコピーする。同じ名前があれば、`-2`、`-3` を付けて上書きしない。

## 診断と検索

check、lint、preflight の診断と検索は [ADR 0015](adr/0015-diagnostics-and-search.md) に従う。

- 左のサイドバーの「診断」で、プロジェクトを選び、check、lint、preflight のどれかを実行する。`golem <種類> --format json` の JSON を標準エラー出力から読み、check と lint には `-v` を付ける（preflight には付けない）。JSON の配列として読めないときは、出力をそのまま出す。
- 結果はファイルごとにまとめ、重大度（error、warning、notice、info）、ファイル、行、列の順に並べる。各項目に重大度の印、文言、コード、行と列、`facts`、関連の情報を出し、押すとその位置を開く。
- ステータスバーの LSP の隣に lint と preflight を出す。色は、エラーがあれば赤、警告があれば黄、notice があれば青、それ以外は緑とし、実行できなかったときは赤とする。件数は error、warning、notice の合計で、info は数えない。実行していないときは色を付けず、実行中は薄くする。押すと、診断のパネルにその結果を出す。
- プロジェクトのシートを初めて開いたときと、`.gm`、`.emet`、`.toml` を保存して 2.5 秒たったときに、lint、preflight の順に裏で実行する。check はパネルからだけ実行する。
- 左のサイドバーの「検索」（⌘⇧F）で、このプロジェクト、このワークスペース、すべてのワークスペースのどれかを範囲に、正規表現と大文字と小文字の区別を切り替えて検索する。検索は Rust の側で、`.gitignore` に従い、Aleph がテキストとして開く形式のファイルだけを読み、2000 件で打ち切る。結果はファイルごとに、一致した部分の前後 40 字とともに出し、押すとその位置を開く。入力欄は描き直さず、結果だけを描き直す。

## Markdown から gm への変換

`.md` のシートで、ツールバーのメニューの「gm に変換」を選ぶと、同じディレクトリに同じ名前の `.gm` を作る（[ADR 0016](adr/0016-markdown-to-gm.md)）。

- 同じ名前の `.gm` があれば、上書きするかを確かめる。プロジェクトの中なら、作った `.gm` を `manifest.toml` の `chapters` の末尾に足し、`golem check` を実行して、作った章にエラーがあるか実行できなかったときは診断のパネルに出す。
- 読み方は Markdown のプレビューと同じ自前の読み方を使う。
- 見出しはそのまま（末尾の `#` は除く）、箇条書きは `- `（入れ子は空白 2 つの字下げ）、番号付きリストは `+ `、強調は `[strong: …]`、斜体は `[italic: …]`、インラインのコードは `[code: …]` にする。リンクは文字だけを残し、画像だけの行は `@figure パス alt="…"` にする。引用は記号を除いて段落にし、区切り線は空行にする。表とコードブロックはそのまま残す。行末の空白 2 つ（と `\`）の強制改行は行末の `\` にする。
- エスケープ：地の文の `[` と `\` の前に `\` を付け、`%%` は `\%%`、`##` の直後に ASCII の数字が続くときは `\##` にする。強調、斜体、コードの中身では、`]` と `|` にも `\` を付ける。段落の行頭が `#`、`-`、`+`、`=`、`@`、`|` になるときは、最初の文字の前に `\` を付ける。
- 段落：作る `.gm` を読む様式（プロジェクトの `paragraph-separator`。プロジェクトの外では空行の様式）が改行の様式なら、一つの段落の行をつないで一行にする（強制改行の行の終わりは残す）。空行の様式なら、行をそのまま残す。

## Aleph のプラグイン

Aleph の画面に機能を足すプラグインは [ADR 0017](adr/0017-aleph-plugins.md) に従う（Golem の `.wasm` のプラグインは共有ライブラリで扱う）。

- アプリの設定のディレクトリの `plugins/` に置いた `.js`（ES モジュール）を、起動して画面を描いたあとに名前の順で読み込み、書き出した `activate(aleph)` を呼ぶ。
- `aleph` は、`version`（API の版、今は 1）、`registerCommand(名前, 処理)`（ツールバーのメニューに項目を足す）、`registerStatus(処理)`（ステータスバーに文字を足す）、`onSave(処理)`（保存したあとに呼ぶ）、`toast(文言)` を持つ。処理には、開いているシートのパス、形式、本文、プロジェクトを渡す。本文を書き換える API はない。互換を壊す変更をするときは版を上げる。
- 読み込みか `activate` が失敗したプラグイン（例外、`activate` のないモジュール、構文の誤り）は、それが登録したものを外して無効にし、通知と設定の画面に理由を出す。ほかのプラグインは読み続ける。プラグインの処理が例外を投げたときは、通知を出すかその項目を出さずに続ける。
- 設定の「Aleph のプラグイン」に、フォルダの場所、プラグインが Aleph と同じ権限で動く旨の注意、読み込んだプラグインの一覧と状態を出す。プラグインごとに有効と無効を切り替えられ（設定の `disabledPlugins` に残す）、「読みなおす」でフォルダを読み直す。
