# ADR 0062: 外部のプログラムをメインスレッドの外で走らせる

ステータス: 採択（未実装）

## 文脈

Aleph は、golem（組版、検査、整形）、shem（PDF を PNG にする）、git を、Rust の側のコマンドから走らせ、終わるまで待つ（[ADR 0042](0042-ipc-trust-boundary.md)）。
そのコマンドのうち、`tool`、`git`、`tool_info`、`git_info` は `async` の付かない同期のコマンドである（[src-tauri/src/lib.rs](https://github.com/tett23/aleph/blob/5512ec8/src-tauri/src/lib.rs#L459)、[L622](https://github.com/tett23/aleph/blob/5512ec8/src-tauri/src/lib.rs#L622)）。

Tauri 2 は、`async` の付かないコマンドをメインスレッドで動かす（参考文献の「Calling Rust from the Frontend」）。
メインスレッドは、ウィンドウとウェブビューのイベントも受け持つ。
そのため、golem が組んでいるあいだ、アプリ全体の入力と描画が止まる。

ページのプレビューは、保存の後、入力が 5 秒止まってから `golem build --target pdf` を走らせる（[ADR 0056](0056-wait-before-building-pages.md)）。
試験のプロジェクト（約 1 万字、21 ページ）でも、組版に 1.5 秒かかった（shem は 0.05 秒）。
書き手の手元の長い原稿では、組版のあいだ画面が固まり、そのあいだの打鍵は組版が終わるまで反映されない。
golem の側の高速化はすでに入れたが、原稿の長さに比例する時間は残る。

組版の時間そのものは、Aleph の側では縮められない。
しかし、組版のあいだも書けるようにすることはできる。

## 実装すること

- 外部のプログラムを走らせて待つコマンド（`tool`、`git`、`tool_info`、`git_info`）を `async` のコマンドにし、プログラムを走らせて待つ部分を `tauri::async_runtime::spawn_blocking` の中で動かす。メインスレッドと、Tauri の非同期の実行の土台のスレッドを、どちらも塞がない。
- 同じく長くかかりうる `list_tree`（ワークスペースの木を辿る）も、同じ形にする。
- コマンドの引数、戻り値、検査（[ADR 0042](0042-ipc-trust-boundary.md) のパスとサブコマンドの検査）は変えない。検査はプログラムを走らせる前に、これまでどおり行う。
- これまでは、メインスレッドが一つずつ動かしていたので、外部のプログラムは結果として同時には走らなかった。メインスレッドの外に出すと、種類の違うものが同時に走る。次の組み合わせを、画面の側で一つずつ走らせる。
  - 同じワークスペースの、git の書き込み（`add`、`commit`、`init`、`pull`、`push`）。`index.lock` を取り合わないためである。読むだけのもの（`status`、`diff`、`log`、`show`、`rev-parse`）は、`--no-optional-locks` を付けているので（[ADR 0046](0046-safe-automatic-git.md)）、並んで走ってよい。
  - 同じプロジェクトの `golem fmt` と、そのプロジェクトの `build/` に書くもの（[ADR 0058](0058-build-from-aleph.md) の `withBuildDir`）。整形が書き換えているファイルを、組版が読まないためである。
- すでに一つずつ走らせているもの（同じ種類の検査、ページの組版と shem、Aleph からのビルド）は、今の仕組みのまま変えない。
- 仕様書のアーキテクチャの節に、外部のプログラムをメインスレッドの外で走らせることと、一つずつ走らせる組み合わせを書く。

## 実装しないこと

- 組版の途中で、古い組版を止めること（新しい入力があったら golem を止めて組みなおす）。必要になったら別の ADR で扱う。
- 組版の時間を縮めること。golem の側の仕事である。
- ファイルの読み書きのコマンド（`read_text`、`write_text` など）を `async` にすること。一つのファイルの読み書きで、待ち時間は短い。
- `spell_check` を `async` にすること。AppKit の `NSSpellChecker` を呼んでおり、メインスレッドの外から呼んでよいかを確かめていない。語の数だけの短い問い合わせで、待ち時間も短い。
- LSP の中継（[ADR 0009](0009-lsp-and-formatting.md)）を変えること。すでに別のスレッドで読み書きしている。

## テスト設計

`node --test` と `cargo test` で、テストを先に書いて失敗させてから実装する。

- TypeScript：キーごとに一つずつ走らせる関数（`withBuildDir` を一般にしたもの）が、同じキーの仕事を頼んだ順に一つずつ走らせ、違うキーの仕事は並んで走らせること。前の仕事が失敗しても、次の仕事が走ること。
- TypeScript：git の引数から、書き込みかどうかを決める関数が、`add`、`commit`、`init`、`pull`、`push` を書き込み、`status`、`diff`、`log`、`show`、`rev-parse` を読むだけと判定すること。
- Rust：プログラムを走らせる部分が、`spawn_blocking` の中で走っても、これまでと同じ `Out`（終了コード、標準出力、標準エラー出力）を返すこと。見つからない実行ファイルのときに、これまでと同じ文言の誤りを返すこと。
- 自動のテストで確かめられないこと（メインスレッドが塞がらないこと）は、画面で確かめる。
  - 設定の golem のパスに、5 秒待ってから本物の golem を呼ぶ試験用のスクリプトを選ぶ。
  - ページのプレビューを開き、章に打鍵して組版を始めさせる。組版の 5 秒のあいだも、打った字がすぐに出て、カーソルが動き、パネルを開け閉めできることを確かめる。
  - 組版が終わると、ページのプレビューが新しくなることを確かめる。
  - 組版のあいだに ⌘⇧K でコミットし、git の誤りが出ないことを確かめる。

## トレードオフ

- 種類の違う外部のプログラムが同時に走るので、CPU を取り合い、それぞれの終わる時刻は延びることがある。そのかわり、画面は止まらない。
- 一つずつ走らせる組み合わせを、画面の側で決めて持つことになる。新しく外部のプログラムを呼ぶ機能を足すときは、その組み合わせに入るかを確かめる必要がある。
- `spawn_blocking` のスレッドは Tauri の実行の土台が持つ数に限られる。同時に走る外部のプログラムがその数を超えると、待たされる。Aleph が同時に走らせる数は、多くて数個である。
