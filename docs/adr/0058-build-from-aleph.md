# ADR 0058: Aleph からプロジェクトをビルドする

ステータス: 採択

## 文脈

Golem のプロジェクトの出力（PDF、HTML、EPUB、テキスト）は、`golem build` で `build/` の下に書く。
`golem build` は、`--target html|epub|text|pdf`（省くとすべて）、`--profile dev|prod`（既定は dev）、`--marks japanese|western|none`（PDF のトンボ、既定は none）を取り、`--format json` で診断を JSON の配列として標準エラー出力に書く。

Aleph は、プレビューのために `golem build --target html` と `--target pdf` を自分で走らせる（[ADR 0010](0010-previews.md)、[ADR 0056](0056-wait-before-building-pages.md)）。
しかし書き手が、入稿や配布のために出力を作る手段はない。
書き手はターミナルに移って `golem build` を打つことになる。

`build` は、Aleph から走らせてよい golem のサブコマンドにすでに入っている（[ADR 0042](0042-ipc-trust-boundary.md)）。
診断は問題のパネル（[ADR 0055](0055-problems-panel.md)）にまとめて出せる。
`build/` は「Finder で表示」（[ADR 0053](0053-reveal-in-finder.md)）で開ける。

## 実装すること

- ツールバーの右側（プレビューの切り替えの右）に、ビルドのボタン（lucide の `hammer`）を置く。押すと、その下にビルドのポップアップを開く。開いているシートが Golem のプロジェクトに入っていないときは、ボタンを出さない。
- ポップアップには、次のものを置く。
  - 見出しに「ビルド」と、プロジェクトの名前。
  - ターゲット：すべて、pdf、html、epub、text のどれか一つ（既定はすべて）。
  - プロファイル：dev、prod のどちらか（既定は dev）。
  - トンボ：なし、日本式、西洋式（既定はなし）。ターゲットがすべてか pdf のときだけ出す。
  - 「build/ を Finder で表示」のボタンと、「ビルド（⇧⌘B）」のボタン。
  - 選んだものは `config.json` の `ui` の `buildOptions` に残す。形の違う値は既定に戻す。
- 「ビルド」を押すと、ポップアップを閉じ、選んでいるシートのプロジェクトで次を走らせる。
  - `golem build --format json --no-notices --profile <p>`。ターゲットがすべてでなければ `--target <t>` を、トンボがなしでなく、ターゲットがすべてか pdf なら `--marks <m>` を足す。
- コマンドを足す。
  - `project.build`（「ビルド」、⇧⌘B）：ポップアップを開かず、残した選択ですぐビルドする。
  - `project.buildOptions`（「ビルドの設定」）：ポップアップを開く。
- 走らせ方は次のとおりとする。
  - 同じプロジェクトのビルドは一つずつ走らせる。走っているあいだに頼まれたら、終わってからもう一度走らせる（重なった頼みは一回にまとめる）。
  - 同じプロジェクトでページのプレビューの組み立てが走っているあいだは、それが終わってから始める。どちらも `build/` に書くからである。
- 結果の出し方は次のとおりとする。
  - ステータスバーの lint と preflight の右に「● build」を出す。走っているあいだは薄く、終わったら、エラーがあれば赤、警告があれば黄、それ以外は緑とし、かかった秒数を添える。押すと問題のパネルを開く。プロジェクトで一度もビルドしていなければ出さない。
  - 診断は、出どころ `build` として問題のパネルに出す。check、lint、preflight と同じ位置の同じ文言は一つにまとめる（[ADR 0055](0055-problems-panel.md) の決まりのとおり）。
  - 標準エラー出力が JSON の配列として読めないとき（golem が起動できない、途中で落ちたなど）は、失敗とし、出力の先頭の 20 行を位置のない診断として出し、問題のパネルを開く。
  - 成功したら「ビルドしました（0.7 秒）」と通知する。エラーがあれば「ビルドでエラーが n 件あります」と通知し、問題のパネルを開く。
- 仕様書に「ビルド」の節を足す。

## 実装しないこと

- 出力したファイルを、ほかのアプリで開くこと（PDF をプレビューで開くなど）。Finder で表示するところまでとする。
- `build/` の掃除、出力先の変更。
- 保存のたびの自動のビルド。
- ビルドの途中で止めること。
- `golem build` の進み具合の表示。
- 複数のプロジェクトをまとめてビルドすること。

## テスト設計

`node --test` で、テストを先に書いて失敗させてから実装する。

- ビルドの引数を作る関数が、次を返すこと。
  - 既定（すべて、dev、なし）で `["build", "--format", "json", "--no-notices", "--profile", "dev"]`。
  - ターゲット pdf、プロファイル prod、トンボ日本式で、`--target pdf`、`--profile prod`、`--marks japanese` を含むこと。
  - ターゲット html でトンボを選んでいても、`--marks` を含まないこと。
- `buildOptions` を読む関数が、形の違う値や知らない値を既定に戻すこと。
- 結果を読む関数が、JSON の配列を診断に、読めない出力を失敗と先頭 20 行の位置のない診断にすること。
- 走らせ方の関数が、走っているあいだの頼みを、終わったあとの一回にまとめること。
- ステータスバーの色と文言を決める関数が、エラー、警告、成功、走っている、未実行で、それぞれ正しいものを返すこと。
- 画面の確かめ方：試験のプロジェクトで、ツールバーのボタンからポップアップを開き、ターゲットとプロファイルを選んでビルドし、`build/` に出力ができ、ステータスバーに秒数が出ることを確かめる。⇧⌘B で同じ選択のままビルドできること、トンボの行が html では消えること、「build/ を Finder で表示」で Finder が開くこと、起動し直しても選択が戻ることを確かめる。誤りを入れた章でビルドし、問題のパネルにエラーが出ることを確かめる。

## トレードオフ

- ビルドのボタンでツールバーの右側が一つ混む。ビルドはよく使う操作なので、メニューの奥には置かない。
- ページのプレビューの組み立てを待つので、プレビューが走っているとビルドの始まりが遅れる。二つが同時に `build/pdf` に書いて壊すよりよい。
- プロジェクトの外の設定（`--profile` の既定など）は、プロジェクトごとではなく Aleph 全体で一つとする。プロジェクトごとに分けたくなったら、別の ADR で扱う。
