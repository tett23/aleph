# ADR 0117: アシスタントで日本語 20 万字の原稿を扱う

Status: accepted-pending

## 文脈

長い章を対象にした頼みでは、対象本文を含めるだけで、アシスタントが資料や答えに使える領域が足りなくなる。
日本語 20 万字程度の原稿を、複数章にまたがる場合も含めて扱いたい。

## 調査した事項

ローカルの llama-server は、選んだモデルによらず `--ctx-size 4096` で起動する。
答えの上限は 1,024 トークンで、上限で切れた答えは失敗にする。
[ローカルサーバーの起動と答えの上限](https://github.com/tett23/aleph/blob/fd0067b19dc3d0194220ce1e4892b13ab3e3156d/src-tauri/src/llama.rs#L9-L12)、[起動引数と要求の本文](https://github.com/tett23/aleph/blob/fd0067b19dc3d0194220ce1e4892b13ab3e3156d/src-tauri/src/llama.rs#L34-L79)

Claude Code と Codex を選んでも、Aleph はローカルの 4,096 を使って資料の量を決める。
トークン数を数える処理もローカルのモデルを起動する。
ローカルのモデルを使えずに数えられない場合は、マニュアルやコマンド一覧を外したメッセージを送る。
長い本文で資料を外しても上限を超える場合を、この段階で検知する処理は無い。
[プロンプトの組み立て](https://github.com/tett23/aleph/blob/fd0067b19dc3d0194220ce1e4892b13ab3e3156d/app/assistant/mount.ts#L57-L75)、[資料の上限の計算](https://github.com/tett23/aleph/blob/fd0067b19dc3d0194220ce1e4892b13ab3e3156d/app/assistant/request.ts#L11-L38)

外部コネクタの一回の実行は 120 秒で打ち切る。ローカルのソケットの読み書きには 10 分の待ち時間の上限を使う。
[外部コネクタの実行上限](https://github.com/tett23/aleph/blob/fd0067b19dc3d0194220ce1e4892b13ab3e3156d/src-tauri/src/connectors.rs#L15)、[ローカルの待ち時間](https://github.com/tett23/aleph/blob/fd0067b19dc3d0194220ce1e4892b13ab3e3156d/src-tauri/src/llama.rs#L189-L219)

同梱の `llama-server` と `Qwen3.5-4B-Q4_K_M.gguf` を使い、現行の `messages` で組んだメッセージに `/apply-template` と `/tokenize` をかけた。
頼みは「原稿全体を読み、同じ語の表記ゆれを探して編集案を出してください。」とした。
本文と資料を空にしても、指示、作業例、頼みとテンプレートで 654 トークンあった。
資料ありの列には、頼みと一緒に渡す資料の例として、同梱の Golem のマニュアルから 8,000 字を加えた。
下の値は入力のトークン数であり、答えの領域を含まない。

| 原稿 | 文字数 | 資料なし | 資料あり |
| --- | ---: | ---: | ---: |
| 小説風の日本語を繰り返した試験用の本文 | 10,000 | 6,770 | 11,056 |
| 小説風の日本語を繰り返した試験用の本文 | 200,000 | 122,972 | 127,258 |
| Golem のマニュアルをつないで繰り返した本文 | 200,000 | 101,381 | 105,667 |

小説風の 20 万字に資料と 4,096 トークンの答えの枠を足すと、131,354 トークンになる。
Qwen3.5-4B の公開モデルのコンテキスト長は 262,144 トークンである。
上の測定はトークン化までであり、長いコンテキストでの推論の速度、メモリ、回答の品質は未計測である。 [ADR 0086](0086-qwen3-5-4b-as-provisional-default-model.md)、[Qwen3.5-4B のモデルカード](https://huggingface.co/Qwen/Qwen3.5-4B)

## 実装すること

### ローカルのコンテキスト

設定の「アシスタント」に「ローカルのコンテキスト長の上限」を置く。
選択肢は自動、8,192、16,384、32,768、65,536、131,072、262,144 トークンとする。
既定と値の無い既存の設定には自動を使う。
自動では、本文、頼み、指示、作業例と答えが収まる最小の長さを、サーバーとモデルが使える候補から選ぶ。
設定で数を指定した場合は、その数以下から選ぶ。
短い上限があるときは、実際に使う長さと理由を設定に出す。

有効なコンテキスト長は Rust が決め、トークン数の計算と llama-server の起動に同じ値を使う。
候補を選ぶための予備計数には、選べる最も短い長さで動く同じモデルを使う。
送信前の計数と推論は、選んだ長さで動く同じサーバーで行う。
設定または次の頼みによって必要なコンテキスト長が変わるときは、進行中の頼みが終わってからサーバーを起動し直す。
答えの上限は 4,096 トークンと有効なコンテキスト長の 4 分の 1 のうち、小さい方とする。
答えがそこで切れた場合は、途中の変更案を適用せず、実際の上限を知らせる。

### 頼みと資料を収める

ローカルで一回の推論に送るときは、頼みと対象本文を全文残す。
上限から答えの領域を引き、本文、頼み、指示、作業例をモデルのチャットテンプレートに当てて数える。
利用者が頼み欄に入力した資料は、頼みの一部として数える。
収まる範囲で Aleph が選んだ補足資料を既存の優先順に足し、送信直前に組み上がったメッセージをもう一度数える。
全体が上限に収まらない場合は、優先順位の低い補足資料から外す。
補足資料をすべて外しても収まらない入力は、下の「原稿全体を扱う」に従う。

Claude Code と Codex では、実際に使うモデルとコンテキストの設定を、それぞれの CLI に任せる。
Aleph は頼みと対象本文の全文に、優先順に選んだ補足資料を添える。
補足資料は Aleph のコマンド一覧と Golem のマニュアルから選び、UTF-8 で 64 KiB まで加える。
マニュアルは節の途中で切らない。
外部コネクタの頼みを組むために、ローカルモデルは起動しない。

外部コネクタに失敗してローカルに頼み直す場合は、同じ頼みと本文からローカルの上限で組み直す。
一回の要求に収まらなければ、その理由と分割の扱いを応答欄に出す。
コネクタの承認、開始するソフトウェア、一つのファイルを対象とする JSON の応答形式は今の決まりに従う。 [ADR 0081](0081-assistant-with-local-llm-and-connectors.md)

### 原稿全体を扱う

アシスタントの対象に「原稿全体」を加える。
プロジェクトではマニフェストに載る章を記載順で取り、プロジェクトに属さないシートではそのシートの本文を取る。
開いているシートでは未保存の本文を使う。対象の一覧と本文の版を、頼みを始めるときに決める。
Unicode のコードポイントで 20 万字以上の日本語の原稿を受け付ける。
複数章の本文をまとめて送るときは、章ごとにファイル名と本文を対応づける。
この対象を外部コネクタに送るときは、一回の実行の上限を 10 分にする。
時間切れは、処理できなかった範囲とともに表示する。

一回の要求に収まるときは、全文をそのまま渡す。
一回の要求に収まらないか、その長さでローカルサーバーを起動できなかったときは、章と段落を境に収まる部分に分ける。
外部コネクタから上限を超えたと分かる応答があった場合も、補足資料を外して再試行し、それでも超える場合は本文を分ける。
段落だけでも収まらなければ、文字を壊さない位置で切る。
分割を始めるときは、その理由と全体の進み具合を表示する。
そのとき選ばれた原稿のすべての部分を順に処理し、送らなかった部分があれば理由と範囲を示す。

部分ごとの結果は対応する章と範囲に結びつける。
章をまたいで比べる頼みでは、各部分の結果を照合する段を設け、照合できた範囲を応答に示す。
複数章の編集案には、現在の `find` と `replace` に加え、対象のファイル名を文字列の `file` として必ず返す。
`file` の値には、頼みが章の本文に添えたプロジェクトからの相対パスを使う。
編集案は元の版とファイル名で照合し、重なる案や元の箇所を一つに定められない案には理由を添える。
途中で対象を捨てたり、照合できなかった箇所を確認済みと表示したりしない。

### 計測

旧設定の 4,096 と自動で選んだ設定を、同じモデルと同じ頼みで比べる。
日本語 20 万字の全文を送る場合と分割する場合を含め、入った資料、処理した範囲、出力の打ち切り、応答時間と最大 RSS を記録する。
既存の性能予算は、別の決定で更新するまで 4,096 トークンのベンチマークに適用する。
この ADR は [ADR 0086](0086-qwen3-5-4b-as-provisional-default-model.md) の利用時のコンテキスト長と資料上限を置き換える。

## 実装しないこと

コネクタの追加、既定モデルの変更、会話履歴の再送、モデルの学習時の上限を超える設定。

## 不変条件

- I1: 一回のローカル推論のサーバーのコンテキスト長と、その推論のメッセージを組むときに使う上限は等しい。
- I2: ローカルに送るメッセージのトークン数と答えの上限の和は、有効なコンテキスト長以下である。
- I3: 一回で送るときは、頼みと対象本文を全文保つ。分割するときは、すべての範囲を元の順で処理し、処理できなかった範囲を知らせる。
- I4: 外部コネクタだけで完了する頼みはローカルモデルを起動せず、補足資料は 64 KiB 以下になる。
- I5: 外部コネクタからローカルへ切り替えるときは、同じ対象と頼みを使い、ローカルの上限でメッセージを組み直す。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 設定なしで、利用者が入力した資料と答えを足すと 131,072 を超え、262,144 に収まる | 262,144 の候補を使える環境では、本文と資料をまとめて送れる | I1, I3 |
| 資料なしのトークン数と答えの上限の和が、使える上限と等しいか 1 トークン多い | 等しければ資料なしで送り、多ければ分割の理由を知らせて全体を処理する | I2, I3 |
| 20 万字で複数章あり、最後の章にも調べる語がある | 分割の場合も最後の章まで処理し、章と位置を示す | I3 |
| ローカルモデルが無い状態で外部コネクタが成功 | 補足資料を節の境で 64 KiB 以下にし、ローカルの起動はゼロ回 | I4 |
| 外部コネクタが全文を上限超過として拒み、補足資料を外しても同じ応答を返す | 原稿を順に分割し、処理できた範囲を示す | I3, I4 |
| 外部コネクタが失敗し、補足資料を含むメッセージはローカルに収まらない | 同じ頼みと対象に、ローカルに収まる補足資料だけを添える | I2, I5 |

## 受けいれ条件

- A1: 日本語 20 万字の原稿で、単一の章と複数章の両方を扱える。全文を送れる場合と順に分割する場合の両方で、末尾の章または段落も処理する。
- A2: ローカルモデルを入れていない場合でも、Claude Code または Codex に資料つきの頼みを送れる。
- A3: 選んだ長さに収まらない頼みでは、分割する理由、処理が進んだ範囲、処理できなかった範囲が分かる。

## テスト設計

チャットテンプレートのトークン数を制御できるテストで、上限の直前、ちょうど、超過、フォールバックを確かめる。
コネクタとサーバーを差し替えて、起動引数、答えの上限、利用中の設定変更と起動し直す順序を記録する。
テスト名には `ADR 0117 I1: ` のように条件の番号を付ける。

Tauri のデバッグ版で、日本語 20 万字の原稿、章をまたぐ表記の比較、外部コネクタのみで完了する頼みを試す。
末尾にしか現れない語と二つの章にまたがる表記ゆれを入れ、章と位置が得られることを確かめる。
実装時に仕様書と両言語の README に、設定の値とコネクタごとの扱いを反映する。

## トレードオフ

長いコンテキストでは、モデルが保持する情報と最初の答えまでに読む量が増える。
ローカルの長さを選べるようにすると、長い章を扱う必要に合わせて、メモリと待ち時間を調整できる。
分割した場合に章をまたいで照合できるのは、各部分の処理で拾った情報に限られる。
