# ADR 0041: ワークスペース全体の置換のあとに lint と preflight を走らせる

ステータス: 採択（未実装）

## 文脈

[ADR 0032](0032-replace-across-workspace.md) は、置換したあと、開いているシートの変更の印、ツリー、診断（lint と preflight）を、保存したときと同じように更新すると決めた。

lint と preflight は、プロジェクトを開いたときと、開いているシートの `.gm`、`.emet`、`.toml`、`.json` を保存したときに走る（[app/diag/mount.ts](https://github.com/tett23/aleph/blob/3ec575e/app/diag/mount.ts#L118-L140)）。
置換は、開いているシートを保存し、開いていないファイルはディスクの上で書き換える（[app/searchpanel.ts](https://github.com/tett23/aleph/blob/3ec575e/app/searchpanel.ts#L140-L151)）。
開いていないファイルだけが変わったプロジェクトでは、保存の知らせが起きないので、lint と preflight が走らず、診断が置換の前のままになる。
[ADR 0021](0021-json-files.md)〜0035 を実装と照らしたレビューで、この食い違いが見つかった。
メンテナーは、レビューで残った点のすべてについて ADR を書くよう求めた（2026-11-08）。

## 実装すること

- 置換が終わったら、置換したファイル（開いているシートとディスクの上のファイルの両方）を含むプロジェクトごとに、lint と preflight を一度ずつ走らせる。保存のあとと同じく、`.gm`、`.emet`、`.toml`、`.json` のファイルが一つ以上あるプロジェクトに限る。
- 開いているシートの保存で 2.5 秒後に走る分と重ならないよう、置換のあとに走らせるプロジェクトの、保存のあとの待ちは取り消す。
- 診断の部品に、プロジェクトの一覧を受けて lint と preflight を走らせる関数（`recheck(projects)`）を足し、置換の処理から呼ぶ。
- 置換したファイルからプロジェクトの一覧を求める処理は、DOM に触れない関数（`projectsTouched`）に分ける。

## 実装しないこと

- プロジェクトの外のファイル（lint と preflight はプロジェクトに対して走る）の検査。
- 置換のたびの、Golem の組版（プレビュー）の作り直し。

## テスト設計

`node --test` で、テストを先に書いて失敗させてから実装する。

- `projectsTouched`：置換したファイルとプロジェクトの一覧から、対象のプロジェクトを重ねずに返すこと、対象の拡張子のないプロジェクト（`.md` だけが変わったものなど）を除くこと、プロジェクトの外のファイルを除くこと（app/replace.test.ts）。
- 画面の確かめ方：開いていない章に lint の警告が出る語を置換で入れ、診断の一覧にその警告が出ることを確かめる。

## トレードオフ

- 置換のたびに、触れたプロジェクトの lint と preflight を走らせるので、多くのプロジェクトをまたぐ置換では時間がかかる。診断が置換の前のまま残ることを避けるほうを優先した。
