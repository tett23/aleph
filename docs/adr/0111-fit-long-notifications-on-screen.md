# ADR 0111: 長い通知を画面の中に収め、展開してもスクロールで読めるようにする

Status: proposed

## 文脈

通知は、ウィンドウの右下、ステータスバーの上に、下から上へ積む ([ADR 0064](0064-unified-notifications.md))。
文は複数行でよく、閉じるボタン (×) は、いつも通知の右上に置く。

`golem build` などの失敗の通知は、診断を一件ずつ文に並べるので、数十行になることがある。
文が長いと、通知の高さがウィンドウの高さを超え、通知の上の端がウィンドウの上を突き抜ける。
× は通知の右上にあるので、画面の外に出て押せなくなる。
消えない通知は、それを出した機能が閉じないかぎり、書き手は × かボタンでしか閉じられない。そのため、書き手はその通知を閉じられなくなる。

この ADR は、長い文を折りたたんで出し、展開しても通知が画面の中に収まり、文をスクロールして読めるようにすることを決める。
[ADR 0064](0064-unified-notifications.md) の「通知の形」に、文の見せ方と高さの上限を補う。

## 調査した事項

この節には、ソースで確かめたことだけを書く。
ソースは main のコミット `97e8eef` で読んだ。

通知の積み重ねは `.toasts` の要素で、`position: fixed; right: 12px; bottom: 34px;` に置き、縦に並べる flex である ([style.css:349](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/style.css#L349))。
`.toasts` は `pointer-events: none` で、子の要素だけがポインタを受ける ([style.css:350](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/style.css#L350))。
`.toasts` にも、一つの通知 `.nt` にも、高さの上限が無い ([style.css:349-361](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/style.css#L349-L361))。
`.nt` は三列の grid で、行の高さは中身で決まる。
文 `.msg` は `white-space: pre-wrap` で、改行と折り返しのとおりにすべての行を出す。

一つの通知は、アイコン、文、×、進み具合の棒、ボタンを、grid に並べる ([notices.ts:56-59](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/ui/notices.ts#L56-L59))。
× は文と同じ一行目に置くので、文が長くても通知の上の端にある。
通知の要素は id ごとに残し、中身の HTML が変わったときだけ `innerHTML` を書き直す ([notices.ts:61-75](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/ui/notices.ts#L61-L75))。
押した操作は、積み重ねの要素の `mouseup` で一か所で受ける ([notices.ts:83-95](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/ui/notices.ts#L83-L95))。

同じ鍵で通知を出すと、前の通知を取り除き、新しい id で作る ([notify.ts:125-139](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/notify.ts#L125-L139))。
返り値の `Handle` の `update` で文を変えたときは、id は変わらない ([notify.ts:212-215](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/notify.ts#L212-L215))。

一度に見せる通知は 4 つまでで、超えた消えない通知は「ほか n 件の通知」の行にまとめる。この行を押すと、すべての通知を見せる ([notify.ts:246-250](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/notify.ts#L246-L250))。
すべての通知を見せたときも、積み重ねの高さに上限は無い。

指示者が貼った画面の写しでは、通知の文が数十行続き、通知の上の端と × がウィンドウの外に出ていた。

## 実装すること

### 長い文と折りたたみ

- 文の行の高さを `1.5em` に固める。文の内容の高さ (`scrollHeight`) が、行の高さの 6 倍を超える文を **長い文** と呼ぶ。行は、改行と、通知の幅での折り返しの両方で数えることになる。
- 長い文かどうかは、通知を描いた後に、文の要素で測る。`scrollHeight` は見えている高さの上限に関わらず内容の高さを返すので、折りたたみでも展開でも同じ規則で測れる。測った結果は、通知ごとの状態に持ち、通知の HTML を作る入力にする。結果が変わったときだけ、その通知を描き直す。
- 長い文は、初めは **折りたたみ** で出す。折りたたみでは、文を行の高さの 6 倍で切り、超えた分を隠す。
- 長い文の下 (grid の 2 列目、文の次の行) に、下線を付けた文字のボタンを出す。折りたたみでは「すべて表示」、展開では「折りたたむ」とする。押すと、折りたたみと **展開** を入れ替える。
- 長くない文には、ボタンを出さず、今のとおりすべてを出す。
- 通知ごとの状態 (長い文か、展開か) は、通知の鍵ごとに、鍵の無い通知は id ごとに持つ。
  - 画面にある通知を、同じ鍵の通知で置き換えたときと、`Handle` の `update` で文を変えたときは、状態を引き継ぐ。長い文かは測り直す。
  - 通知が画面から消えたら、その状態を捨てる。後で同じ鍵の通知を出しても、折りたたみから始める。

### 画面に収めること

- 積み重ね `.toasts` の高さの上限を、ウィンドウの高さから下の位置 (34px) と上の余白 (12px) を引いた高さ (`calc(100vh - 46px)`) にする。超えるときは、積み重ねを縦にスクロールできるようにする。
- 積み重ねがスクロールできるあいだは、積み重ねの要素もポインタを受けるようにする (スクロールバーを掴むため)。スクロールできないあいだは、今のとおり子の要素だけが受ける。
- 新しい通知を足したときと、積み重ねがスクロールできるようになったときは、積み重ねを下の端までスクロールし、いちばん新しい通知を見せる。
- 展開した文の高さの上限を、積み重ねの高さの上限から 96px (通知の余白、ボタン、進み具合の棒、「折りたたむ」の分) を引いた高さにし、超える分は文の要素の中で縦にスクロールする。アイコン、×、進み具合の棒、ボタン、「折りたたむ」は文の外に置き、文と一緒にスクロールしない。
- これにより、一つの通知の高さは積み重ねの高さの上限を超えず、その通知を積み重ねの中にスクロールして見せたとき、通知の上の端と × は積み重ねの見えている範囲の中にある。
- 文を選んでコピーできることは、折りたたみと展開のどちらでも変えない。
- ページのプレビューとプロットの別のウィンドウの通知も、同じにする。

### 記録と仕様書

- 採択するときに、[ADR 0064](0064-unified-notifications.md) のステータスの変更の配列に、`part` を「通知の形 の、文の見せ方と高さ」、`by` をこの ADR、`kind` を `supplement` とする要素を足す。
- 仕様書の通知の節に、長い文、折りたたみ、展開、画面に収めることを書き足す。

## 実装しないこと

- 下部パネルの「通知」のタブの履歴の行を折りたたむこと。履歴は下部パネルの中でスクロールして読める。
- 行数の上限 (6 行) を設定で変えること。
- 長い文を通知から外し、別のダイアログやタブに出すこと。

## 不変条件

- I1: 長い文でない通知には、「すべて表示」も「折りたたむ」も出ない。
- I2: 長い文の通知は、出したときに折りたたみであり、「すべて表示」を出す。
- I3: 長い文の通知のボタンを押すたびに、その通知の折りたたみと展開が入れ替わる。ほかの通知の状態は変わらない。
- I4: 状態は、画面にある通知の同じ鍵での置き換えと `update` では引き継ぎ、通知が画面から消えると捨てる。
- I5: 積み重ねの見えている範囲は、ウィンドウの中にある。
- I6: 文の長さと展開の状態に関わらず、どの通知の高さも積み重ねの高さの上限以下である。そのため、通知の上の端を積み重ねの中にスクロールして見せると、その通知の × は積み重ねの見えている範囲の中にある。

境界の入力は次のとおりである。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 空の文 | ボタンなし | I1 |
| ちょうど 6 行の文 | ボタンなし | I1 |
| 7 行の文 | 折りたたみ、「すべて表示」 | I2 |
| 改行の無い、幅で 7 行に折り返す文 | 折りたたみ、「すべて表示」 | I2 |
| 7 行の文で「すべて表示」を押す | 展開、「折りたたむ」 | I3 |
| 展開した後に「折りたたむ」を押す | 折りたたみ、「すべて表示」 | I3 |
| 長い文の通知が二つあり、一つ目だけ展開する | 二つ目は折りたたみのまま | I3 |
| 展開した鍵付きの通知を、画面にあるうちに同じ鍵の長い文で置き換える | 展開のまま | I4 |
| 展開した通知の文を `update` で別の長い文に変える | 展開のまま | I4 |
| 展開した鍵付きの通知を閉じ、同じ鍵の長い文の通知を出す | 折りたたみ | I4 |
| 展開した 7 行の通知の文を `update` で 3 行に変える | ボタンなし | I1, I4 |
| ウィンドウの高さを超える 200 行の文を展開する | 積み重ねと通知はウィンドウの中、文は中でスクロールし、× は見えている | I5, I6 |
| 200 行の文の通知を四つ、すべて展開する | 積み重ねはウィンドウの中でスクロールし、どの通知も、上の端をスクロールで見せると × が見えている | I5, I6 |

## 受けいれ条件

- A1: 数十行の診断を持つ `golem build` の失敗の通知が、6 行に折りたたまれて出る。× で閉じられる。
- A2: 「すべて表示」を押すと、文の全体を通知の中でスクロールして読める。通知の上の端と × は、ウィンドウの中にある。「折りたたむ」で戻る。
- A3: ウィンドウの高さを縮めても、展開した通知の × は押せる。
- A4: 長い通知が積み重ねからあふれたとき、積み重ねのスクロールバーを掴んでスクロールできる。
- A5: 長い文の通知を含む複数の通知 (「ほか n 件の通知」を押してすべてを見せたときを含む) が出ているときに、そのうちの一つか全部を展開しても、積み重ねはウィンドウの上の端を突き抜けない。どの通知も、積み重ねをスクロールすれば × を押せる。

## テスト設計

- I3 と I4 は、TypeScript で、通知ごとの状態を持つ関数を、DOM から離して確かめる。押す、ほかの通知を押す、同じ鍵で置き換える、`update` する、通知が消える、を順に与える。
- I1、I2、I5、I6 は、行の高さと幅で決まるので、ブラウザで描く確かめのページ (`app/fixtures/`) で確かめる。境界の表の文を描き、ボタンの有無、文の `scrollHeight` と `clientHeight`、通知と × と積み重ねの `getBoundingClientRect()` を、ウィンドウの高さを変えて比べる。
- テストの名前と、確かめのページの検査の文には、この ADR と不変条件の番号を入れる。
- A1〜A5 は、Tauri のデバッグ版で、エラーを数十件出す使い捨てのプロジェクトをビルドして確かめる。

## トレードオフ

- 6 行を超えると折りたたむので、少しだけ長い文も、押さないと全体を読めない。代わりに、通知がエディタを広く隠すことを避けられる。
- 長い文かを描いた後の高さで測るので、描くたびに要素の高さを読む。通知は一度に 4 つほどなので、読む回数は少ない。
- 展開した文を通知の中でスクロールさせるので、とても長い文は狭い範囲で読むことになる。全体を読むには、下部パネルの「通知」のタブの履歴も使える。
- 積み重ねがスクロールできるあいだは、通知のあいだの隙間もポインタを受けるので、その隙間の下のエディタは押せない。隙間は 8px で、スクロールできるのは通知があふれたときだけである。
