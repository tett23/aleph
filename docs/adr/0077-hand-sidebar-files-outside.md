# ADR 0077: サイドバーのファイルをアプリケーションの外に渡す

Status: accepted-pending

## 文脈

書き出した PDF などのビルドの成果物を、書き手は人に送ったり、ほかのアプリケーションで開いたりする。
しかし今のサイドバー (ファイルツリー) は、プロジェクト (`manifest.toml` を持つフォルダ) の `build/` を表示しない。
そのため書き手は、成果物を Finder で探し直している。

成果物に限らず、サイドバーのファイルをアプリケーションの外に渡す手段も無い。
今あるのは、ファイルやフォルダを Finder で表示する項目 ([ADR 0053](0053-reveal-in-finder.md)) と、画像を章にドラッグして差し込む操作 ([ADR 0018](0018-drag-image-from-tree.md)) である。
後者はアプリケーションの中で完結し、Finder やメールのアプリケーションにはドロップできない。

フォルダを一つにまとめて送る手段として、書き手は zip を使う。
しかし macOS の標準の圧縮で作った zip は、Windows で展開すると日本語の名前が化けることがある。
この ADR は、成果物の表示と、ファイルを外に渡す三つの手段 (ドラッグ、クリップボード、zip) を決める。

## 調査した事項

この節には、コマンドとソースで確かめたことだけを書く。

サイドバーは `build/` を二か所で除いている。
一つめは Rust の側の一覧で、名前が `build`、`node_modules`、`target`、`dist` のフォルダを中身ごと除く ([fsops.rs:17](https://github.com/tett23/aleph/blob/0966994371f0b672f1be72231b7ce372859dbceb/src-tauri/src/fsops.rs#L17))。
二つめは TypeScript の側の行の組み立てで、Aleph が開ける種類 (`OPEN_KINDS`) のファイルだけを行にする ([workspace.ts:39](https://github.com/tett23/aleph/blob/0966994371f0b672f1be72231b7ce372859dbceb/app/workspace.ts#L39))。
[ADR 0067](0067-tree-visibility-and-directories.md) は、`build/` などの除外を引き続き当てはめると定めている。
Golem は、PDF を `build/pdf/` に、テキストを `build/text/` に書き出す。

外部での変更の監視 ([ADR 0063](0063-watch-files-changed-outside.md)) は、プロジェクトの `build/` の中の変更を送らない ([watchfs.rs:31](https://github.com/tett23/aleph/blob/0966994371f0b672f1be72231b7ce372859dbceb/src-tauri/src/watchfs.rs#L31))。
そのため、`build/` を表示しても、外で動かしたビルドの成果物は、ほかの再読み込みの契機が来るまでサイドバーに現れない。

macOS の `ditto` は、Finder の「圧縮」と同じ形式の zip を作る。
日本語の名前のフォルダ `原稿` (中身は `第1章.gm` と `.DS_Store`) を `ditto -c -k --sequesterRsrc --keepParent` で圧縮し、Python の `zipfile` で中身を読んだ結果は次のとおりである。

- 名前は UTF-8 のバイトで書かれているが、汎用フラグのビット 11 (EFS、名前が UTF-8 であることの印) はどのエントリーでも 0 だった。
- `zipfile` は、EFS の無い名前を CP437 として読み、`原稿/第1章.gm` を `σÄƒτ¿┐/τ¼¼1τ½á.gm` と読んだ。
- `.DS_Store` と、リソースフォークを入れる `__MACOSX/` のエントリーが入っていた。

zip の形式の仕様 (PKWARE の APPNOTE 6.3.10) は、次のことを定めている。

- 汎用フラグのビット 11 が立っているとき、名前とコメントは UTF-8 で書かれている。
- 名前を UTF-8 で書くもう一つの方法として、拡張フィールド 0x7075 (Info-ZIP Unicode Path) がある。ビット 11 を使うときは、0x7075 を作るべきではない (SHOULD NOT)。
- ZIP64 の拡張を使わない zip は、エントリーの数を 65535 まで、一つのファイルの大きさと中央ディレクトリの位置を 0xFFFFFFFF バイトまで書ける。

Windows のエクスプローラーが、ビット 11 の立った zip の名前を正しく展開するかは未確認である。

アプリケーションの外へのドラッグは、macOS では `NSDraggingSession` で行う。
drag-rs (crabnebula-dev、MIT と Apache-2.0、コミット 6cd4c2f) の macOS の実装は、次の手順でファイルのドラッグを始める ([macos/mod.rs](https://github.com/crabnebula-dev/drag-rs/blob/6cd4c2fefdd0c0617833bec654694d603527769b/crates/drag/src/platform_impl/macos/mod.rs#L180-L234))。

1. ファイルごとに `NSURL::fileURLWithPath_isDirectory` で URL を作り、`NSDraggingItem` に包む。
2. 今のポインタの位置で `LeftMouseDragged` の `NSEvent` を作る。
3. ウィンドウの content view の `beginDraggingSessionWithItems_event_source` を、メインスレッドで呼ぶ。

Aleph は `objc2-app-kit` 0.3 と `objc2-foundation` 0.3 を、macOS の依存としてすでに持つ ([Cargo.toml](https://github.com/tett23/aleph/blob/0966994371f0b672f1be72231b7ce372859dbceb/src-tauri/Cargo.toml))。
今は `NSSpellChecker` などの機能だけを有効にしている。

## 実装すること

### 成果物の表示

プロジェクトの直下の `build/` を、サイドバーに表示する。
これは、[ADR 0067](0067-tree-visibility-and-directories.md) の「`build/` の既存の除外を引き続き適用する」を、プロジェクトの直下の `build/` について変える。
隠しファイルとシンボリックリンクの扱いは、ほかのフォルダと同じとする。
`build/` の中では、Aleph が開けない種類 (HTML、EPUB など) のファイルも行にする。
開けない種類の行は、クリックしても開かず、選ぶだけにする。
その行は、この ADR のドラッグ、コピー、zip と、Finder での表示の対象になる。

プロジェクトの直下でない `build/` と、`node_modules/`、`target/`、`dist/` は、今までどおり除く。
Aleph の中でビルドが終わったときは、サイドバーを読み直す。
外で動かしたビルドの成果物は、読み直しのボタンなど、ほかの契機で現れる。

### アプリケーションの外へのドラッグ

サイドバーの行のドラッグで、ポインタがウィンドウの外に出たら、macOS の `NSDraggingSession` を始める。
渡すファイルは、押した行が選ばれていれば選ばれているすべての行、選ばれていなければ押した行だけとする。
順はサイドバーの行の順とする。
ドロップ先がファイルをどう扱う (コピー、移動、添付) かは、ドロップ先に任せる。

ウィンドウの中でのドラッグは、今までどおり扱う。
画像を章に差し込む操作 ([ADR 0018](0018-drag-image-from-tree.md)) は変えない。

`NSDraggingSession` は、drag-rs の手順を参考に objc2 で自前で書き、drag-rs を依存に入れない。
`objc2-app-kit` と `objc2-foundation` に、要る機能 (`NSDraggingSession`、`NSDraggingItem`、`NSPasteboard`、`NSURL` など) を足す。

### クリップボードへのコピー

ファイルとフォルダの行の右クリックのメニューに「コピー」を足す。
「コピー」は、渡すファイル (ドラッグと同じ決め方) の URL を、macOS の一般のペーストボード (`NSPasteboard`) に書く。
Finder でペーストすると、ファイルがコピーされる。

### フォルダの zip

フォルダとプロジェクトの行の右クリックのメニューに「zip で書き出す…」を足す。
保存先は、macOS の保存のダイアログで書き手が決める。
既定の名前は `<フォルダの名前>.zip`、既定の場所はそのフォルダの親とする。

zip の中身は次のとおりとする。

- エントリーの名前は、フォルダの名前を頭に付けた相対パスで、区切りは `/` とする (`原稿/第1章.gm`)。
- 名前の Unicode を NFC に正規化して UTF-8 で書き、すべてのエントリーで汎用フラグのビット 11 を立てる。拡張フィールド 0x7075 は書かない。
- フォルダごとに、`/` で終わるエントリーを書く。空のフォルダも展開した後に残る。
- 名前が `.DS_Store` のファイルと、名前が `.git` のフォルダの中身を除く。`__MACOSX/` とリソースフォークは書かない。
- シンボリックリンクは、たどらず、入れない。
- 圧縮はせず、格納 (stored、方式 0) で書く。

zip の書き出しは、Rust の側で、ファイルの一覧、CRC-32、書き込みまで自前で書き、zip のライブラリを依存に入れない。
書き出しは別のスレッド ([ADR 0062](0062-run-programs-off-the-main-thread.md) の `blocking`) で行う。
書き出しは保存先と同じフォルダの一時ファイルに書き、終えてから保存先の名前に変える。
次のときは書き出しを止め、一時ファイルを消し、理由を通知する ([ADR 0064](0064-unified-notifications.md))。

- エントリーが 65535 を超える。
- ファイルの大きさか中央ディレクトリの位置が 0xFFFFFFFF バイトを超える。
- NFC に正規化した後に、二つのエントリーの名前が同じになる。
- ファイルを読めない。

## 実装しないこと

- ZIP64 の拡張、deflate などの圧縮、暗号化。
- CP932 などの、UTF-8 でない名前の書き方。
- zip の展開。
- macOS のほかの OS でのドラッグとクリップボード。
- 外のアプリケーションから Aleph のサイドバーへのドロップ ([ADR 0078](0078-accept-drops-on-the-tree.md) が決める)。
- 外で動かしたビルドの成果物を、監視 ([ADR 0063](0063-watch-files-changed-outside.md)) で見つけてすぐに表示すること。
- ドラッグとコピーで、ファイルの中身や Markdown のリンクを文字列として渡すこと。

## 不変条件

- I1: サイドバーの行は、プロジェクトの直下の `build/` と、その中のファイルとフォルダのうち隠しファイルの設定とシンボリックリンクの決まりで除かれないものを種類によらず含み、プロジェクトの直下でない `build/` を含まない。
- I2: zip のファイルのエントリーの集合は、対象のフォルダの下のシンボリックリンクでない通常のファイルのうち、名前が `.DS_Store` でなく、`.git` フォルダの下にないものの集合に等しい。
- I3: zip のすべてのエントリーの名前は、NFC に正規化された UTF-8 で、区切りは `/` で、対象のフォルダの名前で始まり、汎用フラグのビット 11 が立ち、拡張フィールド 0x7075 を持たない。
- I4: zip の各ファイルのエントリーの中身は元のファイルとバイト単位で等しく、記録された CRC-32 と大きさはその中身のものに等しい。
- I5: 書き出しを止めたとき、保存先にファイルは無く (前からあったファイルは変わらず)、一時ファイルも残らない。
- I6: ドラッグとコピーで渡すファイルは、押した行が選ばれていれば選ばれた行のすべてをサイドバーの順に並べたもの、選ばれていなければ押した行だけである。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 空のフォルダ `空` | エントリーは `空/` だけ | I2, I3 |
| `.DS_Store` だけのフォルダ | エントリーはフォルダの `/` だけ | I2 |
| 大きさ 0 のファイルが一つ | 中身 0 バイト、CRC-32 は 0 | I4 |
| NFD の `か゛` (U+304B U+3099) を含む名前 | 名前は NFC の `が` (U+304C) | I3 |
| NFC と NFD で同じ名前になる二つのファイル | 書き出しを止める | I5 |
| `.git/HEAD` と `a/.DS_Store` を含むフォルダ | どちらも入らない | I2 |
| フォルダの外を指すシンボリックリンク | 入らず、たどらない | I2 |
| エントリーがちょうど 65535 | 書き出す | I2 |
| エントリーが 65536 | 書き出しを止める | I5 |
| 大きさがちょうど 0xFFFFFFFF バイトのファイル | 書き出す | I4 |
| 大きさが 0x100000000 バイトのファイル | 書き出しを止める | I5 |
| 保存先に前からファイルがあり、書き出しを止めた | 前のファイルは変わらない | I5 |
| プロジェクトの `build/pdf/x.pdf` と `build/html/index.html` | 二つとも行になる | I1 |
| プロジェクトでないフォルダの `build/` | 行にならない | I1 |
| 選ばれていない行を押してドラッグ | 押した行だけ | I6 |
| 三つの行が選ばれ、そのうちの一つを押した | 三つをサイドバーの順に | I6 |

## 受けいれ条件

- A1: プロジェクトで PDF を書き出すと、サイドバーの `build/pdf/` にその PDF が現れる。
- A2: サイドバーの PDF の行を Finder のウィンドウにドロップすると、Finder にその PDF ができる。
- A3: サイドバーの行を三つ選び、そのうちの一つを Finder にドロップすると、三つともできる。
- A4: 行の「コピー」の後に Finder でペーストすると、そのファイルができる。
- A5: 日本語の名前のファイルを含むフォルダの zip を、Windows 11 のエクスプローラーで展開すると、名前が化けない。
- A6: 同じ zip を macOS の Finder で展開すると、名前が化けず、`.DS_Store` も `__MACOSX` もできない。
- A7: 画像の行を章にドラッグすると、今までどおり図の命令が差し込まれる。

## テスト設計

自動のテストは、不変条件ごとに名前の頭に番号を付ける。

- Rust の zip の書き出しには、テストの中だけで使う小さな zip の読み手を書き、境界の表の各行を確かめる。名前は `adr0077_i2_…`、`adr0077_i3_…` のようにする。
  - 65535 と 65536 のエントリーは、大きさ 0 のファイルで作る。
  - 0xFFFFFFFF と 0x100000000 バイトは、ファイルを作らず、大きさの検査の関数に値を渡して確かめる。
- 読み手の正しさを別の実装でも確かめるため、`unzip -Z` があるときは、同じ zip の名前とビット 11 を `unzip -Z` でも読み、一致を確かめる。無いときは、そのテストを飛ばす。
- I5 は、書き込みの途中でファイルを読めなくした入力で、保存先と一時ファイルを確かめる。
- I1 は、Rust の一覧と TypeScript の行の組み立てを、プロジェクトとプロジェクトでないフォルダの `build/` で確かめる (`ADR 0077 I1: …`)。
- I6 は、選択とサイドバーの行から渡すファイルを決める関数を、TypeScript で確かめる (`ADR 0077 I6: …`)。

ドラッグ、クリップボード、Windows での展開は、自動のテストにできないので手で確かめる。

- A1 は、デバッグ版でプロジェクトの PDF を書き出し、サイドバーを見る。
- A2、A3、A7 は、デバッグ版でサイドバーから Finder とエディタにドラッグする。
- A4 は、コピーの前にクリップボードの中身を控え、確かめた後に戻す。
- A5 は、Windows 11 の手元の環境で展開する。環境が無いときは、未確認として記録する。
- A6 は、Finder のダブルクリックで展開する。

## トレードオフ

ドラッグを、ポインタがウィンドウの外に出たときに始めると、ウィンドウの中のドラッグ (画像の差し込み) と両立する。
しかし、ウィンドウの外に出た後も WebView にポインタの動きが届くかは未確認である。
届かないときは、行を押したまま動かし始めた時点で `NSDraggingSession` を始め、画像の差し込みも `NSDraggingSession` のドロップで受ける形に変える。
そのときは、この ADR を変える ADR を書く。

名前を UTF-8 とビット 11 で書くと、仕様に沿い、すべての文字を書ける。
一方、ビット 11 を読まない古い展開の道具は、名前を化かす。
名前を CP932 で書けば、日本語の環境の古い道具でも読めるが、CP932 に無い文字 (絵文字、一部の異体字) を書けず、日本語でない環境の Windows では化ける。
この ADR は、仕様に沿う前者を選ぶ。

格納で書くと、zip の大きさは中身の合計とほぼ同じになる。
成果物の PDF や画像はすでに圧縮されているので、大きさの差は主にテキストで出る。
deflate を自前で書く手間に対して、得るものが小さいので、圧縮はしない。

`.git` を除くと、zip に履歴が入らない。
原稿を人に送る用途では、履歴は要らず、大きさを増やすだけである。
履歴ごと渡したいときは、Finder の圧縮を使える。
