# ADR 0121: ローカルアシスタントの起動時に Golem のマニュアルを読み込む

Status: proposed

## 文脈

ローカルの Qwen に Golem の書き方を聞いたとき、同梱のマニュアルを参照した状態で最初の頼みに答えられるようにする。
Golem マニュアルの原本は、Golem リポジトリの `manual/` にある `.gm` ファイルとする。
マークアップ、マニフェスト、スタイル、Emet の資料と、診断コードの索引を起動時に読み込む。リファレンスや診断の詳しい説明からは、頼みを解くのに必要な箇所を選ぶ。

## 調査した事項

現在は、頼みごとにファイルの種類に対応する章を一つ選び、頼みと対象の本文に含まれる語で節を並べる。
Rust はまず資料を抜いた入力からコンテキスト長を決め、残った枠に資料を足す。そのため、本文が短い頼みでも選んだコンテキストが小さければ、必要な節が入らないことがある。
[資料の選択](https://github.com/tett23/aleph/blob/4682b5c2b3fa88581941d26d9a82e86d07e1257f/app/assistant/mount.ts#L54-L70)、[コンテキスト長の決定](https://github.com/tett23/aleph/blob/4682b5c2b3fa88581941d26d9a82e86d07e1257f/src-tauri/src/llama.rs#L522-L586)

Golem `v0.1.0-rc4` では `manual/manifest.toml` の `chapters` が、本文と付録の `.gm` の原本を列挙する。原本の見出しには章番号やファイル名と別に `@label` があり、同じ版の本文からの参照もそのラベルを使っている。例えば、原稿の記法は `markup`、Emet は `app-emet` である。
[マニュアルのマニフェスト](https://github.com/tett23/golem/blob/v0.1.0-rc4/manual/manifest.toml)、[原稿の記法](https://github.com/tett23/golem/blob/v0.1.0-rc4/manual/chapters/03-markup.gm)、[Emet](https://github.com/tett23/golem/blob/v0.1.0-rc4/manual/appendices/j-emet.gm)

llama.cpp `b12466` の `/tokenize` で同梱の Qwen3.5-4B-Q4_K_M を使って数えた。
`03-markup.gm` は 15,660、`04-manifest.gm` は 5,255、`05-style.gm` は 16,171 トークンだった。ファイル名と区切りを付けて固定順でつないだ試験用の資料は 37,118 トークンだった。チャットの指示、頼み、本文、回答枠はこの数に含めていない。

Golem `v0.1.0-rc4` の付録 J は、`.emet` の構文、型、組み込み関数、`.gm` からの呼び出し、ファイルを読む要求、フィルタ、診断を説明する。第 3 章も、原稿から関数を使う箇所で付録 J を参照している。
同じ Qwen の `/tokenize` で数えると付録 J 単体は 6,650 トークンだった。ファイル名と区切りを付けてつなぐと、三章と付録 J は 43,775 トークン、三章と付録 A〜J は 120,956 トークンだった。付録 E の診断一覧だけでも 32,409 トークンある。
[第 3 章](https://github.com/tett23/golem/blob/v0.1.0-rc4/manual/chapters/03-markup.gm#L383-L384)、[付録 J](https://github.com/tett23/golem/blob/v0.1.0-rc4/manual/appendices/j-emet.gm)

llama.cpp `b12466` は、同じスロットへの次の要求で先頭のトークンが一致したとき、プロンプトの KV キャッシュを再利用できる。
コンテキストを 65,536 にした一時サーバーで、三章を Qwen のテンプレートで書き出した先頭部分を `/completion` に渡した。先読みの計算は一回の試行で約 84 秒だった。続けて先頭が同じ短い試験要求を送ると、`timings.cache_n` は 37,120、`timings.prompt_n` は 15 だった。この試験では回答の正しさを判定していない。
既存の Qwen の計測では、該当する節を渡しても Golem の記法を正しく使わない事例があった。
[llama.cpp `b12466` のサーバー仕様](https://github.com/ggml-org/llama.cpp/blob/b12466/tools/server/README.md)、[2026-11-18 の回答品質の調査](../research/2026-11-18-assistant-prompt-and-context.md)

## 実装すること

### ローカルアシスタントの起動

パネルでローカルを選び、「ローカルを準備」を押すと、Rust がバックグラウンドでモデルを起動する。準備を始めずにローカルへ頼みを送った場合も、回答の前に同じ準備を行う。パネルを開いただけではローカルを起動しない。
マニュアルを読み込んでいるあいだは、アシスタントの欄に進行状態を表示する。読み込み中に送った頼みは準備が終わってから処理する。
モデルと資料の準備に失敗したときは理由を表示する。モデルが使える場合は、収まる節を頼みごとに選ぶ方式で答えられるようにする。

Rust は `markup`、`manifest`、`style`、`app-emet` に対応する `.gm` 原本の全文を、同梱した資料からこの順に読む。各原本にラベルを添え、システムメッセージの先頭に置く。
この後ろに `app-errors` の `.gm` 原本から作った診断コードとメッセージの索引を置く。同じコードに複数のメッセージがあるときは、原本の順にすべて残す。
この固定部分を先読みし、同じトークン列を `.gm`、`.emet`、`manifest.toml`、`style.toml`、`preflight.toml` を対象とする各要求の先頭に含める。
先読みの入力に使うトークン列は、実際の要求と同じチャットテンプレートから作る。モデルが共通部分をキャッシュに残せるように、固定部分は頼みや文書によって変えない。
要求ごとに変わる指示、コマンド一覧、作業例、頼み、本文はその後ろに置く。Golem のマニュアルを使う対象では、既に渡した全文と同じ節を重ねて渡さない。

待機による停止、モデルの変更、コンテキスト長の変更の後は、新しいサーバーで先読みする。動いているサーバーで必要なトークンを数えられるときは、それだけのためにサーバーを起動し直さない。
外部コネクタを選んでパネルを使う操作では、従来の資料の渡し方を使う。外部コネクタにだけ頼むためにローカルのサーバーを起動することはない。

### 同梱資料の選択

同梱する資料は、同梱の `golem` と同じタグの `manual/manifest.toml` の `chapters` に載る `.gm` 原本から選ぶ。各資料の指定には、原本の見出しに付いた `@label` を使う。同梱時にラベルから原本を特定し、マニフェストと選んだ原本を `tools.versions` の SHA-256 で検証する。Aleph は実行時にラベルで同梱資料を引く。

章番号、掲載順、ファイル名の変更には、ラベルから原本を引き直して追従する。指定したラベルが消えたり、複数の原本に現れたりした場合は、同梱を止めてラベルを示す。資料が分割されて別のラベルに移った場合は、版を更新するときに指定を見直す。

Emet の解説 `app-emet` は先読みする。他のリファレンスからは、次の表に該当する節を要求ごとの資料として固定部分の後ろに足す。
試作では、固定資料を全文使うときに足すコマンド一覧と付録の抜粋を、実際のチャットテンプレート上の増分で 2,048 トークンまでとする。

| ラベルと内容 | 渡す場面 |
| --- | --- |
| `app-markup`・`app-manifest`・`app-style`（記法・マニフェスト・スタイル） | コマンド名、テーブル名、キーから該当するリファレンスを選ぶ |
| `app-preflight`（`preflight.toml`） | `preflight.toml` を扱うときや、検査項目を聞かれたときに該当する節を選ぶ |
| `app-errors`（診断一覧） | コードとメッセージを索引として先読みする。頼みや検査結果に診断コードがあるときは、そのコードに一致する原本の意味と直し方を要求ごとの資料に優先して足す |
| `app-indesign`・`app-glossary`・`app-known-issues`（InDesign との対応・用語集・既知の不具合） | 頼みに対応する製品名、用語、不具合がある場合に該当する節を選ぶ |
| `app-roadmap`（今後の予定） | 実装済みの書き方を案内する資料の対象外とする |

### コンテキスト長

起動時は、索引を含む固定部分と回答枠を実際のモデルで数え、設定とモデルの上限内で収まる最小のコンテキスト長を選ぶ。
Golem を対象とする頼みでは、固定部分、指示、頼み、本文、回答枠を数えて、必要ならコンテキストを広げる。
全体が上限に入らない場合、頼みと対象本文を残したまま入り切る節を選び、固定資料を全文使えなかったことを表示する。`.emet` や `.gm` からの関数呼び出しについては `app-emet` の該当節を優先する。本文と頼みが入らないときは、[ADR 0117](0117-expand-assistant-context.md) に従って原稿を分ける。

## 実装しないこと

モデルの学習、モデルファイルの書き換え、Golem のパッケージ内部の仕様書の同梱。

## 不変条件

- I1: 上限内で全文を使うとき、先読みと各 Golem 向け要求は、同じチャットテンプレートで固定資料の共通の先頭トークン列を含む。
- I2: 先読みは同梱の文書だけを使い、利用者の原稿を含めない。
- I3: 送信前に計数し、入力と回答枠は設定とモデルの上限以内に収める。資料を足すために頼みや対象本文を削らない。
- I4: 外部コネクタで完了する頼みのためにローカルの先読みは始めない。
- I5: 要求に応じて選んだ付録の節を足しても、先読みする固定部分の先頭トークン列は変わらない。
- I6: 同梱資料は指定したラベルがマニュアルのマニフェストに登録された `.gm` 原本の一つに決まるときに限り採用する。資料の選択と先読みの順序はファイル名や掲載順で変わらない。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| ローカルを準備してから `.emet` の編集を頼む | `app-emet` を含む固定資料を先読みし、最初の要求にも同じ固定部分が入る | I1, I2 |
| 同じモデルで別の Golem ファイルを開く | 頼みと本文が変わっても固定部分のトークン列が一致する | I1 |
| 固定資料と 20 万字の原稿の両方が収まらない上限を設定する | 資料の範囲を知らせ、原稿を残す。原稿も入らないときは章と段落で分ける | I3 |
| 起動時から外部コネクタだけを使う | ローカルの先読みは起きない | I4 |
| Emet の診断コード `E03100` が返る | 先読み済みの索引にコードとメッセージがあり、`app-errors` の意味と直し方を要求ごとの資料に優先して足す。固定部分は変わらない | I5 |
| `app-emet` の原本を改名してマニフェスト内の順序を変える | 同じラベルから原本を選び、先読みの順序は変わらない | I6 |
| 指定したラベルがない、または複数の原本にある | 問題のラベルを示し、同梱を止める | I6 |

## 受けいれ条件

- A1: 同梱の Qwen と llama-server で、先読み後の最初の Golem 向け要求が固定部分の KV キャッシュを再利用する。再起動後も同じ結果になる。
- A2: 同じモデルを使った現行方式と全文方式を同じ課題で比較し、Golem の記法、マニフェスト、スタイル、Emet の正解数と、検査で止めた件数を記録する。

## テスト設計

サーバーを差し替え、固定部分と通常の要求のトークン列、起動と再起動の順序、先読み時の入力、上限に収まらない場合の資料選択、外部コネクタだけを使ったときの起動回数を確かめる。
同梱の試験には、ラベルを保ったまま原本のファイル名と掲載順を変更したもの、ラベルを削除したもの、別の原本に同じラベルを付けたものを使う。
診断索引の試験では、同じコードに複数のメッセージがある入力を使う。索引に各メッセージが残り、頼みに現れたコードの詳しい説明が要求ごとの資料に加わることを確かめる。
同梱の llama-server で先読みと最初の推論を動かし、計数とキャッシュから再利用したトークン数を確かめる（A1）。
既存のアシスタント計測の `.gm`、`manifest.toml`、`style.toml` の課題に、Emet の関数を書く課題と原稿から関数を呼ぶ課題を加える。同じモデル・量子化・温度とシードで比較し、回答に実際に渡した資料と有効なコンテキスト長を記録する。Emet の回答は、関数を読み込む最小の Golem プロジェクトで検査する（A2）。

## トレードオフ

全文の先読みには、節だけを渡す方式より長い起動時間と大きいコンテキストが要る。読み込みを別スレッドで行い、共通部分のキャッシュはサーバーが動くあいだ再利用する。
マニュアルの全文を渡したときの回答品質は計測して確かめる。編集案の適用前には、従来どおり Golem の検査を行う。
