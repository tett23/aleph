# ADR 0107: ペインの幅を越えたタブの並びをスクロールで扱う

Status: accepted

## 文脈

ペインは、タブの並び（`.tabbar`）を持つ（[ADR 0024](0024-tabs-and-split.md)）。
指示者は、タブがペインの幅を越えたときに、タブを縮めずにスクロールで扱うことを求めた（2026-11-23）。
今の並びも横にあふれるとスクロールするが、あふれていることが見えず、選んだタブが見えないままになることがある。
この ADR は、あふれた並びのスクロールの振る舞いを決める。

## 調査した事項

Aleph の調査対象は main の `4d0e5ed0e0bc83dd2065c1c6513b07573b4c217e` である。

- [`app/style.css` の 637 行](https://github.com/tett23/aleph/blob/4d0e5ed0e0bc83dd2065c1c6513b07573b4c217e/app/style.css#L637) の `.tabbar` は、`display: flex`、`overflow-x: auto`、`scrollbar-width: none` である。そのため、あふれると横にスクロールするが、スクロールバーは出ない。
- [同じファイルの 638 行](https://github.com/tett23/aleph/blob/4d0e5ed0e0bc83dd2065c1c6513b07573b4c217e/app/style.css#L638) の `.tab` は、`white-space: nowrap` と `max-width: 220px` を持ち、`flex-shrink` の指定は無い。
- [`app/editor/panes.ts` の 106〜116 行](https://github.com/tett23/aleph/blob/4d0e5ed0e0bc83dd2065c1c6513b07573b4c217e/app/editor/panes.ts#L106-L116) は、タブと末尾の「＋」（新しいタブ）を、一つの並びの中身にする。「＋」はタブの後ろに並ぶので、あふれると並びと一緒に隠れる。
- [同じファイルの 143 行](https://github.com/tett23/aleph/blob/4d0e5ed0e0bc83dd2065c1c6513b07573b4c217e/app/editor/panes.ts#L143) は、状態が変わるたびに `.tabbar` の `innerHTML` を入れ替える。
- 同じファイルに、タブの並びをスクロールする処理は無い。`scrollIntoView` は無く、`scrollLeft` は [193 行](https://github.com/tett23/aleph/blob/4d0e5ed0e0bc83dd2065c1c6513b07573b4c217e/app/editor/panes.ts#L193) の本文の要素を戻す処理だけである。`wheel` の処理も無い。
- タブのドラッグ（[同じファイルの 257〜281 行](https://github.com/tett23/aleph/blob/4d0e5ed0e0bc83dd2065c1c6513b07573b4c217e/app/editor/panes.ts#L257-L281)）は、ポインターの下の要素から `closest(".tabbar")` で落とし先の並びを決め、`mousemove` のたびに落とし先の印を描く。
- 2026-11-23 に、macOS 27.0 の WebKit 22625.1.29.11.27 の使い捨ての WKWebView で、`.tabbar` と `.tab` と同じ指定の、幅 400px の並びを測った（[検査のページ](../research/2026-11-23-tabbar-scroll-probe/probe.html)、`swiftc -O probe.swift -o probe && ./probe "$PWD/probe.html"`）。
  - 同じ名前のタブの幅は、タブが 1 個のときも 12 個のときも 144.0625px だった。今のタブは、あふれても縮まない（`white-space: nowrap` のタブの最小の幅が、名前の幅になるため）。
  - `scrollLeft` を 500 にした後、同じ中身で `innerHTML` を入れ替えても、`scrollLeft` は 500 のままだった。タブを 3 個に減らすと、`scrollLeft` はスクロールできる最大の値（32）に寄せられた。

## 実装すること

### 並びの組み立て

- ペインの上端を、外枠（`.tabstrip`）の中に、スクロールする並び（`.tabbar`）と「＋」（`.tadd`）を横に並べる形にする。「＋」は並びの外なので、スクロールによらず右端に見える。
- **見える幅** は、並びの `clientWidth` とし、**中身の幅** は、並びの `scrollWidth` とする。見える幅は「＋」の幅を含まない。
- `.tab` に `flex-shrink: 0` を足し、タブを縮めない指定を明示する。タブは今と同じく、名前の幅（220px まで）を保つ。
- ドラッグで「＋」の上にポインターがあるときは、並びの末尾を落とし先にする。

### 選んでいるタブを見せる

- 次のときに、選んでいるタブの全体が見える範囲に入るように、最小の量だけ並びをスクロールする。
  - 並びを描き直したとき（タブを選ぶ、開く、閉じる、移す、並べ替える、分割する、分割をやめる）。
  - 並びの見える幅が変わったとき（ウインドウの大きさ、ペインのあいだの境目のドラッグ、分割と分割をやめること）。`ResizeObserver` で並びの大きさの変化を受ける。
- タブの幅が見える幅より広いときは、タブの先頭を並びの先頭にそろえる。
- 描き直しても、上の場合のほかは、スクロールの位置を変えない。

### ホイール

- 並びの上の `wheel` の量を、`deltaMode` が 0 なら px のまま、1（行）なら 16 倍、2（ページ）なら見える幅の倍で、px に直す。
- 直した量の横（`dx`）と縦（`dy`）の絶対値を比べ、`|dx| >= |dy|` なら、何もせずブラウザに任せる（トラックパッドの横のスワイプ、⇧ を押したホイール）。
- `|dy| > |dx|` で、並びがあふれているときは、`scrollLeft` を `dy` だけ動かし（端で止まる）、既定の処理を止める。あふれていないときは、何もしない。

### 影

- 左端の影は `scrollLeft > 0.5` のときだけ、右端の影は `scrollLeft + clientWidth < scrollWidth - 0.5` のときだけ出す（0.5 は小数の px の誤差を吸う）。スクロールと描き直しのたびに決め直す。
- スクロールバーは、今と同じく出さない。

### ドラッグの自動スクロール

- タブをドラッグしているあいだ、ポインターが並びの左端から 24px の内側にあれば左へ、右端から 24px の内側にあれば右へ、`requestAnimationFrame` のたびに 8px ずつスクロールする。ポインターが止まっていても続け、端から離れるか、ドラッグを終えると止める。

### 文書

- 仕様書の「タブと分割」と、README に書く。

## 実装しないこと

- タブを縮めること、タブの並びを二段にすること。
- あふれたタブの一覧を出すメニュー。⌘P と ⌃Tab で選べるので、今は作らない。
- スクロールバーを出すこと。

## 不変条件

位置と幅は、並びの見える範囲の先頭を 0 とする px で表す。

- I1: タブの位置 `start`、幅 `width`、見える幅 `view`、今の `scrollLeft` から、見せるための新しい `scrollLeft` を返す関数は、`width <= view` なら `start` から `start + width` までを `[新しい scrollLeft, 新しい scrollLeft + view]` に含める値を返し、`width > view` なら `start` を返す。
- I2: I1 の関数は、条件を満たす値のうち、今の `scrollLeft` との差の絶対値が最小のものを返す。すでに全体が見えていれば、今の `scrollLeft` を返す。
- I3: ホイールの量を返す関数は、`|dx| >= |dy|` か、並びがあふれていない（`scrollWidth <= clientWidth`）なら 0 を返し、そのほかは `deltaMode` で px に直した `dy` を返す。
- I4: 影の有無を返す関数は、左を `scrollLeft > 0.5` のときだけ、右を `scrollLeft + clientWidth < scrollWidth - 0.5` のときだけ真にする。
- I5: ドラッグの自動スクロールの量を返す関数は、ポインターが左端から 24px の内側なら -8、右端から 24px の内側なら 8、どちらでもなければ 0 を返す。見える幅が 48px 未満で両方に当たるときは 0 を返す。
- I6: `.tab` は `flex-shrink: 0` を持つ。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| タブが 0 個（`scrollWidth == clientWidth`） | ホイールの量は 0、影は出ない | I3, I4 |
| タブが 1 個で見える範囲に収まる | `scrollLeft` を変えない | I1, I2 |
| 中身の幅がちょうど見える幅に等しい | ホイールの量は 0、影は出ない | I3, I4 |
| 中身の幅が見える幅より 1px 大きい | 縦のホイールで最大 1px 動く、右端に影 | I3, I4 |
| 右に隠れた末尾のタブを選ぶ | 末尾がちょうど右端に来る値 | I1, I2 |
| 左に隠れたタブを選ぶ | そのタブの先頭が左端に来る値 | I1, I2 |
| 見えているタブを選ぶ | 今の `scrollLeft` | I2 |
| 見える幅より広い 1 個のタブ | タブの先頭 | I1 |
| `|dx| == |dy|` のホイール | 0 | I3 |
| `deltaMode` が 1 で `dy` が 3 | 48 | I3 |
| `scrollLeft` が 0.4 | 左の影は出ない | I4 |
| ポインターが左端から 24px、25px | -8、0 | I5 |
| 見える幅 40px の中央 | 0 | I5 |

## 受けいれ条件

- A1: Tauri で、ペインの幅を越える数のタブを開き、縦のホイールとトラックパッドの横のスワイプで並びを動かせること、隠れた側の端に影が出ること、「＋」がいつも見えることを確かめる。
- A2: 隠れているタブを ⌃Tab、⌘ と数字、⌘P、ツリーで選ぶと、そのタブが見える位置までスクロールすることを確かめる。ウインドウを狭めたときも、選んでいるタブが見え続けることを確かめる。
- A3: タブをドラッグして並びの端に近づけると並びがスクロールし、隠れていた位置と「＋」の上（末尾）に置けることを確かめる。
- A4: 左右に分割したそれぞれのペインで A1 と A2 が成り立つこと、分割したときと分割をやめたときに、選んでいるタブが見えることを確かめる。

## テスト設計

- I1 から I5 は、DOM を持たない関数にし、`ADR 0107 I1: …` などの名前のテストで、境界の表の各行を `node --test` で確かめる。今のテストは、`document` に手作りの偽物を入れるだけで、レイアウトとスクロールを計算しない（`app/ui/ribbon.test.ts` など）。そのため、要素の実際の位置は、テストでは確かめない。
- I6 は、`app/style.css` の `.tab` の規則に `flex-shrink: 0` があることを、`ADR 0107 I6: …` のテストで確かめる。
- 要素の実際の位置、`ResizeObserver` と `requestAnimationFrame` の働きは、A1 から A4 として Tauri のデバッグ版で手で確かめ、結果を `docs/audits/` に記録する。

## トレードオフ

- 縮めないので、タブの名前はいつも読める。代わりに、多く開くと、一度に見えるタブは少なくなる。
- スクロールバーを出さないので、並びの高さは今のままである。代わりに、あふれていることは影だけで示す。
- 「＋」を並びの外に置くと、並びの見える幅が「＋」の分だけ狭くなる。
