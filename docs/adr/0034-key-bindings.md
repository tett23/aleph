# ADR 0034: キーの割り当てを変える

ステータス: 採択

## 文脈

Aleph のキーの割り当ては、コードに書いたものだけで、変えられない。
割り当ては、次の場所に分かれている。

- エディタの割り当て（⌘S、⌘Z、⇧⌘Z、⌘Y、⌘A、⌘F、⌃Space、Tab、⇧Tab、Esc）は、エディタの `KEYS` の表にある（[app/ed/editor.ts](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/ed/editor.ts#L151-L170)）。LSP の形式では、プラグインの割り当て（⌘S の整形と保存、⌥⇧F の整形）が先に引かれる。
- 画面の全体の割り当て（⇧⌘F の検索、⇧⌘K のコミット）は、それぞれの部品が `window` の `keydown` で引いている（[app/searchpanel.ts](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/searchpanel.ts#L115-L122)、[app/gitpanel.ts](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/gitpanel.ts#L178-L184)）。
- 割り当ての文字列（`Mod-Shift-z` など）は、文字と、キーの位置（`KeyboardEvent.code`）の両方で引く（[app/ed/keys.ts](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/ed/keys.ts)、[ADR 0019](0019-one-editor-for-both-writing-modes.md)）。macOS で ⌥ が文字を変えるためである。
- メニューの項目の名前に、割り当てを書き込んでいる（「整形（⌥⇧F）」「コミット（⌘⇧K）」）。

Obsidian は、設定の画面ですべての操作の割り当てを変えられる。
メンテナーから、Obsidian と Ulysses にあって Aleph にない機能を比べたうえで、キーの割り当ての変更の ADR を作るよう求められた（2026-11-07）。
同じ比べ方から、コマンドパレットの [ADR 0023](0023-command-palette.md) が、操作を名前と識別子で登録する仕組みを決める。
この ADR は、その識別子に割り当てを結びつける。

下書きのレビューでは、リーダーキーを設定できること、二つ以上のキーを続けて押す割り当てを許すことを求められた（2026-11-08）。
Vim のように、リーダーキーに続けて文字を押して操作を呼びたい、という理由である。
Vim では、割り当ての中の `<Leader>` を、リーダーキー（`mapleader`）の値に置き換える。値は割り当てを定めたときに読まれる。続けて押すキーの並びが割り当ての途中にあるあいだは、次のキーを 1 秒（`timeoutlen`）待ち、過ぎたら短いほうの割り当てとして扱う。
Aleph では、リーダーキーを変えたら `Leader` を含む割り当てがすべて新しいキーで呼ばれるようにする（割り当てを定め直さなくてよいため）。
ただし Aleph のエディタには Vim のノーマルモードがなく、修飾キーのない文字のキーはいつも文字の入力になる。

## 実装すること

### 操作と既定の割り当て

- キーで呼べる操作は、すべて [ADR 0023](0023-command-palette.md) の操作の登録に識別子で載せる。エディタの割り当ても、[ADR 0023](0023-command-palette.md) の一覧の `file.save`、`editor.undo`、`editor.redo`、`editor.selectAll`、`editor.find`、`editor.complete`、`editor.indent`、`editor.outdent`、`editor.format` の識別子の操作として登録する。各部品が `window` の `keydown` で引いていた割り当ても、操作の登録に移す。
- 操作ごとに、既定の割り当てを持つ。割り当ては一つの操作に複数持てる（⇧⌘Z と ⌘Y のやり直し）。
- 割り当ては、一つ以上の打鍵の並びとする。打鍵は `Mod-Shift-k` のような修飾キーとキーの組で、並びは空白で区切って書く（`Mod-k Mod-s`、`Leader f f`）。
- キーの押下を引く処理は一つにまとめ、利用者の割り当て（なければ既定）から操作を探して実行する。エディタの中の操作（`editor.*`）は、エディタに焦点があるときだけ引く。
- メニューの項目の名前の割り当ては、名前に書き込まず、今の割り当てから作って表示する。

### リーダーキーと打鍵の並び

- 設定の「リーダーキー」で、一つの打鍵をリーダーキーにする。既定は ⌘;（`Mod-;`）とする。割り当ての中の `Leader` は、そのときのリーダーキーに読み替える。リーダーキーを変えると、`Leader` を含むすべての割り当てが新しいキーで呼ばれる。
- 並びの 1 打目は、⌘、⌃、⌥ のどれかを含む打鍵か、ファンクションキーでなくてはならない（修飾キーのない文字のキーは、文字の入力だからである）。リーダーキーも同じ制限に従う。2 打目からは、修飾キーのない文字のキーも使える（`Leader f f`）。
- 押した打鍵の並びが、ある割り当ての途中（ほかの割り当ての先頭の部分）にあるあいだは、次の打鍵を待つ。待つあいだは、押したキーをエディタにも入力方式にも渡さず、ステータスバーに押した並び（`⌘; f …` など）を出す。
- 待つ時間は、設定の「続けて押すキーを待つ時間」（既定 1000 ミリ秒）とする。時間が過ぎたとき、そこまでの並びがちょうどある割り当てに当たれば、その操作を実行する。当たらなければ、何もせずに待つのをやめる。
- 待つあいだに、続きのどの割り当てにも当たらない打鍵を押したときは、そこまでの並びを捨て、その打鍵を初めの 1 打目として改めて引く（文字のキーならそのまま入力になる）。Esc は待つのをやめるだけで、ほかの操作には渡さない。
- ちょうど当たる割り当てが、ほかの長い割り当ての先頭でもあるとき（`Leader g` と `Leader g c` など）は、待つ時間が過ぎるまで実行しない（Vim と同じ）。設定の画面では、この重なりを注意として示す。
- 日本語の入力の変換中は、並びを始めない。待つあいだに変換が始まったら、待つのをやめる。

### 変える

- 設定に「キーの割り当て」の節を足す。操作の名前、識別子、今の割り当てを一覧にし、名前で絞り込める。
- 割り当ての欄を押すと、続けて押した打鍵の並びを記録する。打鍵は、修飾キー（⌘、⌃、⌥、⇧）と、文字のキーはキーの位置（`KeyA`、`Digit1` など）から作る。⌥ で文字が変わっても、同じ割り当てになる。打鍵のあいだが待つ時間より空くか、↩ を押すと記録を終え、Esc で記録をやめる。1 打目がリーダーキーなら、`Leader` として記録する。
- 記録した並びが、ほかの操作に割り当て済みなら、その操作の名前を示し、「置き換える」（ほかの操作から外す）か「やめる」を選ばせる。ほかの割り当ての先頭と重なるときは、待つ時間が過ぎるまで実行されないことを注意として示す。
- 操作ごとの「既定に戻す」と、全体の「すべて既定に戻す」を持つ。割り当てを外す（キーなし）こともできる。
- 利用者の割り当ては、`config.json` の `keyBindings` に、既定と違う操作だけを `{ "<識別子>": ["Mod-Shift-k", "Leader g c"] }` の形で置く。リーダーキーは `leaderKey`、待つ時間は `keySequenceTimeout`（ミリ秒、200 から 5000 に丸める）に置く。読み込むとき、知らない識別子と読めない割り当ては捨てる（[ADR 0004](0004-workspaces-and-projects.md) の設定の読み込みと同じ扱い）。

### 変えられないキー

- 日本語の入力（IME）の変換中のキーは、割り当てに関わらず入力方式に渡す（[ADR 0019](0019-one-editor-for-both-writing-modes.md)）。
- アプリのメニューが持つキー（⌘Q、⌘W、⌘C、⌘V、⌘X、⌘M、⌃⌘F など、macOS とメニューの割り当て）は、割り当ての対象にせず、記録しようとしたときは「このキーは使えません」と知らせる。
- 修飾キーのない文字のキー、Enter、Backspace、矢印キーは、編集の入力なので、並びの 1 打目には割り当てられない（Tab、⇧Tab、Esc は既定の操作に限り、エディタの中で使う）。2 打目からは、修飾キーのない文字のキーを使える。

## 実装しないこと

- 割り当ての書き出しと読み込み、ほかのエディタ（VS Code など）の割り当ての取り込み。
- Vim のモード（ノーマルモード、ビジュアルモードなど）による編集と、Vim や Emacs のカーソルの動き。リーダーキーと打鍵の並びは、操作を呼ぶためだけに使う。
- 打鍵の並びに数（`3dd` のような繰り返しの回数）を添えること。
- Aleph のプラグイン（[ADR 0017](0017-aleph-plugins.md)）が登録した操作への割り当て（プラグインの操作は [ADR 0023](0023-command-palette.md) の登録に載るかによって、別に決める）。
- アプリのメニューの割り当ての変更。

## テスト設計

DOM に触れない部分を関数に分け、`node --test` で先に書いて失敗させてから実装する。

- 打鍵の並びを読み書きする関数：空白で区切った並びを打鍵の列にし、`Leader` をリーダーキーに読み替えること。1 打目に修飾キーのない文字のキーを置いた並びを拒むこと、2 打目からは許すこと。
- 打鍵の並びを引く状態の機械（時刻を引数に取る）：1 打で当たる割り当てをすぐ実行すること、途中の並びで待つこと、続きで当たったら実行すること、続きに当たらない打鍵で並びを捨ててその打鍵を改めて引くこと（文字のキーは入力に渡すこと）、Esc で待つのをやめること、待つ時間が過ぎたらちょうど当たる割り当てを実行し当たらなければ何もしないこと、短い割り当てが長い割り当ての先頭のときは時間が過ぎるまで実行しないこと、変換中は始めないこと。リーダーキーを変えると `Leader` の割り当てが新しいキーで引かれること。
- 押下から割り当ての文字列を作る関数：修飾キーの順を決めること（`Mod`、`Ctrl`、`Alt`、`Shift`）、文字のキーは `code` から作ること（⌥⇧F で `key` が `Ï` でも `Shift-Alt-f` になること）、数字のキー、名前のあるキー（`Tab`、`Space`、`F1`）、修飾キーだけの押下は割り当てにしないこと。
- 割り当ての文字列を表示の文字（`⌘⇧K` など）にする関数。
- 利用者の割り当てと既定から、押下に当たる操作を探す関数：利用者の割り当てが既定より先に効くこと、外した割り当てでは呼ばれないこと、エディタの中の操作がエディタの外では引かれないこと。既存の `matchKey` のテストは、そのまま通ること。
- 重なりを見つける関数：記録したキーの組がほかの操作の割り当てに当たるとき、その操作を返すこと。置き換えたときに、ほかの操作から外れること。
- 変えられないキーの判定：メニューのキー、修飾キーのない文字のキー、Enter、Backspace、矢印キー。
- 設定の読み込み：知らない識別子と読めない割り当てを捨てること、既定と同じ割り当ては書き出さないこと、リーダーキーに修飾キーのない文字のキーを置いたものを既定に戻すこと、待つ時間を範囲に丸めること。
- 画面の確かめ方：設定でコミットの割り当てを ⌥⌘C に変え、⌥⌘C でコミットの欄に移ること、⇧⌘K では移らないこと、メニューの表示が変わること。保存（`file.save`）に割り当て済みのキーを別の操作に記録すると、重なりの確かめが出ること。「すべて既定に戻す」で戻ること。日本語の入力の変換中に、割り当てたキーが入力方式に渡ること。コミットに `Leader g c` を割り当て、エディタで ⌘; g c と押すとコミットの欄に移り、文字が入力されないこと、ステータスバーに押した並びが出ること、⌘; のあと 1 秒何も押さないと待つのをやめること、⌘; x のように続きのない文字を押すと x が入力されること。

## トレードオフ

- エディタにノーマルモードがないので、リーダーキーは修飾キーつきの打鍵に限られ、Vim のように空白をリーダーキーにはできない。リーダーキーの直後に打った文字は、割り当ての続きに当たれば、文字として入力されず操作の一部になる。リーダーキーは文字を打つときに押さない修飾キーつきの打鍵なので、ふだんの入力とは混ざりにくい。
- 文字のキーをキーの位置で記録するので、配列の違うキーボード（Dvorak など）では、刻印と違う文字の位置に割り当たる。macOS の ⌥ で文字が変わる問題を避けることを優先した（[ADR 0019](0019-one-editor-for-both-writing-modes.md) と同じ判断）。
- アプリのメニューのキーは変えられないので、⌘W などを別の操作に使うことはできない。コピーや貼り付け、ウィンドウの操作のキーは、macOS のほかのアプリとそろっていることを優先した。
- [ADR 0023](0023-command-palette.md) の操作の登録に依存するので、[ADR 0023](0023-command-palette.md) より先には実装できない。
