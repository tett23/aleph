# ADR 0035: Markdown の改行の扱いと GFM

ステータス: 採択

## 文脈

Markdown のプレビュー（[ADR 0010](0010-previews.md)）は、自前の読み方（[`app/md.ts`](https://github.com/tett23/aleph/blob/22b9ab6b1fc39e0a1b4cad4ca21bee0e9357dec3/app/md.ts)）で HTML にする。
段落の中の改行は CommonMark に従い、行末の空白 2 つか `\` のときだけ強制改行（`<br>`）になる。
それ以外の改行は段落の中の柔らかい改行で、HTML ではそのまま `\n` として出すので、行は一続きに描かれる。
日本語の文を一行ずつ書くと、プレビューでは行がつながり、書いた形と違って見える。

GFM（GitHub Flavored Markdown）のうち、今の読み方が読むのは表だけである。
取り消し線（`~~文~~`）、タスクリスト（`- [ ] 項目`）、自動リンク（`https://…` と `<https://…>`）は、文字として出る。

メンテナーは、改行をそのまま改行にするか、空行（2 つの改行）で改行にするかを設定で選べるようにし、既定を「改行はそのまま改行」にするよう求めた（2026-11-08）。
あわせて、GFM を有効にするよう求めた。

同じ読み方は、gm への変換（[ADR 0016](0016-markdown-to-gm.md)）、字数の数え方、埋め込み（[ADR 0029](0029-embeds.md)）も使う。

## 実装すること

### 改行の扱い

- 設定の「エディタ」の節に「Markdown の改行」を足し、次の二つから選ぶ。値は `config.json` の `markdownBreaks` に置く。
  - **改行をそのまま改行にする**（`"newline"`、既定）：段落の中の改行を、すべて強制改行（`<br>`）として描く。GitHub のコメントや Obsidian の「厳密な改行」を切ったときと同じ扱いである。
  - **空行で改行する**（`"blank-line"`）：今までどおり CommonMark に従う。段落の中の改行は柔らかい改行で、行末の空白 2 つか `\` のときだけ強制改行にする。段落は空行で区切る。
- この設定は、プレビュー（埋め込みの中身を含む）の描き方にだけ効く。どちらでも、空行は段落を区切る。
- 柔らかい改行は、HTML で `\n` のまま出す。WebKit は日本語の文字のあいだの `\n` を空白として描くことがあるので、前後のどちらかが CJK の文字のときは、`\n` を出さずにつなぐ（CSS Text の分節の改行の変換の考え方に合わせる）。
- gm への変換は、今までどおりプロジェクトの `paragraph-separator`（[ADR 0016](0016-markdown-to-gm.md)）に従い、この設定を見ない。字数の数え方も変えない。

### GFM

[GFM の仕様](https://github.github.com/gfm/) の拡張のうち、次のものを読む。

- **取り消し線**：`~~文~~`（`~` 1 つは取り消し線にしない）。行内の要素 `{ t: "del"; c: Inline[] }` として読み、プレビューでは `<del>` にする。
- **タスクリスト**：箇条書きと番号付きリストの項目の先頭の `[ ]` と `[x]`（`[X]` も）。項目に `checked: boolean | null` を持たせ、プレビューでは押せないチェックボックス（`<input type="checkbox" disabled>`）を前に出す。
- **自動リンク**：`<https://…>` と `<mailto:…>`、および文の中の `https://`、`http://`、`www.` で始まる URL（GFM の拡張された自動リンクの規則で、末尾の句読点と閉じ括弧を除く）。プレビューではリンクにする。
- **表**：今の読み方のまま。列の揃え（`:---:` など）を `text-align` として出すことを足す。
- **HTML のタグ**：今までどおり文字として出し、許さない（GFM の「許さない生の HTML」より厳しい）。

これらは、エディタの字句の読み方（`md`）にも足す。取り消し線は `t-del`、タスクリストの `[ ]` と `[x]` は `t-keyword`、自動リンクは `t-link` とする。

gm への変換では、取り消し線は中身の文字だけを残す（Golem に取り消し線の命令がないため）。タスクリストの印は、`☐` と `☑` の文字にして項目の先頭に残す。自動リンクは URL の文字をそのまま残す。
字数の数え方では、取り消し線の中身も数え、タスクリストの印は数えない。

## 実装しないこと

- 脚注（`[^1]`）。GFM の仕様に含まれない、GitHub の独自の拡張であるため。
- 数式、絵文字のショートコード（`:smile:`）、メンション（`@名前`）、Issue の参照（`#123`）。
- プレビューのタスクリストを押して、元の文書の `[ ]` と `[x]` を切り替えること。
- 改行の扱いを、シートやプロジェクトごとに変えること。
- 生の HTML を描くこと。

## テスト設計

DOM に触れない部分を関数に分け、`node --test` で確かめる。テストを先に書いて失敗させてから実装する。

- 改行：`"newline"` で段落の中の改行が `<br>` になること、`"blank-line"` で今までどおり柔らかい改行になり、行末の空白 2 つと `\` だけが `<br>` になること。どちらでも空行が段落を区切ること。柔らかい改行の前後が CJK の文字のとき、`\n` を出さないこと。埋め込みの中身にも同じ設定が効くこと。
- 設定の読み込み：前の版の `config.json`（`markdownBreaks` のないもの）と、知らない値が `"newline"` になること。
- 取り消し線：`~~a~~` が `del` になること、`~a~` と閉じていない `~~` が文字のままであること、強調との入れ子、コードのスパンの中で読まないこと。
- タスクリスト：`[ ]`、`[x]`、`[X]`、入れ子、番号付きリスト、`[ ]` の後に空白のない項目を印として読まないこと。
- 自動リンク：`<https://…>`、文の中の `https://…` と `www.…`、末尾の `。`、`.`、`)` を含めないこと、日本語の文に続く URL、コードのスパンの中で読まないこと、`javascript:` を許さないこと。
- 表の列の揃え：左、中央、右、指定のないもの。
- 字句の読み方：`t-del`、タスクリストの印、自動リンクの範囲。
- gm への変換と字数：上に書いた扱いになること。
- 画面の確かめ方：設定で二つを切り替え、日本語の段落を一行ずつ書いた `.md` のプレビューの描き方が変わること、取り消し線、タスクリスト、自動リンク、揃えのある表が描かれることを確かめる。

## トレードオフ

- 既定で改行をそのまま改行にするので、CommonMark として書いた文書（段落の中で行を折り返して書いたもの）は、プレビューで行が折れて見える。日本語の文を一行ずつ書く使い方を優先した。そうした文書は、設定で「空行で改行する」に切り替えて読む。
- gm への変換は、この設定ではなくプロジェクトの様式に従うので、プレビューの見え方と、変換した `.gm` の段落の区切り方が違うことがある。変換の結果は Golem の組版で決まるので、プロジェクトの様式を正とした。
- 拡張された自動リンクを読むので、文の中の URL らしい文字は、意図しなくてもリンクになる。
