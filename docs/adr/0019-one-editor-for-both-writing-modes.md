# ADR 0019: 縦書きと横書きを一つのエディタで書く

ステータス: 採択→縦書きの矢印キーの向きは [ADR 0059](0059-arrow-keys-in-vertical-writing.md)

## 文脈

Aleph のエディタは二つある。
横書きは CodeMirror 6 で書き、色付け、変更の印、行番号、診断、改ページの見積もり、LSP のホバーと補完と整形を持つ（[ADR 0006](0006-horizontal-editor.md)、[ADR 0009](0009-lsp-and-formatting.md)）。
縦書きは、`writing-mode: vertical-rl` のテキストエリアの裏に、行番号と変更の印を描く影の層を重ねたもので、色付けも LSP の表示も整形も持たない（[ADR 0007](0007-vertical-editor.md)）。

縦書きを別の仕組みにしたのは、CodeMirror 6 が縦書きを扱わないためである。
`@codemirror/view` 6.43.15 の源（[viewstate.ts](https://github.com/codemirror/view/blob/fbff59ba004d80d8c914f64c42586387b08706ac/src/viewstate.ts)、[heightmap.ts](https://github.com/codemirror/view/blob/fbff59ba004d80d8c914f64c42586387b08706ac/src/heightmap.ts)）は、行の位置を上から下への高さとして持ち、カーソルの上下の移動もその前提で求めている。
`writing-mode` に触れる箇所はない。

二つの仕組みを持つため、縦書きでは整形も診断の波線も補完も使えず、二つのエディタで同じ機能を二度書くことになっている。
メンテナーから、エディタを縦書きと横書きの両方に対応する形で作り直すよう求められた（2026-11-07）。
見た目は今と同じでよく、既存のエディタの実装やテストは、ライセンスに問題がなければ取り入れてよいとされた。
続けて、CodeMirror を引き継ぐ必要はなく、全体を一から作るよう求められた。
下書きのレビューでは、表示を仮想化すること、IME の扱いをテストを厚く書いて実装すること、縦書きでも LSP の表示と整形を行うこと、複数のファイルを開いたときも縦書きを保つことを求められた。

## 実装すること

### 構成

- 縦書きと横書きを、一つのエディタで書く。切り替えは、エディタの根の要素の `writing-mode`（`horizontal-tb` と `vertical-rl`）を変えるだけとし、エディタを作り直さない。
- エディタは、CodeMirror の部品を使わず、一から書く。`@codemirror/*` と `@lezer/*` の依存をすべて外す。CodeMirror の源とテスト（MIT）は参考にし、取り入れた部分には出典と著作権の表示を残す。
- エディタは次の部品からなる。DOM に触れない部品（文書、変更、履歴、字句の読み方、行の描画の材料）と、DOM に触れる部品（表示、入力、溝、浮かぶ窓）を分ける。
  - **文書**：文字列と行の始まりの位置の表を持つ、変えられない値。行と位置の相互の変換を持つ。
  - **変更**：元の文書に対する置き換えの並び。文書に当て、位置を写し（変更の前の位置を後の位置に直す）、逆の変更を作れる。
  - **状態**：文書、選択、履歴などをまとめた変えられない値。状態に変更を当てたトランザクションが、新しい状態を作る。
  - **履歴**：変更とその逆を積む。続けて打った文字は、入力が 500 ミリ秒止まるまで一つにまとめる。整形（[ADR 0009](0009-lsp-and-formatting.md)）や `@figure` の差し込みは、一つの変更として積む。
  - **字句の読み方**：形式ごとに、行の始まりの状態を受けて、その行のトークン（範囲と種類）と次の行の状態を返す関数。`.gm` は今の `app/gm.ts` の読み方を使い、`.emet`、`.md`、`.toml`、`.svg`（XML）、Mermaid の読み方を自前で書く。行の状態を覚えておき、変わった行から状態が元と同じになる行まで読み直す。

### 表示

- 編集する部分は `contenteditable` の一つの要素とし、文書の 1 行を一つのブロックの要素に描く。行の中は、色付け、semantic tokens（[ADR 0009](0009-lsp-and-formatting.md)）、診断、不可視文字の範囲を重ねて分けた `span` の並びとする。
- 文書が変わったら、変わった行だけを描き直す。
- 表示を仮想化する。見えている行と、その前後に少しの余白の行だけを描き、描かない行は、行の大きさ（ブロックの向きの長さ。横書きでは高さ、縦書きでは幅）の合計を持つ空きの要素で置き換える。
  - 行の大きさは、描いたときに測って覚え、まだ測っていない行は、字数と 1 行の字数から折り返しの数を見積もって求める。行の大きさの表は、変更のたびに写して保つ（CodeMirror の heightmap と同じ考え方を、ブロックの向きに一般化する）。
  - スクロールと枠の大きさの変化で、描く範囲を決め直す。縦書きではスクロールは横の向きになり、右端が文書の始まりである。
  - 選択の両端と、IME の変換中の行は、見えていなくても描く。見えていない行をまたぐ選択は状態に持ち、コピーと削除は状態から行う。⌘A は状態の選択を全体にする。
  - 指定の行へ移る（`goto`、診断の一覧、検索）ときは、その行のあたりを先に描いてからスクロールする。
- 1 行の字数は、論理の大きさ（`max-inline-size` に字数を掛けた値）で決める。横書きでは幅、縦書きでは高さになる（[ADR 0006](0006-horizontal-editor.md)）。
- 溝（変更の印、行番号、診断の印）は、各行の要素に、論理の位置（`inset-inline-start` を負にした絶対位置）で付ける。横書きでは行の左、縦書きでは行の上に出る（[ADR 0007](0007-vertical-editor.md) の「各行の上に行番号」と同じ見た目になる）。折り返した行では、最初の折り返しの位置にそろえる。
- 改ページの見積もりの印は、行と行のあいだの編集できない要素とする。縦書きでも出す。
- 縦書きでは、エディタの外側の枠を横にスクロールし、開いたときは冒頭（右端）を出す。

### 入力

- 文字の入力、削除、改行、貼り付け、⌘Z と ⇧⌘Z は、`beforeinput` を受けてトランザクションに直し、ブラウザに DOM を変えさせない。
- 日本語の入力（IME）は、変換を受け持つ部品に分け、厚くテストする。
  - 変換中（`compositionstart` から `compositionend` まで）は、ブラウザに DOM を変えさせ、その行を描き直さない。ほかの行の描き直し（LSP の色付けや診断の到着、自動保存）は、変換が終わるまで待たせる。
  - 確定のときに、変換を始めたときの行の文字と、確定のあとの DOM の行の文字から変更を求め、一つのトランザクションにする。選択した範囲を変換で置き換えた場合も扱う。
  - 変換の取り消し（何も確定しないで終わる）、変換中の Enter での確定、確定の直後の続けての変換、変換中のフォーカスの移動を扱う。
  - WebKit の `beforeinput`（`insertCompositionText`）、`input`、`compositionupdate`、`compositionend` の順と中身は、Tauri の WebView で実際に記録した列を試料にし、それに合わせる。
- カーソルの移動と範囲の選択は、ブラウザの `contenteditable` に任せる。縦書きでの矢印キーの向き（上下が行の中、左右が行のあいだ）もブラウザが決める。選択は `selectionchange` で文書の位置に直して状態に持つ。
- キーの割り当ては、`Mod-s`、`Shift-Alt-f`、`Mod-z`、`Mod-Shift-z`、`Tab` などを、文字ではなくキーの位置（`KeyboardEvent.code`）でも引けるようにする（macOS で ⌥ が文字を変えるため）。

### 機能

今の横書きのエディタが持つ機能を、縦書きでも同じように持つ。

- 色付けと、命令と式の等幅（[ADR 0006](0006-horizontal-editor.md)、[ADR 0009](0009-lsp-and-formatting.md)）。
- HEAD からの変更の印（[ADR 0011](0011-saving-and-git.md)）、行番号、不可視文字、改ページの見積もり。
- LSP の診断の波線と溝の印、エディタの診断の一覧、ホバー、補完、整形、⌘S での整形（[ADR 0009](0009-lsp-and-formatting.md)）。縦書きでは、[ADR 0007](0007-vertical-editor.md) と [ADR 0009](0009-lsp-and-formatting.md) が縦書きで出さないとした LSP の表示と整形も出す。
- 検索（⌘F）と置換のパネル。
- ツリーの画像のドラッグ（[ADR 0018](0018-drag-image-from-tree.md)）とファイルのドロップ（[ADR 0014](0014-shared-library-and-assets.md)）による `@figure` の差し込み。縦書きでも差し込める。
- 複数のファイルをまとめて開いたとき（[ADR 0006](0006-horizontal-editor.md)）も、縦書きを保つ。縦書きでは、ファイルを右から左へ並べ、各ファイルの見出しをその右端に付ける。横書きでは、今までどおり上から下へ並べる。[ADR 0006](0006-horizontal-editor.md) の「複数の章を開いているあいだは、エディタは横書きとする」を、この ADR で置き換える。

### 置き換え

- 新しいエディタができたら、CodeMirror で作った今のエディタ（`app/editor/cm.ts`）と、縦書きのテキストエリア（`app/editor/vertical.ts`、`app/editor/mirror.ts`）を消し、`package.json` から `@codemirror/*` と `@lezer/*` を外す。
- [ADR 0007](0007-vertical-editor.md) は、この ADR で置き換える。[ADR 0006](0006-horizontal-editor.md) と [ADR 0009](0009-lsp-and-formatting.md) のうち、CodeMirror で作るとした部分と、縦書きで LSP の表示と整形をしないとした部分を、この ADR で置き換える。

## 実装しないこと

- 複数の選択範囲（複数のカーソル）と矩形の選択。
- 横書きと縦書きの混在（一つのシートの中で縦中横以外の向きを変えること）。縦中横は Golem の組版の側の機能で、エディタでは横に倒したまま出す。
- 右から左へ書く文字（アラビア文字など）の双方向の扱い。

## テスト設計

DOM に触れない部分は関数に分け、`node --test` で確かめる。CodeMirror のテストのうち、使う部分に当たるものを参考にする。

- 行の描画の材料：一つの行について、色付け、semantic tokens、診断、不可視文字の範囲を重ね、境目で分けた `span` の並び（範囲と class）を求める関数を確かめる。範囲の重なり、行をまたぐ範囲、空の行、日本語とサロゲートペアを含める。
- 変わった行の求め方：変更の前後の文書から、描き直す行の範囲を求める関数を確かめる（行の追加、削除、行の中の変更、末尾への追加）。
- 入力の変換：`beforeinput` の種類（`insertText`、`insertParagraph`、`deleteContentBackward`、`deleteContentForward`、`deleteWordBackward`、`insertFromPaste`、`historyUndo`、`historyRedo`）と選択から、変更の内容を求める関数を確かめる。
- IME：変換を受け持つ部品を、DOM のイベントの列を受けて変更と描き直しの指示を返す状態の機械として書き、イベントの列を与えて確かめる。
  - 試料は、Tauri の WebView（WebKit）で日本語入力（macOS の日本語入力と、使えれば ATOK などほかのもの）を使って記録したイベントの列とする。記録の手順と道具（イベントを JSON に書き出すデバッグ用の画面）も置く。
  - 確かめる場合：行の先頭、途中、末尾での変換と確定、選択した範囲の置き換え、変換の取り消し、Enter での確定、確定の直後の続けての変換、変換中の矢印キーでの文節の移動、変換中の別の行の描き直しの要求（待たせること）、変換中のフォーカスの移動、変換中の自動保存、空の行での変換、サロゲートペアと結合文字を含む確定、縦書きと横書きの両方。
  - 確定した変換の取り込み：変換の前の行の文字と、確定のあとの DOM の行の文字から変更を求める関数を、上の各場合で確かめる。
- 仮想化：行の大きさの表（測った値と見積もり）、変更による写し、スクロールの位置から描く行の範囲を求める関数、選択の両端と変換中の行を描く範囲に含めることを確かめる。横書きと縦書きの両方で、ブロックの向きの長さとして同じ関数を使う。
- 位置の対応：行の要素と、その中の文字ノードの並び（溝や改ページの印の要素を含む）から、文書の位置と DOM の位置を相互に直す関数を、DOM の代わりの簡単な木で確かめる。
- キーの割り当て：`key` と `code` と修飾キーの組から、割り当てを引く関数を確かめる（`⌥⇧F` で `key` が `Ï` になる場合を含む）。
- 文書：行と位置の相互の変換（空の文書、末尾の改行、日本語とサロゲートペア）を確かめる。
- 変更：当てた結果、複数の置き換えの順序、位置の写し（挿入の前と後への寄せ方）、逆の変更、二つの変更のつなぎを確かめる。CodeMirror の `ChangeSet` のテストを参考にする。
- 履歴：取り消しとやり直し、続けて打った文字のまとまり、500 ミリ秒の切れ目、整形のような一回の変更、取り消しのあとの新しい変更でやり直しが消えることを確かめる。
- 字句の読み方：各形式の代表的な行と、行をまたぐ状態（`.gm` のコメントとコードブロック、`.emet` のブロックのコメント、`.md` のコードブロック、XML のコメント）を確かめる。行の状態が元と同じになったところで読み直しが止まることも確かめる。
- 今のエディタの関数のテスト（変更の印、改ページの見積もり、`@figure` の差し込み、LSP の位置と編集と semantic tokens）は、そのまま通るようにする。
- 画面の確かめ方：見本のプロジェクトの章と、長い文書（10 万字ほど）を、縦書きと横書きのそれぞれで開き、スクロールの滑らかさ、日本語の入力と変換、改行、削除、貼り付け、⌘Z、矢印キーでの移動、範囲の選択、⌘S での整形、診断の波線とホバー、補完、検索、行番号と変更の印の位置、改ページの印、縦横の切り替えで内容とカーソルが保たれることを確かめる。

## トレードオフ

- エディタの全体を自前で書くので、CodeMirror が長年かけて直してきたブラウザごとの入力の癖（特に IME）と、変更と履歴の細部を、自分で抱えることになる。対象を macOS の WebKit（Tauri の WebView）に絞ることで、扱う癖を減らす。その代わり、依存が減り、縦書きと横書きを同じ仕組みで扱える。
- `contenteditable` にカーソルの移動を任せるので、縦書きの矢印キーの振る舞いはブラウザに従う。描いていない行へは、ブラウザの移動が届かないので、描く範囲の端でカーソルが止まらないよう、端に近づいたら先の行を描く。
- 仮想化するので、行の大きさの見積もりが外れると、スクロールのつまみの位置がずれたり、描いたときに位置が動いたりする。描いた行の大きさで表を直していくので、一度通ったところは合う。
- 縦書きでも LSP の表示が出るので、縦書きの見た目が今より情報の多いものになる。
