# ADR 0056: 入力が 5 秒止まってから、ページを組み直す

ステータス: 採択

## 文脈

ページのプレビューは、保存のたびに `golem build --target pdf` と `shem render` で組み直す（[ADR 0010](0010-previews.md)、設定の「保存したらページを組みなおす」、既定はオン）。
保存は、⌘S のほかに、変更のあるシートを「自動保存の間隔」（既定 10 秒）ごとに行う（[ADR 0011](0011-saving-and-git.md)）。
組み直しのきっかけは、保存した文書の `saved` が変わったことである（[app/preview/mount.ts](https://github.com/tett23/aleph/blob/0be87a2/app/preview/mount.ts#L310)）。

そのため、書き続けているあいだは、自動保存のたびに組み直しが走る。
組み直しは golem と shem の二つのプロセスを動かし、PDF を PNG にするので重い。
走っているあいだ、入力がもたつく。
書き手からは、キーを打つたびに PDF を組み直しているように見える。

## 実装すること

- 保存をきっかけにしたページの組み直しを、最後の編集から 5 秒たつまで待たせる。
  - 保存のあと、すでに 5 秒入力がなければ、すぐ組む。
  - 待っているあいだにそのプロジェクトのシートが編集されたら、その編集から 5 秒数え直す。
  - 待っているあいだに保存が重なっても、組み直しは一回にまとめる。
  - 待つ時間は、プロジェクトごとに数える。
- 見出しの「組みなおす」のボタン、「ページ」を選んだときに組んだ結果がなければ組むこと、解像度の変更による描き直し（shem だけ）は、これまでどおり待たずに行う。
- 待っているあいだは、ページの見出しに「入力が止まったら組みなおします」と出す。
- 仕様書のプレビューの節を書き直す。

## 実装しないこと

- 本文のプレビュー（`golem build --target html`）の組み直しを待たせること。PDF と PNG を作らないので軽い。もたつきが残るなら、別の ADR で扱う。
- 待つ時間を設定で変えられるようにすること。
- 走っている組み直しを止めること。
- 自動保存の間隔を変えること。

## テスト設計

`node --test` で、テストを先に書いて失敗させてから実装する。

- 待ちを決める関数（最後の編集の時刻、保存の時刻、今の時刻から、組むまでの残りの時間を返す）が、最後の編集から 5 秒たっていれば 0 を、たっていなければ残りを返すこと。
- 待っているあいだの編集で、残りの時間が延びること。
- 保存が重なっても、組む予定が一つにまとまること（予定を表す値を、保存のたびに置き換えること）。
- 画面の確かめ方：試験のプロジェクトで「ページ」を出し、自動保存の間隔を短く（2 秒）して書き続け、書いているあいだは組み直しが走らず、手を止めて 5 秒たつと組み直すことを確かめる。「組みなおす」のボタンはすぐ組むことを確かめる。

## トレードオフ

- 書き終えてから、ページが新しくなるまでに最大で 5 秒余計にかかる。すぐ見たいときは、ボタンで組める。
- 待つ時間を 5 秒に決め打ちする。書き手の手の止まり方によっては長すぎたり短すぎたりするが、設定を増やすほどではない。
