# ADR 0030: 表記と綴りの検査

ステータス: 採択

## 文脈

Obsidian はスペルの検査を、Ulysses はスペルと文法と文体の検査を持つ。
Aleph のエディタは、ブラウザのスペルの検査を切っており（[`app/ed/view.ts`](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/ed/view.ts) の `content.spellcheck = false`）、本文の書き方を検査する仕組みを持たない。

メンテナーは、Obsidian と Ulysses にあって Aleph にない機能を比べ、スペルと文法の検査の ADR を求めた（2026-11-07）。
検査は設定で無効にできるようにするよう求められた。

本文は主に日本語である。
macOS のスペルの検査（`NSSpellChecker`）は日本語の綴りを検査しない。
日本語の文法（助詞の重なりなど）を正しく検査するには、形態素の解析が要る。
形態素の解析の辞書と仕組みは大きく、依存を増やさない方針（プロジェクトの CLAUDE.md）に合わない。
そこで、日本語は、形態素の解析なしに文字の並びで判断できる規則に絞る。

今の Aleph の関わる部分は次のとおりである。

- エディタ（[ADR 0019](0019-one-editor-for-both-writing-modes.md)）は、診断を波線、溝の印、診断の一覧で出す層を持つ（[`app/ed/diag.ts`](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/ed/diag.ts)、[`app/ed/editor.ts`](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/ed/editor.ts) の `setDiagnostics`）。今は LSP（[ADR 0009](0009-lsp-and-formatting.md)）だけが使い、渡すたびに一覧を置き換える。
- `.gm` の字句の読み方（[`app/gm.ts`](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/gm.ts) の `tokenizeLine`）は、命令（`command`）、式（`expression`）、コメント、エスケープ、コードブロック（`fence`、`code`）、見出しの記号（`headingMark`）、見出し（`heading`）の範囲を返す。命令の散文スロットと地の文には字句を付けない。
- macOS の AppKit を Rust から呼ぶための `objc2` と `objc2-app-kit` は、Tauri を通じて、すでに依存の木に入っている（`src-tauri/Cargo.lock`）。

## 実装すること

### 検査する範囲

- `.gm`、`.md`、`.txt` のシートを検査する。縦書きでも横書きでも同じに検査する。
- `.gm` は、`tokenizeLine` が返す範囲のうち、見出し（`heading`）以外のすべてを除いた文字を検査する。命令の頭と引数、式、コメント、エスケープ、コードブロックは検査しない。命令の散文スロットと地の文と見出しの文字は検査する。
- `.md` は、コードのスパンとコードブロック、リンクと画像の URL、ウィキリンクの行き先（[ADR 0027](0027-wikilinks-in-markdown.md)）を除いた文字を検査する。
- `.txt` は全体を検査する。
- 除いた範囲をまたいで規則を当てない（除いた範囲の前後を一続きの文とみなさない）。

### 規則

各規則は、設定で一つずつ切れる。既定はすべてオンとする。

- **ら抜き言葉**（情報）：一段活用と「来る」のうち、よく使う動詞の可能の形のら抜き（「見れる」「来れる」「食べれる」「出れる」「寝れる」など）を、活用（「れない」「れた」「れます」など）を含めて、決まった一覧で探す。一覧にない動詞は検査しない。
- **表記ゆれ**（情報）：一つのシートの中で、同じ語が二つの書き方で書かれているものを探す。
  - 決まった組の一覧（「出来る」と「できる」、「下さい」と「ください」、「頂く」と「いただく」、「致す」と「いたす」、「様に」と「ように」など、補助の言葉として開くかどうかが分かれるもの）。
  - 片仮名の語の、末尾の長音の有無（「サーバー」と「サーバ」）。
  - 少ないほうの書き方（同じ数なら後に出たほう）に、多いほうの書き方を添えて診断を出す。
- **句読点の連続**（警告）：「、、」「。。」「、。」「。、」と、全角のカンマとピリオド（「，」「．」）の同じ並び。
- **全角の英数字**（情報）：全角のラテン文字と数字（Ａ〜Ｚ、ａ〜ｚ、０〜９）。
- **半角の片仮名**（警告）：半角の片仮名と、半角の濁点と半濁点。
- **英語の綴り**（情報）：ラテン文字の語（2 文字以上）を、macOS の `NSSpellChecker`（英語）で検査する。Rust の側にコマンドを足し、語の一覧を渡して、綴りの誤った語の一覧を返す。結果は語ごとに覚え、同じ語を二度問い合わせない。

### 出し方

- 診断の層に、出どころを分けて渡せるようにする（`setDiagnostics(一覧, 出どころ)`）。LSP の診断と検査の診断を、互いに置き換えずに重ねて出す。
- 検査の診断は、規則の名前を出どころとし、文言は「ら抜き言葉：見れる → 見られる」「表記ゆれ：サーバ（このシートではサーバー が 5 回）」のように書く。重さは上に書いたとおりとし、情報は点線、警告は波線で出す（今の診断の CSS のまま）。
- ステータスバーの LSP のエラーと警告の数には、検査の診断を数えない。
- 検査は、文書が変わって入力が 700 ミリ秒止まったときと、シートを開いたときに、文書の全体に対して行う。30 万字を超えるシートでは検査せず、ステータスバーに「長いため文章の検査をしていません」と出す。

### 設定

- 設定に「文章の検査」の節を足す。全体のオンとオフ、規則ごとのオンとオフ、英語の綴りで無視する語の一覧（1 行に 1 語）を置く。値はアプリの設定（`config.json`）に置く。
- 設定を変えたら、開いているエディタの検査をやり直す。

## 実装しないこと

- 形態素の解析が要る日本語の検査（二重助詞、文の係り受け、「の」の連続、敬語の誤り、受け身の多用など）。[ロードマップ](../roadmap.md) に載せ、別の ADR で検討する。
- 文の長さや、読みやすさの点数。
- 英語の文法の検査と、英語以外の言語の綴りの検査。
- 誤りの直し方の提案を押して直す操作（クイックフィックス）。
- `.md` と `.txt` 以外のテキスト（`.toml`、`.emet` など）の検査。
- WebKit のスペルの検査（`spellcheck` 属性）を使うこと。エディタが行を描き直すたびに印が消え、診断の一覧にも出せないためである。

## テスト設計

DOM に触れない部分を関数に分け、`node --test` で確かめる。テストを先に書いて失敗させてから実装する。

- 範囲の取り出し：`.gm` で命令の頭と引数、式、コメント、エスケープ、コードブロックが除かれ、散文スロット、地の文、見出しが残ること。`.md` でコードと URL とウィキリンクの行き先が除かれること。除いた範囲をまたいで規則が当たらないこと。位置が元の文書の位置（UTF-16）で返ること。
- ら抜き言葉：一覧の動詞と活用で見つかること、正しい形（「見られる」）と、可能の形でない語（「入れる」「晴れる」）で見つからないこと。
- 表記ゆれ：組の一覧の両方が出るときに少ないほうに出ること、片方だけのときに出ないこと、片仮名の長音の有無、同じ数のとき。
- 句読点の連続、全角の英数字、半角の片仮名：見つかるものと見つからないもの、サロゲートペアの前後で位置がずれないこと。
- 英語の綴り：語の取り出し（2 文字以上のラテン文字の並び、アポストロフィを含む語）、無視する語、問い合わせの結果を覚えること。`NSSpellChecker` を呼ぶ部分は関数として渡し、Rust を呼ばずに確かめる。Rust の側は、`cargo test` で、誤った綴りの語が返り、正しい語が返らないことを確かめる。
- 設定：全体と規則ごとのオンとオフで、出る診断が変わること。設定の読み込みで、前の版の `config.json`（節のないもの）が既定に戻ること。
- 診断の出どころ：LSP の診断と検査の診断が置き換え合わずに重なること、出どころごとに置き換わること。
- 画面の確かめ方：見本の章に、ら抜き言葉、表記ゆれ、句読点の連続、全角の英数字、半角の片仮名、綴りの誤った英語の語を書き、点線と波線と溝の印が出て、診断の一覧から移れること、命令の中では出ないこと、縦書きでも出ること、設定で切ると消えることを確かめる。

## トレードオフ

- 日本語を形態素の解析なしに検査するので、見つけられる誤りは限られ、ら抜き言葉と表記ゆれは決まった一覧の範囲だけになる。その代わり、依存を増やさず、誤った指摘も少なくできる。
- 英語の綴りに macOS の `NSSpellChecker` を使うので、macOS でしか動かない。Aleph は今 macOS の WebKit を対象にしている（[ADR 0019](0019-one-editor-for-both-writing-modes.md)）ので、これを受け入れる。`objc2-app-kit` は今も依存の木にあるが、直接の依存として宣言することになる。
- 検査の診断を LSP の診断と同じ層に出すので、行の溝の印は、もっとも重いものだけが見える。情報の重さの検査の印は、LSP のエラーや警告に隠れることがある。
