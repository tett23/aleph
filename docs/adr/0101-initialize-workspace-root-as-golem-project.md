# ADR 0101: ワークスペースのルートを Golem プロジェクトに初期化する

Status: accepted-pending

## 文脈

既存のフォルダをワークスペースに登録した後、そのフォルダ自体を Golem プロジェクトにしたい。
今の新規プロジェクト作成のように、下に新しいフォルダを作る操作とは区別する。

## 調査した事項

[ADR 0004](0004-workspaces-and-projects.md) は、ワークスペース自体がプロジェクトになる構成を許す。
現在の新規プロジェクト作成は名前を尋ね、ワークスペースを作業ディレクトリとして `golem new <名前> --no-fonts` を実行する。
作成後には共有ライブラリのフォントを用意してツリーを読み直す。

同梱の Golem 0.1.0-rc4 で、一時ディレクトリ内の既存の空フォルダを指定して `golem new <パス> --no-fonts` を実行すると、プロジェクトが作られた。
`note.md` と `style.toml` のあるフォルダでは「ディレクトリが空ではありません」と拒まれ、両ファイルの内容は保たれた。
そのため、既存のファイルがあるルートに、このコマンドを直接実行するだけでは初期化できない。

## 実装すること

### 操作と対象

ワークスペースのルートを対象にするメニューに「Golem プロジェクトに初期化」を追加する。
ルートがツリーの行として出ない構成でも、ワークスペースの操作メニューから実行できるようにする。
コマンドパレットにも同じ操作を置く。
現在のワークスペースのルートだけを対象にし、フォルダ名と登録済みのパスは変えない。

すでにプロジェクトであるルートでは実行できないことを示す。
配下に既存のプロジェクトがあるときも、その一覧と理由を示して中止する。
ルートをプロジェクトにすると内側のプロジェクトが無視されるためである。
判定できない読み込みエラーの場合も中止し、空のフォルダとは扱わない。

### 既存ファイルを保った初期化

空でないフォルダも、生成するファイルと衝突しなければ初期化できる。
`.git/`、原稿、画像などの既存の項目は名前も内容も保つ。
既存の `.gm` を自動で章に登録せず、生成した manifest の章だけを登録する。

生成内容は Golem に任せる。
一時ディレクトリで `golem new <ルートと同じ名前> --no-fonts` を実行し、そこに生成されたファイルの一覧を求める。
Aleph に Golem のテンプレートを複製しない。
生成したファイルをルートへ配置する前に、同じ相対パスの既存ファイル、ファイルとフォルダの衝突、書き込めない場所、シンボリックリンク経由の書き込みがないか調べる。
既存の通常フォルダは、生成ファイルの置き場所として使える。
衝突が一つでもあれば一覧を示し、ルートに何も追加しない。

事前検査の後も、ファイルは排他的な新規作成で配置し、既存のものを上書きしない。
`manifest.toml` は最後に配置し、配置が完了してからプロジェクトとして読み直す。
初期化の途中は、このルートに対する Aleph からの二重実行を拒み、ツリーの自動走査で未完成のプロジェクトを開かない。

失敗した場合は、この操作で作ったファイルと空になったフォルダだけを戻す。
既存の項目と、作成後に別の操作で変更された項目は消さない。
戻せない項目があればパスと理由を通知し、初期化成功とは表示しない。
アプリや OS の強制終了までを一つのトランザクションにするものではなく、次回に衝突した場合は残ったパスを示す。

### 初期化後

共有ライブラリのフォントを用意する処理は、既存の新規プロジェクト作成と共通にする。
フォントの配置でも既存ファイルは上書きしない。
フォントが用意できなかった場合は、プロジェクトの初期化結果とフォントの不足を分けて通知する。
この操作によるフォントのダウンロードは行わない。

ツリーを読み直してルートをプロジェクトとして表示する。
開いている既存のシートと編集内容は保ち、新しいプロジェクトを作った後の画面を開くために既存の編集を置き換えない。
開いている既存シートも新しいプロジェクトへの所属と設定を再評価し、LSP とプレビューを切り替える。
この切り替えで本文をディスクから読み直して未保存の編集を失わない。
再起動後も同じルートがプロジェクトとして認識される。
この ADR は [ADR 0004](0004-workspaces-and-projects.md) のプロジェクト作成を補う。

## 実装しないこと

既存の manifest や style の上書き、既存の章の自動登録、子プロジェクトの統合、Git リポジトリの初期化、フォルダの改名は行わない。
任意の子フォルダの初期化はこの操作には含めない。

## 不変条件

- I1: 成功後のワークスペースのパスは実行前と等しく、ルートの manifest が指す生成ファイルがすべて存在する。
- I2: 初期化前から存在する項目の名前と内容は、成功と失敗のどちらでも変わらない。
- I3: 既存プロジェクト、子プロジェクト、事前に分かる衝突、走査失敗では、ルートに項目を追加しない。
- I4: 配置中の競合でも既存の項目を上書きせず、失敗時の削除対象はこの操作で作り、その後変更されていない項目に限る。
- I5: 初期化後も開いていた既存シートの編集内容とパスを保ち、その所属と設定は新しいルートのプロジェクトに対応する。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 空のルート | ルート自体に初期化 | I1 |
| `.git/` と原稿だけのルート | 既存の内容を保って初期化 | I1, I2 |
| 生成先と同名の既存 style や章 | 衝突を示して変更なし | I2, I3 |
| 既存の通常フォルダ内に衝突しない生成ファイル | フォルダを使い、既存内容を保持 | I1, I2 |
| ルートに manifest、または配下にプロジェクト | 初期化不可 | I3 |
| 配置の直前に同名ファイルが作られる | 上書きせず失敗 | I2, I4 |
| 配置失敗、巻き戻し中に外部から変更 | 変更された項目を保持して通知 | I4 |
| 編集中の既存シート | 編集内容とパスを保持 | I5 |

## 受けいれ条件

- A1: 空の登録済みルートをメニューから初期化し、下に同名フォルダを作らず Golem プロジェクトとして使える。
- A2: `.git/` と原稿があるルートを初期化しても、それらの内容と編集が保たれる。
- A3: 衝突または子プロジェクトがあるときは、理由と対象のパスが表示され、既存の内容が変わらない。
- A4: 初期化後に再起動しても同じルートがプロジェクトとして表示される。

## テスト設計

Rust の一時ディレクトリで、生成結果の配置処理に成功、衝突、権限エラー、競合を与え、I1〜I4 を確かめる。
一覧とファイルの内容を実行前後で比較し、巻き戻し前に変更されたファイルが消えないことも確かめる。
Golem の起動失敗と不完全な生成結果では、配置を開始しないテストを書く。
TypeScript ではメニューとパレットの実行条件、二重実行の抑制、初期化後の再走査と I5 を確かめる。
テスト名にこの ADR と条件の番号を入れる。
A1〜A4 は試験用ワークスペースで、同梱の Golem を使うデバッグ版を操作し、再起動後まで確かめる。

## トレードオフ

一時ディレクトリから配置するため、Golem の生成に加えて衝突検査と失敗時の片付けが必要になる。
その代わり、Golem のテンプレートを Aleph に複製せず、既存の原稿があるルートを初期化できる。
子プロジェクトのあるルートは拒むため、作品をまとめたワークスペース全体を一つの作品に変える用途には、別途整理が必要になる。
