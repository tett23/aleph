# ADR 0065: ツリーでフォルダとシートを作り、Markdown を gm に変換する

ステータス: 下書き

## 文脈

現在の新規シート操作はプロジェクト内で `chapters/NN.gm` を作る。
右クリックでは書き手が指した場所と選んだ種類を作成先に反映したい。

## 実装すること

プロジェクト行とフォルダ行の両方に「フォルダを追加」「シートを追加」を置く。
名前を入力し、シートの場合は種類も選ぶ。
種類は gm、md、emet、txt、toml、csv、tsv、svg、mmd、json、jsonc、json5、jsonl とし、拡張子を一度だけ付けた空ファイルを作る。
右クリックで作った gm の章登録は別操作とする。
既存の新規シート操作には従来の作成先と登録規則を適用する。

`.md` 行には「gm に変換」を置く。
対象を右クリックしたパスに固定し、開いている場合は編集中の本文を使う。
変換、同名出力の確認、章登録、診断には [ADR 0016](0016-markdown-to-gm.md) の手順を使う。

## 実装しないこと

画像と PDF の新規作成。

## 不変条件

1. 作成の成功時には指定したディレクトリの子が、ファイルシステム上で一項目だけ増える。
2. 入力が空、パス区切りを含む名前、同名、取消では既存の内容も項目数も変わらない。
3. 変換元は右クリックした md に一致し、元ファイルは残る。

| 境界の入力 | 期待する結果 |
| --- | --- |
| プロジェクト直下、入れ子のフォルダ | 選んだ親にだけ作成 |
| 同名のファイルまたはフォルダ | 作成を拒む |
| 別のタブがアクティブ | 指定した md の内容を変換 |

## テスト設計

不変条件ごとに番号をテスト名に含め、上表の入力について実装前に失敗を確かめる。
作成先と種類の全組合せ、上書き確認の取消、変換元とアクティブタブが異なる場合を試す。

## トレードオフ

種類を選ぶ手順が一つ増えるが、作った後で拡張子や場所を直す手間が省ける。
