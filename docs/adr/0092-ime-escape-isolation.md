# ADR 0092: IME の変換を取り消す Esc を画面の操作に渡さない

Status: proposed

## 文脈

指示者から、新規シートのファイル名を入力しているときなどに、変換中の Esc が画面の操作にまで届くとの報告があった（2026-11-22）。
変換を取り消すキーで、入力ダイアログまで閉じないようにする。

## 調査した事項

調査したコミットは `8a102bdfa38df9fb2fa7a0852a5ca7da39d186af` である。
[`ask`](https://github.com/tett23/aleph/blob/8a102bdfa38df9fb2fa7a0852a5ca7da39d186af/app/ui/dom.ts#L25) は Enter では `isComposing` を確認するが、Escape では確認せず入力を取り消す。
[`app/keybind.ts`](https://github.com/tett23/aleph/blob/8a102bdfa38df9fb2fa7a0852a5ca7da39d186af/app/keybind.ts#L106) には `isComposing` と `keyCode === 229` の判定がある。
今回の報告に対応する実機のイベント列はまだ採取していない。

## 実装すること

入力欄とエディタで IME が消費する Esc は、変換の取り消しだけに使う。
ダイアログを閉じる、補完を閉じる、背面のショートカットを実行する処理へは渡さない。
IME の既定動作は妨げず、アプリの操作を抑止する。
変換を終えてから別に押した Esc は、通常の取り消しとして扱う。

判定は `isComposing`、互換用の `keyCode === 229`、入力先の `compositionstart` と `compositionend` で管理する変換状態を合わせて行う。
WebKit で `compositionend` と Esc の通知順が異なる場合は、採取したイベント列に基づいて同じキー操作を識別する。
一定時間の Esc を無差別に捨てる方法は使わない。
入力先の破棄とフォーカス移動で状態を片付け、別の入力欄に持ち越さない。

新規シートの名前、名前の変更、検索欄、アシスタント入力、エディタのキー処理を対象にする。
既存のキー割り当ての決定である [ADR 0073](0073-contextual-editor-shortcuts.md) を補足する。
実装時に仕様書と README の日本語入力の説明へ反映する。

## 実装しないこと

IME 自体の変換操作の変更、Esc の割り当て変更、すべてのダイアログの作り直し。

## 不変条件

- I1: IME が消費した Esc で起きるアプリの取り消しとショートカットの実行回数は0である。
- I2: 変換を終えた後の独立した Esc は、変換していないときと同じ操作を1回だけ行う。
- I3: 入力先を破棄した後の変換状態は、ほかの入力先のキー判定に影響しない。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 変換中の Esc 1回 | 変換だけを取り消し、ダイアログは残る | I1 |
| 変換終了後に改めて Esc | 通常の取消 | I2 |
| `isComposing` が偽でキーコードが229 | アプリの操作をしない | I1 |
| Esc に伴う compositionend が先に通知される列 | 同じキーでダイアログを閉じない | I1 |
| 変換中に入力先を閉じ、別の入力欄へ | 状態を持ち越さない | I3 |

## 受けいれ条件

- A1: 新規シートの名前を日本語変換中に Esc を押してもダイアログが残り、続けて名前を入力できる。
- A2: エディタの縦書きと横書きで、変換取消の Esc が補完や背面の操作を実行しない。

## テスト設計

判定とイベント列のテストを `ADR 0092 I1: …` の形で先に書く。
新規シートの `ask` まで含むテストで、変換取消後に Promise が未解決でダイアログが残ることを検査する。
I2 と I3 は通常の Esc、フォーカス移動、入力先の再作成を検査する。
A1 と A2 は macOS 標準の日本語入力と利用環境の SKK で確認し、通知順を記録して回帰用のイベント列にする。

## トレードオフ

変換状態を共有の判定で扱うと、入力先ごとの判定漏れを減らせる。
一方、WebKit と IME ごとの通知順を実機で確認する必要がある。
