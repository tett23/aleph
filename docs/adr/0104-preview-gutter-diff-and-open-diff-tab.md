# ADR 0104: 行番号横で差分を確認して差分タブを開く

Status: accepted-pending

## 文脈

指示者は、エディタの行番号横にある差分マーカーにマウスを乗せると変更前後を表示し、クリックすると差分画面へ移動することを求めた（2026-11-22）。
ホバーの表示は、マウスが乗っている間は消さない。
指示者は、クリック先でも未保存の変更を含め、該当箇所を表示する方針を選んだ。
マーカーが示す変更を、その場で読み、必要なときに大きな差分画面で確認できるようにする。

## 調査した事項

調査したコミットは `d05733a214605008c71e22fe21a717d1c3cf0f42` である。
[app/ed/view.ts](https://github.com/tett23/aleph/blob/d05733a214605008c71e22fe21a717d1c3cf0f42/app/ed/view.ts) の `gutterOf` は、行番号の横に `.chg-slot` と `.chg` を描画する。
縦書きでは、この溝は行の上に配置される。
[app/diff.ts](https://github.com/tett23/aleph/blob/d05733a214605008c71e22fe21a717d1c3cf0f42/app/diff.ts) の `lineMarks` は比較元と現在の本文から追加、変更、削除の種類を返すが、変更前後の本文は返さない。
削除だけの変更は、削除位置に続く行の番号に対応づける。
現行の比較元取得処理は、Git が使えない場合には `false` を返し、それ以外の取得失敗では `null` を返す。
`lineMarks` は `null` を全行追加として扱うため、リポジトリ外や取得失敗も全行追加になる。

[app/main.ts](https://github.com/tett23/aleph/blob/d05733a214605008c71e22fe21a717d1c3cf0f42/app/main.ts) は `git show HEAD:<path>` で比較元を取得し、[app/ed/editor.ts](https://github.com/tett23/aleph/blob/d05733a214605008c71e22fe21a717d1c3cf0f42/app/ed/editor.ts) はその比較元とエディタの現在の本文でマーカーを更新する。
一方、[app/difftab/mount.ts](https://github.com/tett23/aleph/blob/d05733a214605008c71e22fe21a717d1c3cf0f42/app/difftab/mount.ts) の `load` は Git の状態と作業ツリーの差分を取得する。
`showDiff` は既存の差分タブを選ぶか新しく作るが、ファイルや変更箇所を指定する引数は持たない。

診断マーカーのホバーは [app/ed/editor.ts](https://github.com/tett23/aleph/blob/d05733a214605008c71e22fe21a717d1c3cf0f42/app/ed/editor.ts) にあり、350 ミリ秒の待ち時間と、マーカーとポップアップの間を移動したときの保持処理を持つ。
差分マーカーはこの対象に含まれていない。
[ADR 0096](0096-word-diff-display.md) は、日本語を含む文字単位の差分表示と、本文のエスケープを定めている。
これらはコードを読んだ事実であり、今回の調査では新しい動作の実機確認は行っていない。

## 実装すること

### 比較する本文と変更のまとまり

比較元はマーカーを描画したときの HEAD の本文、比較先は未保存の編集を含む現在のエディタ本文とする。
HEAD にないファイルは空の比較元として扱う。
ワークスペースがリポジトリの下位フォルダでも、リポジトリからの相対パスで対象ファイルの比較元を取得する。
比較元の取得には [ADR 0105](0105-use-libgit2-without-git-executable.md) の libgit2 バックエンドを使い、Git コマンドがなくてもマーカー、ホバー、専用差分を利用できるようにする。
本 ADR の実装は、そのバックエンドを前提とする。
リポジトリ外と比較元の読み取り失敗を、HEAD にファイルがない場合から区別する。
前者では比較不能としてマーカーを出さず、読み取り失敗の理由を通知する。
HEAD がまだないリポジトリや、HEAD に対象ファイルがない場合だけ、空の比較元を使う。

連続する削除と追加を一つの変更のまとまりとして保持し、その範囲に属するマーカーから同じ変更前後を取得する。
削除だけのまとまりは直後の現存行に対応づけ、末尾の削除は最後の行に対応づける。
空の本文にも一つの表示行を用い、全削除の内容を確認できるようにする。
同じ表示行に複数のまとまりが対応するときは、本文の順にすべて表示する。
比較処理が大きな入力で粗い範囲に切り替わる場合も、元の本文を失わず、その範囲の変更前後を表示する。

### ホバーとクリック

差分のある `.chg-slot` にマウスが 300 ミリ秒乗ると、変更前と変更後を見出し付きで表示する。
追加だけなら変更前、削除だけなら変更後を「なし」とする。
日本語も [ADR 0096](0096-word-diff-display.md) と同じ Unicode コードポイント単位で変更部分を区別し、削除には取消線、追加には下線も使う。
原稿は文字列として描画し、HTML として解釈しない。

マーカーかホバーの表示内にポインターがある間は、時間の経過だけでは閉じない。
マーカーからホバーに移る途中で消えないよう、両者を隣接させるか移動経路を含む領域で保持する。
両方から離れる、Esc を押す、本文か比較元が変わる、対象行がスクロールで移動する、タブが切り替わる、エディタが破棄される、ウィンドウがフォーカスを失うと閉じる。
閉じた後に古い非同期結果が届いても表示し直さない。

ホバーは本文や行番号の配置を動かさない独立した表示とする。
ホバーの外枠全体を WebView の可視領域内に収める。
可視領域は `visualViewport` のオフセットと幅、高さから取得し、利用できない場合はレイアウトビューポートを使う。
左右と上下の余白はそれぞれ `min(8 CSS px, 可視領域のその軸の長さ / 4)` とする。
表示幅は最大 560 CSS px、高さは最大 560 CSS px とし、枠と内側の余白を含めて可視領域から両側の余白を引いた長さ以下に制限する。

通常はマーカーの右下に出し、右か下に収まらない軸は左か上へ反転する。
反転しても収まらない軸は、実際に計測した外枠を余白の内側に収める位置に補正する。
初回の表示前に寸法と位置を決め、再描画、ウィンドウのサイズ変更、WebView の拡大縮小、可視領域の移動時にも再計算する。
可視領域がゼロの場合や再計算中は表示を隠し、画面外の位置で描画しない。
本文に切れ目のない長い文字列があっても折り返し、ホバーの外枠を押し広げない。

長い差分は変更前と変更後を上下に並べ、それぞれの見出しを固定し、本文を別々に縦スクロールできるようにする。
本文のスクロールはエディタへ伝播させず、ホバー内でのスクロールだけでは閉じない。
高さが足りず見出しと本文を同時に置けない場合は、ホバー全体を一つのスクロール領域に切り替え、どの内容にも到達できるようにする。
枠外には影などの装飾を描かず、スクロールバーも外枠の内側に収める。
横書きと縦書き、ライトとダークで使えるようにし、診断マーカーのホバーとは対象を分ける。
マーカーのない行番号付近には反応しない。

差分マーカーを左クリックすると、ホバーを閉じて差分タブを開き、該当ファイルの変更箇所を表示する。
キャレットと選択範囲は動かさず、保存やコミットは行わない。
既存の差分タブがあれば再利用する。
ホバーの下部にも、同じ差分を開く「詳細」を置く。
[デザインの原則](../design-principles.md) に従い、「詳細」には常時下線を付ける。

### 差分タブへの引き継ぎ

クリック時の比較元、比較先、ファイル、変更範囲を一組として差分タブに渡す。
この入口では対象ファイルの差分を専用の表示として開き、未保存の編集を含むクリック時点の本文であることを明記する。
ワークスペース全体の保存済み差分へ戻る操作を用意する。
従来のメニューから差分タブを開く操作と Git パネルの比較対象は変えない。

専用の表示はクリック時点のスナップショットとし、開いた後の編集によって内容を黙って置き換えない。
別のマーカーをクリックしたときは、新しい一組に置き換える。
再読み込みでは開いている対象エディタの最新の本文と比較元を取得し、対象が閉じられていれば再取得できない理由を表示する。
遅れて完了した以前の読み込みが新しい対象を上書きしないようにする。

専用の表示は対象の変更箇所を中心に最大 2,000 表示行を出し、省略した前後の行数を示す。
ここでの表示行は [ADR 0096](0096-word-diff-display.md) と同じ、ハンク見出しを含む復元した差分の行とし、画面幅による折り返し行は数えない。
専用差分は同じ ADR の共通、削除、追加の区分を使って一つの本文の流れとして描画する。
変更箇所が 2,000 行を超える場合はその先頭を表示し、残りの省略数を示す。
対象が後半にあっても、先頭からの行数制限によって移動先を失わないようにする。
この専用の表示は [ADR 0088](0088-diff-tab-and-commit-before-applying.md) のワークスペース全体の差分に追加する入口であり、全体表示の上限と保存済みファイルの扱いは維持する。

## 実装しないこと

ホバーからの編集、変更の取り消し、ステージ操作、コミット、比較元の選択は追加しない。
従来のワークスペース全体の差分を未保存の編集に切り替えることはしない。

## 不変条件

- I1: マーカー、ホバー、クリック直後の専用差分は、同じ比較元と比較先の変更範囲を指し、本文の保存を発生させない。
- I2: マーカーまたはホバー内にポインターがあり、終了条件が発生していない間は、時間の経過でホバーを閉じない。
- I3: 終了後に届く以前の表示要求や比較結果は、ホバーを再表示せず、新しい差分対象を上書きしない。
- I4: 差分マーカーのホバーとクリックは、エディタの行の矩形、キャレット、選択範囲を変えない。
- I5: 表示する本文は HTML として解釈せず、日本語と補助平面の文字を壊さずに変更前後へ復元できる。
- I6: 専用差分は対象の変更範囲から表示を開始でき、最大 2,000 表示行と前後の省略数が実際の表示範囲に一致する。
- I7: ホバーが描画される各フレームで、枠と装飾の全体は可視領域から軸ごとの余白を除いた矩形に含まれ、本文の長さ、表示倍率、ウィンドウ寸法に左右されない。
- I8: ホバー内のスクロールはエディタのスクロール位置を変えず、ホバーを閉じず、長い変更前後の本文の末尾まで到達できる。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 変更なし、比較元が取得不能 | 反応するマーカーなし | I1 |
| Git コマンドなし、有効なリポジトリに変更あり | libgit2 で変更を表示 | I1 |
| 追加のみ、削除のみ、一行変更 | 対応する変更前後を表示 | I1, I5 |
| 末尾削除、全削除、同じ行に複数の変更範囲 | 最後の行または唯一の行から対象を確認 | I1 |
| 未保存の日本語一文字の置換 | ホバーとクリック先で同じ文字を区別 | I1, I5 |
| ポインターを静止、表示内へ移動、表示内をスクロール | 終了条件まで保持 | I2 |
| 本文更新、タブ変更、Esc の後に比較完了 | 古い表示を復活させない | I3 |
| 行番号や診断マーカーに移動 | 差分を誤って開かない | I4 |
| `<script>`、結合文字、絵文字 | 原稿の文字を保つ | I5 |
| 2,000 行、2,001 行、後半の変更をクリック | 対象を表示し、省略数を正しく示す | I6 |
| 四隅、ちょうど収まる幅と高さ、1 CSS px 足りない領域 | 反転と補正後も外枠が領域内にある | I7 |
| 非常に小さい領域、幅か高さがゼロ、表示中の拡大縮小 | 縮小または非表示にし、画面外へ出さない | I7 |
| 長い一行、変更前後とも数百行、ホバー末尾でのスクロール | 全文へ到達でき、エディタは動かない | I7, I8 |

## 受けいれ条件

- A1: 横書きと縦書きのエディタで、マーカーに乗せると変更前後が現れ、ポインターを静止しても表示が残る。
- A2: ホバーへ移動して長い変更をスクロールでき、領域外へ出るか Esc を押すと閉じる。
- A3: 未保存の変更をクリックすると、保存せずに同じ変更が差分タブに表示される。別のマーカーでも同じタブを再利用する。
- A4: ライトとダーク、画面の上下左右の端で内容を読め、診断のホバーと混同せず操作できる。

## テスト設計

I1 と I5 は、変更範囲と変更前後の抽出のテストを先に書く。
末尾削除、全削除、空文字列、複数行、未追跡ファイル、計算量の上限を超える本文を含める。
Git コマンドなし、リポジトリ外、HEAD なし、HEAD に対象ファイルなし、比較元の取得エラーを分け、比較不能な入力を全行追加にしないことも検査する。
リポジトリ直下と下位フォルダのワークスペースで、同じファイルの同じ HEAD 本文を取得することも検査する。
日本語、補助平面の文字、結合文字、HTML に見える原稿を比較し、表示から復元した本文と入力を照合する。

I2 と I3 は制御できる時計と遅延する比較処理を使い、300 ミリ秒前後、長時間の静止、マーカーからホバーへの移動、取消後の完了、新しい対象より遅い旧要求を検査する。
I4 は実 WebKit で行の矩形と選択位置を操作の前後で比較する。
I6 は表示範囲と省略数の境界を検査し、先頭から 2,000 行を超えた位置への移動を含める。
I7 は配置関数の境界テストに加え、実 WebKit で `getBoundingClientRect` と可視領域を各描画フレームで比較する。
四隅、余白込みでちょうど収まる寸法と 1 CSS px 小さい寸法、狭い幅と高さ、長い連続文字列、100%、200%、400% の倍率、表示中のサイズ変更と可視領域のオフセット変更を含める。
I8 は両本文の末尾までスクロールして内容を確認し、スクロール領域の端でホイールを回してもエディタの位置が変わらないことを実 WebKit と Tauri で確かめる。

A1〜A4 は Tauri で実際のマウスを使って確かめる。
ホバー内とマーカー上でそれぞれ 10 秒静止し、未保存の本文とディスクの内容がクリック後も変わらないことを確認する。
明暗両テーマ、縦横両方向、画面端、長い差分で繰り返す。

## トレードオフ

クリック時点の本文を引き継ぐため、差分タブは従来の全体表示と対象ファイルのスナップショット表示を区別する必要がある。
一方、ホバーで見た変更がクリック先から消えることを避けられる。
長い差分は表示内でのスクロールと省略を伴うため、変更前後の見出しと対象ファイルの表示を保つ。
