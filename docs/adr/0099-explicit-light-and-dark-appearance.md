# ADR 0099: OS と独立してライトとダークを指定する

Status: accepted

## 文脈

指示者は、ダークモードとライトモードを OS の設定によらず指定できるようにすることを求めた（2026-11-22）。
書き手が指定した外観を、メインと別ウィンドウで一貫して使う。

## 調査した事項

調査したコードは `d62c18cb9dcc65304dd1b1c50379eb04d24fb393` である。
[`app/main.ts`](https://github.com/tett23/aleph/blob/d62c18cb9dcc65304dd1b1c50379eb04d24fb393/app/main.ts#L136) は既に「一般」の「外観」に「ライト」「ダーク」「自動」の三つを表示し、選択を保存する。
[`isDark`](https://github.com/tett23/aleph/blob/d62c18cb9dcc65304dd1b1c50379eb04d24fb393/app/config.ts#L143) は、`dark` なら OS によらず真、`light` なら偽、`auto` の場合だけ OS の値を返す。
メインウィンドウは保存時と OS の変更通知時に `applyTheme` を呼ぶ。

[`app/preview/window.ts`](https://github.com/tett23/aleph/blob/d62c18cb9dcc65304dd1b1c50379eb04d24fb393/app/preview/window.ts#L15) と [`app/plot/mount.ts`](https://github.com/tett23/aleph/blob/d62c18cb9dcc65304dd1b1c50379eb04d24fb393/app/plot/mount.ts#L95) は起動時に外観を適用するが、外観設定の変更を受信して再適用する処理はない。
新しい切り替え機能を一から作る必要はなく、既存の明示指定を維持して別ウィンドウにも反映させる変更である。

## 実装すること

設定の「一般 → 外観」で「OS に合わせる」「ライト」「ダーク」を選べるようにする。
保存する値は既存の `auto`、`light`、`dark` を使い、既定は `auto` とする。
不明な値と欠けた値は `auto` に戻す。
現在選んでいる値を選択状態として表示する。

ライトとダークの明示指定は、OS の設定が変わっても維持する。
「OS に合わせる」を選んでいるときだけ、OS の変更を開いている全ウィンドウへ反映する。
設定の保存に成功したら、メイン、本文プレビュー、ページプレビュー、プロットの各ウィンドウへ変更を通知する。
新たに開くウィンドウとアプリの再起動後も保存値を使う。
既に描画した図のうちテーマに依存するものも再描画し、スクロール位置は維持する。
設定の保存に失敗した場合はエラーを知らせ、全ウィンドウを直前の保存値に保つ。

変更するのはアプリの外観であり、原稿の文字列、組版の色指定、PDF などの書き出しの色は変えない。
[ADR 0005](0005-layout-and-appearance.md) の「見た目」を補足する。
「実装しないこと」のうちライト、ダーク、OS 追従の切り替えを禁じる部分は、この三択の外観指定を許す決定に置き換える。
実装時に仕様書と日英 README に設定の場所と全ウィンドウへの適用を書く。

## 実装しないこと

OS の外観設定の変更、ウィンドウごとの外観設定、カスタムテーマ、時刻による切り替え。

## 不変条件

- I1: 保存値が light なら全ウィンドウはライト、dark なら全ウィンドウはダークであり、OS の値には依存しない。
- I2: 保存値が auto なら全ウィンドウの外観は現在の OS の外観に等しい。
- I3: 保存に成功した値は、新しいウィンドウと再起動後にも使われ、失敗時には直前の保存値が使われる。
- I4: 外観変更は原稿と書き出しの内容を変更しない。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| OS ダーク、light を指定 | 全ウィンドウがライト | I1 |
| OS ライト、dark を指定 | 全ウィンドウがダーク | I1 |
| 明示指定中に OS を切り替え | アプリの外観は変わらない | I1 |
| auto 中に OS を切り替え | 全ウィンドウが追従 | I2 |
| 設定なし、不明値 | auto | I2 |
| 保存失敗、新規ウィンドウ、再起動 | 最後に保存できた値を使用 | I3 |

## 受けいれ条件

- A1: OS と逆の外観を指定し、プレビューとプロットの別ウィンドウにも反映される。
- A2: アプリを再起動すると明示指定が残る。
- A3: 図を含むプレビューを途中までスクロールして外観を変えても、図の配色と位置が正しく保たれる。

## テスト設計

既存の `isDark` のテストに、全ウィンドウへの通知と設定の保存失敗を加える。
名前は `ADR 0099 I1: …` の形にし、別ウィンドウへ反映されない現行動作で先に失敗させる。
OS の外観変更通知をテストで与え、明示指定と auto の違いを検査する。
I4 は原稿と書き出し用の設定が不変であることを確かめる。
A1 から A3 は Tauri で確認し、検証後は外観の設定を元に戻す。

## トレードオフ

アプリ全体で一つの外観にそろえるため、ウィンドウごとに別の外観は選べない。
既存の保存値を保つことで設定の移行は不要になる。
