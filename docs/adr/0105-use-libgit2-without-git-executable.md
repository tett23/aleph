# ADR 0105: Git コマンドに依存せず libgit2 を使う

Status: proposed

## 文脈

指示者は、Rust 側に libgit2 の依存を追加し、Git コマンドがなくても Aleph の Git 機能を使えるようにすることを求めた（2026-11-22）。
push と pull の認証は SSH エージェントと HTTPS の認証入力に対応し、独自の `core.sshCommand` と外部 credential helper は使わない方針を指示者が選んだ。
名前とメールアドレスがない場合は設定画面で入力できるようにし、当初は対象リポジトリへの保存を指定した。
その後、指示者は全体の設定画面ではグローバル設定を編集し、プロジェクトのリポジトリ設定は独立したモーダルで編集する方針を指定した。
設定画面には、グローバル設定があればリポジトリごとの入力を省けることを案内する。

## 調査した事項

調査したコミットは `1e7ec895e5f1d96721636d05e000f10eb05c50b1` である。
[app/tools.ts](https://github.com/tett23/aleph/blob/1e7ec895e5f1d96721636d05e000f10eb05c50b1/app/tools.ts) は `gitInfo` の結果を保持し、実行ファイルを使えないときに Git 操作を拒む。
[src-tauri/src/lib.rs](https://github.com/tett23/aleph/blob/1e7ec895e5f1d96721636d05e000f10eb05c50b1/src-tauri/src/lib.rs) は外部 Git の検索、版の取得、実行を行う。
[src-tauri/Cargo.toml](https://github.com/tett23/aleph/blob/1e7ec895e5f1d96721636d05e000f10eb05c50b1/src-tauri/Cargo.toml) に `git2` の依存はない。

[app/gitpanel.ts](https://github.com/tett23/aleph/blob/1e7ec895e5f1d96721636d05e000f10eb05c50b1/app/gitpanel.ts) は状態、履歴、差分、初期化、コミット、push、pull を Git コマンドで行う。
コミットは保存、add、commit の順であり、名前とメールアドレスの事前検査はない。
差分タブ、エディタの変更マーカー、置換の確認、アシスタントによる変更前のコミットも Git の利用可否に依存する。

[git2 の Repository API](https://docs.rs/git2/0.21.0/git2/struct.Repository.html) は状態、差分、コミット、設定、リモート操作を提供する。
[libgit2 の認証ガイド](https://libgit2.org/docs/guides/authentication/) は fetch と push の認証コールバックを説明する。
[git2 の Cred API](https://docs.rs/git2/0.21.0/git2/struct.Cred.html) の `credential_helper` は外部プロセスを起動するため、今回の方式では使わない。
これらはコードと公開文書の調査であり、今回の調査では libgit2 による実機動作は確認していない。

## 実装すること

### 組み込みの Git 処理

Rust の `git2` crate を通じて libgit2 を利用する。
配布アプリに必要なライブラリを含め、実行時の Git、Homebrew、Xcode コマンドラインツールを要求しない。
採用する版と機能は実装時に固定し、Cargo.lock と配布物のライセンス表示に反映する。
外部 Git へのフォールバックと、起動時の `git --version` は廃止する。
既存の `gitPath` は読み込み時に無視し、バイナリ選択と実行ファイルの再確認 UI を削除する。

対象は状態とブランチの表示、HEAD の本文、履歴、行と文字の差分、初期化、ステージ、手動と日次自動のコミット、push、pull とする。
エディタ、Git パネル、差分タブ、置換、アシスタントの変更前確認を同じバックエンドへ移す。
Git コマンドの引数列と出力文字列を IPC の契約にせず、許可した操作と必要な入力を型で定義し、状態、差分、履歴、エラーを構造として返す。

リポジトリではない状態、HEAD がまだない状態、HEAD に対象ファイルがない状態、読み取り失敗を区別する。
リポジトリの下位フォルダのワークスペースと linked worktree でも正しいリポジトリとパスを使う。
ワークスペースの正規化と許可範囲、読み取り専用の権限境界は Rust 側で維持する。
書き込みは同じリポジトリのインデックスと参照を同時に更新しないよう直列化し、処理は UI スレッドの外で行う。

差分の表示は [ADR 0096](0096-word-diff-display.md) の日本語を含むコードポイント単位の区別、HTML のエスケープ、末尾改行と行数、省略上限を維持する。
Git CLI の porcelain 形式を取得する規定は、libgit2 の行差分と本文から共通、削除、追加を構造化する処理に置き換える。
文字比較は Unicode 正規化を行わず、コードポイント列の最長共通部分列を使い、同点では削除を先に選ぶ。
一致する前後を除いた比較領域が 4,000,000 セルを超える場合は、メモリ使用量が列長に比例する同じ結果のアルゴリズムを使い、行全体の変更へ黙って切り替えない。
従来の Git CLI と同じ分割を返すことまでは要求しないが、表示から変更前後を欠落なく復元できることを求める。

### 名前とメールアドレスの設定

既存のアプリ設定画面の「Git」にはグローバル設定のフォームだけを置く。
プロジェクトのリポジトリ設定は、全体の設定画面とは別の「プロジェクト設定」モーダルに置く。
プロジェクト設定モーダルは、全体の設定画面と同じサイドバー、入力欄、ボタンの見た目を使い、サイドバーの「Git」にリポジトリ用フォームを表示する。
グローバルのフォームでは名前とメールアドレスを編集する。
保存先の設定ファイルを表示し、「グローバルに保存」を押したときだけグローバル設定の `user.name` と `user.email` を更新する。
既存のグローバル設定ファイルを使い、存在しない場合は `~/.gitconfig` を作成する。
複数のグローバル設定ファイルがある場合は libgit2 の設定の優先順位に従い、更新するファイルと有効値の取得元を表示する。
include 先を自動で書き換えず、保存先への上書き設定が有効値に反映されることを保存後に確認する。
説明は「全リポジトリの既定値です。ここで設定すると、リポジトリごとの入力を省けます。リポジトリ内の設定がある場合は、そちらが優先されます」とする。

プロジェクト設定モーダルでは、開くときに指定されたプロジェクトが所属するリポジトリの名前とメールアドレスを編集する。
ファイルツリーの各プロジェクト行に、常時表示する歯車の設定ボタンを設ける。
ボタンのツールチップは「Git 設定を開く」、アクセシブルな名前は対象プロジェクト名を含む「〈プロジェクト名〉の Git 設定を開く」とする。
このボタンからは、アクティブなシートにかかわらず、その行のプロジェクトを対象としてプロジェクト設定モーダルの「Git」を開き、名前欄へフォーカスする。
モーダルを閉じると呼び出し元へフォーカスを戻す。保存ボタン以外で閉じた場合は入力を設定ファイルへ書き込まない。
ボタンはキーボードでも操作でき、操作によってプロジェクト行の展開・選択・ドラッグを起こさない。
対象プロジェクトとリポジトリの場所、ローカル値、継承による有効値と取得元を表示する。
ローカル値がない入力欄は空欄とし、継承値は別の説明で示して、表示だけではローカルへ複製しない。
「このリポジトリに保存」は対象リポジトリのローカル設定だけを更新する。
ローカルフォームではキーごとに、入力があればその値を保存し、空欄ならそのローカルキーを削除して継承する。
保存後の継承を含む有効な名前とメールアドレスが揃えば保存でき、継承値の複製は不要とする。
「グローバル設定を使う」はローカルの両キーを削除して継承へ戻す。
この操作で有効値が不足する場合は、そのことを事前に示す。
Git コミットの著者設定はプロジェクト固有の manifest ではなくリポジトリの設定なので、同じリポジトリ内のほかのプロジェクトにも適用される旨を表示する。
linked worktree では、同じリポジトリのほかの worktree にも適用される旨を表示する。
プロジェクトに属さないワークスペースでも、Git パネルから対象リポジトリを指定して同じモーダルを開けるようにする。プロジェクトに属さない場合のモーダルのタイトルは「リポジトリ設定」とする。

どちらのフォームも、存在しない保存先ファイルは保存時に作成し、名前とメールアドレス以外の設定項目を保つ。
対象が切り替わった場合は入力中の保存先を黙って変更せず、対象を再確認できるようにする。
リポジトリでない場合はローカル保存を無効にし、Git パネルの初期化へ案内する。
グローバルのフォームはリポジトリを開いていない場合も使える。
有効な値が継承されている場合、ローカルに書き直すことを要求しない。

名前とメールアドレスは前後の空白を除き、値として保存する場合は空文字列、改行、NUL、署名に使えない値を拒否する。
ローカルフォームの空欄は前述の継承指定として扱う。
OS のアカウント名やホスト名から著者情報を推測しない。
コミットでは有効な設定値を著者とコミッターに使い、環境変数の著者指定で置き換えない。

コミット処理は、本文の保存やステージを始める前に著者情報を検査する。
未設定なら手動コミットとアシスタントの変更前コミットを中止し、案内モーダルを表示する。
モーダルには「Git の名前とメールアドレスを設定してください」、対象リポジトリ、不足している項目、「キャンセル」と「グローバル設定を開く」のボタン、および「このリポジトリだけに設定」のテキストリンクを表示する。
前者は案内モーダルを閉じて全体の設定画面の「Git」を開く。
後者は案内モーダルを閉じて対象リポジトリの設定モーダルを開く。
どちらも名前欄へフォーカスし、設定モーダルを重ねて表示しない。
キャンセルでは元の画面に戻る。
設定ファイルが存在しない場合も、継承を含めた有効値が不足するときだけ案内する。
設定画面では設定ファイルが存在しないことと、保存時にそのフォームが対象とする設定を作成することを示す。
グローバルフォームは両入力が有効になるまで保存を無効にし、ローカルフォームは入力と継承を合成した保存後の有効値で判定する。
モーダルと設定画面のテキストリンクには [デザインの原則](../design-principles.md) に従い常時下線を付け、ボタンのラベルには付けない。
不足が片方だけなら不足する項目を示す。
自動コミットも停止し、同じリポジトリの同じ不足状態について起動中は一度だけ通知する。
その間、日次コミットの成功日は更新しない。
設定の保存後は有効な値を読み直し、手動操作は利用者が再実行し、自動処理は次の通常の実行時から再開する。
差分、状態、履歴、通常のシート保存、初期化は著者情報なしでも利用できる。

### リモートとの通信

push と pull も libgit2 で行い、外部 Git を起動しない。
SSH は SSH エージェント、HTTPS は操作時のユーザー名とパスワードまたはトークンの入力に対応する。
入力した秘密は操作の間だけ保持し、設定、ログ、通知、履歴に保存しない。
認証の取消と失敗を明示し、無限に入力を繰り返さない。
HTTPS の証明書と SSH のホスト鍵を検証し、未知または不一致の SSH 鍵は接続を拒否して既知ホストの設定を案内する。
`core.sshCommand`、外部 credential helper、hooks、fsmonitor、外部 diff、外部フィルターを起動しない。
外部フィルターが必要な属性を持つファイルのステージやチェックアウトは、変換を黙って省略せず、未対応として対象と理由を表示する。

push は現在のブランチに設定されたリモートと送信先を使い、force push はしない。
pull は fetch 後に現在の追跡先を統合し、rebase は行わない。
fast-forward できる場合は参照と作業ツリーを更新し、分岐している場合はマージする。
マージコミットが必要なのに著者情報がなければ、作業ツリーを変更する前に停止して設定へ案内する。
競合がある場合は競合状態を明示し、解消後の手動コミットまで自動コミットを止める。
未保存のエディタ本文やローカル変更を上書きする統合は開始せず、理由を表示する。

### 既存 ADR との関係

採択時に [ADR 0060](0060-when-git-is-missing.md) 全体を本 ADR による置換として記録する。
[ADR 0046](0046-safe-automatic-git.md) の外部 Git への引数指定とリモート認証コマンドの利用を、本 ADR の組み込み処理に置き換えたことを記録する。
[ADR 0096](0096-word-diff-display.md) の CLI による取得方法と I1 の比較元を、本 ADR の差分構造と比較規則に置き換えたことを記録する。
[ADR 0042](0042-ipc-trust-boundary.md) の Git サブコマンド許可を型付き操作の許可へ置き換え、ワークスペース境界は維持する。
仕様書、README、設定と Git パネルの案内を同時に更新する。

## 実装しないこと

Git CLI の同梱、任意の Git コマンドの実行、外部認証コマンド、秘密の永続化、force push、rebase、Git の全機能との互換性は対象にしない。

## 不変条件

- I1: 対象の全 Git 機能は Git 実行ファイルの有無に依存せず、Git と外部認証コマンドを起動しない。
- I2: 読み取り操作はリポジトリのインデックスと参照を変更せず、書き込みは許可されたリポジトリで直列化される。
- I3: 著者情報が不足するコミットは保存、ステージ、コミットを開始せず、成功日も更新しない。
- I4: 設定の保存はフォームに明示した範囲の名前とメールアドレスだけを更新し、別の範囲の設定と他の設定項目を変えない。
- I5: 差分から復元した変更前後は比較入力と一致し、日本語、補助平面の文字、改行を失わない。
- I6: 認証の取消、失敗、証明書またはホスト鍵の検証失敗で、秘密を記録せず成功扱いしない。
- I7: pull は未保存本文とローカル変更を上書きせず、競合状態のまま自動コミットしない。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| Git なし、失敗する Git、通常の Git が PATH にある | 同じ結果、外部起動なし | I1 |
| 非リポジトリ、HEAD なし、対象ファイルなし、取得失敗 | 別の状態として返す | I1, I5 |
| 名前とメールなし、片方だけ、空白のみ | 設定を案内し、コミット前に停止 | I3 |
| グローバル継承、ローカル上書き、linked worktree | 有効値と保存先を正しく表示 | I4 |
| 設定ファイルなし、既存の remote 設定あり | 選択した範囲に必要項目だけ保存 | I4 |
| 日本語一文字、末尾改行、長い本文、改名、バイナリ | 内容と種類と上限を維持 | I5 |
| SSH、HTTPS、認証取消、未知の鍵 | 正しい接続または明示した失敗 | I6 |
| fast-forward、分岐、競合、未保存本文 | 安全に統合または中止 | I7 |

## 受けいれ条件

- A1: Git コマンドがない環境で、初期化、状態、履歴、差分、設定、手動コミット、自動コミットを行える。
- A2: 各プロジェクト行の設定ボタンから、そのプロジェクトのリポジトリ用フォームを開ける。名前とメールアドレスがない場合、グローバルとリポジトリ用の各フォームから保存してコミットできる。ローカル優先と継承への復帰を確認できる。
- A3: SSH エージェントと HTTPS 認証を使い、Git コマンドなしで push と pull を行える。
- A4: エディタの変更マーカー、差分タブ、置換の確認、アシスタントの変更前コミットが新しいバックエンドを使う。

## テスト設計

プロジェクト行からの入口は、別のプロジェクトのシートを開いた状態でも押した行のリポジトリが対象になることを A2 のテストで確かめる。マウスとキーボードの両方で開き、全体の設定画面から独立したモーダルの表示とフォーカス、行の展開・選択・ドラッグが発生しないことも確認する。

Rust の型付き操作と TypeScript の表示のテストを先に追加して失敗させる。
テスト用リポジトリも libgit2 で作り、Git がない PATH と、起動されたら印を残して失敗する偽の Git を使って I1 を確かめる。
署名や差分の期待値には固定した入力を使い、現行 Git CLI との比較は互換性の参考とし、CI の成功条件を CLI の存在に依存させない。

I2 は読み取り前後のインデックスと参照、同じリポジトリを指す複数ワークスペース、拒否した範囲外パスで検査する。
I3 と I4 は隔離した設定探索先を使い、設定なし、グローバル保存、ローカル保存、継承への復帰、同じリポジトリ内の複数プロジェクト、継承、上書き、不正入力、書き込み失敗、操作中のワークスペース変更を検査する。
グローバルに名前だけがある場合にローカルでメールアドレスだけを保存できることと、空欄によるキー削除後の継承を検査する。
設定の失敗で名前だけが保存されないよう、両キーの変更を一つの設定更新として検査する。
I5 は追加、削除、改名、バイナリ、未追跡、末尾改行、巨大な比較領域と表示上限を含める。
I6 と I7 はローカルの試験用 SSH と HTTPS サーバーで認証、取消、証明書、ホスト鍵、push 拒否、fast-forward、マージ、競合を検査する。
悪意ある hooks、フィルター、fsmonitor、外部 diff、認証コマンドが実行されないことも印のファイルで検査する。

A1〜A4 は配布用にビルドした Tauri で確認する。
Git を起動できない環境で設定からリモート操作まで行い、アプリが外部 Git を起動していないことと、リポジトリの結果を検査する。

## トレードオフ

実行ファイルの導入が不要になる一方、libgit2 と通信に必要なライブラリが配布物に加わる。
CLI の文字列処理は減るが、差分の構造化、認証、マージ状態を Aleph が扱う必要がある。
外部認証コマンドを使う既存環境では、対応する認証方法へ設定を変更する必要がある。
