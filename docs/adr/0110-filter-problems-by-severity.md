# ADR 0110: 下部パネルの問題を重大度の数で絞りこむ

Status: proposed

## 文脈

下部パネルの「問題」のタブは、開いているシートの診断と、選んでいるシートのプロジェクトの `check`、`lint`、`preflight` と手動のビルドの結果を、ファイルごとにまとめて出す ([ADR 0055](0055-problems-panel.md))。
タブの名前の横には、エラー、警告、そのほかの数を出している。
しかし、この数は表示だけで、押しても何も起きない。

書き手は、notice が多いプロジェクトでエラーだけを直したいときに、長い一覧から目で拾うことになる。
この ADR は、タブの横の数を押すと、その重大度の診断だけを一覧に出すことを決める。

[ADR 0055](0055-problems-panel.md) は、「実装しないこと」に「パネルの中の、文字による絞り込みと、重大度による絞り込み。」を挙げている。
この ADR は、そのうちの重大度による絞り込みの部分を置き換える。文字による絞り込みは、今のまま扱わない。
採択するときは、[ADR 0055](0055-problems-panel.md) のステータスの変更の配列に、`part` を「実装しないこと の、重大度による絞り込み」、`by` をこの ADR とする要素を足す。

## 調査した事項

この節には、ソースで確かめたことだけを書く。
ソースは main のコミット `97e8eef` で読んだ。

診断の重大度は、`error`、`warning`、`info` の三つである ([problems.ts:11](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/problems.ts#L11))。
Golem の結果の `notice` と `info` は、どちらも `info` にまとめる ([problems.ts:21-31](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/problems.ts#L21-L31))。
一覧には、手動のビルドの診断 (出どころは `build`) も入る ([problemsmount.ts:45-48](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/problemsmount.ts#L45-L48))。
エディタの診断も、エラーと警告のほかは `info` にする ([problemsmount.ts:32-43](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/problemsmount.ts#L32-L43))。

下部パネルは、押した位置の要素で処理を分ける `mousedown` の処理を一つ持つ ([problemsmount.ts:126-145](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/problemsmount.ts#L126-L145))。
一覧の行は、まとめた後の `groups` の番号で、開く診断を引く。

## 実装すること

- 「問題」のタブの横の三つの数 (エラー、警告、そのほか) を、押せるようにする。この ADR では、押して選んだ重大度を **絞りこみ** と呼ぶ。
- 絞りこみは一度に一つだけである。数を押すと、押した重大度が今の絞りこみと同じなら絞りこみを外し、違えば押した重大度を絞りこみにする。今絞りこんでいる数をもう一度押せば、いつでも絞りこみを外せる。
- 数を押すと、ほかのタブ (通知、ビルドログ、アシスタント) を見ているときも、「問題」のタブに移る。
- 絞りこみがあるときは、一覧に、その重大度の診断だけを出す。
  - ファイルのまとまりのうち、その重大度の診断を持たないものは出さない。
  - まとまりの見出しの数は、出した診断の数にする。
  - 並び順は、絞りこみが無いときと同じにする。
  - 出す診断が無いときは、「エラーはありません」「警告はありません」「そのほかの問題はありません」のどれかを出す。
- 三つの数は、絞りこみに関わらず、すべての診断から数える。
- 絞りこみの数には、選んでいることが分かる印 (背景を、ツリーで選んだ行と同じ `--sel` の色にする) を付ける。数の上では、ポインタを指の形にする。数には、押したときの働きを示すツールチップ (「エラーだけを出す」「警告だけを出す」「そのほかだけを出す」、選んでいるときは「絞りこみを外す」) を付ける。
- 行を押して開く診断は、出している一覧から引く。
- 絞りこみは、アプリケーションのメモリにだけ持つ。設定には書かず、Aleph を終えると消える。
- 絞りこみは、選んでいるシートやプロジェクトを替えても残る。
- 仕様書の下部パネルの節に、数を押して絞りこむことを書き足す。

## 実装しないこと

- 二つ以上の重大度を同時に選ぶこと。
- 出どころ (LSP、lint など) やファイルでの絞りこみ、文言での検索。
- ステータスバーの「エラー n　警告 m」を押したときに絞りこむこと。今のとおり、絞りこみを変えずに下部パネルを開く。
- 絞りこみを Aleph を終えた後まで残すこと。
- Golem の `notice` と `info` を分けて数えること。

## 不変条件

- I1: 絞りこみが無いときの一覧は、今の一覧と同じである。
- I2: 絞りこみがあるときの一覧の診断は、どれもその重大度を持ち、まとめた後の一覧のその重大度の診断をすべて含む。並び順は、絞りこみが無いときの一覧での順と同じである。
- I3: 絞りこみがあるときの一覧に、診断を持たないファイルのまとまりは無い。まとまりの見出しの数は、そのまとまりに出した診断の数に等しい。
- I4: 三つの数は、絞りこみに関わらず、まとめた後のすべての診断から数える。
- I5: 数を押した後の絞りこみは、今の絞りこみと押した重大度だけで決まり、見ているタブに依らない。押した重大度が今の絞りこみと同じなら無しに、違えば押した重大度にする。

境界の入力は次のとおりである。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 診断が無い、絞りこみ無し | 一覧は空 (「問題はありません」) | I1 |
| 診断が無い、絞りこみがエラー | 一覧は空 (「エラーはありません」)、数は 0、0、0 | I2, I4 |
| エラー一つだけ、絞りこみがエラー | そのエラー一つ | I2, I3 |
| エラー一つだけ、絞りこみが警告 | 一覧は空 (「警告はありません」)、数は 1、0、0 | I2, I3, I4 |
| 二つのファイルに、エラーと警告が混ざる、絞りこみが警告 | 警告を持つファイルのまとまりだけ、見出しの数は警告の数 | I2, I3 |
| 同じ位置の同じ文言の警告が二つ、絞りこみが警告 | まとめた後の一つ | I2 |
| 絞りこみ無しでエラーを押す | 絞りこみはエラー | I5 |
| 絞りこみがエラーでエラーを押す | 絞りこみは無し | I5 |
| 絞りこみがエラーで、そのほかを押す | 絞りこみはそのほか | I5 |
| 通知のタブを見ていて、絞りこみがエラーでエラーを押す | 「問題」のタブに移り、絞りこみは無し | I5 |
| 通知のタブを見ていて、絞りこみ無しで警告を押す | 「問題」のタブに移り、絞りこみは警告 | I5 |

## 受けいれ条件

- A1: エラー、警告、notice を持つプロジェクトで、問題のタブの横のエラーの数を押すと、一覧がエラーだけになり、数に選んだ印が付く。もう一度押すと、すべての診断に戻る。
- A2: 通知のタブを見ているときに警告の数を押すと、問題のタブに移り、警告だけが出る。
- A3: 絞りこんだ一覧の行を押すと、その診断の位置が開く。

## テスト設計

- I1〜I4 は、TypeScript で、まとめた後の一覧と絞りこみを受け取り、出す一覧を返す関数を、DOM から離して確かめる。境界の表の各行を入力にする。
- I5 は、今の絞りこみと押した重大度から次の絞りこみを返す関数で、三つの重大度と無しのすべての組を確かめる。
- テストの名前には、この ADR と不変条件の番号を入れる。
- A1〜A3 は、Tauri のデバッグ版で、エラー、警告、notice を出す使い捨てのプロジェクトを開いて確かめる。

## トレードオフ

- 絞りこみを一つの重大度に限るので、「エラーと警告」をまとめて見ることはできない。押すたびに一つに替わる単純な操作を優先した。
- 数を押す場所にしたので、新しいボタンを足さずに済む。代わりに、数が押せることはツールチップと指の形のポインタでしか分からない。
- 絞りこみを残さないので、Aleph を起動し直すと、すべての診断が出る。前の絞りこみが残って診断を見落とすことを避けた。
