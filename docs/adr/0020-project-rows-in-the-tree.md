# ADR 0020: ツリーのプロジェクトの行を高くして目立たせる

ステータス: 採択

## 文脈

左のサイドバーの「ファイル」のツリーは、ワークスペースのディレクトリとファイルを同じ高さ（27 ピクセル）の行で出す（[ADR 0004](0004-workspaces-and-projects.md)、[ADR 0005](0005-layout-and-appearance.md)）。
プロジェクト（`manifest.toml` のあるディレクトリ）の行は、フォルダの代わりに本の印を付けるだけで、ほかの行と高さも文字も同じである。
ワークスペースに複数のプロジェクトがあると、章やメモの行に紛れて、どこからどこまでが一つのプロジェクトかを見分けにくい。

メンテナーから、サイドバーのプロジェクトの行を、ファイルなどの行より高くして目立たせるよう求められた（2026-11-07）。

## 実装すること

- ツリーのプロジェクトの行を、ほかの行（27 ピクセル）より高い 34 ピクセルにする。
- プロジェクトの名前を太字（600）にし、文字を 13.5 ピクセル（ほかの行は 13 ピクセル）にする。本の印は文字と同じ色にする。
- 最初の行でないプロジェクトの行は、上に 6 ピクセルの間を空け、上に細い区切りの線を引く。プロジェクトの中の行（章、プロット、ほかのファイル）は今までどおりとする。
- 選んだときとポインタを重ねたときの背景は、ほかの行と同じとする。

## 実装しないこと

- プロジェクトの中の行の高さや字の大きさを変えること。
- プロジェクトを畳んだときに字数などの集計を出すこと。
- プロジェクトでないディレクトリの見た目を変えること。

## テスト設計

見た目だけの変更なので、自動のテストは書かない。
画面で次を確かめる。

- 見本のワークスペース（プロジェクトが二つ以上あるもの）で、プロジェクトの行がほかの行より高く太字で、二つ目以降のプロジェクトの上に区切りの線と間があること。
- プロジェクトの行を押すと、今までどおり開いたり畳んだりできること。ダークの外観でも区切りの線が見えること。

## トレードオフ

- プロジェクトの行が高くなるぶん、サイドバーに一度に見える行が少し減る。プロジェクトの数は章やファイルより少ないので、減る量は小さい。
