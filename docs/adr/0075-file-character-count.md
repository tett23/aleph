# ADR 0075: 本文文字数とファイル文字数を並べて表示する

ステータス: 採択（未実装）

## 文脈

シートの目標には、読者が読む本文の分量を使う。
一方、編集中のファイルの分量には、命令、コメント、空白も含まれる。
原稿から記法だけを削ったときには、後者の変化も分かるようにする。

## 調査した事項

[ADR 0012](0012-sheet-goals-and-notes.md) は、本文から空白を除いて字数を求め、その値で目標の達成度を表示すると定めている。
現在の集計はシートの種類に応じて本文を取り出し、空白を除いた文字列を Unicode コードポイント単位で数えている。[集計処理](https://github.com/tett23/aleph/blob/ef4589a937c025ec7fd85b05ba7826c13fe99d60/app/count.ts)

## 実装すること

字数を表示するシートのステータスバーに「本文文字数」と「ファイル文字数」を並べる。
ファイル文字数は、保存前の変更を含む現在の編集バッファ全体の Unicode コードポイント数とする。
記法、コメント、空白、バッファ内の改行を含め、埋め込み先の内容は展開しない。
入力、取り消し、やり直し、シート切り替えの後も現在の値を表示する。
目標との比較には従来の本文文字数を使う。

## 実装しないこと

PDF などのバイナリファイルにテキストの字数を表示しない。

## 不変条件

1. テキストバッファのファイル文字数は、そのバッファを構成する Unicode コードポイントの数に等しい。
2. 本文が同じまま記法だけを変更した場合、目標の達成度は変わらない。

| 編集バッファ | 本文文字数 | ファイル文字数 |
| --- | --- | --- |
| 空の Markdown | 0 | 0 |
| Markdown の見出し `# 猫` | 1 | 3 |
| 同じ見出しに LF を一つ追加 | 1 | 4 |
| Markdown の段落に絵文字 🐈 が一つ | 1 | 1 |
| テキストの A と B の間に空白と LF が一つずつ | 2 | 4 |
| Markdown の e に結合アキュートを一つ付ける | 2 | 2 |

## テスト設計

- `inv1_file_count` で境界表を検査する。保存していない改行を追加して取り消し、値が4から3に戻ることも確かめる。
- `inv2_goal_counts_body` で「猫」を「# 猫」に変え、目標の達成度と本文文字数が同じで、ファイル文字数が2増えることを確かめる。
- `inv1_gm_source` で、本文のある .gm にコメントだけを追加し、本文文字数は同じでファイル文字数が追加したコードポイント数だけ増えることを確かめる。

## トレードオフ

編集バッファを使うと入力中にも数が更新される。
エディタが読み込み時に改行を正規化した場合、バッファでの値とディスク上のコードポイント数には差が生じる。
