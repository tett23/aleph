# ADR 0091: 選択した文字列と同じ箇所をハイライトする

Status: accepted-pending

## 文脈

指示者は、エディタで文字列を選択したときに、同じ文字列があるほかの箇所もハイライトすることを求めた（2026-11-22）。
検索欄に入力せず、今選んでいる語の出現箇所を見たい。

## 調査した事項

調査したコミットは `8a102bdfa38df9fb2fa7a0852a5ca7da39d186af` である。
[`selectionMatches`](https://github.com/tett23/aleph/blob/8a102bdfa38df9fb2fa7a0852a5ca7da39d186af/app/ed/search.ts#L46) は既に同一文字列を探す。
200 UTF-16 コード単位超、改行を含む選択、空白だけの選択は除外し、大小文字を区別する。
検索結果には先頭から10,000件の上限がある。
[`updateSelMatches`](https://github.com/tett23/aleph/blob/8a102bdfa38df9fb2fa7a0852a5ca7da39d186af/app/ed/editor.ts#L155) の更新判定は、選択した文字列と開始位置だけをキーにしている。
このキーには本文の版が含まれない。
ハイライトが見えない状況の実機再現は未確認であり、機能が一切無いとは判断しない。

## 実装すること

同じシート内の、選択と完全一致する文字列をハイライトする。
大小文字は区別し、正規表現として解釈しない。
語の境界は要求せず、より長い語の中の一致も対象とする。
一致は文書の先頭から重ならない順に求め、選択範囲そのものは候補から除く。
現行の長さ、改行、空白による除外をなくし、空でない選択を対象にする。
上限10,000件は、選択範囲を除外した後の件数に適用する。

選択変更、本文変更、文書の差し替えで結果を更新する。
文書が変わった場合、選択文字列と開始位置が同じでも再計算する。
仮想化で隠れた行にも一致位置を保持し、その行を表示するときにハイライトする。
検索の一致、選択、校正の波線と別の表示層を使い、IME 変換中の DOM の再構築は既存の変換保護に従って遅延する。

[ADR 0019](0019-one-editor-for-both-writing-modes.md) を補足する。
実装時に仕様書と README に対象と上限を書く。

## 実装しないこと

別シートのハイライト、複数カーソル、全一致箇所の同時編集。

## 不変条件

- I1: 表示する範囲は、現在の選択文字列の重ならない完全一致から選択範囲自体を除いた、先頭から最大10,000件に等しい。
- I2: 選択が空なら一致の表示層は空である。
- I3: 選択または本文が変わった後には、現在の本文に対する I1 の結果を表示する（変換中は変換終了後）。
- I4: ハイライトの更新は本文、選択、履歴、検索条件を変えない。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 空の選択、一致が自分だけ | ハイライトなし | I1, I2 |
| `猫 猫` の先頭の猫を選択 | 後ろの猫を表示 | I1 |
| 200、201コード単位、複数行、空白だけ | いずれも同じ一致規則 | I1 |
| `aaaa` の先頭2文字を選択 | 後ろ2文字だけを表示 | I1 |
| 選択以外の一致を編集、取り消し | 一致の消失と復帰を反映 | I3, I4 |
| ほかの一致が10,000件、10,001件 | 先頭10,000件まで | I1 |

## 受けいれ条件

- A1: マウスとキーボードの選択で、縦書きと横書きの一致箇所が明暗両テーマで見分けられる。
- A2: 画面外の一致へスクロールすると、その箇所もハイライトされる。

## テスト設計

`ADR 0091 I1: …` の形のテストで境界表を検査する。
本文だけが変わる更新と、同一選択のままの文書差し替えのテストを追加し、先に失敗させる。
I4 は表示層以外の状態の不変を比較する。
A1 と A2 は Tauri で日本語、英語、複数行を選択して確認する。
変換中に本文の更新要求が届く場合も、変換終了後の結果を確認する。

## トレードオフ

長い選択や空白だけの選択にも対応すると検索量と表示量が増える。
表示上限と行の仮想化を維持するため、10,000件を超える一致はハイライトされない。
