# ADR 0016: md から gm への変換

ステータス: 採択

## 文脈

メンテナーは、md から gm への変換をサポートするようにと求めた（2026-11-07）。
メモや下書きを Markdown で書き、原稿にするときに `.gm` に移す使い方を想定する。

Golem の記法は、見出し（`#`）、箇条書き（`-`）、表（`|`）、コードブロック（```` ``` ````）が Markdown と同じ形で、次のものが違う。

- 番号付きリストは `+ ` で始める（番号を書かない）。
- 強調は `[strong: …]`、斜体は `[italic: …]`、コードは `[code: …]` と書く。
- 図版は `@figure パス alt="…"` と書く。
- エスケープは `\` で行う。本文の `[` は常に、`%%` は `\%%` と書く。`]` と `|` は命令の散文スロットの中でだけエスケープが要る。行頭の `#`、`-`、`+`、`=`、`@`、`|` と、`##` の直後に ASCII の数字が続く位置の `#` もエスケープが要る。
- 段落の区切り方は、プロジェクトの `[source] paragraph-separator` で決まる。空行の様式（既定）では、段落の中の改行は文字を生まず、空行で段落を区切る。改行の様式では、改行ひとつで段落を区切る。どちらの様式でも、行の末尾の `\` が強制改行になる。

プロトタイプでは、行ごとに読む簡単な変換を書き、ツールバーのメニューから実行できるようにした。
変換の結果は、確かめていない。

## 実装すること

- `.md` のシートで、メニューの「gm に変換」を選ぶと、同じ名前の `.gm` を同じディレクトリに作る。同じ名前があれば、上書きするかを確かめる。
- プロジェクトの中なら、作った `.gm` を `manifest.toml` の `chapters` の末尾に足す。
- 変換は次のとおりとする。
  - 見出し：そのまま。末尾の `#` は除く。
  - 箇条書き（`-`、`*`、`+`）：`- ` にする。入れ子は空白 2 つの字下げに直す。
  - 番号付きリスト（`1.`、`1)`）：`+ ` にする。
  - 強調（`**…**`、`__…__`）：`[strong: …]`。斜体（`*…*`、`_…_`）：`[italic: …]`。インラインのコード：`[code: …]`。
  - リンク（`[文字](URL)`）：文字だけを残す。
  - 画像だけの行：`@figure パス alt="代替テキスト"` にする（[ADR 0014](0014-shared-library-and-assets.md)）。
  - 引用（`>`）：記号を除いて段落にする。
  - 区切り線：空行にする。
  - 表とコードブロック：そのまま。コードブロックの中は変換しない。
  - 行末の空白 2 つの強制改行：`\` にする。
  - エスケープ：地の文の `[` と `\` は前に `\` を付け、`%%` は `\%%` にする。強調、斜体、コードの中身（散文スロットになる）では、`]` と `|` にも `\` を付ける。段落の行頭が `#`、`-`、`+`、`=`、`@`、`|` になるときと、`##` の直後に ASCII の数字が続くときは、最初の文字に `\` を付ける。
  - 段落：変換した `.gm` を置くプロジェクトが改行の様式なら、Markdown の一つの段落の行をつないで一行にする。空行の様式なら、行をそのまま残す。プロジェクトの外では空行の様式とする。
- 変換の字句の読み方は、Markdown のプレビュー（[ADR 0010](0010-previews.md)）と共有する。
- 変換したあと、Golem の check で誤りがないことを確かめ、誤りがあれば診断のパネル（[ADR 0015](0015-diagnostics-and-search.md)）に出す。

## 実装しないこと

- gm から md への変換。
- Markdown の拡張（脚注、定義リスト、数式、HTML のタグ）の変換。脚注と定義リストは Golem にも対応する記法があるので、使う場面が出てから別の ADR で決める。HTML のタグは文字として残す。
- 一度に複数のファイルを変換すること。

## テスト設計

- 上の各規則について、入力の Markdown と期待する `.gm` の組を `node --test` で確かめる。入れ子の強調、強調の中のコード、強調の中の `]` と `|`、地の文の `]` と `|`（エスケープしない）、行頭の `#`、`-`、`+`、`=`、`@`、`|` で始まる段落、`##1` を含む文、`%%`、コードブロックの中の記法、行末の空白を含める。
- 段落：同じ Markdown を、空行の様式と改行の様式のそれぞれで変換した結果を確かめる。
- 変換した結果を `golem check` に通し、誤りが出ないことを確かめる結合のテストを置く（golem があるときだけ動かす）。

## トレードオフ

- 変換を Aleph の中に書くと、Golem の記法の変更に合わせて直す必要がある。Golem の側に `golem import md` のような機能が入れば、そちらに移す。
- リンクの URL は捨てる。Golem にリンクの記法がないためである。必要なら、変換のあとに書き手が脚注などで補う。
