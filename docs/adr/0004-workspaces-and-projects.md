# ADR 0004: ワークスペースとプロジェクト

ステータス: 採択

## 文脈

Golem のプロジェクトは、`manifest.toml` を持つディレクトリである。
メンテナーは、一つの Git のリポジトリを単位とし、そのサブディレクトリにプロジェクトを置くワークフローを使っている。
このワークフローは変えるかもしれない、とメンテナーは述べている（2026-11-07）。

プロトタイプでは、Git のリポジトリを一つの **ワークスペース** とし、複数のワークスペースを設定に並べて、サイドバーの上で切り替えた。
ツリーには、ワークスペースの中のファイルを、プロジェクトの章を `manifest.toml` の順に並べて出した。
アプリの設定と、ウィンドウの位置と大きさは、アプリの設定のディレクトリ（macOS では `~/Library/Application Support/dev.tett23.aleph/`）に置いた。

## 実装すること

### ワークスペース

- ワークスペースは、Aleph に登録したディレクトリである。Git のリポジトリであることを前提とはしないが、Git の機能（[ADR 0011](0011-saving-and-git.md)）はリポジトリのときだけ働く。
- ワークスペースは複数登録でき、一つのウィンドウで切り替える。切り替えはサイドバーの上の名前から行う。
- ワークスペースの中で `manifest.toml` を持つディレクトリを **プロジェクト** とする。深さは問わない。プロジェクトの中にプロジェクトは置かない（内側の `manifest.toml` は無視する）。
- ワークスペースの構成の決まり（リポジトリとプロジェクトの対応）を、コードの一か所（ワークスペースの走査）に閉じ込める。ワークフローを変えるときに、そこだけを変えれば済むようにする。

### ツリー

- ツリーには、ワークスペースの中のディレクトリと、Aleph が開ける形式のファイル（[ADR 0002](0002-purpose-scope-and-name.md)）を出す。`.` で始まるもの、`build/`、`node_modules/`、`target/`、`dist/` は出さない。
- プロジェクトの中では、`manifest.toml` の `chapters` に並んだ章を、その順で先に出し、ほかのファイルとディレクトリを後に出す。`plot.csv` は「プロット」として出す（[ADR 0013](0013-plot-and-gantt-chart.md)）。
- `.gm` と `.md` は、最初の見出しを名前として出し、ファイル名を小さく添える。`.gm` には字数を添える。
- 未コミットの変更があるファイルには印を付ける（[ADR 0011](0011-saving-and-git.md)）。目標のあるシートには、進み具合の円を付ける（[ADR 0012](0012-sheet-goals-and-notes.md)）。
- ツリーで、新しいシート、新しいフォルダ、新しいプロジェクトを作れる。新しいプロジェクトは `golem new --no-fonts` で作り、フォントは共有ライブラリからコピーする（[ADR 0014](0014-shared-library-and-assets.md)）。新しい章は `manifest.toml` の `chapters` の末尾に足す。
- ファイルの名前はツリーで変えられる。消す操作は持たない（Finder か Git で行う）。

### アプリの設定

- アプリの設定は、アプリの設定のディレクトリの `config.json` に置く。ワークスペースの一覧、golem と shem の場所、共有ライブラリの場所、エディタの設定などを持つ。
- 設定は画面の設定のダイアログで変える。範囲のある値（文字サイズ、行間など）は、範囲の外の値を上限と下限に丸める。

### ウィンドウの位置と大きさ

- メインのウィンドウの位置と大きさを、動かしたとき、大きさを変えたとき、閉じるとき、アプリを終えるときに記録する。記録は `window.json` に置く。
- 起動したとき、記録した矩形がどれかのディスプレイに収まれば、その位置と大きさに戻す。どのディスプレイにも収まらないとき（ディスプレイを外したときなど）は、既定の大きさで中央に置く。
- 判定は物理的な画素で行う。記録したときとディスプレイの倍率が変わっても、収まるかどうかで判断する。

## 実装しないこと

- ワークスペースの設定（どのワークスペースを開くか、表示の状態など）をワークスペースの中に置くこと。設定はアプリの設定だけに置く。シートのメタデータ（[ADR 0012](0012-sheet-goals-and-notes.md)）は、プロジェクトの中か、プロジェクトの外のシートについてはワークスペースのルートの `.aleph/` に置く。これは原稿に付く情報であり、ワークスペースの設定ではない。
- ファイルを消す操作、ゴミ箱。
- 別ウィンドウ（ページ、プロット、本文）の位置の記録。メインのウィンドウだけを記録する。

## テスト設計

- ワークスペースの走査：一時ディレクトリにプロジェクトを入れ子と並列で置き、プロジェクトの一覧と、ツリーの並び（章が `manifest.toml` の順に先に来る、隠すものが出ない）を `node --test` で確かめる。
- 章の追加：`chapters` が一行の配列、複数行の配列、空の配列、表形式の項目（`{ file = ... }`）を含む配列、入れ子の配列（全体で一つの章になるもの）を含む配列の各場合に、末尾に足した結果と、ツリーに並ぶ章の順を確かめる。
- ウィンドウの記録：矩形とディスプレイの一覧から、戻す位置か既定かを決める関数を `cargo test` で確かめる（収まる、はみ出す、ディスプレイの外、大きさが小さすぎる、の各場合）。
- 画面の確かめ方：ウィンドウを動かして終了し、起動して同じ位置に戻ること。記録を画面の外の値に書き換えて起動し、既定の大きさで中央に開くこと。

## トレードオフ

- リポジトリとプロジェクトの対応を前提にしないことで、ワークフローを変えても使える。その代わり、ワークスペースの中のどこにプロジェクトがあるかを毎回走査する。
- ウィンドウの位置を物理的な画素で記録すると、倍率の違うディスプレイに移ったときに見た目の大きさが変わる。収まらないときは既定に戻すので、ウィンドウが見えなくなることはない。
