# ADR 0072: ⌘S で保存したら PDF のページをすぐ組み直す

ステータス: 採択（未実装）

## 文脈

ページのプレビューは、保存された原稿から Golem が PDF を組み、shem が各ページを画像にして表示する。
[ADR 0056](0056-wait-before-building-pages.md) は、執筆中の自動保存で重い処理が繰り返されないよう、最後の編集から 5 秒たつまで組み直しを待つことにした。
現在は ⌘S で保存して組版結果を確かめたいときにも同じ待ち時間が入る。

## 実装すること

「保存」コマンド（既定は ⌘S）でシートの保存内容が変わり、その変更がページに未反映なら（組版中なら完了時に判定する）、保存完了後すぐに組版を要求する。
保存内容の変更は、コマンド開始前に保存されていた本文と、整形を終えて実際に保存した本文を比べて判定する。
同じ本文を書き戻した場合は、新しい組版もタイマーも要求しない。
自動保存の後で変更のない ⌘S を押しても、その自動保存ですでに予約した更新の期限は動かさない。

通常のエディタ、LSP の整形、JSON の整形、コマンドパレットからの保存に共通の判定を使う。
整形のための中間保存は数えず、最終保存の結果を対象パスごとに判定する。
競合で上書きを取り消した場合や書き込みに失敗した場合は、その操作による更新を要求しない。

自動保存による 5 秒の待ちが満了したときにも、プロジェクトの保存内容と表示中のページを最後に正常に組んだ入力内容を照合する。
待機中に変更を元に戻して保存した場合など、差が消えていれば予約を終え、Golem も shem も起動しない。
比較は内容で行い、保存時刻だけが変わった場合は同じものとして扱う。

対象は「保存したらページを組みなおす」がオンで、従来の保存時更新の対象になっているプロジェクトとする。
すなわち、シートに対して「ページ」が選ばれているか、そのプロジェクトに前回のページ結果がある場合に更新する。
新しい結果は既存の経路でメイン画面と、そのプロジェクトのページを表示している別ウィンドウに届ける。

「すぐ」は、保存完了時に 5 秒の待ちを取り消して組版を要求することを指す。
組版が進行中なら完了後に、その組版に使った内容と最新の保存内容を比べる。
差が残っているときだけ最新の内容で一回組む。
手動ビルドが出力先を使っていれば既存の順番を守る。
新しい PDF を生成してから描画し、処理中は直前の表示を保つ。
保存後に別のタブに移っても、更新先は保存したプロジェクトのままとする。

## 実装しないこと

自動保存の待ち時間、本文の HTML プレビュー、配布用の手動ビルドの変更。

## 不変条件

1. 対象プロジェクトでは、明示保存で本文が変わり、ページへの反映が必要なら、5 秒待たずに更新を要求する。
2. 同じ保存に由来する遅延要求は残らず、組版中に重なった要求による後続の組版は、未反映の差が残れば一回、差が消えればゼロ回である。
3. 自動保存だけの場合は最後の編集から 5 秒の規則を保ち、別プロジェクトの ⌘S はその待ちに影響しない。
4. 保存に失敗した場合と、保存時更新の対象外の場合は、その保存による組版要求はゼロである。
5. 本文が変わらない保存による新規要求はゼロであり、待機満了時の保存内容がページに反映済みなら組版回数もゼロである。

| 入力 | 期待する結果 |
| --- | --- |
| 編集直後に ⌘S、組版は空き | 保存完了後、タイマーを進めずに PDF 組版を開始 |
| 自動保存から 5 秒を待つ途中で変更のない ⌘S | 新しい要求はゼロ。元の期限に未反映の変更があれば一回組む |
| 待機中に変更を元に戻して自動保存し、期限に到達 | PDF 組版も描画もゼロ回 |
| 変更せずに ⌘S を二回、待機予約なし | 要求も組版もゼロ回 |
| 組版中に二度編集し、それぞれ ⌘S | 実行中の組版の後、最後の保存内容で一回組む |
| 未反映の変更を自動保存、最後の編集から 4,999 ms と 5,000 ms | 前者は待機、後者で開始 |
| 保存失敗、プロジェクト外、設定オフ、ページ未選択かつ過去の結果なし | 保存による組版なし |

## テスト設計

条件 1 と 4 は「保存」コマンドから保存の完了時刻と組版要求を記録し、LSP の整形、golem fmt のための中間保存、変更なし、書き込みエラー、競合による取消、対象外の各入力を試す。
条件 2、3、5 は仮の時計と二つのプロジェクトを使い、表の時刻で組版回数と対象を比較する。
各テスト名に条件の番号を含める。
画面ではページを別ウィンドウに開き、見出しを書き換えて ⌘S を押し、待機表示を経ずに組版が始まり、保存後の見出しが両方に表示されることを確かめる。

## トレードオフ

プロジェクトごとにどの保存内容からページを組んだか記録する必要がある。
その記録を使えば、保存の連打や元に戻した編集で PDF の組版と描画を繰り返さずに済む。
