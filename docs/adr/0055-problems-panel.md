# ADR 0055: 診断を画面の下の「問題」のパネルにまとめる

ステータス: 採択

## 文脈

Aleph の診断は、出どころによって見る場所が分かれている。

- エディタの診断（LSP、ウィキリンク、文章の検査、JSON の検査）は、波線と溝の印で出す。一覧は、ステータスバーの「エラー n　警告 m」を押すと、そのエディタの下に開く（[app/ed/panels.ts](https://github.com/tett23/aleph/blob/ca96d89/app/ed/panels.ts#L121)、[app/lsp/mount.ts](https://github.com/tett23/aleph/blob/ca96d89/app/lsp/mount.ts#L289)）。一覧は開いているシート一つ分で、ほかのシートの診断は見られない。また、この数は LSP の診断だけを数え、LSP を持たない形式（`.toml` など）では出ない。
- `golem check`、`lint`、`preflight` の結果は、左のサイドバーの「診断」に出す（[ADR 0015](0015-diagnostics-and-search.md)）。ステータスバーの「lint」「preflight」を押すと、このパネルに切り替わる（[app/diag/mount.ts](https://github.com/tett23/aleph/blob/ca96d89/app/diag/mount.ts#L116)）。

書き手は、ツリーを見たいときに左のサイドバーを診断に取られる。
シートを移ると、エディタの診断の一覧は閉じる。
VS Code の「問題」のパネルのように、診断を一か所にまとめ、エディタの下に開いたまま書けるようにしたい。

## 実装すること

- 中央の列（エディタのペインの下、ステータスバーの上）に「問題」のパネルを置く。
  - 上端の境目をドラッグして高さを変える。高さ（既定 220 ピクセル、最小 80 ピクセル、中央の列の高さの 70% まで）と、開いているかどうかを `config.json` の `ui` の `problemsHeight`、`showProblems` に残す。
  - 見出しの行に、「問題」の語、エラー、警告、そのほかの数、× のボタンを置く。× で閉じる。
- パネルには、次のものをファイルごとにまとめて出す。
  - 開いているすべてのシートのエディタの診断（出どころを問わない）。
  - 選んでいるシートのプロジェクトの、最後に実行した `check`、`lint`、`preflight` の結果。位置のない診断は「（位置のない診断）」にまとめる。
  - ファイルの並びは、選んでいるシートを先にし、ほかは相対パスの順とする。ファイルの中は、行、列の順とする。
  - 各行に、重大度の印、文言、出どころ（`golem`、`lint`、`preflight`、`proofread` など）とコード、行と列を出す。同じファイルの同じ位置に同じ文言の診断が LSP と `check` の両方から来たときは、一つにまとめる。
- 行を押すと、そのファイルを開き（開いていれば、そのタブを選び）、その位置にカーソルを置く。
- 開き方は次のとおりとする。
  - ステータスバーの「エラー n　警告 m」、「lint」、「preflight」を押すと、パネルを開く。開いていれば閉じない。
  - コマンド `view.problems`（「問題のパネル」）と ⇧⌘M で、開け閉めする。キーは [ADR 0034](0034-key-bindings.md) の割り当ての画面で変えられる。
  - Esc は、パネルの中に焦点があるときだけ、パネルを閉じる。
- ステータスバーの「エラー n　警告 m」を、LSP を持たない形式でも出す。数は、そのシートのエディタの診断すべて（出どころを問わない）とする。
- エディタの下に開く「エディタの診断の一覧」は、このパネルで置き換えて、なくす。
- 左のサイドバーの「診断」は残す。プロジェクトを選び、`check`、`lint`、`preflight` を実行する場所とする。
- 仕様書のエディタ、LSP、診断と検索、画面の構成の節を書き直す。

## 実装しないこと

- パネルの中の、文字による絞り込みと、重大度による絞り込み。
- 開いていないシートの、エディタの診断（LSP に開かせて診断を集めること）。
- パネルを右や左に移すこと、別のウィンドウに出すこと。
- 診断のほかの中身（出力、ターミナルなど）を、このパネルのタブとして足すこと。

## テスト設計

`node --test` で、テストを先に書いて失敗させてから実装する。

- 問題の一覧を作る関数が、エディタの診断と `check`、`lint`、`preflight` の結果を、ファイルごとにまとめ、選んでいるシートのファイルを先に、ほかを相対パスの順に並べること。
- ファイルの中を、行、列の順に並べること。位置のない診断を「（位置のない診断）」にまとめること。
- 同じファイル、同じ位置、同じ文言の診断を一つにまとめること。
- 数を、重大度ごと（エラー、警告、そのほか）に数えること。
- パネルの高さを、最小と最大のあいだに丸めること。`config.json` の形の違う値を既定に戻すこと。
- ステータスバーの数が、LSP を持たない形式でも、出どころを問わずに数えること。
- 画面の確かめ方：試験のプロジェクトで、`.gm` と `.toml` を開き、⇧⌘M とステータスバーからパネルを開くこと、行を押すとその位置に移ること、× と Esc で閉じること、高さを変えて起動し直すと戻ることを確かめる。

## トレードオフ

- 中央の列の高さを、パネルの分だけエディタから取る。閉じれば元に戻る。
- 左のサイドバーの「診断」とパネルに、`check`、`lint`、`preflight` の結果が二か所に出る。左は実行する場所、下は読む場所と分ける。
- エディタの診断の一覧をなくすので、これを開いていた操作（ステータスバーの数を押す）は、下のパネルを開く操作に変わる。
