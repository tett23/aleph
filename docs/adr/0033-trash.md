# ADR 0033: シートとフォルダをゴミ箱に移し、戻す

ステータス: 採択

## 文脈

Aleph のツリーは、ファイルの名前を変える操作を持つが、消す操作を持たない（[docs/specifications.md](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/docs/specifications.md) の「ワークスペースとプロジェクト」）。
要らなくなったシートや下書きは、Finder で消すことになる。

Ulysses は、消したシートをゴミ箱に移し、あとから戻せる。
メンテナーから、Obsidian と Ulysses にあって Aleph にない機能を比べたうえで、ゴミ箱と復元の ADR を作るよう求められた（2026-11-07）。

消す操作には、Aleph の中の次のものが関わる。

- プロジェクトの章は、`manifest.toml` の `chapters` に並ぶ（[app/manifest.ts](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/manifest.ts#L51-L115)）。章のファイルが消えて `chapters` に残ると、Golem の組版が失敗する。
- シートの目標とノートは、`.aleph/notes.json` にシートのパスをキーとして置く（[ADR 0012](0012-sheet-goals-and-notes.md)）。名前を変えるときは、`onRename` でキーも変えている（[app/ui/tree.ts](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/ui/tree.ts#L195-L212)）。
- 開いているシートは、保存していない変更を持つことがある（[ADR 0011](0011-saving-and-git.md)）。
- ワークスペースは Git のリポジトリであることが多く、1 日 1 回の自動コミットは `git add -A` を使う（[ADR 0011](0011-saving-and-git.md)）。

ゴミ箱の置き場所は、二つの案がある。

- **macOS のゴミ箱**：Finder の「戻す」で戻せる。ただし、Aleph からゴミ箱の中身を一覧にしたり、元の場所に戻したりするには、Finder を AppleScript で操作するか、ゴミ箱の内部の記録を読むことになる。`manifest.toml` やノートのキーを一緒に戻すことはできない。
- **Aleph のゴミ箱**：Aleph が移した先と元の場所を記録し、Aleph の中で一覧にして戻す。

## 実装すること

### 置き場所

- ゴミ箱は Aleph のものとし、アプリの設定のディレクトリの `trash/` に置く（macOS では `~/Library/Application Support/dev.tett23.aleph/trash/`）。ワークスペースの中には置かない。ワークスペースの中に置くと、自動コミットの `git add -A` がゴミ箱の中身をコミットしてしまうためである。
- 消すたびに `trash/<日時と連番>/` を作り、その中に消したファイルかフォルダを移す。同じ所に `entry.json` を置き、元の絶対パス、消した日時、ワークスペース、`manifest.toml` から外した章の項目（下記）、`notes.json` から外したキーと値を記録する。

### 消す

- ツリーで選んだシートかフォルダ（[ADR 0004](0004-workspaces-and-projects.md) の選択）で ⌘⌫ を押すか、ツールバーのメニューの「ゴミ箱に移す」を選ぶと、ゴミ箱に移す。プロットの行（`plot.csv`）と、ワークスペースそのものは移さない。
- ファイル一つは確かめずに移し、通知で「ゴミ箱に移しました」と、そのまま戻す「戻す」のボタンを出す。フォルダは、中のファイルの数を示して確かめてから移す。プロジェクト（`manifest.toml` のあるフォルダ）は、プロジェクトであることを示して確かめる。
- 開いているシートを消すときは、保存してから閉じて移す。
- 章を消すとき：そのプロジェクトの `chapters` から、その章の項目を外し、外した項目の文字と、並びの中の位置を `entry.json` に記録する。フォルダを消すときは、中に入る章をすべて同じように外す。`chapters` の書き方（一行か、一行に一項目か）は保つ。
- ノート：消すシート（フォルダなら中のシート）の `notes.json` のキーを外して、`entry.json` に記録する。
- 移したあと、ツリーを読み直す。Git のリポジトリでは、Git のパネルに消えたファイルとして出る。

### 戻す

- 左のサイドバーに「ゴミ箱」のパネルを足す。消した日時の新しい順に、元の場所、種類（シート、フォルダ、プロジェクト）、日時を出し、項目ごとに「戻す」と「完全に消す」を持つ。
- 「戻す」は、元の場所に移し戻す。元の場所に同じ名前のものがあれば、[ADR 0014](0014-shared-library-and-assets.md) と同じく `-2` を付けた名前で戻し、そのことを知らせる。元のフォルダがなければ作る。
- 章を戻すとき：プロジェクトの `manifest.toml` がまだあれば、記録した項目を記録した位置（並びが短くなっていれば末尾）に戻す。名前を変えて戻したときは、項目のパスも変える。
- ノート：記録したキーと値を、戻した場所のパスで `notes.json` に戻す。同じキーがすでにあれば、上書きしない。
- 「完全に消す」と「ゴミ箱を空にする」は、消すものと、元に戻せないことを示して確かめてから、ディスクから消す。
- 起動のときに、消してから 30 日を過ぎた項目を、ゴミ箱から消す。

## 実装しないこと

- macOS のゴミ箱への移動と、Finder の「戻す」との連携。
- ゴミ箱の保存の日数を設定で変えること。
- ワークスペースの外（共有ライブラリなど）のファイルを消すこと。
- Git の操作（消したファイルの `git rm`、戻したファイルの `git add`）。Git の変更は、ふだんのコミットか自動のコミットに任せる。
- プロットの `plot.csv` の `file` の列から、消した章の参照を外すこと。

## テスト設計

DOM に触れない部分を関数に分け、`node --test` で、Rust の部分は `cargo test` で、先に書いて失敗させてから実装する。

- `chapters` から項目を外す関数と、記録した位置に戻す関数：一行の書き方と一行に一項目の書き方、文字列の項目、`file` を持つ表の項目、入れ子の配列の中の項目、フォルダの中の複数の章、外したあとで並びが短くなったときに末尾に戻すこと、名前を変えて戻すときのパスの書き換え。外して戻すと元の文字に戻ること。
- ノートの記録と復元：キーを外して記録し、戻すと元の値になること、同じキーがあるときに上書きしないこと、フォルダの中の複数のシート。
- 戻す先の名前：元の場所が空いていればその名前、ふさがっていれば `-2` を付けた名前（`freeName` と同じ規則）。
- 30 日を過ぎた項目を選ぶ関数（境目の日時を含める）。
- `entry.json` の読み書き（壊れた記録を飛ばすこと）。
- Rust：アプリの設定のディレクトリの下にフォルダごと移すこと（ボリュームが違うときは複製してから消す）、完全に消すこと。
- 画面の確かめ方：見本のプロジェクトで章を一つ消すと、ツリーと `chapters` から消え、Git のパネルに出ること。通知の「戻す」で、ファイル、`chapters` の項目、ノートが元に戻ること。フォルダを消すと確かめが出ること。ゴミ箱のパネルから戻すこと、完全に消すこと、空にすること。

## トレードオフ

- Aleph のゴミ箱なので、Finder から消したファイルや、Aleph の外のゴミ箱とはつながらない。その代わり、`chapters` とノートを一緒に戻せる。
- ゴミ箱をワークスペースの外に置くので、ワークスペースを別の Mac に移したり、ワークスペースの登録を外したりしても、ゴミ箱の中身はこの Mac のこの Aleph に残る。Git のリポジトリなら、消したファイルは Git の履歴からも戻せる。
- 30 日でゴミ箱から消えるので、それより前に消したものは Aleph からは戻せない。Git のリポジトリなら、Git の履歴から戻せる。
