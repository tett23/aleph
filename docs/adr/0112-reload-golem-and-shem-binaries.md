# ADR 0112: 設定から Golem と shem のバイナリを読み込みなおし、デフォルトに戻す

Status: accepted-pending

## 文脈

設定の「Golem と shem」の節は、Golem と shem のバイナリを一つずつ行に出す ([ADR 0008](0008-golem-and-shem-binaries.md))。
各行は、見つかったバイナリの版とパス、パスの欄、ネイティブのダイアログで選ぶ「選ぶ」のボタンを持つ。

書き手は、Golem をソースからビルドして、同じパスに入れなおすことがある。
しかし、Aleph は、開いているプロジェクトごとに `golem lsp` を起動して残すので、入れなおした後も古い Golem に話し続ける。
新しい Golem を使うには、今は Aleph を終えて起動しなおすしかない。
パスを別のバイナリに変えたときも、同じく古い `golem lsp` が残る。

また、一度パスを指定すると、デフォルトの探し方 (同梱のもの、`~/.local/bin`、Homebrew、PATH の順) に戻すボタンが無い。
欄の文字を消せば戻るが、そのことは画面からは分からない。

この ADR は、各行に「再読み込み」と「デフォルトに戻す」のボタンを足し、アプリケーションを起動しなおさずに、新しいバイナリやデフォルトのバイナリを使い始められるようにすることを決める。
あわせて、「選ぶ」のボタンの名前を「選択」に変える。

## 調査した事項

この節には、ソースで確かめたことだけを書く。
ソースは main のコミット `97e8eef` で読んだ。

### 設定の行

設定の行は `mountTools` が描く ([tools.ts:23-50](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/tools.ts#L23-L50))。
版とパスは、描くたびに `api.toolInfo` で Rust に尋ね、Rust の側は残さずにその場で探す ([tools.ts:11-19](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/tools.ts#L11-L19))。
「選ぶ」と、欄にパスを打つことは、Rust の側がネイティブのダイアログで確かめてから設定に書く ([ADR 0042](0042-ipc-trust-boundary.md)、[ADR 0050](0050-paths-the-writer-chooses.md))。
欄に打ったときは、確かめで断られても設定を保存しなおす ([tools.ts:40-48](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/tools.ts#L40-L48))。
仕様書は、画面からの保存で、パスを空にすることを受け付けると定めている。パスが空のときは、デフォルトの順に探す。

### 一度だけ動かす呼び出し

`golem` と `shem` を一度だけ動かす呼び出し (`api.tool`) は、呼ぶたびに Rust の側が設定からバイナリを探す ([lib.rs:1370-1385](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/src-tauri/src/lib.rs#L1370-L1385))。
そのため、`golem build`、`golem check`、`golem kinsoku`、`shem` は、入れなおした次の呼び出しから新しいバイナリを使う。

### golem lsp の接続

`golem lsp` の接続は二種類ある。
この ADR では、プロジェクトごとに起動して残す接続を **プロジェクトの接続** と、移動のたびに起動して止める接続を **移動の接続** と呼ぶ。

- **プロジェクトの接続**：画面の側は、プロジェクトごとの接続を `clients` に残す ([lsp/mount.ts:27](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/lsp/mount.ts#L27))。接続は、初期化の応答で `planFileMove` と `planMovedReferences` に応じるかと、色分けの凡例を読み、その接続のあいだ持つ ([lsp/client.ts:112-136](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/lsp/client.ts#L112-L136))。
- **移動の接続**：ツリーでの移動と外での移動は、移動ごとに別の `golem lsp` を起動し、終わると止める ([tree-move-flow.ts:51](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/tree-move-flow.ts#L51)、[watchmount.ts:205](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/watchmount.ts#L205))。移動の接続は、次の移動から新しいバイナリを使う。

プロジェクトの接続の対象は、プロジェクトの中の `.gm` と `.emet` (`lspDoc`) と、`.toml`、`.md`、`.csv` (`renameDoc`) の文書である ([lsp/mount.ts:37-38](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/lsp/mount.ts#L37-L38))。
この ADR では、これらの文書を **LSP の対象の文書** と呼ぶ。
ストアが変わるたびに、開いている LSP の対象の文書と、同期した文書 (`synced`) を比べ、新しい文書はプロジェクトの接続につないで開いたと送る ([lsp/mount.ts:145-167](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/lsp/mount.ts#L145-L167))。
`resetLspAfterMove` は、指定したプロジェクトの同期した文書を閉じたと送って `synced` から外し、接続を止めて捨てる ([lsp/mount.ts:403-432](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/lsp/mount.ts#L403-L432))。
つなぎなおすのは、次にストアが変わって同期が動いたときである。

### 古いバイナリの結果が残るもの

古いバイナリから読んで残す値と、古いバイナリの出力で描いたものは、次のとおりである。

- 禁則とぶら下げの設定は、プロジェクトごとに `golem kinsoku` で読み、`last` に残す。読みなおすのは、シートを開いたときと `style.toml` を保存したときである ([compositionmount.ts:13-57](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/compositionmount.ts#L13-L57))。
- 外で移したときの「Golem LSP が移動後の参照の更新に対応していません」の通知は、ワークスペースと `golemPath` の組ごとに一度だけ出す ([outside-move.ts:274-279](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/outside-move.ts#L274-L279))。同じパスに入れなおしたときは、組が変わらないので、新しい Golem が応じなくても二度目の通知は出ない。
- プレビューの HTML (Golem の出力) と、shem が描いたページの画像は、次にビルドするまで残る ([preview/mount.ts:52-62](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/preview/mount.ts#L52-L62))。
- `check`、`lint`、`preflight` の結果は、次に走らせるまで残る ([diag/mount.ts:14](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/diag/mount.ts#L14))。

shem は、ページのプレビューで呼ぶたびに動き、続けて動く処理を持たない。

### 移動の最中

ツリーでの移動は、ワークスペースごとに実行中を `active` の集合に記録し ([tree-move-flow.ts:29-30](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/tree-move-flow.ts#L29-L30))、終わると外す ([tree-move-flow.ts:217](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/tree-move-flow.ts#L217))。
外での移動の参照の更新には、実行中を記録するものが無い。

## 実装すること

### ボタン

- 設定の「Golem と shem」の各行のボタン「選ぶ」を「選択」に変える。
- 各行の「選択」の右に、「再読み込み」と「デフォルトに戻す」のボタンをこの順に置く。どちらも「選択」と同じ文字だけのボタン (`span.btn`) とする。「再読み込み」の書き方は、差分のタブの「再読み込み」にそろえる。
- 「デフォルトに戻す」は、設定に保存したその行のパス (`golemPath` か `shemPath`) が空でないときだけ押せる。空のときは、押せない見た目 (`disabled` の印) にし、押しても何もしない。欄に打っている途中の文字は数えない。

### Golem の再読み込み

- Golem の行の「再読み込み」は、次のことを順に行う。この ADR では、これをまとめて **Golem の再読み込み** と呼ぶ。
  1. その時点でプロジェクトの接続を持つすべてのプロジェクト (`clients` の鍵) を、`resetLspAfterMove` と同じ手順で止めて捨てる。開いているシートの診断と色分けは、いったん消える。
  2. ストアの変化を待たずに、Golem の再読み込みが同期の処理を自分で呼ぶ。同期は、開いている LSP の対象の文書ごとに、そのプロジェクトの接続を新しいバイナリで起動し、文書を開いたと送る。
  3. 禁則とぶら下げの設定を読みなおす。エディタに当てているプロジェクト (`.gm` のエディタを開いているプロジェクト) ごとに `golem kinsoku` を一度走らせ、エディタに当てなおす。ほかのプロジェクトの残した値 (`last`) は捨てる。シートを開いたときには今のとおり読みなおすので、捨てても困らない。
  4. 「移動後の参照の更新に対応していません」を一度出したことの記録を捨てる。
  5. 設定の節を描きなおし、行の版とパスを新しいバイナリのものにする。
- Golem の再読み込みは、手順 2 で起動したすべての接続に文書を開いたと送り、手順 3 の `golem kinsoku` が終わったときに終わる。接続の初期化を終えるのは待たない。
- **移動の最中** を、ツリーでの移動の `active` が空でないあいだと、外での移動の参照の更新 (計画を求めてから、編集を当て終えるか断られるまで) のあいだとする。外での移動の参照の更新にも、実行中の記録を足す。
- 移動の最中は、Golem の再読み込みをせず、「移動が終わってから読み込みなおしてください」と通知する。Golem の行のパスを変える操作 (下の「パスを変えたとき」) も、移動の最中は設定に書かず、同じ通知を出し、欄を設定の値に戻す。
- プレビューの HTML とページの画像、`check`、`lint`、`preflight` の結果は、読みなおさない。次のビルドと検査で、新しいバイナリの結果に替わる。
- 走っているビルドや検査は止めない。走っているものは、古いバイナリのまま終わる。

### shem の再読み込み

- shem の行の「再読み込み」は、設定の節を描きなおし、行の版とパスを新しいバイナリのものにする。shem は呼ぶたびに探すので、プロジェクトの接続は変えない。

### パスを変えたとき

- 次のときは、設定に書いた後に、その行の再読み込み (Golem なら Golem の再読み込み) を行う。
  - 「選択」で、Rust の側がパスを設定に書いたとき。
  - 欄にパスを打ち、Rust の側の確かめで書いたとき。確かめで断られたときは、再読み込みしない。
  - 欄の文字を消して、パスを空にしたとき。
  - 「デフォルトに戻す」を押したとき。
- 「デフォルトに戻す」は、欄の文字を消したときと同じ経路 (Rust の側の `set_binary` に空のパスを渡す) で、その行のパスを空にして設定を保存する。`set_binary` は、前後の空白を除いて空のパスを、確かめのダイアログを出さずに受け付ける ([lib.rs:820-835](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/src-tauri/src/lib.rs#L820-L835))。パスが空のときの探し方は今のとおりで、同梱のもの、`~/.local/bin`、Homebrew、PATH の順に探す。

### 知らせ

- 再読み込みを終えたら、「Golem を読み込みなおしました：<版>」(shem では「shem を読み込みなおしました：<版>」) と、時間で消える通知を出す。
- バイナリが見つからないときは、「<名前> が見つかりません」とエラーの通知を出す。プロジェクトの接続は止めたままにし、次に同期が動いたときにつなぎなおしを試す。
- 再読み込みは、アプリケーションを起動しなおさない。開いているタブ、エディタの中身、まだ保存していない変更、下部パネル、設定の画面は、そのまま残す。

### 仕様書

- 仕様書の「Golem と shem」の節に、「選択」「再読み込み」「デフォルトに戻す」を書く。
- 仕様書の「LSP と整形」の節の、接続を止めるときの記述に、Golem の再読み込みで止めてつなぎなおすことを書き足す。

## 実装しないこと

- バイナリのファイルが変わったことを見張り、自動で読み込みなおすこと。
- 再読み込みで、プレビューを作りなおすことと、`check`、`lint`、`preflight` を走らせなおすこと。
- 移動の最中に、再読み込みを待たせておいて、移動の後に行うこと。
- 同梱の Golem と shem を入れなおすこと。

## 不変条件

- I1: Golem の再読み込みの後、再読み込みの前からあったプロジェクトの接続は一つも残らない。
- I2: Golem のバイナリが見つかるとき、Golem の再読み込みが終わった時点で、LSP の対象の文書を開いているプロジェクトには、再読み込みの後に起動したプロジェクトの接続があり、その文書を開いたと送っている。LSP の対象の文書を開いていないプロジェクトには、接続が無い。バイナリが見つからないときは、どのプロジェクトにも接続が無く、エラーの通知を一つ出す。
- I3: Golem の再読み込みは、開いているタブ、文書の中身、保存していない変更を変えない。
- I4: Golem の再読み込みの後、移動後の参照の更新に応じない Golem で外の移動を検出すると、前に同じワークスペースで通知を出していても、もう一度だけ通知を出す。
- I5: shem の再読み込みと、shem の行の「デフォルトに戻す」は、プロジェクトの接続を変えない。
- I6: 移動の最中の Golem の再読み込みと、Golem の行のパスを変える操作は、プロジェクトの接続も設定の `golemPath` も変えない。
- I7: 「デフォルトに戻す」の後、その行の設定のパスは空で、「デフォルトに戻す」は押せない。設定のパスが空の行の「デフォルトに戻す」は、何も変えない。
- I8: 移動の最中でないとき、行のパスを変える操作 (「選択」、欄に打って確かめで書いたとき、欄を空にしたとき、「デフォルトに戻す」) で設定が変わると、その行の再読み込みを一度行う。Golem の行なら Golem の再読み込み、shem の行なら shem の再読み込みである。確かめで断られて設定が変わらないときは、再読み込みしない。
- I9: Golem の再読み込みは、`.gm` のエディタを開いているプロジェクトごとに `golem kinsoku` を一度だけ走らせ、ほかのプロジェクトの残した禁則とぶら下げの値を捨てる。
- I10: 再読み込みが終わると、見つかったバイナリの版を含む情報の通知を一つ出す。見つからないときは、情報の通知を出さず、「<名前> が見つかりません」のエラーの通知を一つ出す。

境界の入力は次のとおりである。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 接続が無い (LSP の対象の文書を開いていない) | 接続は無いまま、通知を出す | I1, I2 |
| 一つのプロジェクトの `.gm` を開いている | その接続が新しくなり、`.gm` を開いたと送る | I1, I2 |
| 二つのプロジェクトの文書を開いている | 二つとも新しくなる | I1, I2 |
| プロジェクトの `.md` だけを開いている | そのプロジェクトの接続が新しくなる | I2 |
| 文書を閉じたプロジェクトに接続が残っている | その接続は捨て、つなぎなおさない | I1, I2 |
| 保存していない変更のあるシートを開いている | 変更はそのまま残る | I3 |
| 前に「対応していません」を出したワークスペースで、再読み込みの後に外で移す | もう一度出す | I4 |
| shem の再読み込み | プロジェクトの接続は同じもの | I5 |
| Golem のバイナリが見つからない | 接続は無い、エラーの通知を一つ、情報の通知は無い | I2, I10 |
| ツリーでの移動の最中に Golem の再読み込みを押す | 接続は同じもの、通知を出す | I6 |
| 外での移動の参照の更新の最中に、Golem の行で「選択」する | `golemPath` も接続も変わらない、通知を出す | I6 |
| パスを指定した Golem の行で「デフォルトに戻す」を押す | パスは空、ボタンは押せない、Golem の再読み込みを一度 | I7, I8 |
| パスを指定した shem の行で「デフォルトに戻す」を押す | パスは空、shem の再読み込みを一度、接続は同じもの | I5, I7, I8 |
| パスが空の行の「デフォルトに戻す」 | 押せない、何も変わらない | I7 |
| 欄にパスを打ち、確かめで断る | 設定も接続も変わらない、再読み込みしない | I8 |
| `.gm` のエディタを開いたプロジェクト一つと、`.md` だけを開いたプロジェクト一つ | `golem kinsoku` は前のプロジェクトだけで一度 | I9 |
| 再読み込みが終わる | 版を含む情報の通知を一つ | I10 |

## 受けいれ条件

- A1: 設定の「Golem と shem」の各行に、「選択」「再読み込み」「デフォルトに戻す」のボタンが並ぶ。パスが空の行では、「デフォルトに戻す」は押せない。
- A2: シートを開いたまま、Golem をビルドして同じパスに入れなおし、「再読み込み」を押すと、行の版が新しくなる。Aleph を起動しなおさずに、開いているシートの診断と色分けが、新しい Golem のものになる。
- A3: 「選択」で別の Golem を選ぶと、同じく新しい Golem の接続に替わる。
- A4: パスを指定した行で「デフォルトに戻す」を押すと、行のパスが空になり、版とパスがデフォルトの探し方で見つかったバイナリ (同梱のものがあれば同梱のもの) になる。
- A5: 再読み込みの前後で、開いているタブと、保存していない変更が残る。

## テスト設計

- I1〜I3、I5、I6、I9、I10 は、TypeScript で、接続を作る関数と止める関数、`golem kinsoku` を走らせる関数、バイナリの情報を返す関数を差しかえて、Golem の再読み込みと shem の再読み込みを確かめる。LSP の対象の文書を開いているプロジェクトと開いていないプロジェクト、`.md` だけを開いているプロジェクト、保存していない変更のある文書、移動の最中の状態 (ツリーでの移動の `active` と、外での移動の実行中の記録)、バイナリが見つからない場合を用意する。
- I4 は、外の移動の処理を、応じない接続で二回 (あいだに再読み込みを挟む) 動かし、通知の数を数える。
- I7 と I8 は、設定の行の処理に、空のパスと空でないパス、確かめで書いた場合と断った場合を与え、「デフォルトに戻す」が押せるか、設定のパス、どの再読み込みを何回行ったかを確かめる。
- テストの名前には、この ADR と不変条件の番号を入れる。
- A1〜A5 は、Tauri のデバッグ版で、Golem をソースからビルドして入れなおして確かめる。

## トレードオフ

- 再読み込みの後、開いているシートの診断と色分けは、新しい接続が初期化を終えるまで消える。古い接続の結果を残すと、新しいバイナリの結果と混ざるためである。
- パスを変えたときにも自動で再読み込みするので、パスを変えた直後は診断がいったん消える。代わりに、古いバイナリと新しいパスが食い違う状態が残らない。
- バイナリのファイルを見張らないので、同じパスに入れなおしたときは、書き手が「再読み込み」を押す必要がある。見張ると、ビルドの途中の半端なファイルで再読み込みが走るおそれがある。
- プレビューと検査の結果は読みなおさないので、次のビルドと検査までは古いバイナリの結果が残る。ビルドと検査は時間がかかるので、押しただけで走らせることを避けた。
- 移動の最中は再読み込みと Golem のパスの変更を断るので、書き手は移動が終わってから押しなおす。移動の計画と当てるあいだに接続が替わることと、古いバイナリと新しいパスが食い違うことを避けた。
