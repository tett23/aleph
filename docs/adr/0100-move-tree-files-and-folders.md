# ADR 0100: ツリーのドラッグでシートとフォルダを移動する

Status: proposed

## 文脈

シートや資料を整理するとき、ツリーから別のフォルダへ直接移したい。
フォルダ自体も、中身を含めて別のフォルダへ移したい。
通常のフォルダの表示は名前順を保ち、同じ階層での手動の並べ替えは追加しない。

## 調査した事項

今の改名処理は、開いている子孫の保存、参照更新の準備、パス変更、タブなどの追従を順に行う。
Rust の `rename_path` は移動先を同じ親に限定し、macOS では既存の項目を置き換えない改名を使う。
ツリーからウィンドウ外へのドラッグは、ポインターが外へ出たときにネイティブのドラッグを始める。
外部からのドロップはコピーであり、内部の移動とは区別が必要である。
根拠は末尾の固定した版のソースに示す。

## 実装すること

### 移動する項目と行き先

ツリーのシート、その他のファイル、通常のフォルダ、プロジェクトフォルダを、一件ずつドラッグして移動する。
フォルダは内部の階層を保って移す。
フォルダまたはプロジェクトの行に落とすとそのフォルダに、ファイルの行に落とすとその親に、ツリーの空白に落とすと現在のワークスペースのルートに移す。
ドラッグ中は行き先を強調し、移動できない行き先は不可の表示にする。

移動では名前を変えない。
同じ親へ落としたときは何もしない。
通常のフォルダは移動後も名前順に表示する。
章の順序は manifest に従い、既存のプロジェクトの表示順の操作は [ADR 0074](0074-reorder-workspace-projects.md) のままとする。
ドラッグで表示順を変える操作は追加しない。

### 範囲と保護

移動元と移動先は同じ登録済みワークスペース内に限る。
登録済みワークスペース自体と、その祖先は移動しない。
フォルダ自身または子孫への移動、シンボリックリンクを経由する移動、同名の項目がある場所への移動を拒む。
判定は画面だけでなく Rust 側でも行い、実際の移動でも上書きを禁止する。
異なるファイルシステムへの移動はコピーと削除に置き換えず、理由を通知して中止する。

同じワークスペース内なら、別プロジェクトへの個別シートやフォルダの移動と、プロジェクト内外をまたぐ移動も受けいれる。
プロジェクトを丸ごと移すときは、別のプロジェクトの中に入れない。
プロジェクトの入れ子は作らず、個別の項目の所属の変更は次の規則で扱う。
プロジェクト直下の `manifest.toml`、`style.toml`、`plot.csv` の単独移動は拒む。
プロジェクトを含む祖先フォルダも、移動後にプロジェクトが入れ子になる場合は拒む。

### プロジェクト境界を越える移動

プロジェクト境界を越えるときは、移動元と移動先の所属を実行前に表示する。
章の登録変更と、移動先のスタイルが適用されて見た目が変わり得ることも示し、確認してから移す。
通常のフォルダの場合は、移動対象の子孫に対して所属を判定する。
プロジェクトを丸ごと移した場合は、そのプロジェクトの所属と内部設定を保つ。

登録済みの章を別のプロジェクトへ移す場合、移動元の manifest からその章を取り除き、移動先の chapters の末尾へ登録する。
移動元に残る章と移動先の既存の章の順序は変えない。
複数の登録済みの章を含むフォルダでは、元の chapters から移動対象だけを残した構造を作り、その順序と入れ子のまとまりを保って末尾へ加える。
パスは新しいプロジェクトからの相対パスに変え、表形式の章の追加属性を保つ。
元の chapters から対象を取り除いた結果、空になった入れ子の配列は取り除く。
すべての章が移った場合は空の chapters を残す。

プロジェクト外へ出す章は、移動元から登録を外す。
未登録の `.gm` やプロジェクト外の `.gm` をプロジェクトへ入れても、自動登録はしない。
これは外部からのコピーと同じで、必要なときに「chapters に追加」で登録する。

開いているシートの所属、Golem LSP の接続、プレビュー、組版設定は移動先で再評価する。
編集内容とノートと目標は新しいパスへ引き継ぐ。
プロジェクトごとに保存するメタデータも移動先の保存領域へ移し、移動元に二重に残さない。
移動先に同じ対象のメタデータがすでにある場合は上書きせず、衝突を示して中止する。

### 保存と参照の追従

開いている移動対象と子孫を保存し、保存が取消または失敗になったら移動しない。
既存の改名で使う参照更新の準備と追従を基に、移動前に次の範囲の更新を準備する。

- プロジェクト内の項目は、Golem LSP が改名の対象とする manifest と原稿内の参照を更新する。プロジェクトをまたぐ場合は移動元と移動先の両方の編集計画を取得し、重複する編集を一度だけ適用する。
- 同じワークスペースの Wiki リンクは、既存のリンク解決規則で移動対象を指すものを更新する。フォルダの場合は子孫のシートを列挙して準備する。移動するシートから外側を指す相対 Wiki リンクも、移動前と同じ対象を指すように更新する。移動後の任意確認にはしない。
- プロジェクト丸ごと、またはその祖先を移す場合、内部のプロジェクト相対参照は変わらないため編集不要とし、外側の Wiki リンクだけを上と同じ規則で更新する。

移動した原稿から動かない画像やシートを指す相対参照も、移動前と同じファイルを指すように更新する。
Golem の参照の解釈と編集計画は Golem に任せ、Aleph にパーサーを複製しない。
新しい所属で許されない参照が生じる場合は、そのパスと理由を示して中止する。
Golem の公開インターフェースで必要な計画を取得できない場合は、実装前に Golem 側の追加契約を別の ADR で定める。

この範囲の索引と編集計画を取得して対象が0件なら、参照編集なしで移動できる。
索引を取得できない場合は0件とは扱わず中止する。
任意の文字列として書かれたパス、ワークスペース外からの参照、上の解決規則が扱わない形式のリンクは更新対象外である。
同じプロジェクト内の章の移動では、manifest の順序を保ってパスを更新する。
タブ、編集対象、ノート、プロットの保存先、プロジェクト一覧も新しいパスに追従する。

参照更新を準備できなければ理由を示し、移動を中止する。
章の登録変更、参照更新、メタデータの引き継ぎを一つの移動計画として事前に検査し、対象への別の移動操作を完了まで開始させない。
ファイルシステムの移動または後続の計画適用が失敗したら、この操作で行った変更を逆順に戻す。
外部操作で変更された内容は巻き戻しで上書きせず、残ったパスを示す。
移動前に完了した保存は、中止しても巻き戻さない。
戻す処理も失敗したときは、失敗したパスを通知し、成功と表示しない。
移動後の通知や接続更新に失敗しても、実際に移った項目を移動前の場所にあるものとして扱わない。

### 既存のドラッグとの関係

内部の移動と、[ADR 0078](0078-accept-drops-on-the-tree.md) の外部からのコピーを、同じパスという理由だけで混同しない。
内部のドラッグ開始時に記録した項目と操作の寿命で識別する。
ウィンドウ外への受け渡しと、画像をエディタへ落として図を挿入する操作は維持する。
一回のドラッグで、内部の移動と外部への受け渡しを重ねて実行しない。
Esc または対象外へのドロップで取り消した場合は、何も移さない。

この ADR は [ADR 0070](0070-rename-sheets-and-folders-from-tree.md) の改名に移動を補い、[ADR 0078](0078-accept-drops-on-the-tree.md) の対象外だった内部の移動を定める。
外部からのコピーの規則は変更しない。

## 実装しないこと

複数項目の一括移動、ワークスペース間の移動、同名のフォルダの統合、ドラッグによる章やフォルダの並べ替えは含めない。

## 不変条件

- I1: 成功した移動では、移動元がなくなり、移動先に同じ名前の項目が一つあり、フォルダ内部の相対パスとファイルの内容が保たれる。ただし準備した参照更新は内容の比較から除く。
- I2: 取消、同じ親、無効な行き先、同名衝突では、移動によるパス変更はなく、参照編集の巻き戻しが成功した場合は移動前の保存を除いてこの操作は内容を変えない。外部操作による変更は比較から除く。
- I3: 移動の前後で既存の他の項目を上書きせず、登録済みワークスペースのパスは変わらない。
- I4: 成功後の開いている対象と子孫のタブと保存先は、新しいパスに対応する。
- I5: 同じプロジェクト内の移動は章の順序と所属を保ち、別プロジェクトへの移動では登録済みの移動対象だけが元の構造と順で移動先の末尾に移り、残る章の順序は変わらない。参照更新を準備できない場合は移動しない。
- I6: 一回のドラッグによる内部移動の実行は一回以下であり、外部ドロップはコピー元を削除しない。
- I7: 移動計画の巻き戻しに失敗した場合は、残ったパス変更、章登録、参照編集、メタデータ変更の対象パスと理由を通知し、移動成功とは表示しない。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| ファイル一つ、空フォルダ、孫を含むフォルダ | それぞれ中身ごと移動 | I1, I4 |
| 同じ親、Esc、ツリー以外へのドロップ | 移動なし | I2 |
| 自分自身、子孫、登録済みルート、シンボリックリンク経由 | 拒否して保持 | I2, I3 |
| 同名項目がある、確認後に同名項目が作られる | 上書きせず失敗 | I2, I3 |
| 章を含むフォルダを同じプロジェクト内へ | manifest の順序を保ってパス更新 | I4, I5 |
| 登録済みの章と未登録シートを含むフォルダを別プロジェクトへ | 登録済みの章だけを移動先の末尾へ登録 | I1, I4, I5 |
| 章のすべてをプロジェクト外へ | 元の chapters は空、移動先では未登録 | I4, I5 |
| 作品を別作品の中へ | 理由を示して拒否 | I2 |
| 移動失敗後にパス、章登録、参照、メタデータを戻せない | 残った変更のパスと理由を通知 | I7 |
| Finder からドロップ | 従来どおりコピー | I6 |

## 受けいれ条件

- A1: シート、資料、空フォルダ、子孫を持つフォルダをドラッグして別のフォルダへ移せる。
- A2: 移動先が強調され、無効な行き先は不可と分かり、取消で内容が変わらない。
- A3: 編集中の子孫を持つフォルダの移動後、同じタブから新しいパスへ保存できる。
- A4: 内部移動、Finder からのコピー、外への受け渡し、画像の挿入がそれぞれ一度だけ動く。
- A5: 別プロジェクトへ章を含むフォルダを移すと、登録、参照、ノート、目標が引き継がれ、既存の章の順序を保つ。

## テスト設計

I1〜I3 は Rust の一時ディレクトリで、境界の表の各入力と同名作成の競合を確かめる。
I4、I5 は TypeScript で保存取消、参照準備失敗、移動失敗、巻き戻し失敗と成功を注入し、タブ、manifest、参照編集の結果を比べる。
I7 は巻き戻しに失敗したパスと通知の対応を確かめる。
I6 は内部操作の識別と終了後の再実行防止を確かめる。
テスト名にはこの ADR と不変条件の番号を入れる。
プロジェクトをまたぐ I5 は、文字列、表形式、入れ子配列の章を混在させ、移動元と移動先の manifest、移動元から外への相対参照、メタデータを照合する。
登録変更後の失敗、パス復元失敗、メタデータ復元失敗と、巻き戻し中の外部編集も注入する。
A1〜A5 は macOS の試験用ワークスペースで、通常フォルダ、プロジェクト、編集済みの子孫を用意し、実際のドラッグで確かめる。

## トレードオフ

プロジェクト境界を越える移動では、ファイルだけでなく章の登録と参照とメタデータも変わる。
事前確認と失敗時の復旧が必要になるが、フォルダを使った作品間の整理を一つの操作で行える。
参照更新なしの移動を許さないため、LSP が利用できないときにはプロジェクト内の整理を待つ必要がある。
