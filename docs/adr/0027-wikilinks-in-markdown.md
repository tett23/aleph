# ADR 0027: Markdown のシートのウィキリンク

ステータス: 採択

## 文脈

Obsidian は、`[[名前]]` の形でシート同士をつなぎ、つながれた側からも、どのシートがそこを指しているか（バックリンク）を一覧できる。
Aleph には、シートのあいだを行き来する手段が、ツリーと検索（[ADR 0015](0015-diagnostics-and-search.md)）しかない。
設定のメモ（人物、場所、用語）と本文の章を行き来しながら書くと、そのたびにツリーを探すことになる。

メンテナーは、Obsidian と Ulysses にあって Aleph にない機能を比べ、ウィキリンクを Markdown のシートにだけ入れるよう求めた（2026-11-07）。
`.gm` は Golem の記法で、`[` で始まる命令を持つので、`.gm` の中には入れない。
ただし、`.gm` はリンクの行き先にはなれる。

今の Aleph の関わる部分は次のとおりである。

- Markdown のプレビュー（[ADR 0010](0010-previews.md)）は、自前の読み方 [`app/md.ts`](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/md.ts) で HTML にする。行内の要素は、文字、コード、強調、斜体、リンク、画像の六つである。同じ読み方を、gm への変換（[ADR 0016](0016-markdown-to-gm.md)）も使う。
- エディタ（[ADR 0019](0019-one-editor-for-both-writing-modes.md)）は、形式ごとの字句の読み方（[`app/ed/lang.ts`](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/ed/lang.ts) の `md`）で色を付け、プラグインの補完の口（[`app/ed/editor.ts`](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/ed/editor.ts) の `EditorPlugin.complete`）を持つ。
- ツリーを読み直すとき、`.gm` と `.md` の最初の見出しを、シートの名前（`ctx.titles`）として読む（[`app/ui/tree.ts`](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/ui/tree.ts)）。
- ファイルの名前を Aleph で変えると、`ctx.onRename` に登録した処理を順に呼ぶ（同じファイル）。

## 実装すること

### 書き方

- `.md` のシートの中で、次の形をウィキリンクとする。
  - `[[行き先]]`
  - `[[行き先|表示する文字]]`
  - `[[行き先#見出し]]`、`[[行き先#見出し|表示する文字]]`
  - `[[#見出し]]`（同じシートの見出し）
- コードのスパンとコードブロックの中、`\[[` のように `\` を前に置いたものは、ウィキリンクにしない。
- 行き先に `]`、`|`、`#` は書けない。行き先と見出しの前後の空白は除く。

### 行き先の決め方

行き先は、そのシートのワークスペースの中の、Aleph がテキストとして開く形式のファイル（[`app/workspace.ts`](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/workspace.ts) の `TEXT_KINDS`）から、次の順で探す。
最初に見つかった段階の候補を使う。

1. **パス**：行き先に `/` を含むか、拡張子が付いているときは、パスとして読む。リンクを書いたシートのディレクトリからの相対パス、次にワークスペースのルートからのパスの順に探す。拡張子がなければ `.md` を補う。
2. **ファイル名**：拡張子を除いたファイル名が行き先と一致するもの。`.md` を `.gm` より先に、ほかの形式をその後に置く。
3. **シートの名前**：Aleph が出すシートの名前（最初の見出し）が行き先と一致するもの。

- 一致は、大文字と小文字を区別し、Unicode の正規化（NFC）をそろえてから比べる。
- 一つの段階に候補が複数あるときは、リンクを書いたシートと同じディレクトリのもの、次にパスの近いもの（共通の祖先までの段数が少ないもの）を選ぶ。それでも決まらなければ、パスの順で最初のものを選び、あいまいであることを情報の診断で出す。
- `#見出し` は、行き先のシートの見出し（`.md` は `#` の行、`.gm` は見出しの行）の文字と一致するものを、上から探す。見つからなければ、シートの先頭を開き、警告の診断を出す。
- 見つからない行き先は、色を変えて示し（後述）、警告の診断を出す。

### リンクの索引とバックリンク

- ワークスペースの `.md` のリンクの索引を持つ。ツリーを読み直すとき（シートの名前を読むのと同じ時）にすべての `.md` を読んで作り、開いているシートは入力が 500 ミリ秒止まったときに、保存したシートは保存したときに直す。
- 右のパネルに「リンク」を足す。開いているシートを指すリンクを持つシート（バックリンク）を、シートごとにリンクのある行の文字とともに並べ、押すとその行を開く。開いているシートが `.md` なら、そのシートから出ているリンクとその行き先（見つからないものを含む）も並べる。`.gm` のシートでは、バックリンクだけを出す。

### エディタ

- 字句の読み方 `md` に、ウィキリンクの字句（`t-wikilink`）を足す。`[[`、`]]`、`|`、`#` は記号の色、行き先は本文と区別できる色にする。
- 行き先が見つからないリンクには、エディタの層（[ADR 0019](0019-one-editor-for-both-writing-modes.md) の `setLayer`）で、見つからないことを示す印（点線の下線）を重ねる。
- ⌘ を押しながらリンクを押すと、行き先を開く（`#見出し` があればその行へ）。見つからない行き先では、「<行き先>.md を作りますか」と確かめ、リンクを書いたシートと同じディレクトリに、`# <行き先>` だけを書いたシートを作って開く。
- `[[` を打つと補完を始める。候補は、ワークスペースのシートのファイル名（拡張子なし）とシートの名前で、打った文字で始まるものを出す。`#` を打った後は、行き先のシートの見出しを出す。候補を選ぶと、行き先の文字と、まだなければ `]]` を入れる。

### プレビュー

- `app/md.ts` の行内の要素に、ウィキリンク（`{ t: "wikilink"; target; heading; text }`）を足す。プレビューでは、表示する文字（なければ行き先、`#見出し` があれば `行き先 > 見出し`）のリンクとして出し、押すと行き先を開く。見つからない行き先は、色を変えて出し、押すとエディタと同じく作るかを確かめる。
- gm への変換（[ADR 0016](0016-markdown-to-gm.md)）では、ウィキリンクは表示する文字だけを残す（Markdown のリンクと同じ扱い）。

### 名前を変えたとき

- `ctx.onRename` に、リンクの書き換えを登録する。名前を変えたファイルを、パスかファイル名で指していたリンク（シートの名前で指していたものは除く）があれば、件数を示して「<n> 件のリンクを書き換えますか」と確かめる。
- 書き換えるときは、パスで指していたリンクは新しいパスに、ファイル名で指していたリンクは新しいファイル名にする。表示する文字と `#見出し` は変えない。開いているシートはエディタの一回の変更として当て（⌘Z で戻せる）、開いていないシートはファイルを書き換える。

## 実装しないこと

- `.gm` の中のウィキリンク。
- リンクのない言及（行き先の名前が本文にリンクなしで出てくる所）の一覧と、グラフの表示。
- ワークスペースをまたぐリンク。
- ブロックへの参照（`[[名前#^id]]`）。
- 埋め込み（`![[名前]]`）。これは [ADR 0029](0029-embeds.md) で決める。
- ホバーでの行き先の中身の表示。

## テスト設計

DOM に触れない部分を関数に分け、`node --test` で確かめる。テストを先に書いて失敗させてから実装する。

- 書き方の読み取り：各形、空白の除き方、コードのスパンとブロックの中で読まないこと、`\[[` を読まないこと、閉じていない `[[`、一行に複数のリンク、日本語とサロゲートペアを含む行き先、それぞれのリンクの位置（UTF-16）。
- 行き先の決め方：パス（相対、ルートから、拡張子の補い）、ファイル名（`.md` が `.gm` より先）、シートの名前、段階の順、同じディレクトリと近いパスの選び方、あいまいなときの選び方と診断、正規化（NFC と NFD の同じ名前）、見つからないとき。見出しの照合（`.md` と `.gm`、見つからないとき）。
- 索引とバックリンク：シートの追加、リンクの変更、シートの削除で、バックリンクの一覧が変わること。
- 補完：`[[` の後の候補、打った文字での絞り込み、`#` の後の見出しの候補、`]]` を二重に入れないこと。
- 名前を変えたときの書き換え：パスとファイル名で指していたリンクだけが書き換わり、表示する文字と見出しが残り、シートの名前で指していたリンクが変わらないこと。
- 字句の読み方：`t-wikilink` の範囲と、記号の範囲。
- プレビュー：`parseInline` がウィキリンクを読み、`markdownHtml` が行き先を持つリンクを出すこと。gm への変換が表示する文字だけを残すこと。
- 画面の確かめ方：見本のワークスペースに人物のメモ（`.md`）と章（`.gm`）を置き、⌘ を押しながらの押下で開くこと、`#見出し` の行に移ること、見つからない行き先で作るかを確かめること、補完、右のパネルの「リンク」、プレビューのリンク、名前を変えたときの確かめと書き換え（⌘Z で戻ること）を確かめる。

## トレードオフ

- `.md` だけに入れるので、本文の `.gm` から設定のメモへは、リンクで行けない。`.gm` から `.md` へのリンクは、Golem の記法に何かを足すことになり、Golem の側の決めごとなので、ここでは扱わない。
- 行き先をシートの名前でも探すので、ファイル名を知らなくても書けるが、見出しを変えるとリンクが切れることがある。名前を変えたときの書き換えは、ファイル名とパスで指したリンクにしか効かない。
- 索引のために、ツリーを読み直すたびにワークスペースのすべての `.md` を読む。シートの名前を読むために、すでに `.gm` と `.md` を読んでいるので、同じ時に済ませる。
