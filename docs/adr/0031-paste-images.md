# ADR 0031: クリップボードの画像を貼り付けて添付する

ステータス: 採択

## 文脈

Aleph で原稿に画像を入れる方法は、Finder からのドロップ（[ADR 0014](0014-shared-library-and-assets.md)）と、ツリーの画像のドラッグ（[ADR 0018](0018-drag-image-from-tree.md)）の二つである。
どちらも、画像がファイルとしてどこかにあることを前提にする。
スクリーンショットや、ほかのアプリでコピーした画像のように、クリップボードにしかない画像は、一度ファイルに書き出してからでないと入れられない。

Obsidian は、クリップボードの画像を貼り付けると、添付のファイルとして保存し、その参照を本文に入れる。
メンテナーから、Obsidian と Ulysses にあって Aleph にない機能を比べたうえで、画像を貼り付けて添付する機能の ADR を作るよう求められた（2026-11-07）。

エディタの貼り付けは、`beforeinput` の `insertFromPaste` で受け、`dataTransfer` の `text/plain` を文書に当てている（[app/ed/view.ts](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/ed/view.ts#L399-L408)、[app/ed/input.ts](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/ed/input.ts#L38-L41)）。
ブラウザは、`beforeinput` の前に `paste` イベントを送り、その `clipboardData` の `items` と `files` で、クリップボードの画像を `File` として渡す。
`paste` イベントで既定の動きを止めると、`beforeinput` は届かない。
この二つは、Tauri の WebView（WebKit）で実装の前に確かめる（テスト設計の画面の確かめ方）。

`@figure` の行を差し込む処理と、名前の衝突を避ける処理は、すでにある（[app/library.ts](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/library.ts#L93-L130) の `freeName`、`figureInsert`）。

## 実装すること

- エディタの `paste` イベントで、クリップボードの中身を調べる。`text/plain` が空で、画像（`type` が `image/` で始まる `File`）が一つ以上あるときだけ、画像の貼り付けとして扱い、既定の動きを止める。文字があるとき（ウェブのページから文と画像をまとめてコピーしたときなど）は、今までどおり文字だけを貼り付ける。
- 画像のファイルの形式は、`image/png` は PNG、`image/jpeg` は JPEG のまま書く。そのほかの形式（TIFF、GIF、WebP など）は、`createImageBitmap` と `canvas` で PNG に直して書く。`@figure` が受ける形式（PNG、JPEG、SVG、PDF）に合わせるためである。
- ファイルの名前は `pasted-YYYYMMDD-HHMMSS.png`（`.jpg`）とし、日時は貼り付けたときの手元の時刻とする。同じ名前があれば、[ADR 0014](0014-shared-library-and-assets.md) と同じく `-2`、`-3` を付けて上書きしない。一度に複数の画像があれば、すべて書き、名前は同じ規則で重ならないようにする。
- `.gm` のシート：
  - プロジェクトの中の章なら、プロジェクトの `images/` に書き、カーソルのある行の後に、`figureInsert` で `@figure images/<名前> alt="<名前>"` と字下げしたキャプションの行を差し込む。
  - プロジェクトの外の `.gm` には差し込まず、「Golem のプロジェクトの章に貼り付けられます」と知らせる（[ADR 0018](0018-drag-image-from-tree.md) と同じ扱い）。
- `.md` のシート：シートのディレクトリの `images/` に書き、カーソルのある行の後に、`![<名前>](images/<名前>)` の行を、前後を空行で区切って差し込む。
- 差し込みは一回の変更として当て、⌘Z で一度に戻せる。⌘Z で戻しても、書いた画像のファイルは消さない。
- 縦書きと横書きの両方で、同じように動く（[ADR 0019](0019-one-editor-for-both-writing-modes.md)）。
- 画像を書いたら、ツリーを読み直して、`images/` の新しいファイルを出す。通知で「images/ に保存し、@figure を差し込みました」（`.md` では「画像を差し込みました」）と知らせる。
- `.gm` と `.md` でないシートに画像を貼り付けたときは、何もせず、「画像を貼り付けられるのは .gm と .md のシートです」と知らせる。

## 実装しないこと

- 画像の縮小、切り抜き、形式の選択。
- 貼り付けた画像の保存先や名前の付け方を、設定で変えること。
- ⌘Z で戻したときや、`@figure` の行を消したときに、使われなくなった画像を消すこと。
- `.txt`、`.toml` などへの画像の参照の差し込み。
- Finder でコピーしたファイル（ファイルの参照としてのコピー）を、そのファイルのコピーとして扱うこと。WebView が `File` として画像を渡す場合は、上の規則で新しい名前で書く。

## テスト設計

DOM に触れない部分を関数に分け、`node --test` で先に書いて失敗させてから実装する。

- 貼り付けの振り分け：クリップボードの中身（`text/plain` の文字と、`File` の `type` の並び）から、「文字」「画像」「何もしない」を決める関数。文字だけ、画像だけ、文字と画像の両方、画像でないファイルだけ、空のとき。
- 名前：日時から `pasted-YYYYMMDD-HHMMSS.png` を作る関数（月日時分秒の 0 埋め）、`image/png` と `image/jpeg` の拡張子、そのほかの形式を PNG に直すかの判定。複数の画像で名前が重ならないこと（`freeName` のテストの形で、すでにある名前を与えて確かめる）。
- 差し込み：`.gm` では既存の `figureInsert` のテストで足りる。`.md` の差し込み（空の行、文字のある行、文書の末尾の後）を確かめる関数を足す。
- 置き場所：シートのパスとプロジェクトの一覧から、書くディレクトリと参照のパスを決める関数（プロジェクトの中の `.gm`、プロジェクトの外の `.gm`、プロジェクトの中と外の `.md`）。
- 画面の確かめ方：スクリーンショットを ⌘⌃⇧4 でクリップボードに取り、横書きと縦書きの `.gm` の章、`.md` のシートに ⌘V で貼り付ける。`images/` にファイルができ、ツリーに出て、`@figure`（`.md` では画像のリンク）が入り、⌘Z で一度に戻ること。ウェブのページから文と画像をコピーしたときは、文字だけが入ること。

## トレードオフ

- 文字と画像の両方があるときは文字を優先するので、ウェブのページの画像だけを入れたいときは、画像だけをコピーし直す必要がある。誤って画像のファイルができるより、文字が入るほうが戻しやすい。
- ⌘Z で画像のファイルを消さないので、使われない画像が `images/` に残ることがある。書いたファイルを消す処理は、取り消しとやり直しのたびにファイルを消したり書いたりすることになり、失う危険がある。残った画像は、ツリーから消せばよい。
- 日時の名前は中身を表さないので、あとで名前を変えたくなることがある。名前を聞くと貼り付けの流れが止まるため、まず保存し、名前はツリーで変える。
