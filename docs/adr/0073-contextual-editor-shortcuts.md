# ADR 0073: ショートカットにコンテキストを指定し、Ctrl+E で補完を閉じるか行末に移る

ステータス: 採択（未実装）

## 文脈

原稿の入力中に出る補完候補の一覧を、ここでは「サジェスト」と呼ぶ。
候補を採用せずに入力を続けたいとき、書き手は Esc と Ctrl+E のどちらでも一覧を閉じたい。
一覧が閉じているときは、同じ Ctrl+E で現在の行の末尾へ移りたい。
ほかの操作と同じように、一方だけを残したり、別のキーを追加したりできるようにする。

## 調査した事項

[ADR 0034](0034-key-bindings.md) は、一つの操作に複数のショートカットを割り当てる仕様をすでに定めている。
設定画面は各割り当てを個別に表示し、「＋」で追加し、「×」で一件ずつ外す。
現在のエディタでは Esc が補完、ホバー、検索の順に閉じる対象を探すが、この処理には設定用の操作識別子がない。
また、設定の記録中は Esc が取消を表し、設定の読み込みでは修飾キーのない Escape を先頭に持つ利用者の割り当てを除外する。

現在のキー処理は、エディタにフォーカスがあるかと操作の実行条件で候補を絞る。
設定画面の競合判定は、割り当て先の操作名と打鍵の並びを比較し、サジェストの表示状態を区別しない。

## 実装すること

### Ctrl+E と Esc の既定の動作

設定の「キーの割り当て」に「サジェストを閉じる」（`editor.dismissCompletion`）を登録する。
既定値は `["Escape", "Ctrl-e"]` とする。
各要素が独立したショートカットで、どちらか一回の打鍵で同じ操作を呼ぶ。
Ctrl は macOS の Control キーを指す。

操作は、フォーカスのあるエディタにサジェストが開いている間だけ有効にする。
候補を選択中でも、閉じたときは本文、選択範囲、キャレットを保つ。
閉じる前に開始した補完の遅延処理や応答で一覧が再表示されることを防ぎ、次の入力や明示的な補完要求から再び候補を出す。
一覧が閉じているときは、この操作は打鍵を消費しない。
一覧が閉じているときの Ctrl+E はエディタの「行末に移動」（`editor.moveToLineEnd`）に割り当てる。
行末はキャレットがある論理行の改行直前とし、最終行では文書末尾とする。
折り返しと縦書きでも同じ位置に移る。
範囲選択がある場合は選択の移動端がある行の末尾に選択を畳む。
一覧が閉じているときの Esc は、ホバーや検索を閉じる既存の処理へ渡る。
IME の変換中は IME を優先し、複数打鍵の続き待ちでの Esc は [ADR 0034](0034-key-bindings.md) のとおり待機の取消に使う。

| フォーカスとサジェストの状態 | Ctrl+E | Esc |
| --- | --- | --- |
| 本文エディタ、表示中 | 候補を採用せず閉じ、キャレットを保つ | 同じ |
| 本文エディタ、非表示 | 行末に移動する | ホバーや検索の既存の処理へ渡す |
| 設定画面の入力欄など、本文エディタの外 | 入力先の処理へ渡す | 入力先の処理へ渡す |

### 割り当てごとのコンテキスト

設定の各ショートカットに、どこで有効かを示すコンテキストを表示する。
追加や編集では「操作の有効範囲全体」「エディタ」「サジェスト表示中」「サジェスト非表示」を選べる。
後の二つはフォーカス中の本文エディタの状態を指す。
実際にキーを引く範囲は、操作自体の実行条件と、割り当てに指定したコンテキストの両方を満たす範囲とする。
設定画面では、その操作の実行条件と重なる範囲だけを選べる。
たとえば閉じる操作には「サジェスト非表示」を指定できない。
行末移動の操作自体は、本文エディタにフォーカスがあれば実行できる。
その既定の Ctrl+E に「サジェスト非表示」を指定する。

同じ打鍵でも有効範囲が交わらない二つの割り当ては併存できる。
範囲が交わる場合だけ、同一キーの置き換え確認と先頭が重なる並びの警告を従来どおり行う。
たとえば「エディタ」は「サジェスト表示中」を含むが、「表示中」と「非表示」は重ならない。
打鍵の処理を始めた時点の状態で操作を一度だけ選ぶ。
Ctrl+E で一覧を閉じた直後に、同じイベントが行末移動に使われることを防ぐ。
続けて押すキーの待機中にフォーカスや表示状態が変わったら、有効範囲を外れた候補を除き、候補が空なら待機を取り消す。

### 設定の保存と復元

複数割り当てには既存の設定画面と `keyBindings` の配列を使う。
キー単位の追加・削除、競合の確認、すべて外した空配列、既定に戻す操作をこのコマンドにも適用する。
既存の文字列は「操作の有効範囲全体」として読み込む。
範囲を指定した項目は、たとえば `{"key":"Ctrl-e","context":"completionHidden"}` の形で同じ配列に保存する。
指定できる値は `editor`、`completionVisible`、`completionHidden` とし、未対応の条件を含む項目は読み飛ばす。
既定のキーを別の操作に割り当て済みの設定を読み込んだときは、範囲が交わる間は利用者の設定を優先する。
特に、閉じる操作から Ctrl+E だけを削除して保存した場合は、再起動後も Esc のみが有効でなければならない。
Esc の削除後に他のカスタム割り当てを残して再追加できるよう、この操作の設定行に Esc を直接追加する選択肢を設ける。
記録中の Esc は引き続き取消として扱う。
この操作の単独の Escape を設定の読み込みでも受け入れる。
外された Esc で一覧が閉じる抜け道が残らないよう、エディタの固定キー処理から補完を閉じる分岐を外す。

## 実装しないこと

コマンドパレットやクイックオープンの候補一覧、OS の日本語入力候補のショートカット変更。

## 不変条件

1. 既定設定で一覧を開き、IME 変換中でも打鍵の続き待ちでもないとき、Esc と Ctrl+E はそれぞれ一回で候補を採用せず一覧を閉じる。
2. 設定を保存して読み直した後も、各ショートカットの有効・無効は読み直す前と一致する。一つを外しても残りは有効である。
3. サジェストを閉じる操作は一覧がないときや IME 変換中にキーを消費しない。
4. 一覧を閉じてから次の補完要求まで、閉じる前に予約または送信した要求による候補は表示されない。
5. 既定の Ctrl+E を二回押すと、一覧が開いていれば一回目で閉じ、二回目で行末に移る。どちらの打鍵でも本文は変化しない。
6. 同じキーや先頭が重なる並びは、有効範囲が交わるときだけ競合判定の対象になる。

| 境界の入力 | 期待する結果 |
| --- | --- |
| 既定の二件、候補が一件または複数件 | Esc と Ctrl+E のどちらでも、本文とキャレットを保って閉じる |
| Esc のみ、Ctrl+E のみ、割り当てなし | 再起動後も残したキーだけが一覧を閉じる |
| 第三のキーを追加し、Esc を削除して再追加 | 三件とも一打鍵の独立した割り当てとして働く（第三のキーも一打鍵の場合） |
| すべて外してから「既定に戻す」 | Esc と Ctrl+E が両方戻る |
| 候補ゼロ、IME 変換中、打鍵の続き待ちでの Esc | 候補なしでは閉じる操作は無効。IME と待機取消はそれぞれ優先される |
| 一覧を開き行の途中で Ctrl+E を二回 | 一回目は位置を保ち、二回目で行末へ移る |
| 一覧なし、空行またはすでに行末 | Ctrl+E で次の行に移らない |
| 折り返した最終行の途中 | Ctrl+E で文書末尾へ移る |
| 閉じた直後に古い補完応答が届く | 一覧は閉じたまま |

## テスト設計

条件 1 と 3 は実際のエディタのキー処理に打鍵を渡し、一覧、イベントの消費、本文と選択範囲を確認する。
条件 2 は設定画面の追加、削除、既定復元と同じ処理を通し、設定を読み直して双方のキーを試す。
別の操作に追加キーが割り当て済みなら、置き換えを取り消して両方の割り当てが元どおりであることも確かめる。
条件 4 は候補表示中に二回目の補完を予約または送信し、閉じてからタイマーを進め、応答を返す。
条件 5 は横書きと縦書き、逆方向の範囲選択、本文外の入力欄でも同じキーを試し、実行回数と位置を確かめる。
条件 6 は表示中と非表示への割り当てが確認なしに保存できること、範囲を「エディタ」に広げると競合が示されることを確かめる。
各テスト名に不変条件の番号を入れる。

## トレードオフ

一覧が表示されている間は Ctrl+E を閉じる操作が使う。
一覧が開いている間も行末に移りたい書き手は、閉じる操作から Ctrl+E を外し、行末移動の Ctrl+E の範囲を「エディタ」に広げられる。
Esc を設定画面から直接追加する手段を一つ設けることで、他の割り当てを保ったまま Esc を戻せる。
