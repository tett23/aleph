# ADR 0088: 差分のタブと、アシスタントの書き換えを適用する前のコミット

Status: accepted

## 文脈

[ADR 0081](0081-assistant-with-local-llm-and-connectors.md) のアシスタントは、書き換えの案を出し、書き手が「適用」を押したときだけ原稿を変える。
しかし、ローカルの小さなモデルの案は、正しくないことも、原稿を壊すこともある。
アシスタントの計測 ([2026-11-18 の調査](../research/2026-11-18-assistant-prompt-and-context.md)) では、計測した二つのモデルは、どの渡し方でも選び方の決まりを満たさなかった。
適用の取り消しは ⌘Z でできるが、ほかの編集と混ざると、どこまで戻せばよいかが分からなくなる。

メンテナーは、次の二つを求めた (2026-11-18)。

- LLM による書き換えを適用する前に、一度コミットするよう促すダイアログを出す。このダイアログは、答えるまで画面のほかの操作を止めるモーダルでよい。コミットするかどうかを決めないと、書き換えの作業を先に進められないためである。
- 書き換えた後に、差分をまとめて見せる。書き手の多くは `git status` や `git diff` を使えないので、この機能はいつでも使えるようにする。リボンに差分の一覧のボタンを足し、専用のタブで見せる。

メンテナーは、同じ日に次のことを決めた。

- ダイアログは、「適用」を押したときに、ワークスペースにコミットしていない変更があるときだけ出す。
- 差分のタブは、最後のコミット (`HEAD`) との差分を出す。
- 差分のタブでできることは、差分を見ることと、ファイルを開くことだけとする。コミットや元に戻すことは、今の Git のパネルに任せる。
- [画面のモック](../research/2026-11-18-diff-tab-mock.svg) の形でよい。

ファイルでないタブの形は、プレビューのタブ ([ADR 0087](0087-preview-in-a-tab.md)) で作った。
この ADR は、二つ目のファイルでないタブとして、差分のタブを足す。

## 調査した事項

この節には、コードを読んで確かめたことと、使い捨てのリポジトリで Git (2.56.0) を動かして確かめたことだけを書く。
コードは、main のコミット [0c45fba](https://github.com/tett23/aleph/tree/0c45fbab24114a7483580bdf9314f1eb2af872b2) のものである。

### アプリのコード

- アシスタントの「適用」は、まだ無い。アプリの側には、案を当てる純粋な関数 (`app/assistant/edits.ts`) と、資料の選び方 (`app/assistant/material.ts`) だけがある。
- Git のパネル ([`app/gitpanel.ts`](https://github.com/tett23/aleph/blob/0c45fbab24114a7483580bdf9314f1eb2af872b2/app/gitpanel.ts)) は、ワークスペースを作業のフォルダにして `git status --porcelain=v1 -z -uall` で変更のあるファイルを読み、選んだ一つのファイルの `git diff HEAD -- <file>` を、行頭の `+` と `-` に色を付けて出す。リポジトリでなければ `git init` のボタンを出す ([ADR 0011](0011-saving-and-git.md)、[ADR 0051](0051-git-init-and-the-pages-window.md))。ワークスペースが無いときは「ワークスペースがありません。」と出す。
- 同じファイルの `commit` は、開いているシートをすべて保存してから、`git add -A` と `git commit -m <メッセージ>` を走らせ、失敗すれば通知を出して `false` を返す。
- Git が無いときは、Git の機能を止める ([ADR 0060](0060-when-git-is-missing.md))。Git の呼び出しは、許可したサブコマンドだけを、メインスレッドの外で走らせる ([ADR 0042](0042-ipc-trust-boundary.md)、[ADR 0062](0062-run-programs-off-the-main-thread.md))。`diff`、`status`、`rev-parse` は許可されている。Rust の側は、`diff` に `--no-ext-diff` を足す ([ADR 0046](0046-safe-automatic-git.md))。
- 選択のダイアログ (`app/ui/dom.ts` の `choiceDialog`) は、画面全体を覆う `.dim` の上に出し、ポインタの操作を背面に通さない。キーの入力を止める仕組み (`inert` やフォーカスの閉じ込め) は無く、ボタンは焦点を受けない `span` である。
- キーの割り当ては、`window` の `keydown` で受けてコマンドを走らせ、イベントの的を見ない (`app/keybind.ts`)。コマンドパレットは、開くときに `document.body` に足す。
- タブは `{ id, open, focus, plot, preview }` の形である ([`app/store.ts`](https://github.com/tett23/aleph/blob/0c45fbab24114a7483580bdf9314f1eb2af872b2/app/store.ts))。映すタブの決め方は、シートを持つタブだけを数える (`isSheetTab`)。プレビューのタブを選んでいるときにシートを開くと、プレビューのタブは残り、映すタブの中身を入れ替える (`place`)。ほかのタブを選んでいるときは、そのタブの中身を入れ替える。
- 開いているシートが保存されていないかは、`dirty` で分かる。シートは、ワークスペースか共有ライブラリのものである (`Doc.workspace`)。
- リボンのボタンは、`app/ui/shell.ts` の `RIBBON` に並べる。サイドバーのパネルを切り替えるもののほかに、タブを開く「プロット」があり、プロットのタブを選んでいるあいだ印 (`on`) が付く。アイコンは、`app/icons/` に置いた lucide の SVG である。

### Git の振る舞い

- ワークスペースがリポジトリの下のフォルダのとき、そのフォルダを作業のフォルダにした `git status --porcelain=v1 -z -uall` は、ワークスペースの外の変更も、リポジトリのルートからのパスで返す。`-- .` を付けると、ワークスペースの中だけを返す。リポジトリのルートからのパスを `git diff HEAD -- <path>` にそのまま渡すと、差分は空になる。`git add -A` は、ワークスペースの外の変更もステージする。
- 名前を変えたファイルは `R` で、新しいパスと前のパスを返す。競合は `UU` である。
- コミットが一つも無いリポジトリでは、`git diff HEAD` は `fatal: bad revision 'HEAD'` で終了の状態 128 になる。
- 追跡していないファイルの差分は、`git diff --no-index --no-color -- /dev/null <path>` で取れ、終了の状態は 1 になる。
- パスに `[` や `*` があると、`git diff` はそれを型として読み、ほかのファイルの差分も返す。`:(literal)` を付けると、その一つだけを返す。

## 実装すること

### 差分のタブ

- タブの種類に、**差分のタブ**を足す。`Tab` に `diff: boolean` を足し、`diff` が `true` のタブを差分のタブと呼ぶ。差分のタブは、シートを持たない (`open` は空、`plot` は `null`、`preview` は `false`)。
- 差分のタブは、ウィンドウの中で多くとも一つとする。題は「差分」とする。
- 差分のタブは、今のワークスペースの中の、最後のコミットとの差分を出す。
  - 見出しに、ワークスペースの名前、「HEAD との差分」、変更のあるファイルの数、「再読み込み」のボタンを出す。
  - ワークスペースのリポジトリの中での位置を `git rev-parse --show-prefix` で読み、`git status --porcelain=v1 -z -uall -- .` でワークスペースの中の変更だけを読む。パスは、位置を除いた、ワークスペースからのパスにする。
  - ファイルを `git status` の順に並べる。ファイルごとに、ワークスペースからのパス、変更の種類、足した行と除いた行の数を出し、その下に差分を出す。
  - 変更の種類は、`git status` の二字 (XY) から次のとおりに決める。上から順に当て、最初に当たったものとする。X か Y が `U` のものと `AA`、`DD` は「競合」、`??` と、X か Y が `A` のものは「追加」、X か Y が `D` のものは「削除」、X か Y が `R` のものは「名前の変更」、それ以外は「変更」とする。
  - 差分は、パスに `:(literal)` を付けて読む。追跡しているファイルは `git diff HEAD --no-color -- <path>`、名前を変えたファイルは `git diff HEAD --no-color -M -- <前のパス> <新しいパス>`、追跡していないファイルは `git diff --no-index --no-color -- /dev/null <path>` で読む。
  - コミットが一つも無いとき (`git rev-parse --verify HEAD` が失敗するとき) は、見出しに「コミットはまだありません」と出し、すべてのファイルを、追跡していないファイルと同じく足した行として出す。
  - 差分の出力のうち、初めの `@@` より前の行は見出しとして出さず、数えない。`@@` の行とその後の行を出し、`@@` の後の行の行頭の一字 (`+`、`-`) で足した行と除いた行を数え、色を付ける。数は、下の上限で切る前の全体の数とする。
  - 出力が `Binary files` の行を持つファイルは、「バイナリ」とだけ出す。`git status` がフォルダとして返したもの (入れ子のリポジトリ) は、「フォルダ」とだけ出す。差分が空のものは、「差分はありません」と出す。
  - 一つのファイルで出す行は、`@@` の行を含めて 2,000 行までとし、超えたら「ほか N 行」と添える。並べるファイルは 200 までとし、超えたら「ほか N ファイル」と添える。
  - 変更が無いときは「HEAD との差分はありません」と出す。
  - ワークスペースが Git のリポジトリでないときと、Git が無いときは、そのことを一行で出す。`git init` のボタンは出さない (Git のパネルに任せる)。
- ファイルの名前を押すと、そのシートを開く。開き方は、ツリーで押したときと同じとする (下の「差分のタブを選んでいるときに開くこと」)。削除したファイルと、フォルダとして出したものの名前は押せない。
- 差分のタブは、それを持つペインで選ばれたとき、「再読み込み」を押したとき、それを持つペインで選ばれているあいだに Git の状態が変わったとき (保存、コミット、FSEvents の知らせ、[ADR 0063](0063-watch-files-changed-outside.md)) に読み直す。それを持つペインで選ばれていないあいだは読まない。
- 読み直しでは、ファイルの差分を、同時に多くとも四つまで読む。前の読み直しが終わる前に次の読み直しを始めたら、前の結果は捨てる。
- 差分のタブは、コミットも、元に戻すことも、差分の一部を選ぶこともしない。

### 開くこと

- リボンに「差分」のボタンを足す。アイコンは lucide の `git-compare` とし、`app/icons/` に足す。置く場所は「Git」の次とする。差分のタブを選んでいるあいだ、ボタンに印 (`on`) を付ける。
- コマンド `view.diff` (「差分」) を足す。リボンのボタンは、このコマンドを走らせる。`view.diff` は、ワークスペースがあるときに使える。
- `view.diff` は、次のとおりに差分のタブを出す。
  - 差分のタブがあれば、それを持つペインを選び、そのペインの選んでいるタブにする。
  - 差分のタブが無ければ、選んでいるペインの、選んでいるタブの次に開いて選ぶ。ペインにタブが無ければ、そのペインに開く。
- 差分のタブは、ほかのタブと同じく、閉じられ、ドラッグでもう一方のペインに移せる。
- 差分のタブは、映すタブ ([ADR 0087](0087-preview-in-a-tab.md)) にならない。差分のタブを選んでいるあいだ、ツールバー、右サイドバー、ステータスバーは、プロットのタブを選んでいるときと同じく、映すタブに従う (`shown(s)`)。
- タブの並びに `{ "diff": true }` として残し、戻す。二つ以上あれば、最初のもの (左のペインから、ペインの中では左から) だけを戻す。

### 差分のタブを選んでいるときに開くこと

- 差分のタブを選んでいるときにシートかプロットを開いても、差分のタブは残る。開く先は、[ADR 0087](0087-preview-in-a-tab.md) の「プレビューのタブを選んでいるときに開くこと」と同じとし、プレビューのタブを差分のタブと読みかえる。そのため、差分のタブのファイルの名前を続けて押すと、映すタブの中身が順に入れ替わり、差分のタブは残る。

### 適用の前のダイアログ

- アシスタントの「適用」を押したら、まず、案が今のテキストに当てられるかを [ADR 0081](0081-assistant-with-local-llm-and-connectors.md) のとおり確かめる。当てられなければ、ダイアログを出さず、今のとおり理由を示す。
- 当てられるなら、**適用の前の判定**で、次のどれにするかを決める。判定は、Git が使えるか、ワークスペースがリポジトリか、対象のシートがワークスペースの中か、コミットしていない変更があるかを受ける純粋な関数とする。
  - Git が使えて、ワークスペースがリポジトリで、対象のシートがワークスペースの中で、コミットしていない変更があるときは、**コミットを促すダイアログ**を出す。
  - 同じく、コミットしていない変更が無いときは、ダイアログを出さずに適用する。
  - それ以外 (Git が無い、リポジトリでない、`git status` が失敗した、対象のシートが共有ライブラリにある) は、**戻せないことを知らせるダイアログ**を出す。
- **コミットしていない変更がある**とは、そのワークスペースの、保存していないシートがあるか、`git status --porcelain=v1 -z -uall -- .` が一つ以上の項目を返すことである。これも、保存していないシートの数と `git status` の項目の数を受ける純粋な関数で決める。
- コミットを促すダイアログは、題「適用する前に、コミットしますか？」、本文 (コミットしていない変更があること、書き換えは正しくないことや壊れることがあること、コミットしておくと書き換えの分だけを差分で見て戻せること) と、「やめる」「コミットせずに適用」「コミットして適用」の三つのボタンを持つ。「コミットして適用」を主のボタンにする。
  - 「コミットして適用」を押したら、ダイアログを閉じてから、そのワークスペースの開いているシートを保存し、`git add -A -- .` と `git commit -m <メッセージ>` でコミットする。メッセージは `Before the assistant's edit YYYY-MM-DD HH:MM` (書き手の地域の時刻) とし、時刻からメッセージを作る純粋な関数で作る。コミットに失敗したら、適用せず、通知を出す。コミットの後に、案が当てられるかをもう一度確かめてから適用する。
  - 「コミットせずに適用」は、そのまま適用する。
  - 「やめる」、ダイアログの外を押すこと、Esc は、適用しない。案は残る。
- 戻せないことを知らせるダイアログは、題「このワークスペースでは、書き換えを Git で戻せません」、本文 (取り消し ⌘Z のほかに戻す方法が無いこと)、「やめる」「適用」の二つのボタンを持つ。
- どちらのダイアログも、モーダルとする。
  - 出ているあいだは、画面の状態に「モーダル中」の印を立て、キーの割り当て (`dispatchKey`) はコマンドを走らせない。コマンドパレットも開かない。
  - ダイアログのほかの、`body` の直下の要素に `inert` を付け、ポインタと焦点を背面に届かせない。閉じたら、付けた `inert` だけを外し、印を下ろす。
  - ボタンは焦点を受ける要素にする。開いたときに焦点を主のボタンに置き、Tab と ⇧Tab はダイアログの中で回り、Enter は焦点のあるボタンを押し、Esc は「やめる」と同じにする。閉じたら、開く前に焦点のあった要素に焦点を戻す。
- この判定とダイアログは、アシスタントの「適用」の前に呼ぶ関数として作る。「適用」のボタンは [ADR 0081](0081-assistant-with-local-llm-and-connectors.md) のアシスタントのタブとともに作るので、ボタンにつなぐのは、そのときとする。

### 適用の後に差分を見せること

- 適用は、エディタの今の文書を変える。差分のタブは保存したファイルと `HEAD` を比べるので、適用した後に、適用したシートを保存する。これは、[ADR 0081](0081-assistant-with-local-llm-and-connectors.md) の「保存は今までどおり書き手が行う」を置き換える。
- 保存した後、Git が使えて、ワークスペースがリポジトリなら、差分のタブを、書き換えたシートを隠さない側に出す。選んでいるペインは、どの場合も変えない。
  - 差分のタブが選んでいないペインにあれば、そのペインで選ぶ。
  - 差分のタブが選んでいるペインにあれば、もう一方のペインの末尾に移して選ぶ。ペインが一つなら、右に新しいペインを作って移す。差分のタブがそのペインのただ一つのタブなら、移さずに選ぶ。
  - 差分のタブが無ければ、ペインが一つなら右に新しいペインを作り、ペインが二つなら選んでいないペインの末尾に開いて選ぶ。
- これも、[ADR 0081](0081-assistant-with-local-llm-and-connectors.md) のアシスタントのタブとともにつなぐ。この ADR では、差分のタブを出す画面の状態の操作 (`showDiffAfterApply`) までを作る。

### 文書

- 仕様書に、差分のタブ、リボンの「差分」、適用の前のダイアログと適用の後の差分 (アシスタントの実装を待つこと) を書く。
- 用語集の「映すタブ」の行の次に、次の行を足す。用語集のテストの名前の列の決まり ([ADR 0087](0087-preview-in-a-tab.md) I7) は、この行を足したものに置き換える。

| 正式な名前 | 英語の名前 | 指すもの | 画面の文字 | コードの名前 | 前のコードの名前 | 前の呼び名 |
| --- | --- | --- | --- | --- | --- | --- |
| 差分のタブ | Diff tab | ペインのタブの一つ。ワークスペースの、最後のコミットとの差分を出す | 「差分」 | `Tab.diff`、`view.diff` | (無し) | (無し) |

- README は変えない。README には、Git の機能の記述が無い。
- 採択した後、次の ADR のステータスの変更の配列に、この ADR を足す。
  - [ADR 0081](0081-assistant-with-local-llm-and-connectors.md): 「アシスタントの役割 の、保存は今までどおり書き手が行うこと」の置き換えと、「アシスタントの役割 の、適用の前のダイアログと適用の後の差分」の補足 (`"kind":"supplement"`)。
  - [ADR 0087](0087-preview-in-a-tab.md): 「不変条件 I7」の置き換え。
- リボン、コマンド、タブの種類に足すことは、足すだけで元の ADR の決まりを変えないので、[ADR 0005](0005-layout-and-appearance.md)、[ADR 0023](0023-command-palette.md)、[ADR 0024](0024-tabs-and-split.md) のステータスには記録しない。
- この ADR の実装は、差分のタブ、リボンの「差分」、判定とダイアログの関数、`showDiffAfterApply` を作った時点で終わりとし、ステータスを `accepted` にする。「適用」へのつなぎは、[ADR 0081](0081-assistant-with-local-llm-and-connectors.md) の実装として行う。

## 実装しないこと

- 差分のタブでのコミット、元に戻すこと、差分の一部を選んでステージすること。
- `HEAD` のほかのもの (前のコミット、適用の前の状態) と比べること。前の書き換えの差分を後から見せたくなるかもしれないが、メンテナーは、差分のタブを触ってから決めるとした (2026-11-18)。足すときは、別の ADR で決める。
- 左右に並べる差分の表示と、行の中の文字ごとの差分。
- 「適用」のほかの書き換え (検索と置換、整形など) の前にダイアログを出すこと。
- この二つのほかのダイアログ (`choiceDialog` など) をモーダルにすること。
- 差分のタブを二つ以上開くこと。
- Git のパネルの、ワークスペースがリポジトリの下のフォルダのときのパスのずれを直すこと。差分のタブでは `-- .` と位置で避けるが、Git のパネルは別の ADR で直す。

## 不変条件

- I1: どの画面の状態でも、差分のタブは、すべてのペインを通して多くとも一つである。

- I3: 差分のタブの `id` は、`followed` にならない。

- I5: 適用の前の判定は、Git が使えて、リポジトリで、対象のシートがワークスペースの中で、変更があれば「コミットを促す」、変更が無ければ「そのまま適用」、それ以外は「戻せないことを知らせる」を返す。変更があるかは、保存していないシートの数か `git status` の項目の数が一つ以上のときに限り、真である。
- I6: 差分の読み取りは、`git status` の出力、位置、各ファイルの差分の出力から、ファイルの並び (ワークスペースからのパス、変更の種類、足した行と除いた行の数、出す行、ほかの行の数) を作る純粋な関数で行う。ファイルの順は `git status` の順に等しく、変更の種類は上の XY の表に等しく、行の数は初めの `@@` より後の行だけから数える。

- I8: 保存したタブの並びに `{ "diff": true }` が二つ以上あれば、最初のものだけを戻す。
- I9: 用語集の名前の列は、[ADR 0087](0087-preview-in-a-tab.md) I7 の名前の列の「映すタブ」の次に「差分のタブ」を足したものに等しい。
- I10: モーダル中の印が立っているあいだ、キーの割り当てはコマンドを走らせない。
- I11: 適用の後に差分のタブを出す操作の後には、差分のタブがちょうど一つあり、選んでいないペインで選ばれている (ペインが一つで、差分のタブがそのただ一つのタブのときを除く)。選んでいるペインは、実行の前と同じである。
- I12: コミットのメッセージは、`Before the assistant's edit ` に、時刻の年月日と時分を `YYYY-MM-DD HH:MM` の形で続けたものである。

## 受けいれ条件

- A1: リボンの「差分」を押すと、差分のタブが開き、ワークスペースの変更のあるファイルと差分が出る。ファイルの名前を続けて押すと、映すタブの中身がそのシートに替わり、差分のタブは残る。
- A2: シートを書きかえて保存すると、選んでいる差分のタブが読み直され、その変更が出る。Git のパネルでコミットすると、その変更が消える。
- A3: Git のリポジトリでないワークスペースで差分のタブを開くと、リポジトリでないことが一行で出る。
- A4: アシスタントの「適用」につないだ後、コミットしていない変更があるときに「適用」を押すと、コミットを促すダイアログが出て、答えるまでエディタにキーが届かず、⌘W も効かない。「コミットして適用」の後、差分のタブに書き換えの分だけが出る。A4 は、[ADR 0081](0081-assistant-with-local-llm-and-connectors.md) のアシスタントのタブを作った後に確かめる。

## テスト設計

- I1 から I4、I8、I11 は、画面の状態の reducer とタブの並びを読み書きする関数のテストで、I5 は二つの判定の関数のテストで、I6 と I7 は差分の読み取りの関数のテストで、I12 はメッセージの関数のテストで、境界の表の行を確かめる。名前は `ADR 0088 I1: …` のようにする。
- I9 は、`app/glossary.test.ts` の `ADR 0087 I7` のテストを、`ADR 0088 I9: …` の名前のテストに置き換えて確かめる。
- I10 は、モーダル中の印を立てた画面の状態で `dispatchKey` を呼び、コマンドが走らないことをテストする。ダイアログの `inert` と焦点は、偽の DOM で、出したときにほかの要素が `inert` を持ち、閉じたときに外れ、焦点が戻ることをテストする。
- A1 から A3 は、デバッグ版で手で確かめる。A4 は、アシスタントのタブを作った後に手で確かめる。

## トレードオフ

ダイアログを、未コミットの変更があるときだけ出すと、変更が無いときは何も聞かずに適用する。
そのときは、`HEAD` がちょうど適用の前の状態なので、差分のタブに書き換えの分だけが出て、Git のパネルで戻せる。
毎回聞く形にすると、守りは同じで、書き手の手間だけが増える。

差分のタブを `HEAD` との差分だけにすると、「コミットせずに適用」を選んだときは、書き換えの分と前からの変更が混ざって出る。
適用の前の状態を覚えて比べる形なら分けられるが、作りが大きくなる。
ダイアログで、コミットしてから適用することを先に勧めるので、混ざるのは書き手がそれを選んだときに限られる。

ダイアログをモーダルにすると、書き手はダイアログに答えるまで何もできない。
メンテナーは、コミットするかどうかを決めないと書き換えの作業を先に進められないので、止めてよいとした。
ほかのダイアログは、今のとおり、キーが背面に届きうる。
同じ作りを広げるかは、別の ADR で決める。

「コミットして適用」は、そのワークスペースの変更だけ (`git add -A -- .`) をコミットする。
ワークスペースがリポジトリの下のフォルダのとき、外の変更までコミットすると、書き手の知らない変更がコミットに入るためである。

適用の後にシートを保存すると、書き手が保存を決めるという今までの決まりを変える。
しかし、保存しないと、差分のタブに書き換えの分が出ない。
書き換えは取り消し (⌘Z) と Git で戻せるので、保存を先に行う。

差分のタブは見るだけで、元に戻すことはできない。
壊れた書き換えを戻すには、Git のパネルか、エディタの取り消しを使う。
差分のタブに戻す操作を置くと、書き手の変更まで消す操作が、一つのボタンで届く所に増える。

`inert` は、macOS 12.3 より前の WebKit では効かない (未確認)。
キーは「モーダル中」の印で止めるので、`inert` が効かなくても、キーのコマンドは走らない。
