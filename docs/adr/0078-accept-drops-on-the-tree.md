# ADR 0078: Finder やほかのアプリケーションからサイドバーへのドロップを受けいれる

Status: accepted-pending

## 文脈

書き手は、Finder や Obsidian などのほかのアプリケーションにある資料や原稿を、ワークスペースに取りこむ。
[ADR 0014](0014-shared-library-and-assets.md) は、サイドバーのファイルツリー (以下、ツリー) のフォルダにファイルを落とすと、そのフォルダにコピーすると定めている。
しかし今の実装は、ファイルしかコピーできず、フォルダを落とすと失敗する。
失敗しても書き手には何も知らされず、落とす前に、どのフォルダに入るかも見えない。

この ADR は、サイドバーへのドロップで受けいれるもの、落とす先の決め方、コピーの仕方、失敗の知らせ方を決める。
サイドバーのファイルを外に渡す向き (ドラッグ、コピー、zip) は、[ADR 0077](0077-hand-sidebar-files-outside.md) が決める。

## 調査した事項

この節には、ソースで確かめたことだけを書く。

ウィンドウへのドロップは、Tauri のドラッグアンドドロップの事象で受けている。
Rust の側は、`Drop` の事象で落ちてきたパスを、アプリケーションが動いているあいだだけ読める範囲に足す ([lib.rs:1124-1129](https://github.com/tett23/aleph/blob/0966994371f0b672f1be72231b7ce372859dbceb/src-tauri/src/lib.rs#L1124-L1129)、[ADR 0050](0050-paths-the-writer-chooses.md))。
足したパスは読めるが、書けない ([guard.rs:107-113](https://github.com/tett23/aleph/blob/0966994371f0b672f1be72231b7ce372859dbceb/src-tauri/src/guard.rs#L107-L113))。

TypeScript の側は、落ちた位置の要素で行き先を決める ([libpanel.ts:171-203](https://github.com/tett23/aleph/blob/0966994371f0b672f1be72231b7ce372859dbceb/app/libpanel.ts#L171-L203))。

- 共有ライブラリのパネルなら、共有ライブラリにコピーする。
- `.gm` のエディタなら、画像を `images/` にコピーして図の命令を差し込む。
- ツリーのフォルダの行ならそのフォルダに、ファイルの行ならそのファイルのフォルダにコピーする。
- ツリーの行のない場所 (行の下の空いたところ) に落としたときは、何もしない。

ツリーへのコピーは、パスごとに `copy_file` を呼ぶ ([libpanel.ts:145-153](https://github.com/tett23/aleph/blob/0966994371f0b672f1be72231b7ce372859dbceb/app/libpanel.ts#L145-L153))。
`copy_file` は Rust の `std::fs::copy` を使う ([fsops.rs:298-304](https://github.com/tett23/aleph/blob/0966994371f0b672f1be72231b7ce372859dbceb/src-tauri/src/fsops.rs#L298-L304))。
Rust の標準ライブラリの文書によれば、`std::fs::copy` は、コピー元が通常のファイルでもそれを指すシンボリックリンクでもないときに失敗する。
そのため、フォルダを落とすとコピーは失敗する。
ドロップの事象の処理には失敗を受ける箇所が無く、書き手には知らせない。
ツリーの上を通るあいだ、落とす先の行の見た目は変わらない (共有ライブラリのパネルは、`drop-over` の印で変わる)。

同じ名前のファイルがあるときは、名前の後ろに `-2`、`-3` と付けて上書きしない ([library.ts:93-100](https://github.com/tett23/aleph/blob/0966994371f0b672f1be72231b7ce372859dbceb/app/library.ts#L93-L100)、[ADR 0014](0014-shared-library-and-assets.md))。

wry 0.57.1 (Tauri 2.12.5 の WebView) の macOS の実装は、ドラッグのペーストボードから、ファイルの URL (`public.file-url`) と、古い形式のファイルのパスの一覧 (`NSFilenamesPboardType`) だけを読む ([drag_drop.rs:20-66](https://github.com/tauri-apps/wry/blob/wry-v0.57.1/src/wkwebview/drag_drop.rs#L20-L66))。
ファイルでない URL は読み飛ばす。

Obsidian からドラッグしたときにペーストボードにファイルの URL が載るかは未確認である。
Obsidian の中のノートの URL (`obsidian://` で始まる) や、ノートの文字列だけが載るなら、上の実装はそれをパスとして渡さない。

## 実装すること

### 受けいれるもの

この節から「コピーの仕方」までは、[ADR 0014](0014-shared-library-and-assets.md) の「ツリーのフォルダに落とすと、そのフォルダにコピーする」を補う。

ファイルの URL かファイルのパスとして落ちてきたファイルとフォルダを受けいれる。
Finder のほか、ファイルの URL を載せるアプリケーションからのドロップは、すべて同じに扱う。

### 落とす先

落とす先のフォルダは、落ちた位置で次のように決める。

| 落ちた位置 | 落とす先 |
| --- | --- |
| フォルダかプロジェクトの行 | そのフォルダ |
| ファイルの行 | そのファイルのフォルダ |
| ツリーの行の無い場所 | 開いているワークスペースのフォルダ |

ツリーの上をドラッグしているあいだは、落とす先のフォルダの行と、その中の行の背景の色を変える。
行の無い場所の上では、ツリー全体の枠の色を変える。
共有ライブラリのパネルと `.gm` のエディタに落としたときの扱いは変えない。

### コピーの仕方

落ちてきたものは、移動せず、コピーする。
コピー元はほかのアプリケーションが持つファイル (Obsidian の保管庫など) なので、動かすとそのアプリケーションの側が壊れるからである。

- フォルダは、中身ごとコピーする。
- コピー元の中のシンボリックリンクは、たどらず、コピーしない。
- 名前が `.DS_Store` のファイルは、コピーしない。
- 落とす先に同じ名前のものがあれば、今までどおり名前の後ろに `-2`、`-3` と付ける。フォルダの名前にも付ける。名前を付けるのは、落としたものの名前だけである。フォルダの中の名前には付けない。
- `.gm` をプロジェクトに落としても、`manifest.toml` の `chapters` には足さない。足すときは、ツリーの「chapters に追加」を使う。

コピーは Rust の側で、新しいコマンドで行う。
このコマンドは、コピー元を一覧してからコピーし、落とす先には書けるか、コピー元は読めるかを、今の範囲の検査で確かめる。
コピーは別のスレッド ([ADR 0062](0062-run-programs-off-the-main-thread.md) の `blocking`) で行う。
コピーのあいだも、書き手はエディタとツリーを使える。
二度目のドロップは、一度目のコピーが終わるのを待たずに始める。
落とす先に同じ名前が無いかの確かめと、作ることは、Rust の側で一度に行う (ファイルは `create_new`、フォルダは `create_dir` で作り、すでにあれば次の番号を試す)。
そのため、二つのコピーが同じ名前を取りあっても、どちらかが上書きされることは無い。

### 進み具合のトースト

コピーを始めてから 500 ms たっても終わらないときは、進み具合のトーストを出す。
進み具合は、モーダルではなく、トースト ([ADR 0064](0064-unified-notifications.md)) で出す。
コピーのあいだも、画面を固めず、書き手の操作を止めないためである。

- トーストには、落とす先のフォルダの名前、コピーした件数と全体の件数、進み具合の棒を出す。
- 棒の長さは、コピーしたバイト数を全体のバイト数で割った値とする。全体が 0 バイトのときは、件数で割った値とする。
- 全体の件数とバイト数は、コピーを始める前のコピー元の一覧から求める。
- Rust の側は、コピーしたバイト数と件数を、0.1 秒に一度を超えない間隔で事象として送る。
- 進み具合のトーストは時間では消えず、書き手が閉じても、コピーは止まらない。
- コピーが終わったら、進み具合のトーストを、結果の通知 (下の節) に置き換える。
- 500 ms より前に終わったときは、進み具合のトーストを出さず、結果の通知だけを出す。

[ADR 0064](0064-unified-notifications.md) の通知のモデルに、進み具合 (0 から 1 の値と、件数の文) を持つ通知を足す。
進み具合の通知は、同じ鍵の `notify` で値を更新し、トーストの数を増やさない。
通知のタブの履歴には、進み具合の途中の値を残さず、結果の通知だけを残す。

### 拒むものと失敗の知らせ方

次のときは、そのものをコピーせず、終わった後の通知 ([ADR 0064](0064-unified-notifications.md)) に理由を載せる。

- フォルダを、そのフォルダ自身かその中に落とした。
- コピー元を読めない、または落とす先に書けない。

一つの失敗で、ほかの落としたもののコピーは止めない。
途中で失敗したフォルダは、それまでにコピーした中身を残す。
終わった後は、コピーしたものの名前と、失敗したものの名前と理由を、一つの通知にまとめる。
コピーの後はツリーを読み直し、落とす先のフォルダを開く。

## 実装しないこと

- ドロップでの移動。
- Obsidian の `obsidian://` の URL や、ドラッグに載った文字列から、ファイルを探すこと。必要になったら、Obsidian で確かめた後に別の ADR で決める。
- ツリーの中での行のドラッグによる移動や並べ替え。
- 同じ名前のものを上書きするか、名前を変えるかを、書き手に選ばせること。
- コピーの途中での取り消し。
- macOS のほかの OS での確かめ。

## 不変条件

- I1: 落とす先は、フォルダかプロジェクトの行ならそのフォルダ、ファイルの行ならそのファイルのフォルダ、行の無い場所なら開いているワークスペースのフォルダである。
- I2: コピーした後の落とす先には、落としたもののうち拒まれず、失敗しなかったものが一つずつあり、前からあったものは名前も中身も変わらない。
- I3: フォルダのコピーの中のファイルの集合は、コピー元のシンボリックリンクでない通常のファイルのうち名前が `.DS_Store` でないものの集合に、相対パスで等しく、各ファイルの中身はバイト単位で等しい。
- I4: コピー元は、コピーの後も名前も中身も変わらない。
- I5: フォルダをそのフォルダ自身かその中に落としたとき、ファイルシステムは何も変わらない。
- I6: 通知に並ぶコピーしたものと失敗したものの名前を合わせると、落としたものの名前のすべてにちょうど一度ずつなる。
- I7: 進み具合のトーストは、コピーが始まってから 500 ms たった時点でまだ終わっていないときに限って出て、出たときはコピーが終わるまで残る。
- I8: 進み具合の値は、0 以上 1 以下で、減らず、コピーが終わったときに 1 である。
- I9: 同じ落とす先に同時に二つのコピーが同じ名前を取ろうとしても、二つは別の名前になり、どちらの中身も欠けない。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| ファイルの行に `a.md` を一つ落とす | そのファイルのフォルダに `a.md` | I1, I2 |
| 行の無い場所に落とす | ワークスペースのフォルダに入る | I1 |
| 落とす先に `a.md` があるところへ `a.md` | `a-2.md` ができ、前の `a.md` は変わらない | I2 |
| 落とす先に `資料` があるところへフォルダ `資料` | `資料-2` ができ、中身の名前には付かない | I2, I3 |
| 空のフォルダ | 空のフォルダができる | I3 |
| `.DS_Store` と `x.md` だけのフォルダ | `x.md` だけが入る | I3 |
| 中にシンボリックリンクがあるフォルダ | リンクは入らず、たどらない | I3 |
| フォルダ `w/a` を `w/a/b` に落とす | 何も変わらず、通知する | I5, I6 |
| 読めるファイルと読めないファイルを一度に落とす | 読める方だけ入り、通知に両方が並ぶ | I2, I6 |
| 大きさ 0 のファイル | 大きさ 0 のファイルができる | I3 |
| 499 ms で終わるコピー | 進み具合のトーストは出ず、結果の通知だけ | I7 |
| 500 ms の時点で終わっていないコピー | 進み具合のトーストが出て、終わると結果の通知に変わる | I7, I8 |
| 大きさ 0 のファイルだけのフォルダ | 進み具合は件数で進み、終わると 1 | I8 |
| 同じ `a.md` を同じ落とす先に続けて二度落とし、一度目がまだ終わっていない | `a.md` と `a-2.md` ができる | I9 |

## 受けいれ条件

- A1: Finder からファイルとフォルダを一度にツリーのフォルダの行に落とすと、両方がそのフォルダにコピーされ、フォルダの中身もそろう。
- A2: ツリーの上をドラッグしているあいだ、落とす先のフォルダの行の色が変わる。
- A3: ツリーの行の無い場所に落とすと、ワークスペースのフォルダにコピーされる。
- A4: Obsidian のファイルの一覧からノートをツリーに落とすと、ノートの `.md` がコピーされる。ペーストボードにファイルの URL が載らないときは、何もコピーされず、この受けいれ条件を満たせないことを記録する。
- A5: 画像を `.gm` のエディタに落としたとき、ファイルを共有ライブラリのパネルに落としたときの扱いは、今までどおりである。
- A6: 1 GB ほどのフォルダを落とすと、進み具合のトーストが出て、そのあいだもシートを打てる。

## テスト設計

- Rust の新しいコピーのコマンドの中身を、一時フォルダで確かめる。名前は `adr0078_i2_…`、`adr0078_i3_…` のようにし、境界の表の各行を一つ以上のテストで確かめる。
  - 読めないファイルは、権限を外したファイルで作る。
  - I4 は、コピーの前と後でコピー元の一覧と中身を比べる。
  - I5 は、コピーの前と後で落とす先の一覧を比べる。
- 落ちた位置から落とす先を決める関数を、TypeScript で切り出し、`ADR 0078 I1: …` で確かめる。
- 通知の文を組み立てる関数を、`ADR 0078 I6: …` で確かめる。
- I7 は、時計を差し替えられる進み具合のトーストの関数で、499 ms と 500 ms の境界を確かめる。
- I8 は、Rust の側の進み具合の事象の列を、大きさの違うファイルと大きさ 0 のファイルで確かめる。
- I9 は、同じ落とす先に二つのコピーを並べて走らせ、名前と中身を確かめる。

ドロップの事象は自動のテストで起こせないので、受けいれ条件はデバッグ版で手で確かめる。

- A1、A2、A3、A5、A6 は、試験のワークスペースに Finder から落とす。
- A4 は、手元の Obsidian の試験の保管庫から落とす。本人の保管庫は使わない。

## トレードオフ

コピーにすると、同じファイルが二か所にでき、片方を直してももう片方は変わらない。
しかし移動にすると、Obsidian などのコピー元のアプリケーションが、ファイルを見失う。
取りこむ用途では、元を残す方を選ぶ。

途中で失敗したフォルダのコピーを残すと、中身がそろわないフォルダができることがある。
すべてを消して戻すと、書き手が先に確かめたい中身まで消える。
通知に失敗したものの名前を出し、書き手が残りを手で直せるようにする。

フォルダの名前に `-2` を付けて別のフォルダにすると、同じ名前のフォルダの中身を合わせたいときに手間がかかる。
合わせると、どちらのファイルを残すかの選択が要る。
この ADR は、上書きの起きない方を選ぶ。
