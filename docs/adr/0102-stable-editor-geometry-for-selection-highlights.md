# ADR 0102: 一致箇所のハイライトで本文の幅と位置を変えない

Status: proposed

## 文脈

指示者から、同一文字列を選択して他の一致箇所がハイライトされると、エディタの表示の幅が微妙にずれてがたつくとの報告があった。
折り返しが変わるかどうかは未確認であり、原因とは断定しない。
選択範囲の変更は日常的に行うため、ハイライトを付け外しするだけで本文の幅や位置が揺れないようにしたい。

## 調査した事項

調査した [ADR 0091](0091-selection-occurrence-highlights.md) の実装ブランチ（末尾の固定した版）では、選択の変更から一致範囲を計算し、表示レイヤーの変更を通知して同期的に描き直す。
一致範囲をインライン要素の分割に含めているため、一致の付け外しでも行の描画キーが変わり、行の DOM が交換される。
描画後は行の矩形を計測し、前の値との差が 0.5 CSS px を超えると仮想表示の寸法を更新する。
表示先頭行の積算位置が変わった場合はスクロールを補正し、フォーカス中は選択も設定し直す。
これらの経路は、一致ハイライトを拡充した [ADR 0091](0091-selection-occurrence-highlights.md) の前から存在する。

同 ADR の実装ブランチの CSS は、一致箇所に内側の影と角丸を指定している。
通常の一致箇所に幅、余白、フォントサイズを追加する指定はない。
一方、テキストの分割、DOM の交換、寸法計測、選択復元のどれが今回のずれを起こすかは、実機で切り分けられていない。
根拠のソースは末尾に固定した版で示す。

## 実装すること

### 本文の配置とハイライトの更新を分ける

同じ本文に対する一致範囲の変更では、本文のテキストノードとインライン要素を分割し直さず、行の DOM も交換しない。
本文の配置を変えない装飾として、一致箇所のハイライトを更新する。
ブラウザの範囲装飾 API または本文とは別の描画面を使い、本文と同じ場所に別の文字を描いて重ねる方法は使わない。
API の対応状況と縦書きでの表示は、同梱する Tauri の WebKit で実装前に確かめる。
利用できない API を前提にハイライトを省くことはせず、別の描画面を使う場合も同じ受けいれ条件を満たす。

一致の更新だけでは、行の寸法キャッシュ、仮想表示の空き領域、エディタの幅、スクロール位置を変更しない。
一致の装飾はスクロール可能な領域を広げず、スクロールバーの出現で本文幅を変えない。
選択変更に本来必要なブラウザのスクロールと、選択端を表示する処理は残すが、ハイライトのために追加の移動を起こさない。

本文編集、フォント、ウィンドウサイズ、字詰め、縦横の変更では、これまでどおり必要な再配置と計測を行う。
再配置の後に現在の一致範囲から装飾を描き直し、古い座標や破棄済みの行にハイライトを残さない。
スクロールで新たに見える行にも一致を出す。

### 選択と入力を保つ

ハイライトの付け外しだけでは、DOM の選択を設定し直さず、フォーカス、カーソル、選択の向き、IME の変換状態を変えない。
IME 変換中の DOM を変えない規則は維持する。
一致の計算条件、最大 10,000 件、選択範囲自体の除外、空白と改行の一致は [ADR 0091](0091-selection-occurrence-highlights.md) のままとする。
一致の印は、選択の背景、検索結果、診断の波線と区別できるようにする。

この ADR は [ADR 0091](0091-selection-occurrence-highlights.md) に、ハイライトによって本文の配置を変えない条件を補う。

## 実装しないこと

今回の報告だけを根拠に、フォント、字詰め、禁則処理を変更することはしない。
本文編集やウィンドウのリサイズなど、本来の再配置に伴う動きまで止めない。
選択文字列との一致条件や、一致ハイライトの件数上限は変更しない。

## 不変条件

- I1: 本文、フォント、表示方向、表示領域が等しく、一致ハイライトだけが異なる二つの状態では、本文の各文字と行の矩形、エディタの幅、スクロール可能な領域の寸法が等しい。
- I2: ハイライト更新処理の前後で、スクロール位置、選択の両端と向き、フォーカス、変換中の文字列は等しい。
- I3: 同じ本文に対するハイライト更新では、本文のテキストノードと行の DOM の同一性を保ち、寸法キャッシュを無効化しない。
- I4: 再配置または仮想表示範囲の変更が完了したとき、描かれたハイライトは現在の本文の一致範囲だけを指す。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 空の選択、一致なし、一致一つ | 本文の幅と位置は同じ | I1, I2, I3 |
| 一文字の一致を選択、解除、再選択 | 一致の印だけが変わる | I1, I2, I3 |
| 行末付近、幅いっぱいの行、複数行の一致 | 行と文字の矩形を保持 | I1, I3 |
| 日本語、英字の合字、約物、空白、結合文字 | テキスト分割による幅の変化なし | I1, I3 |
| 画面外にも一致がある長文をスクロール | 新たに見える一致へ描画 | I4 |
| 10,000 件と上限を超える一致 | 既存の上限を保ち、寸法に影響しない | I1, I4 |
| IME 変換中に一致更新が必要になる | 変換状態と選択を保持 | I2 |
| 本文編集、フォント変更、縦横変更、リサイズ | 再配置した本文へ装飾が追従 | I4 |

## 受けいれ条件

- A1: 横書きと縦書きのエディタで同じ文字列の選択と解除を繰り返しても、本文の幅と位置が微妙にずれる現象が起きない。
- A2: 明暗両モードで一致の印を確認でき、選択、検索結果、診断の表示と区別できる。
- A3: 長いシートの途中や複数シートを連続表示した状態でも、選択によるハイライトだけで表示位置が動かない。

## テスト設計

最初に WebKit 上で選択と解除の前後の矩形と DOM の交換を記録し、今の実装が I3 を破る回帰テストを先に失敗させる。
幅のずれを再現できた場合は、使用したフォント、字詰め、本文、表示方向、倍率も記録し、I1 の再現ケースにする。
再現できない場合は、ユーザー報告を再現済みとは書かない。

I1 は、装飾なし、装飾あり、解除後の各状態で、同じ文字位置の `Range` と行とエディタの矩形を比較する。
フォントの読み込みと本来の再配置が完了した後に測り、CSS px の浮動小数点の比較許容差は 1/64 px とする。
一文字の選択と解除を 100 回繰り返して、累積のずれもないことを確かめる。
横書きと縦書き、明暗、境界の表の入力を含める。

I2 と I3 は、ハイライト更新の直前と直後で選択とスクロール、ノードの同一性、寸法キャッシュ更新回数を比較する。
選択そのものが発生させるスクロールを比較に混ぜず、装飾更新が追加の移動を発生させないことを確かめる。
I4 は、スクロール、本文編集、リサイズの前後で装飾の範囲を比べる。
テスト名にこの ADR と条件の番号を入れる。

A1〜A3 は、Tauri のデバッグ版で短いシート、長いシート、複数シートを開き、マウス選択とキーボード選択で確かめる。
静止画だけでなく、選択と解除を続けたときの幅と位置の動きも確かめる。
IME では変換中と確定後を確認する。

## トレードオフ

本文と装飾を分けると、再配置やスクロールに装飾を追従させる処理が必要になる。
一方、ハイライトだけの変更で本文の形や選択を作り直さずに済み、幅のずれと余分なスクロールを防ぐ条件を独立して検証できる。
