# ADR 0081: 下部パネルに、ローカル LLM で動くアシスタントを置く

Status: proposed

## 文脈

Golem の原稿を書くには、覚えることが多い。
原稿の記法の命令 (`@figure` など)、`style.toml` と `manifest.toml` のキーと値、Aleph のコマンドがそれである。
以下、この ADR で「命令」と書くときは、原稿の記法の命令だけを指す。
書き手は、覚えていないもののたびにリファレンスを引き、記法の細かな直しを手で行っている。
この ADR は、自然な言葉の頼みから、書き換えの案を出す補助を Aleph に置くことを決める。
以下、この補助を**アシスタント**と呼ぶ。

アシスタントは、手元で動く小さな LLM (以下、ローカル LLM) を既定で使う。
クラウドの LLM の利用枠 (トークン) が切れても、書き手の作業が止まらないようにするためである。
ローカル LLM は、アカウントも API キーも要らない。
性能はそこそこでよく、応答の速さと、使うメモリの少なさを重く見る。
書き手がエラーに出会う回数を減らすため、ローカルのモデルは、いつも一つ以上入っているようにする。

頼みをモデルに渡す口を**コネクタ**と呼ぶ。
コネクタは、ローカル LLM、Claude Code、Codex の三つとする。
書き手が Claude や Codex を使えるときは、より強いモデルに頼めるようにするためである。

どのモデルを既定にするかは、この ADR では決めない。
実装の最初の段で候補を同じ条件で計測し、この ADR が定める選び方の規則で決める。

この ADR の議論は、依頼者が別に行った調べもの (候補のモデル、llama.cpp、計測の方針) を出発点にしている。
その中の事実は、下の「調査した事項」で確かめ直したものだけを使う。

| Qwen/Qwen3.5-0.8B | Apache-2.0 | いいえ | image-text-to-text | 約 8.7 億 |

Qwen3.5 は、画像も入力にとる型である。

Gemma 3 1B は、ダウンロードに承認が要るので、候補から外す。

llama.cpp で動かす形式 (GGUF) の 4 ビットの量子化 (Q4_K_M) の大きさは次のとおりである。

| モデル | GGUF の配布元 | Q4_K_M の大きさ |
| --- | --- | --- |
| Qwen3-0.6B | unsloth/Qwen3-0.6B-GGUF | 397 MB |
| Qwen3.5-0.8B | unsloth/Qwen3.5-0.8B-GGUF | 533 MB |
| Qwen3.5-2B | unsloth/Qwen3.5-2B-GGUF | 1,281 MB |
| Qwen3.5-4B | unsloth/Qwen3.5-4B-GGUF | 2,741 MB |

Qwen3-0.6B には、Qwen の公式の GGUF (Qwen/Qwen3-0.6B-GGUF) もあるが、Q8_0 (639 MB) だけである。
Qwen3.5 の GGUF は、unsloth、bartowski、lmstudio-community などの第三者が作ったものだけで、Qwen の公式のものは見つからなかった。
配布の大きさは、動かすときのメモリの量ではない。
動かすときのメモリの量と速さは未確認である。

### 推論のエンジン

llama.cpp (ggml-org/llama.cpp) のライセンスは MIT である。
ビルド番号のタグ (例 `b12466`、2026-11-17) ごとに、`llama-b12466-bin-macos-arm64.tar.gz` (17 MB) が配布され、GitHub の API が SHA-256 を返す。
配布元は、`SHA256SUMS` のファイルを置いていない。
このアーカイブには、`llama-server`、計測の道具の `llama-bench`、Metal と BLAS の動的ライブラリ、`LICENSE` が入っている (`tar -tzf` で確かめた)。
タグ `v1.0.0` のリリースには、macOS のアーカイブは無く、`nightly-tag.txt` だけがあった。

`llama-server` の文書 ([tools/server/README.md](https://github.com/ggml-org/llama.cpp/blob/b12466/tools/server/README.md)) によれば、次のことができる。

- `--host` に `.sock` で終わるパスを渡すと、TCP の代わりに UNIX ソケットで待ち受ける。既定は `127.0.0.1` である。
- `-c` でコンテキストの長さを、`-ngl` で GPU に載せる層の数を決める。
- 頼みに `json_schema` を付けると、出力をその JSON Schema に合う形に縛る。

llama.cpp の `src/llama-arch.cpp` (`b12466`) は、Qwen3 (`qwen3`) と Qwen3.5 (`qwen35`) の構造を持つ。

### Claude Code と Codex

手元の Claude Code 2.1.322 と Codex 0.167.1 の `--help` で、非対話の実行の仕方を確かめた。

| CLI | 非対話の実行 | 出力の形を縛る | ツールと書き込みを止める | 履歴を残さない |
| --- | --- | --- | --- | --- |
| `claude` | `-p` (`--print`)、`--output-format json` | `--json-schema <schema>` | `--tools <tools...>`、`--permission-mode` | `--no-session-persistence` |
| `codex` | `codex exec [PROMPT]`、`--json` | `--output-schema <FILE>` | `--sandbox read-only` (書き込みだけを止める) | `--ephemeral` |

`codex exec` は、`-C` で作業のフォルダを、`-o` で最後の答えを書くファイルを決められ、`--skip-git-repo-check` で Git のリポジトリの外でも動く。
`codex exec --help` には、コマンドの実行やファイルの読み取りを止める引数は見つからなかった。
どちらの CLI も、書き手がすでにログインしたアカウントで動く。
そのため、Aleph が API キーを持つ必要は無い。

この Mac では、`claude` は mise の shims (`~/.local/share/mise/shims/claude`)、`codex` は Nix のプロファイル (`/etc/profiles/per-user/<ユーザー>/bin/codex`) にあった (`command -v`)。
どちらも、git を探す場所 (`/usr/bin`、Homebrew) にも、golem を探す場所 (同梱、`~/.local/bin`、Homebrew) にも無い。

### 今の Aleph

- 画面の下には、「問題」「通知」「ビルドログ」のタブを持つ下部パネルがある ([ADR 0055](0055-problems-panel.md)、[ADR 0064](0064-unified-notifications.md)、[ADR 0069](0069-build-log-and-reveal.md)、[problemsmount.ts:98](https://github.com/tett23/aleph/blob/02b966a835c5c49a0ae18137310a9cf2cc4978f6/app/problemsmount.ts#L98))。「ビルドログ」のタブは、そのプロジェクトをビルドした後だけ出る。
- 画面の CSP の `connect-src` は `ipc:` と `http://ipc.localhost` だけである ([tauri.conf.json:17](https://github.com/tett23/aleph/blob/02b966a835c5c49a0ae18137310a9cf2cc4978f6/src-tauri/tauri.conf.json#L17))。画面から外の HTTP には繋げないので、LLM とのやり取りは Rust の側で行う ([ADR 0042](0042-ipc-trust-boundary.md))。
- [ADR 0042](0042-ipc-trust-boundary.md) は、書き手の承認を画面の中の確認ではなく、Rust の側のネイティブのダイアログで受けると決めている。画面の中の確認は、注入されたスクリプトが押せるからである。
- golem と shem は、`tools.versions` の版を [`scripts/bundle-tools.sh`](https://github.com/tett23/aleph/blob/02b966a835c5c49a0ae18137310a9cf2cc4978f6/scripts/bundle-tools.sh) が同梱する ([ADR 0008](0008-golem-and-shem-binaries.md))。このスクリプトは、配布元を `https://github.com/tett23/<name>` に決め、配布元の `SHA256SUMS` で照らし、アーカイブから `<name>` の一つのファイルだけを写す。
- 外部のプログラムを探す順は、golem と shem が「設定の値、同梱、`~/.local/bin`、Homebrew、PATH」、git が「設定の値、`/usr/bin`、Homebrew、PATH」である ([process.rs:104-112](https://github.com/tett23/aleph/blob/02b966a835c5c49a0ae18137310a9cf2cc4978f6/src-tauri/src/process.rs#L104-L112))。[ADR 0008](0008-golem-and-shem-binaries.md) によれば、macOS の GUI アプリはログインシェルの PATH を受け継がない。
- 外部のプログラムを待つコマンドは、メインスレッドの外で走らせる ([ADR 0062](0062-run-programs-off-the-main-thread.md))。
- `golem check` は、プロジェクトのディスクのファイルを読み、`--format json` で診断を返す。[ADR 0015](0015-diagnostics-and-search.md) は、書き手に見せる check をパネルからだけ実行すると決めている。

## 実装すること

### アシスタントの役割

アシスタントは、書き手の頼み (自然な言葉) と対象のテキストを受け、書き換えの案と短い説明を返す。
対象のシートは、選んでいるタブの焦点のあるシートとする。
対象の範囲は、エディタの選択した範囲、なければそのシートの全体である。
`style.toml`、`manifest.toml`、`.gm`、`.md` のシートを主な対象とする。
Aleph のコマンドを尋ねる頼みには、書き換えの案を空にし、説明だけを返す。

アシスタントは、ファイルを直接書き換えない。
書き換えの案は、次の形の JSON で受け取る。

```json
{
  "explanation": "行送りを 18H から 20H に広げます。",
  "edits": [{ "find": "line-pitch = \"18H\"", "replace": "line-pitch = \"20H\"" }]
}
```

- 各 `find` は、適用のときの対象の範囲に、ちょうど一度だけ現れなければならない。
- 二つの `find` の現れる範囲は、重なってはならない。
- `find` の位置は、適用の前のテキストで決める。前の `edit` を当てた後のテキストでは探さない。
- 頼んだ後に書き手が対象を変えていても、適用のときの今のテキストで数えなおす。対象が選択の範囲のときは、頼んだときの範囲のテキストが今のシートにちょうど一度だけ現れることを求め、その中で数える。
- 条件に合わない案は、適用せず、理由を示す。
- 書き換えの案は、適用の前に、変わる行を差分で示す。
- 書き手が「適用」を押したときだけ、エディタの一つの変更として当てる。取り消しで戻せる。保存は今までどおり書き手が行う。

対象が Golem のプロジェクトの `.gm`、`style.toml`、`manifest.toml` のときは、案を示す前に `golem check` で確かめる。

- プロジェクトをキャッシュの一時のフォルダに写し、対象のファイルを、案を当てた後のテキストに置き換えて、`golem check --format json` を走らせる。
- 案を当てる前のテキストでも同じように走らせ、対象のファイルのエラーの数を比べる。
- エラーが増えたときは、増えた診断を付けて一度だけ頼み直す。それでも増えるときは、診断と一緒に案を示し、適用は書き手に任せる。
- この検査の結果は、問題のタブにも診断のパネルにも出さない。そのため、書き手に見せる check をパネルからだけ実行するという [ADR 0015](0015-diagnostics-and-search.md) の決まりは変えない。
- プロジェクトの外のシートと `.md` は、検査しない。

### 下部パネルのタブ

下部パネルに、タブ「アシスタント」を足す。
画面の要素の名前は、[ADR 0082](0082-ui-names-and-glossary.md) の用語集に従い、このタブの名前も、この ADR の実装で用語集に足す。

- 頼みを書く欄、対象 (選択の範囲かシートの全体か) の表示、コネクタを選ぶ欄、送るボタンを置く。
- 答えは、説明、差分、「適用」と「捨てる」のボタンで示す。答えたコネクタとモデルの名前と、かかった時間を添える。
- 頼みと答えの履歴は、Aleph を閉じるまで、そのタブの中に残す。ファイルには書かない。
- 頼みは、⌘↩ で送る。
- コマンド `assistant.open` (タブを開く) と `assistant.askSelection` (選択した範囲で頼む) を足す ([ADR 0023](0023-command-palette.md))。

### コネクタ

コネクタは、頼みと対象と資料を受け取り、上の JSON を返す。

| コネクタ | 動かすもの | 外に送るもの |
| --- | --- | --- |
| ローカル | 同梱の `llama-server` と、ダウンロードしたモデル | 無し |
| Claude Code | 書き手の `claude` | 頼み、対象、資料を Anthropic に |
| Codex | 書き手の `codex` | 頼み、対象、資料と、Codex が読んだファイルを OpenAI に |

- 既定のコネクタは、ローカルとする。ローカルは承認なしで使う。
- CLI と `curl` は、[ADR 0062](0062-run-programs-off-the-main-thread.md) に従い、メインスレッドの外で走らせる。
- `claude` と `codex` は、設定の値 (`config.json` の `claudePath` と `codexPath`)、`~/.local/bin`、Homebrew、ログインシェルの PATH の順に探す。ログインシェルの PATH は、書き手のシェル (`$SHELL`) を `-l -c` で起こし、`command -v` で探して得る。見つかったときだけ、そのコネクタを選べる。設定の値は、[ADR 0042](0042-ipc-trust-boundary.md) と同じく、Rust の側だけが読み、画面からは変えられない。
- Claude Code と Codex を初めて使うときは、Rust の側のネイティブのダイアログで、何がどの会社に送られるかを示し、書き手が認めたときだけ使う。承認は `config.json` の、Rust の側だけが変える鍵に残す。Rust の側は、承認の無いコネクタを呼ばない。
- Claude Code は、`claude -p --output-format json --json-schema <schema> --tools "" --no-session-persistence` で呼び、頼みを標準入力で渡す。ツールを渡さないので、ファイルの読み書きも、コマンドの実行もしない。
- Codex は、空の一時フォルダを作業のフォルダにして、`codex exec --sandbox read-only --ephemeral --skip-git-repo-check --output-schema <file> -o <file> -C <一時フォルダ>` で呼び、頼みを標準入力で渡す。読むだけのサンドボックスは書き込みを止めるが、コマンドの実行とファイルの読み取りは止めない。承認のダイアログで、このことを示す。
- CLI の終了の状態が 0 でない、答えが JSON の形に合わない、時間切れ (既定 120 秒) のときは、失敗とする。
- Claude Code か Codex で失敗したときは、同じ頼みをローカルで一度だけ頼み直す。答えには、どのコネクタで答えたかと、頼み直した理由を示す。ローカルのモデルはいつも入っているので、利用枠が切れたときも、作業は止まらない。

### ローカルの推論

- `llama-server` は同梱のものだけを使い、ほかの場所から探さない。
- `llama-server` を、golem と同じく `tools.versions` と `scripts/bundle-tools.sh` で同梱する。ただし、行の形を広げる。llama.cpp の行は、配布元のリポジトリ (`ggml-org/llama.cpp`)、ビルド番号のタグ、アーカイブの名前、アーカイブの SHA-256、写すファイル (`llama-server`、その動的ライブラリ、`LICENSE`) を持つ。golem と shem の行は、今の形のまま `SHA256SUMS` で照らす。
- `llama-server` は、最初の頼みのときに起こし、Aleph の一時のフォルダの UNIX ソケットで待ち受けさせる。TCP のポートは開かない。
- 最後の頼みから 5 分たったら、`llama-server` を止めてメモリを返す。Aleph を閉じるときも止める。
- 頼みには `json_schema` で上の JSON の形を渡し、温度 0、考える過程を出さない設定で呼ぶ。
- Rust の側で、UNIX ソケットの上の HTTP/1.1 の小さな口を自前で書き、HTTP のクライアントの依存は足さない。

### モデルの管理

ローカルのモデルは、いつも一つ以上入っているようにする。

- **既定のモデル**を、アプリに同梱する。既定のモデルは、下の「既定のモデルの選び方」で決めたものとする。同梱した既定のモデルは、消せない。
- Aleph は、入れられるモデルの一覧を持つ。一覧には、計測した四つの候補を入れ、既定のモデルに印を付ける。各モデルは、名前、配布元のリポジトリ、リビジョン、ファイル名、大きさ、SHA-256、ライセンスを持つ。一覧の外のモデルは入れない。
- 既定のモデルのほかのモデルは、設定のダイアログの「アシスタント」の節から、ダウンロードして入れる。入れたモデルは、そこから消せる。
- ローカルのコネクタが使うモデルは、設定で選ぶ。選んでいないときと、選んだモデルが無いときは、既定のモデルを使う。
- 既定のモデルの同梱は、`tools.versions` と `scripts/bundle-tools.sh` で行う。Hugging Face のリビジョンを固定した URL から取り、`tools.versions` に書いた SHA-256 で照らす。
- ダウンロードは、Rust の側で `/usr/bin/curl` を使い、Hugging Face のリビジョンを固定した URL から取る。取った後に SHA-256 を照らし、合わなければ消す。
- ダウンロードしたモデルは、Tauri のアプリのデータのディレクトリ (`app_data_dir`) の `models/` に置く。このディレクトリは Rust の側だけが読み書きし、画面の側の読み書きの範囲には入れない。

### アシスタントに渡す資料

アシスタントには、頼みと対象のほかに、Golem のリファレンスの一部と Aleph のコマンドの一覧を渡す。

- Golem のマニュアルの章 (`03-markup.gm`、`04-manifest.gm`、`05-style.gm`) を、同梱の golem と同じタグのソースから取り、Aleph に同梱する。`bundle-tools.sh` は、`tools.versions` に書いた各章の SHA-256 で照らす。
- 章は、見出しで節に分ける。
- 対象の種類で章を選ぶ (`.gm` と `.md` は `03-markup`、`manifest.toml` は `04-manifest`、`style.toml` は `05-style`)。
- Aleph のコマンドの名前と説明の一覧を、最初に入れる。
- 選んだ章の節を、頼みの言葉と、対象に出るキーや命令の名前との重なりの数で並べ、上から順に入れる。
- 資料の上限は、トークンの数で、モデルのコンテキストの長さから、決まった指示と頼みと対象の分と、答えのための 1,024 トークンを引いた数とする。コンテキストの長さは、計測で 4,096 と 8,192 を比べて決める。
- 上限に入らない節は、途中で切らずに飛ばし、次の節を試す。

### 既定のモデルの選び方

実装の最初の段で、計測の道具と課題の一揃いを作り、候補を同じ条件で計測する。
候補は、Qwen3-0.6B、Qwen3.5-0.8B、Qwen3.5-2B、Qwen3.5-4B の Q4_K_M とする。

課題の一揃いは、`bench/assistant/` に置く。

- 種類は、`style.toml` の書き換え、`manifest.toml` の書き換え、`.gm` の命令の書き方、Markdown の記法の直し、Aleph のコマンドの尋ね方とする。
- 種類ごとに 10 件以上を置く。
- 各課題は、頼み、対象、正解の判定を持つ。
- 書き換えの課題の判定は、案が適用でき、適用した後のテキストが正解のテキストに等しいこととする。Golem のファイルでは、`golem check` のエラーが増えないことも求める。
- コマンドを尋ねる課題の判定は、`edits` が空で、`explanation` に正解のコマンドの名前か ID が含まれることとする。
- 欠かせない課題に、印を付ける。

計測する値は次のとおりとする。

- 起動からの最初の答えまでの時間
- 起動した後の答えまでの時間 (中央値と p95)
- 最大のメモリ (RSS) と、待っているときのメモリ
- 正解の割合と、欠かせない課題の結果

これらを、全体と課題の種類ごとに集計する。

既定のモデルは、次の三つを満たすもののうち、最大のメモリが最も小さいものとする。

- 欠かせない課題に、すべて正解する。
- 全体の正解の割合が 70% 以上で、どの種類の正解の割合も 50% 以上である。
- 下の「予算」の三つを満たす。

満たすものが無いときは、実装を止め、選び方を変える ADR を書く。
計測の結果は `docs/benchmarks/` に残し、選んだモデルと理由を仕様書に書く。

### 予算

既定のモデルの実行時間と最大のメモリの予算を、次のとおりとし、`docs/budgets.md` にも同じ値を書く。
値は、GitHub Actions の標準の macOS のランナーで、課題の一揃いを既定のモデルで解いたときのものである。

| 名前 | 指標と単位 | 比較 | 値 |
| --- | --- | --- | --- |
| アシスタントの起動からの答え | 起動からの最初の答えまでの時間の p95 (ミリ秒) | `<=` | 30000 |
| アシスタントの答え | 起動した後の答えまでの時間の p95 (ミリ秒) | `<=` | 15000 |
| アシスタントのメモリ | `llama-server` の最大の RSS (MB) | `<=` | 2048 |

計測のコマンドは、`bench/assistant/run --metric <指標>` とし、同じ実行の中で課題の一揃いを解いて、p95 か最大の値を一つ、標準出力の最後の行に出す。
予算の値は、計測の後に見直すときも、ADR で変える。

計測は、GitHub Actions の標準の macOS のランナーと、メンテナーの Mac で一度ずつ行う。
メンテナーの Mac の機種とメモリを、記録に書く。
ランナーでは、GPU に層が載ったか (`llama-server` の記録) も残す。

### 計測を CI で続ける

- main への push と週に一度、標準の macOS のランナーで、一覧のすべてのモデルを計測する。main への push のうち、[ADR 0080](0080-skip-app-checks-for-docs-only-changes.md) で文書だけとみなす変更では走らせない。モデルのファイルは、Actions のキャッシュに置く。
- 結果は、Actions の成果物に残す。
- 前の 4 回の中央値と比べて、答えまでの時間の中央値か p95、または最大のメモリが 20% 以上悪くなったら、回帰とする。正解の割合が、前の 4 回の中央値より 5 ポイント以上下がったときも回帰とする。欠かせない課題が一つでも落ちたときも回帰とする。
- 前の結果が 4 回に満たないうちは、回帰と判定しない。
- 同じ回帰が 2 回続いたら、Issue を立てる。Issue は、モデルと値の組で一つとし、同じ組の Issue が開いていれば、新しく立てずにその Issue に書き足す。
- この計測は、プルリクエストの CI では走らせず、マージを止めない。
- 予算 (`docs/budgets.md`) は、同じ計測の後に、dotfiles の `bin/budget-check` で確かめる。計測のジョブ (`--measure-to`) と、Issue に書くジョブ (`--report-from`) を分け、計測のジョブにはトークンを渡さない。予算の違反の Issue は `bin/budget-check` が立て、上の回帰の Issue とは別にする。

### 文書

- 仕様書に、アシスタント、コネクタ、モデルの管理、選んだ既定のモデルを書く。
- README.md と README.ja.md に、アシスタント、外に送るもの、同梱の既定のモデルと `llama-server`、ほかのモデルのダウンロードを書く。
- `docs/budgets.md` に、上の「予算」を書く。この ADR の提案と同じ変更で書く。
- 用語集に、アシスタントのタブを足す。

## 実装しないこと

- 画像を入力にとること。
- アシスタントが、複数のファイルをまたいで書き換えること。
- アシスタントが、書き手の確かめなしにファイルを書き換えること。
- Codex のコマンドの実行とファイルの読み取りを止めること (止める引数が見つからなかった)。
- API キーで Anthropic や OpenAI の API を直接呼ぶこと。
- 一覧の外のモデルや、書き手の手元にある GGUF を入れること。
- 頼みと答えの履歴を、ファイルに残すこと。
- macOS のほかの OS。

## 不変条件

- I1: 各 `find` が適用のときの対象の範囲にちょうど一度だけ現れ、どの二つの `find` の現れる範囲も重ならないとき、そのときに限り、案を適用できる。
- I2: 適用した後のテキストは、適用の前のテキストで決めた各 `find` の一か所を `replace` に変え、それ以外の文字を変えないものに等しい。
- I3: 適用は、エディタの一つの変更で、一度の取り消しで適用の前のテキストに戻る。
- I4: アシスタントは、書き手が「適用」を押す前に、ファイルもエディタのテキストも変えない。
- I5: `llama-server` を起こす引数は、`--host` に UNIX ソケットのパスだけを持ち、TCP のポートとホストの名前を持たない。
- I6: 書き手が認めていない Claude Code と Codex のコネクタは、起こされない。
- I7: SHA-256 が一覧の値と合わないモデルのファイルは、`models/` に残らない。
- I8: Claude Code か Codex で失敗したとき、同じ頼みをローカルで一度だけ頼み直し、答えにそのことを示す。
- I9: 渡す資料のトークンの数は、上限を超えない。上限に入る節は、重なりの数の順に、飛ばした節を除いてすべて入る。
- I10: ローカルのコネクタが使えるモデルは、いつも一つ以上ある。選んだモデルが無いときは、既定のモデルを使う。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| `find` が対象に一度だけ現れる | 適用できる | I1, I2 |
| `find` が対象に無い | 適用できず、理由を示す | I1 |
| `find` が対象に二度現れる | 適用できず、理由を示す | I1 |
| `find` が空の文字列 | 適用できない | I1 |
| `edits` が空 | 何も変わらない | I2 |
| 二つの `find` が、それぞれ一度だけ現れ、範囲が重なる | 適用できない | I1 |
| 二つの `find` が、それぞれ一度だけ現れ、範囲が隣りあう | 適用でき、二か所が変わる | I1, I2 |
| 頼んだ後に、書き手が対象の範囲の外を書き換えた | 今のテキストで数えなおして適用できる | I1 |
| 頼んだ後に、書き手が選択の範囲の中を書き換えた | 適用できず、理由を示す | I1 |
| 適用の後に一度取り消す | 適用の前のテキストに戻る | I3 |
| 答えが返ったが、まだ「適用」を押していない | ファイルもエディタも変わらない | I4 |
| `llama-server` の引数を組み立てる | `--host` は `.sock` のパスで、`--port` が無い | I5 |
| 承認していない Claude Code を選んで送る | `claude` を起こさない | I6 |
| ダウンロードしたファイルの SHA-256 が合わない | ファイルは消え、理由を示す | I7 |
| `claude` が 0 でない状態で終わる | ローカルで頼み直し、そう示す | I8 |
| `codex` が時間切れになる | ローカルで頼み直し、そう示す | I8 |
| 選んだ章の節が無い | 資料はコマンドの一覧だけ | I9 |
| 節の合計がちょうど上限 | すべての節が入る | I9 |
| 節の合計が上限を一トークン超える | 最後に試した節が入らない | I9 |
| 大きい節が上限に入らず、その後の小さい節は入る | 大きい節を飛ばし、小さい節が入る | I9 |
| ダウンロードしたモデルが一つも無い | 既定のモデルを使う | I10 |
| 選んでいたモデルを消した | 既定のモデルを使う | I10 |
| 設定のダイアログで既定のモデルを消そうとする | 消せない | I10 |

## 受けいれ条件

- A1: 計測の結果が `docs/benchmarks/` にあり、既定のモデルがその結果と上の規則で選ばれている。
- A2: アシスタントを使ったことの無い Mac で、ネットワークを切ったまま、アシスタントのタブから頼むと、ダウンロードなしで答えが返る。
- A3: `style.toml` を開き「行送りを少し広げて」と頼むと、`line-pitch` を変える案と差分が出て、「適用」で当たり、⌘Z で戻る。
- A4: ネットワークを切っても、ローカルのコネクタで答えが返る。
- A5: Claude Code を選び、ログアウトした状態で頼むと、ローカルで頼み直した答えが出る。
- A6: 5 分頼まないと、`llama-server` のプロセスが無くなる。
- A7: 既定のモデルが、上の「予算」の三つを満たす。

## テスト設計

- 案の適用 (I1、I2、I3、I4) は、純粋な関数として TypeScript で書き、境界の表の各行をテストする。名前は `ADR 0081 I1: …` とする。
- `llama-server` の引数 (I5) は、引数を組み立てる Rust の関数をテストする。
- コネクタの承認と頼み直し (I6、I8) は、CLI を偽の実行ファイルに差し替えて、Rust と TypeScript でテストする。偽の実行ファイルは、0 でない状態で終わるもの、形の合わない JSON を返すもの、時間切れになるもの、起こされたことを記録するものを用意する。
- SHA-256 の照らし合わせ (I7) は、Rust で、合うファイルと合わないファイルでテストする。
- 資料の選び方 (I9) は、Golem のマニュアルの節と、トークンの数を数える関数を差し替えて、境界の表の行をテストする。
- 計測の課題の判定は、正解と不正解の答えでテストする。
- A1 は、メンテナーが `docs/benchmarks/` の記録と選び方の規則を照らして確かめる。
- モデルの選び方 (I10) は、モデルの一覧と `models/` の中身を入力にとる純粋な関数として書き、境界の表の行をテストする。
- A2 から A6 は、デバッグ版で手で確かめる。A2 と A4 は、Wi-Fi を切って確かめる。
- A7 は、予算の一覧の計測のコマンドで確かめる。

## トレードオフ

既定のモデルを同梱すると、アプリの大きさが、そのモデルの分 (候補の中で 397 MB から 2,741 MB) 増え、アシスタントを使わない書き手にも、その分を配ることになる。
一方、使うときに取りにいく形では、初めて使うときにネットワークが無いと答えが返らず、ダウンロードの失敗にも出会う。
書き手がエラーに出会う回数を減らすことを重く見て、大きさの増えを受けいれる。
既定のモデルの選び方は、最大のメモリが最も小さいものを選ぶので、増える大きさも候補の中で小さい側になる見込みである (推測)。

`llama-server` を常に起こしておけば、答えが速くなる。
しかし、アシスタントを使わないあいだもメモリを使う。
5 分の待ちで止める形は、続けて頼むときの速さと、使わないときのメモリを両立させる。
5 分という値は、計測の後に見直す。

書き換えを JSON の案で受けると、モデルが全文を書き直すより、対象の外を壊しにくい。
一方、小さなモデルは、一度だけ現れる `find` をうまく選べないことがある。
その割合は、計測の正解の割合に表れるので、計測の結果で判断する。

Qwen3.5 の GGUF は、Qwen の公式のものが無く、第三者が作ったものを使う。
配布元のリビジョンと SHA-256 で固定して、取ったファイルが変わらないようにする。

Claude Code と Codex は、書き手のアカウントで動き、頼みと対象を外に送る。
Codex は、読むだけのサンドボックスでも、コマンドを走らせてファイルを読める。
作業のフォルダを空の一時フォルダにして、原稿のフォルダから離すが、ディスクのほかの場所を読むことは止められない。
そのため、初めて使うときに、このことを示して書き手の承認を受け、既定はローカルのままにする。

`claude` と `codex` をログインシェルの PATH で探すと、書き手のシェルの設定を一度走らせることになる。
しかし、mise や Nix で入れた CLI は、決まった場所に無いので、ほかに見つける手段が無い。
