# ADR 0028: シートのキーワード

ステータス: 採択（未実装）

## 文脈

Ulysses はシートにキーワードを、Obsidian はノートにタグを付け、それで絞り込んで横断して集められる。
Aleph のシートには、目標、ノート、書くことのチェックがある（[ADR 0012](0012-sheet-goals-and-notes.md)）が、書き手が自分で付ける分類はない。

メンテナーは、Obsidian と Ulysses にあって Aleph にない機能を比べ、キーワードの ADR を求めた（2026-11-07）。

今の Aleph の関わる部分は次のとおりである。

- シートのメタデータは、プロジェクトの（プロジェクトの外のシートはワークスペースの）`.aleph/notes.json` に、ルートからのパスをキーとして置く（[`app/notes.ts`](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/notes.ts)）。中身のない項目は書き出さず、Aleph で名前を変えるとキーも変える。
- 右のパネルの「添付」には、すでに「キーワード」の節がある。これは、プロットの表（[ADR 0013](0013-plot-and-gantt-chart.md)）のそのシートの行の、視点人物、登場人物、場所、サブプロットを、色を分けて並べたもので、書き換えられない（[`app/attach.ts`](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/attach.ts)）。
- 左のサイドバーのパネルは、ファイル、検索、Git、診断、共有ライブラリである（[`app/store.ts`](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/store.ts) の `LeftPanel`）。

## 実装すること

### 持ち方

- シートのメタデータに、キーワードの並び（`keywords`、文字列の配列）を足す。付けた順を保ち、同じキーワードは一つにまとめる。空の並びは書き出さない。
- キーワードは前後の空白を除いた空でない文字列とし、Unicode の正規化（NFC）をそろえて比べる。大文字と小文字は区別する。

### 添付のパネルで付ける

- 「添付」の「キーワード」の節を、二つの並びにする。
  - **このシートのキーワード**：書き手が付けたもの。各キーワードに × を付けて外せるようにし、末尾の入力欄で Enter を押すと足す。入力欄は、同じルートのシートに付いているキーワードを、打った文字で始まるものから候補に出す。
  - **プロットから**：今までの、プロットの行から読んだもの（視点人物、登場人物、場所、サブプロット）。今までどおり書き換えられない。
- 二つの並びに同じ文字があっても、それぞれに出す（出どころが違うため）。

### キーワードのパネルで集める

- 左のサイドバーに「キーワード」のパネルを足す。
- 今のワークスペースのすべてのルート（プロジェクトとワークスペース）の `.aleph/notes.json` から、書き手が付けたキーワードを集め、件数とともに名前の順に並べる。プロットから読んだキーワードも、出どころ（登場人物、場所など）ごとの見出しの下に並べる。
- キーワードを押すと、それを持つシートの一覧を、ツリーと同じ名前（最初の見出しとファイル名）で出し、押すとそのシートを開く。⌘ を押しながら押すと、選んだキーワードをすべて持つシートに絞る（かつ）。
- キーワードの行のメニューから、名前を変える、すべてのシートから外す、ができる。名前を変えるときは、同じ名前がすでにあれば一つにまとめることを確かめる。プロットから読んだキーワードは、ここでは変えない（プロットの表で変える）。

### 名前を変えたとき

- ファイルの名前を変えたときは、今までどおり、メタデータのキーを変える（[ADR 0012](0012-sheet-goals-and-notes.md)）。キーワードも一緒に移る。

## 実装しないこと

- 本文の中の `#タグ` の読み取り（`.gm` と `.md` では `#` は見出しの記号である）。
- 入れ子のキーワード（`人物/主人公` のような階層）。
- キーワードごとの色の設定。
- ツリーの行へのキーワードの表示。
- プロットの表への、書き手が付けたキーワードの書き戻し。

## テスト設計

DOM に触れない部分を関数に分け、`node --test` で確かめる。テストを先に書いて失敗させてから実装する。

- メタデータ：`keywords` を読み書きすること、空の並びを書き出さないこと、前の版の `.aleph/notes.json`（`keywords` のないもの）を読めること、名前を変えたときにキーワードがキーと一緒に移ること。
- キーワードの操作：足す（前後の空白を除く、空を足さない、重ねて足さない、NFC と NFD の同じ文字を一つにする）、外す、付けた順を保つこと。
- 集め方：複数のルートの `notes.json` から、件数と名前の順の一覧を作ること。プロットの行から読んだキーワードを出どころごとに分けること。
- 絞り込み：一つのキーワードのシート、複数のキーワードをすべて持つシート。
- 名前の変更と外す：すべてのシートで変わること、同じ名前に変えたときに一つにまとまること。
- 候補：打った文字で始まるものを、件数の多い順に出すこと。
- 画面の確かめ方：見本のプロジェクトのいくつかのシートにキーワードを付け、添付のパネルで足して外せること、キーワードのパネルで件数とシートが出て開けること、⌘ での絞り込み、名前の変更、`.aleph/notes.json` の中身を確かめる。

## トレードオフ

- キーワードを本文ではなくメタデータに置くので、原稿の中身を変えずに付けられ、Golem の組版にも影響しない。その代わり、Aleph の外（ほかのエディタや Git の差分）では、本文を見てもキーワードがわからない。
- 書き手のキーワードとプロットの項目を、一つにまとめずに並べて出す。まとめると、どちらで直せばよいかがわからなくなるためである。そのため、同じ人物の名前が二か所に出ることがある。
