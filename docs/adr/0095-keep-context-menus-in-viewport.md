# ADR 0095: コンテキストメニューを画面内に収める

Status: proposed

## 文脈

指示者から、画面端でコンテキストメニューが画面外に出るとの報告があった（2026-11-22）。
ウィンドウ内のどこから開いても、すべての項目へ到達できるようにする。

## 調査した事項

調査したコミットは `8a102bdfa38df9fb2fa7a0852a5ca7da39d186af` である。
[`menu`](https://github.com/tett23/aleph/blob/8a102bdfa38df9fb2fa7a0852a5ca7da39d186af/app/ui/dom.ts#L62) はメニューをアンカーの下端から4px下へ置く。
横位置は幅260pxを仮定して制限するが、高さを測って下端を制限する処理は無い。
[`app/ui/tree.ts`](https://github.com/tett23/aleph/blob/8a102bdfa38df9fb2fa7a0852a5ca7da39d186af/app/ui/tree.ts#L430) の右クリックもこの共通関数を使う。

## 実装すること

共通のメニューを DOM に追加し、実際の幅と高さを測ってから位置を確定する。
表示領域は OS のディスプレイではなく、そのメニューを開いた WebView の可視領域とする。
可視領域に4pxの余白を設け、その内側を配置領域とする。
寸法が8px未満の場合、その軸の余白は0にする。

アンカーの下に収まる場合は下に置く。
下に収まらず上に収まる場合は上に置き、どちらにも収まらない場合は配置領域内に位置を制限する。
横位置はアンカーの左端を優先し、右端を超えた分だけ左へ移す。
アンカー自体が画面外にある場合も配置領域を優先する。

メニューが配置領域より大きければ、その幅と高さを最大寸法にし、長いラベルを折り返してメニュー内をスクロールできるようにする。
項目は削除しない。
ウィンドウのサイズ変更時には再配置し、閉じたら監視を解除する。
実装時に仕様書と README のメニューの説明を更新する。

## 実装しないこと

項目順の変更、OS ネイティブメニューへの置き換え、新たなメニュー階層。

## 不変条件

- I1: 開いたメニューの外接矩形は、正の面積を持つ配置領域の内側に収まる。
- I2: 渡された項目の順序と個数は配置によって変わらず、あふれる項目にもスクロールで到達できる。
- I3: 位置の調整と再配置では項目の操作を実行しない。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 中央、メニュー1項目 | アンカーの下 | I1 |
| 右下端 | 左または上へ調整して全体を表示 | I1 |
| ちょうど収まる、1pxあふれる | 前者は維持、後者は制限 | I1 |
| メニューが画面より高い、長いラベル | 寸法を制限し全項目へ到達 | I1, I2 |
| 開いた後に縮小 | 再配置、操作の実行なし | I1, I3 |

## 受けいれ条件

- A1: ツリーの上下左右の端で右クリックし、全項目を見て選べる。
- A2: 最小ウィンドウ寸法と拡大表示で、最後の項目までスクロールして選べる。

## テスト設計

配置計算を純粋な関数として切り出し、`ADR 0095 I1: …` の形で境界表を検査する。
現在の下端超過を再現するテストを先に失敗させる。
DOM のテストでは測定後の寸法、スクロール、閉じた後の監視解除を検査する。
A1 と A2 は Tauri で確認する。

## トレードオフ

寸法の測定が必要になるが、項目数や文字の幅に依存した固定値を取り除ける。
画面より大きなメニューの全項目を同時には表示できないため、メニュー内のスクロールを使う。
