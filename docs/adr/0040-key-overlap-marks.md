# ADR 0040: キーの割り当ての一覧で、先頭の重なりを印として示し続ける

ステータス: 採択（未実装）

## 文脈

[ADR 0034](0034-key-bindings.md) は、ちょうど当たる割り当てがほかの長い割り当ての先頭でもあるとき（`Leader g` と `Leader g c` など）、待つ時間が過ぎるまで短いほうを実行しないと決めた。
あわせて、「設定の画面では、この重なりを注意として示す」とした。

実装は、割り当てを記録した直後に、重なりを通知で一度だけ知らせる（[app/keybind.ts](https://github.com/tett23/aleph/blob/3ec575e/app/keybind.ts#L132)）。
設定の画面の一覧には、重なりの印がない。
あとから設定を開いたときや、リーダーキーを変えて重なりができたときに、重なりに気づく手がかりがない。
[ADR 0021](0021-json-files.md)〜0035 を実装と照らしたレビューで、この食い違いが見つかった。
メンテナーは、レビューで残った点のすべてについて ADR を書くよう求めた（2026-11-08）。

## 実装すること

- 設定の「キーの割り当て」の一覧で、ほかの割り当ての先頭と重なる割り当ての `kbd` の横に、注意の印を出す。印の説明（ツールチップ）に、重なる相手の操作の名前と、「待つ時間が過ぎるまで短いほうは実行されません」を出す。
- 重なりは、今の割り当て（利用者の割り当てと既定）とリーダーキーから、一覧を描くたびに求める。リーダーキーを変えたときも、描き直した一覧に出る。
- 一覧の上に、重なりのある割り当ての数を出す（「先頭が重なる割り当て：2」）。ないときは出さない。
- 記録した直後の通知は、今のまま残す。
- 重なりを求める処理は、[ADR 0034](0034-key-bindings.md) の `conflicts` を使い、操作ごとの重なりの一覧を返す DOM に触れない関数（`overlaps`）に分ける。

## 実装しないこと

- 重なりを禁じること（重なりは [ADR 0034](0034-key-bindings.md) のとおり許す）。
- 重なりを自動で解くこと。

## テスト設計

`node --test` で、テストを先に書いて失敗させてから実装する（app/keymap.test.ts）。

- `Leader g` と `Leader g c` があるとき、両方の割り当てに相手が重なりとして出ること。
- 重なりのない割り当てには出ないこと。
- リーダーキーを変えても、`Leader` を含む割り当ての重なりが同じに求まること。
- 既定の割り当てと利用者の割り当てのあいだの重なりも出ること。
- 画面の確かめ方：`Leader g` と `Leader g c` を割り当て、設定を開き直して両方の行に印と説明が出ること、一方を外すと印が消えることを確かめる。

## トレードオフ

- 一覧を描くたびにすべての割り当ての重なりを求める。割り当ての数は百に満たないので、二重の繰り返しでも描く時間に響かない。
