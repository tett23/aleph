# ADR 0066: gm の章登録を切り替え、選択した原稿を書き出す

ステータス: 採択（未実装）

## 文脈

原稿をプロジェクトに置くこと、章として組版すること、選んだ部分を取り出すことには、それぞれ別の操作が要る。

## 実装すること

プロジェクト内の `.gm` 行には、未登録なら「chapters に追加」、登録済みなら「chapters から削除」を出す。
追加時はプロジェクト相対パスを末尾に置く。
削除時は文字列、`file` 付きの表、入れ子の配列から対象の参照をすべて除き、空になった入れ子を取り除く。
他の章の順序、属性、配列の書式を保つ。
manifest の読み取りや更新に失敗したら通知する。

ツリーでの複数選択には既存の gm の選択操作を使う。
⌘クリックで gm の選択を切り替え、Shift クリックで表示順の範囲にある gm を選び、従来どおり選択した原稿を開く。
選択内の右クリックは選択を保ち、選択外ならその行だけを選ぶ。
章登録は右クリックした一件に作用する。

一件以上を選び、すべての選択行が `.gm` のとき「選択した原稿を書き出す」を出す。
保存ダイアログで選んだ一つの `.gm` に、ツリーの上から順に本文を書く。
開いているシートは編集中の本文を使い、隣り合う本文の間には LF を二つ挿入する。
入力自身への上書きは拒み、全入力を読めた後で出力を一括で置き換える。
[ADR 0050](0050-paths-the-writer-chooses.md) のパス選択の方針を、書き出し専用の Rust コマンドに適用する。
このコマンド自身がネイティブの保存ダイアログを開き、選ばれたファイルへの今回の書き込みだけを許す。
既存ファイルの置き換えはダイアログで確認する。

## 実装しないこと

書き出し時の組版と章登録。

## 不変条件

1. 追加後の対象参照は一つ、削除後はゼロで、どちらの操作でも gm の内容は変わらない。
2. 書き出す本文の個数と順序は選んだ gm の個数と表示順に一致する。
3. 取消または読み取り失敗なら出力先の内容は変わらない。

| 境界の入力 | 期待する結果 |
| --- | --- |
| 登録ゼロ、同じ章が入れ子に二件 | 追加で一件、削除ですべて解除 |
| 選択ゼロ、異種混在 | 書き出しを提示しない |
| 一件、逆順に選んだ二件 | 本文そのまま、表示順で結合 |

## テスト設計

不変条件ごとに番号をテスト名に含め、上表の入力について実装前に失敗を確かめる。
一時プロジェクトの manifest と書き出したファイルを読み戻し、属性を持つ隣の章と既存の出力先も比較する。

## トレードオフ

原稿の結合順を画面で確かめられる一方、クリックした順に並べ替える用途には使えない。
