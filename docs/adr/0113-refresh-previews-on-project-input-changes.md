# ADR 0113: Emet、マニフェスト、スタイルの変更でプレビューを更新する

Status: accepted-pending

## 文脈

Golem のプロジェクトでは、章を編集せずに Emet の関数、マニフェストの章構成、スタイルの判型を変えることがある。
その変更を保存したら、プロジェクトの本文とページのプレビューで結果を確かめたい。

## 調査した事項

保存時の本文の組み直しは、保存内容の変わった `.gm` を対象にする。
保存時のページの組み直しも、保存したファイルの形式を `.gm` に限っている。
本文はプロジェクトの XHTML を生成し、ページはプロジェクトの PDF を生成してページ画像にする。
[本文とページの組版](https://github.com/tett23/aleph/blob/d80b1a65028e7e7655a216d95e5679de062b45ec/app/preview/mount.ts)、[ページの組み直しの判定](https://github.com/tett23/aleph/blob/d80b1a65028e7e7655a216d95e5679de062b45ec/app/preview/tab.ts)

ファイルの変更の見張りは、ワークスペースで変わったパスを画面側に渡す。
エディタへの読み直しは、開いているシートを対象にする。
そのため、開いていないファイルの変更は、エディタの保存通知だけでは拾えない。
[ファイルの変更の見張り](https://github.com/tett23/aleph/blob/d80b1a65028e7e7655a216d95e5679de062b45ec/app/watchmount.ts)

## 実装すること

### 更新の対象

Golem のプロジェクトに属する `.emet` と、プロジェクトのルートにある `manifest.toml` と `style.toml` を **プレビューの入力ファイル** とする。
プロジェクトの所属は、ワークスペースのツリーと同じ規則で決める。
プロジェクト内のサブフォルダにある `.emet` も対象とする。
`build/` の下は対象から外す。
対象とするのは、変更の前後で同じ Golem プロジェクトに属する入力と、そのプロジェクトで追加または削除された `.emet` と `style.toml` である。

Aleph での保存と、[ADR 0063](0063-watch-files-changed-outside.md) のファイルの変更の見張りで、ディスク上の入力の変化を拾う。
見張りでは、エディタで開いていない入力ファイルも扱う。
更新を判断するときは、保存前の状態か最後に確認したディスク上の状態と、変更後のファイルの有無と内容を照合する。
各プロジェクトのプレビューを初めて組む前に、入力ファイルの一覧と内容を記録する。
比較元がまだ無いときは、その時点の入力から初回の組版を行う。
書き込みに失敗した場合と内容が同じ場合は、組版を要求しない。
保存と見張りの両方で同じ書き込みを拾った場合は、同じ変更として一度だけ扱う。
見張りで先に拾った変更が明示保存によるものと分かった場合は、ページの組版が待機中なら待機を解除する。
保存に整形が伴う場合は、整形前の保存内容と最終保存の内容を比べる。
整形のための中間書き込みは、ファイルの変更の見張りで拾った場合も組版を要求しない。

### 本文の更新

入力が変わったプロジェクトに開いている `.gm` があれば、`golem build --target html` をプロジェクトごとに要求する。
組み直した XHTML で、そのプロジェクトの本文のプレビューをタブと別ウィンドウで更新する。
開いている `.gm` が無ければ、次に本文を表示するときに組む。
組み直した時点のマニフェストから章に登録されていないと分かったシートは、既存の記号を取り除いた本文に戻す。
入力の変更前に取得した XHTML は、表示済みの本文を保つために使う。
変更後に章を開いた場合は、その変更を反映した XHTML を使う。

### ページの更新

設定の「保存したらページを組みなおす」がオンで、変更したプロジェクトが次のいずれかに当てはまる場合にページを組み直す。

- 前のページの結果がある。
- 最初のページの組版が進行中である。
- そのプロジェクトの `.gm` を映すプレビューのタブでページのモードを選んでいる。

変更を保存したファイルをエディタで選んだままでも、前の結果がある同じプロジェクトのページを更新する。
タブと別ウィンドウには、同じ組版結果を届ける。
この決定は [ADR 0087](0087-preview-in-a-tab.md#保存の後の組みなおし) の判定と I10 に、プレビューの入力ファイルが変わったときの条件を加える。

ページを組む時機は、[ADR 0072](0072-refresh-pages-on-explicit-save.md) と [ADR 0056](0056-wait-before-building-pages.md) に従う。
明示保存では最終保存後すぐに組版を要求し、自動保存と見張りでは同じプロジェクトの最後の編集から 5 秒たつまで着手を待つ。
最後の編集から 5 秒以上たっているか、編集の記録が無ければ、待ち時間を加えない。
待ち時間の満了時と、進行中の組版の後で、変更がページにすでに反映されていれば後続の組版を省く。

ページの更新では、Golem が新しい PDF を作ってから shem がページ画像を作る。
ページの順序と組み方向は組版時のマニフェストとスタイルから求める。
解像度が自動なら、同じスタイルから新しい判型と塗り足しを読み、解像度を計算し直す。

### 結果の表示

組版の要求が同じプロジェクトと出力形式で重なったときは、未着手の要求を一回にまとめる。
組版中に再び変わった入力が組版結果に反映されていなければ、最新の入力で後続の組版を行う。
最新の要求より古い世代の結果は破棄する。
組版中と失敗時の表示、および成功時のスクロール位置の扱いは、[ADR 0097](0097-restore-preview-scroll-on-refresh.md) に従う。
マニフェストでページの章のパスや順序が変わった場合は、新しい表示対象として扱う。

実装時に、[仕様書のプレビューの節](../specifications.md#プレビュー) と [README](../../README.md)、[日本語の README](../../README.ja.md) に、更新の対象と時機を反映する。

## 実装しないこと

Golem の章と Emet の間の依存関係の解析、入力ファイルの未保存の編集を使った組版、マニフェストの追加と削除によるプロジェクトの登録と解除の変更。

## 不変条件

- I1: プレビューの入力ファイルが変わった場合、組み直しの対象になるのはそのファイルが属するプロジェクトだけである。
- I2: 同じ内容の書き戻し、書き込みの失敗、保存通知と重複した見張りの通知は新しい組版要求を生まない。
- I3: 設定と対象プロジェクトのページの状態が条件を満たすとき、明示保存では 5 秒の待ちを設けず、自動保存と見張りでは最後の編集から 5 秒が過ぎるまで組版の着手を待つ。
- I4: 同じプロジェクトの同じ出力形式で未着手の組版要求が重なったとき、後続の組版は、反映を要する変更があれば最新の入力で一回、無ければゼロ回になる。
- I5: ページの更新に成功したとき、ページ画像の元になる PDF と、章の順序、組み方向、自動解像度は、同じ組版に使った入力から得る。
- I6: 本文の更新に成功したとき、新しいマニフェストから外れた章には、その章の XHTML が出力先に残っていても、記号を取り除いた本文を表示する。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| プロジェクト A のサブフォルダの `.emet` を保存し、A と B に開いている章がある | A の本文を組み直す。B の組版はゼロ回 | I1 |
| 別のプロジェクトの `style.toml`、または A のルート以外の `style.toml` を保存 | A の本文もページも組み直さない | I1 |
| A に開いている章があり、開いていない A の `.emet` を外部で更新 | A の本文を組み直し、ページは設定と状態に従う | I1, I3 |
| 保存に続く同じ書き込みの通知、内容が同じ保存、または保存失敗 | 新たな組版要求はゼロ | I2 |
| 整形のための中間書き込みを見張りが拾い、後で最終保存が完了 | 更新の判定は最終保存で一回だけ行う | I2, I3 |
| ページの更新条件を満たし、明示保存の通知より先に見張りの通知でページの組版が待機した | 明示保存の通知で待機を解除し、一回組む | I2, I3 |
| ページの前の結果があるプロジェクトで、設定がオンまたはオフのときに `manifest.toml` を明示保存 | オンではすぐにページの組版を要求し、オフでは要求はゼロ | I3 |
| 自動保存後、最後の編集から 4,999 ms または 5,000 ms | 4,999 ms では待機し、5,000 ms に未反映の変更があれば組む | I3 |
| 設定がオンで、ページの初回組版が入力を読んだ後に `.emet` を続けて二回明示保存 | 初回の後、最後に保存した内容で一回組む | I3, I4 |
| `manifest.toml` の章順と `style.toml` の判型を変えて保存 | 新しい章順の PDF を、新しい判型に合う自動解像度で描く | I5 |
| 章をマニフェストから外し、前の XHTML が出力先に残っている | そのシートの本文から記号を取り除いた表示に切り替わる | I6 |

## 受けいれ条件

- A1: 本文のプレビューをタブと別ウィンドウに開く。Aleph で章が呼ぶ `.emet` の関数を変更して保存し、章のタブに戻ると、両方の本文に新しい結果が出る。
- A2: ページのプレビューを別ウィンドウに開いてから、`manifest.toml` の章順と `style.toml` の判型を順に変更して保存すると、それぞれの変更がページに出る。
- A3: 本文とページのプレビューを開き、保存時のページ更新をオンにする。Aleph のエディタで開いていない `.emet` を別のエディタで保存すると、その関数を使う章の本文とページに変更が出る。

## テスト設計

I1 と I2 は、保存とファイルの変更の見張りに異なるプロジェクトとパスを渡し、組版要求の対象と数を TypeScript のテストで確かめる。
初回組版後に届いた見張りの通知では、開いていない入力ファイルの内容が同じ場合と変わった場合を比べる。
I3 と I4 は、仮の時計と完了時刻を制御できる組版を使い、設定、初回組版中、待機中の保存の重なり、変更を元に戻す保存を確かめる。
I5 は、マニフェストとスタイルを差し替え、組版結果の通知と shem へ渡す解像度を確かめる。
I6 は、章を外したマニフェストと、外した章の XHTML が残る出力先を用意し、本文に記号を取り除いたテキストが出ることを確かめる。
テスト名の先頭には `ADR 0113 I1: ` のように ADR と不変条件の番号を付ける。

A1 から A3 は Tauri のデバッグ版で、Emet の関数を呼ぶ章を二つ持つ Golem のプロジェクトを用意して手で確かめる。
A2 では、保存時のページ更新をオフにしてスタイルをもう一度変更し、自動ではページが組み直されないことも確かめる。

## トレードオフ

プロジェクトに属する `.emet` を対象にするため、章から参照されていない関数ファイルを保存したときも組み直しが起こる。
依存関係を Aleph が別に解決する手間を省き、間接的に読み込まれるファイルの変更も拾える。
