# ADR 0122: ローカル Qwen のファイル参照を対象のプロジェクトに限る

Status: accepted

## 文脈

原稿、組版設定、Emet の関数は別々のファイルに置かれる。開いているシートだけでは答えに必要な定義が分からないときは、同じプロジェクトにあるファイルをアシスタントが読めるようにする。
ローカル Qwen が追加で参照するファイルは、利用者が選んだ対象のプロジェクト内に限る。

## 調査した事項

通常の依頼でモデルに渡すのは、選んだ範囲かシートの本文と補足資料である。「原稿全体」では、マニフェストに列挙された章も読む。補足資料を組む段階で、モデルがプロジェクトのファイルを列挙したり追加で読んだりする契約はない。
[現行の仕様](../specifications.md#アシスタントのローカルの推論とモデル)、[ADR 0117](0117-expand-assistant-context.md)

現行の Claude Code はツールを無効にして起動する。Codex は空の作業ディレクトリと `--sandbox read-only` で起動するが、その指定はファイルの読み取り範囲を対象プロジェクトに限定しない。
[ADR 0081](0081-assistant-with-local-llm-and-connectors.md)

## 実装すること

### プロジェクトの読み取り範囲

Rust は依頼開始時に、利用者が選んだ対象シートが属する Golem プロジェクトを確定する。登録済みワークスペース内のマニフェストから、既存のプロジェクト所属の規則でルートを求める。モデルが答えに書いたパスやフォルダ名でルートを決め直さない。依頼の途中で別のタブを開いても、参照の範囲は変わらない。

プロジェクトに属さないシートは、利用者が選んだ本文だけを入力に使う。同じフォルダやワークスペースにあるほかのファイルを追加で読む権限は発行しない。Aleph が同梱するマニュアルは固定資料として扱う。 [ADR 0121](0121-preload-golem-manual-for-local-assistant.md)

### 列挙と読み取り

ローカルモデルは、プロジェクト内のファイル一覧と、選んだファイルの読み取りを Rust に要求できる。マニフェストに載っていないファイルや閉じているシートも対象になる。Rust はプロジェクトからの相対パスで結果を返し、回答に参照したファイルの相対パスを表示する。

読み取るときは、パスの各要素を検査する。絶対パス、`..` を含むパス、プロジェクト外を指すリンクを拒む。プロジェクト内を指すリンクは、リンク先が同じプロジェクト内にあり、ルートから安全に開けた場合に読める。Rust は確認済みのルートからファイルを開き、同じファイルのハンドルから読む。確認後にリンクが置き換わっても、プロジェクトの外の名前を開き直さない。列挙と読み取りは通常ファイルに限り、シンボリックリンクで別のツリーへ降りない。

開いているテキストシートについては、プロジェクト内にあることを Rust が確かめてから、依頼時点の未保存の本文を使う。閉じているファイルはディスクから読む。選んだモデルが扱える形式を入力に使い、変換や読み取りに対応しない形式は読めなかったことを示す。

選んだテキストファイルが UTF-8 で 8 KiB 以下で、残りのコンテキストに収まる場合は全文を渡す。それより大きい場合や全文が収まらない場合は、指定された行範囲を試す。回答には実際に渡した行範囲を示す。

### コネクタと編集案

プロジェクトを検索して読む経路はローカル Qwen に開く。追加で読んだファイルは外部コネクタに送らない。Codex と Claude Code の起動引数、承認、頼みの渡し方には [ADR 0081](0081-assistant-with-local-llm-and-connectors.md) を適用する。

参照したファイルを編集対象に加える操作は利用者が行う。編集案の適用には、既存の対象指定と確認の手順を使う。

## 実装しないこと

ローカル Qwen からのファイル書き込み、任意のコマンド実行、プロジェクト外の参照を許可する設定。

## 不変条件

- I1: 一つの依頼で追加参照できる範囲は、Rust が依頼開始時に確定した一つの Golem プロジェクト内に限る。
- I2: 列挙と読み取りは、絶対パス、親への移動、リンクやその置換によって範囲の外のファイルを返さない。
- I3: 参照したファイルに対する編集権限は発行せず、追加参照で得た内容は外部コネクタへ渡さない。
- I4: 参照に選んだ 8 KiB 以下のテキストが残りのコンテキストに収まるとき、指定された行範囲によらず全文を渡す。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 章に登録していないプロジェクト内の `.emet` を参照する | 閉じていても読み、回答に相対パスを示す | I1 |
| 同じファイルを開いて未保存の変更を加える | 依頼時点の未保存の本文を使う | I1 |
| 短いファイルに対してモデルが1行目だけを指定する | コンテキストに収まれば、末尾まで渡してその行範囲を示す | I4 |
| 同じワークスペースの別プロジェクトへの相対パス、絶対パス、外を指すリンクを渡す | 内容を返さない | I1, I2 |
| 検査のあとにリンク先をプロジェクト外へ置き換える | プロジェクト外の内容を返さない | I2 |
| プロジェクト外のシートから同じフォルダの別ファイルを求める | 追加参照を拒む | I1 |
| 参照したシートへの書き込みをモデルが求める | 書き込みを拒む | I3 |
| プロジェクトに結び付いた依頼で Codex を選ぶ | 従来の確認のあと従来の引数で起動し、ローカル Qwen の追加参照は起きない | I3 |

## 受けいれ条件

- A1: `.gm` から呼ぶ関数の定義が閉じた `.emet` にある試験プロジェクトで、ローカルモデルが定義を参照し、回答にその相対パスが出る。

## テスト設計

Rust のテストでは、対象のプロジェクトと同じワークスペース内に別プロジェクトを置く。通常ファイル、内部と外部を指すリンク、検査と読み取りの間のリンク置換、開いたシートのスナップショット、対象にプロジェクトがない場合を確かめる。差し替えた外部コネクタと既存の起動引数のテストで、ローカルの追加参照が外部に渡らず、Codex が従来どおり起動できることを確かめる。
macOS の開発版で、章から呼ぶ Emet の関数を閉じたままアシスタントに質問し、参照の相対パスと回答に使われた定義を確かめる（A1）。
全文参照の単体テストでは、8 KiB と 1 バイト超のファイル、ディスク上の版と長さが違う未保存の本文、プロジェクト外を指すリンクを使う。

## トレードオフ

プロジェクト全体を毎回読み込むと、大きいプロジェクトでは本文と回答の枠が足りなくなる。必要なファイルだけを追加で読むと、対象を探すために推論が数回に分かれる。
