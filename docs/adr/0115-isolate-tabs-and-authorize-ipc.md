# ADR 0115: タブを隔離し、Rust のコマンドを権限で制限する

Status: proposed

## 文脈

プレビューのエラーをドラッグすると、別のペインのエディタで文字が選ばれることがある。
タブを操作した入力は、そのタブの中で完結させたい。
また、利用者が入れた Aleph の拡張から、別タブの DOM やエディタを直接操作できると、公開した操作だけに権限を絞れない。

## 調査した事項

macOS 27.0 の WKWebView で、左に焦点のある `contenteditable`、右に文字を選択できないプレビューのエラーを置いた。
AppKit のマウスイベントで、右のエラー欄内だけを押してドラッグし、同じ欄で離した。
押下と解放の DOM イベントはどちらも右のエラー要素を指したが、左エディタの二行が選ばれ、選択の始点と終点は左に入った。
右を `sandbox="allow-scripts"` の iframe に置き換えて同じ操作をすると、親の左エディタに範囲選択は生じず、親で焦点を持つ要素は iframe になった。
これは最小構成での再現であり、Aleph の全タブを iframe に移したときの動作は実装時に確かめる。

Aleph の各タブは親の一つの DOM 文書に置かれている。
プレビューの初回の描画に失敗すると、選択を許す `.plain` を付けない `pre.error` を描く。
エディタは文書全体の `selectionchange` を受け、選択の両端がエディタにあると、エディタの選択に反映する。
現在の判定は選択の位置を調べるが、どのタブからドラッグが始まったかは調べない。
[タブの DOM](https://github.com/tett23/aleph/blob/fd0067b19dc3d0194220ce1e4892b13ab3e3156d/app/editor/panes.ts#L52-L96)、[エラー表示](https://github.com/tett23/aleph/blob/fd0067b19dc3d0194220ce1e4892b13ab3e3156d/app/preview/render.ts#L102-L107)、[選択の読み取り](https://github.com/tett23/aleph/blob/fd0067b19dc3d0194220ce1e4892b13ab3e3156d/app/ed/view.ts#L326-L351)

タブ列の閉じる操作と差分タブのファイルを開く操作は、マウスを離した要素から行き先を決める。
最小構成の同じ判定では、エラー欄からドラッグしてタブを閉じるボタンの上で離すと、ボタンの処理に一回入った。
[タブ列の処理](https://github.com/tett23/aleph/blob/fd0067b19dc3d0194220ce1e4892b13ab3e3156d/app/editor/panes.ts#L258-L286)、[差分タブのリンク](https://github.com/tett23/aleph/blob/fd0067b19dc3d0194220ce1e4892b13ab3e3156d/app/difftab/mount.ts#L64-L72)

既存の Aleph プラグインは、メイン画面が生成した blob URL を同じ画面で `import` して起動する。
`activate(aleph)` に渡す API は限っているが、プラグインとメイン画面は同じ実行環境にある。
また、プレビューの埋め込みからエディタへ移る処理には、開いた後で別のエディタの `goto` を直接呼ぶ箇所がある。
[プラグインの読み込み](https://github.com/tett23/aleph/blob/fd0067b19dc3d0194220ce1e4892b13ab3e3156d/app/plugins/mount.ts#L13-L35)、[プラグイン API](https://github.com/tett23/aleph/blob/fd0067b19dc3d0194220ce1e4892b13ab3e3156d/app/plugins/host.ts#L34-L58)、[埋め込みから開く処理](https://github.com/tett23/aleph/blob/fd0067b19dc3d0194220ce1e4892b13ab3e3156d/app/wikilinkmount.ts#L231-L250)

Tauri は WebView と Rust の間の通信を IPC と呼ぶ。
IPC で Rust の処理を呼び出す口はコマンド（command）と呼び、画面では `invoke` を使う。
Tauri の permission は、呼べるコマンドと対象の範囲を定める。
capability は、ウィンドウや WebView にどの permission を与えるかを定める。 [Inter-Process Communication](https://v2.tauri.app/concept/inter-process-communication/)、[Permissions](https://v2.tauri.app/security/permissions/)、[Capabilities](https://v2.tauri.app/security/capabilities/)

## 実装すること

### タブの実行境界

タブの中身は、タブごとに `sandbox="allow-scripts"` を付けた iframe に載せる。
各 iframe は独立した文書と JavaScript の実行環境を持つ。
`allow-same-origin`、親のナビゲーション、ポップアップの許可を付けず、親の DOM、他のタブの DOM、親の状態ストアを渡さない。
Rust との通信には、下の「Rust のコマンドと権限」に定める契約を使う。
メイン画面はペインの分割、タブ列、タブの生成と破棄を受け持つ。

既存の Aleph プラグインも、プラグインごとに独立した sandbox の中で起動する。
メイン画面でプラグインのソースを実行する読み込み方を終了する。
コマンドの登録、ステータスの表示、保存の通知などは、許可されたメッセージに移す。
プラグインに渡すシートのデータは、許可された操作の対象に属する値の写しとする。
プラグインには、既定では別タブの編集、アプリのファイル操作、外部プロセスの起動を許さない。
隔離を確かめられない環境やメッセージによる操作に移せないプラグインでは、設定に理由を出し、プラグインの実行を止める。
この決定は [ADR 0017](0017-aleph-plugins.md) の「プラグインは画面と同じ権限で動く」という決定を置き換える。

### 入力の扱い

押下で始まる操作は、押下を受けたタブかタブ列などの部品に属する。
ポインタが境界を越えても、別タブやタブ列への押下、ドラッグ、クリックに読み替えない。
離した要素だけから操作を実行する箇所は、同じ操作の開始を受けたかも確かめる。
操作中にそのタブを隠すか閉じる、ウィンドウから焦点が外れる、または取り消しを受けたときは、その操作を終える。
タブを離れるときの IME の確定と取消は、入力を始めたタブで処理する。

テキストの選択は、その操作が始まった文書の中に収める。
プレビューのエラーもそのタブで文字を選んでコピーできるようにする。
選択のための入力で、別タブのエディタの選択、カーソル、スクロール位置、編集中の本文を変えない。
独立した押下で別のタブに入ったときは、押したタブを操作する。 [ADR 0024](0024-tabs-and-split.md)、[ADR 0114](0114-copy-problems-previews-and-assistant-responses.md)

### タブ間のメッセージ

タブから別のタブを読むか変更する操作は、メイン画面が中継する型付きのメッセージを通す。
各タブと拡張には、生成時にメイン画面が結びつけた `MessageChannel` のポートだけを渡す。
通信路の確立後は、その通信路で受けた要求だけを処理する。
送り手は受信した通信路から決め、本文に含まれる名乗りを権限の根拠にしない。
既存のタブを宛先にする要求には、タブ ID と表示のインスタンスを指す値を使う。
新しいタブを開く要求には、開く先のペインを指定する。
メイン画面は操作の種類、引数、送り手の許可、送り元と宛先の有効性を検査する。
返信と通知にも通信路を使い、DOM の参照、関数、入力イベントを受け渡さない。

プレビューのウィキリンクと埋め込み、差分タブのファイルを開く操作は、それぞれ明示された操作として移す。
文書を開くことと、指定の位置へ移ることは、一つの要求で行う。
要求を処理するときの選択中のタブから宛先を推測せず、要求に定めた宛先と文書を使う。
処理中に送り元か宛先のタブが閉じられたり、別の内容に置き換えられたりした場合は、その要求を破棄する。
タブ内でアプリ全体のキーバインドを実行するときも、対応するホストの操作をメッセージで求める。
現在の送り元に許されない操作や形式の合わない要求には失敗を返し、変更を行わない。 [ADR 0087](0087-preview-in-a-tab.md)、[ADR 0088](0088-diff-tab-and-commit-before-applying.md)

### Rust のコマンドと権限

タブは、必要になった権限とその対象の範囲を Rust に要求する。
ここでいう権限は、コマンドとその対象・条件を定める Aleph の実行時の permission である。
タブの種類や名前から権限は決まらない。同じ条件と対象の範囲を満たす要求は、どの種類のタブからでも同じ判定になる。
タブの iframe からの要求は、結びつけたポートを通ってメイン画面に届き、メイン画面が Tauri の IPC で Rust に渡す。
Tauri の capability には、IPC を中継する WebView が呼べるコマンドを設定する。
タブの iframe はこの capability を受け継がず、Rust が許可を判定する呼び出し口だけを使う。

Rust は、要求された権限と対象の範囲を、利用者が開いた文書や選んだワークスペースなど、その要求に結びつけてアプリが確認した範囲と照合する。
要求に含まれるパスを、利用者の操作に基づいてメイン画面が伝えた対象と照合する。
許可したときは、呼び出し元の通信路、使えるコマンド、対象の範囲を結びつけた許可を返す。
コマンドを呼ぶたびに、Rust は許可が現在も有効か、送り手、コマンド、引数が許可の範囲に合うかを確かめる。
ファイルを扱う場合は既存のパス検査も行う。
タブを閉じるか内容を入れ替えると、その通信路に結びついた許可を失効させる。

次の表は、要求できる権限と、Rust が許可する条件を定める。

| 権限 | 許可するコマンドの操作 | 許可の条件と対象 |
| --- | --- | --- |
| シートの読み取り | テキスト、PDF、画像を読む | 利用者が開いたか、表示対象として認めたシート |
| シートの保存 | テキストを書く | 利用者が編集できる状態で開いたシート |
| 文書の処理 | 編集と取り消し、Markdown の解析、文書の検査と整形、字数の集計 | 許可した文書の内容と版 |
| LSP の利用 | 文書同期、診断の受信、補完とホバーの要求 | 許可したシートと、それが属するプロジェクトの LSP 接続 |
| 組版と成果物の取得 | 本文とページの組版、本文・ページ画像・本文に添える画像の取得 | 許可したシートかプロジェクトの表示に必要な成果物 |
| Git の読み取り | リポジトリの状態と差分を読む | 許可したワークスペース |
| プロットの読み取り | プロットと予定日ファイルを読む | 許可したプロジェクトの `plot.csv` と `plot-calendar.txt` |
| プロットの保存 | プロットと予定日ファイルを書く | 編集が許可されたプロジェクトの同じ二つのファイル |
| ペーストボードへの書き込み | プレーンテキストをコピーする | 利用者が押したコピーボタンの対象の文字 |

Rust は、一覧にない権限、確認した範囲を超える要求、失効した許可を、データの返却や変更を行う前に拒む。
設定やファイルの汎用操作、任意の外部コマンド、Tauri の汎用の呼び出し口は、権限の一覧から外す。
プラグインの登録、表示、保存通知には、ホストとのメッセージを使う。
文書を開いて別のタブへ移る操作と、複数のシートにまたがる変更も、メイン画面にメッセージで求める。 [ADR 0042](0042-ipc-trust-boundary.md)、[ADR 0114](0114-copy-problems-previews-and-assistant-responses.md)

## 実装しないこと

拡張の配布機能、プラグインへの新しい編集権限、スクリプトを実行する汎用コマンド。

## 不変条件

- I1: タブ内から始まった選択やドラッグだけでは、別タブの選択、カーソル、スクロール、本文、開閉状態を変更しない。
- I2: 押下と対応しない解放は、別タブやタブ列の操作を実行しない。
- I3: タブと拡張は、自分の通信路で許可されたメッセージの操作に限り、他のタブや親の状態にアクセスできる。
- I4: 無効な引数、権限の無い操作、更新前のインスタンス宛ての要求は、どのタブの状態も変えない。
- I5: 許可された文書を開く要求は、指定された宛先と文書だけに作用する。
- I6: Rust のコマンドは、呼び出し元に発行した有効な許可に、その操作と対象の両方が含まれる場合に限って実行する。
- I7: 要求された権限、対象の範囲、確認済みの条件が一致する場合、異なる種類のタブからの要求に対する許否は等しい。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 左エディタに焦点がある状態で、右のエラーを押して右の中でドラッグ | 右の文字を選べる。左の選択とカーソルは動かない | I1 |
| 右のエラーから左のエディタ、差分のリンク、タブの閉じるボタンの上までドラッグ | エディタを選択せず、リンクも閉じるボタンも実行しない | I1, I2 |
| 押下後にタブを隠し、再表示後に解放 | 前の操作の続きとして扱わない | I2 |
| 拡張から親や別タブの DOM を調べ、許可の無い操作をメッセージで求める | DOM にアクセスできず、操作は失敗する | I3, I4 |
| 文書を開く要求の処理中に同じタブを別のシートに入れ替える | 古い要求ではどのタブも変わらない | I4 |
| ウィキリンクで文書と見出しを指定し、処理中に別ペインを選ぶ | 指定先だけを開き、見出しの位置に移る | I5 |
| シートの読み取りだけを許可された通信路から、同じシートの保存か範囲外の読み取りを求める | 保存も範囲外の読み取りも実行せず、失敗を返す | I6 |
| 許可済みの操作と対象を、別の通信路から同じ許可で呼ぶ | 失敗を返す | I6 |
| タブを閉じた後に、その通信路に発行した許可で Rust のコマンドを呼ぶ | 処理を実行せず失敗を返す | I6 |
| 異なる種類の二つのタブから、同じ条件で同じシートの読み取り権限を求める | 同じ判定を返す | I7 |

## 受けいれ条件

- A1: 左で編集中に右のプレビューをエラーにして、右のエラーをドラッグで選択しコピーできる。左の選択、カーソル、スクロール、本文は変わらない。
- A2: 通常のプレビューと差分をまたいでドラッグしても、別タブのリンクやタブ列のボタンが働かない。それぞれを独立して押した場合は働く。
- A3: 拡張をメイン画面とタブの DOM から隔離したまま、許可されたコマンドを登録し、ステータスを表示し、保存の通知を受けられる。
- A4: プレビューのリンクと差分タブのファイル名から、メッセージを通して従来の場所を開ける。
- A5: タブが必要な権限を要求し、Rust が許可したコマンドを許可範囲内で呼べる。許可を受けていない操作、範囲外の対象、失効した許可は拒まれる。

## テスト設計

先に、右のエラー内だけのドラッグで左の文字が選択される最小構成を WKWebView の回帰テストにする。
I1、I2 と A1、A2 は、実際の押下、ドラッグ、解放を使い、横書きと縦書き、エラーと通常表示、タブの非表示と閉鎖、別ペインへの越境で確かめる。
I3 から I5 は、通信路、許可、引数、宛先の組み合わせを使ったテストにする。
I6 と I7 は、権限の要求条件、コマンド、対象の範囲、通信路、許可の有効性を組み合わせて確かめる。
Tauri のデバッグ版で、sandbox から親の DOM と汎用の Tauri 呼び出し口を利用できないことを確かめる。
権限の要求と許可された Rust コマンド、プラグイン操作、リンクの移動がそれぞれ働くことも確かめる。
テスト名には `ADR 0115 I1: ` のように ADR と条件の番号を付ける。

実装時は、仕様書の「画面と Rust の信頼の境界」に、要求できる権限、その権限で呼べるコマンド、引数、対象の範囲、許可と失効の条件の一覧を書く。
権限やコマンドを追加または変更するときは、同じ変更でこの一覧も更新する。
タブ間の操作とプラグインの許可は、仕様書と両言語の README に反映する。
プラグイン API の互換を壊す場合は、版を上げて既存のプラグインへの影響を記す。

## トレードオフ

iframe で文書を分けると、タブごとに選択が分かれ、メイン画面にプラグインのコードを入れずに済む。
一方、テーマ、エディタの状態、リンクの移動、キーバインドなど、これまで同じ画面で扱えた情報は、明示した通信路で渡す必要がある。
