# ADR 0009: LSP と整形

ステータス: 採択→縦書きで LSP の表示と整形をしない部分は[ADR 0019](0019-one-editor-for-both-writing-modes.md)

## 文脈

Golem は `golem lsp` で LSP のサーバーを持つ。
サーバーは、診断、補完、ホバー（式の評価結果）、定義と参照、ラベルと `.emet` の名前の変更、見出しのアウトライン、semantic tokens による色付け、整形（`textDocument/formatting`）を持つ。
位置の単位は、初期化のときに交渉して決まり、クライアントが UTF-8 を申し出れば UTF-8、申し出なければ UTF-16 になる。

プロトタイプでは、Rust の側で `golem lsp` を起動し、標準入出力のメッセージ（`Content-Length` の見出しと本文）を画面の側と中継した。
画面の側で、診断、ホバー、補完をつないだ。
使う中で、次のことがわかった。

- メンテナーから「LSP のエラー表示が効いていない」と指摘を受けた。調べると、サーバーは診断を返しており、画面は波線を引いていたが、文言は波線にマウスを乗せないと出なかった。
- 章に載っていない `.gm`（プロトタイプで足した試しのファイル）には、診断が返らなかった。
- 文書の URI は、パスの各部分をパーセントエンコードしたものでないと、日本語を含むパスのファイルを見つけない。
- 「fmt が効いていない」との指摘もあった。`golem fmt` 自体は動いていたが、変更が小さく（ルビの区切りの空白など）、効いたことがわかりにくかった。

メンテナーは、⌘S でも整形が動くようにと求めた（2026-11-07）。

## 実装すること

### サーバーとの中継

- プロジェクトごとに一つ `golem lsp` を起動し、そのプロジェクトのファイルを開いたすべてのエディタで共有する。そのプロジェクトのファイルを閉じて 10 分たったときと、アプリを終えるときに止める。
- 起動したら `initialize` で `rootUri` と、使う機能（診断、ホバー、補完、整形、semantic tokens）を伝える。位置の単位は UTF-16 を申し出る（CodeMirror の位置が UTF-16 の単位であるため）。サーバーからの要求（`workspace/configuration` など）には空の応答を返す。
- 文書の URI は、パスの各部分をパーセントエンコードして作る。
- 開く、変える（全文を送る）、保存する、閉じる、をそれぞれ `didOpen`、`didChange`、`didSave`、`didClose` で伝える。`didChange` は入力が止まって 250 ミリ秒後に送る。

### 診断

- 診断は、エディタの中に重大度の色の波線を引き、溝に印を出す（[ADR 0006](0006-horizontal-editor.md)）。
- ステータスバーに、そのファイルのエラーと警告の数を出す。数を押すと、エディタの下に **エディタの診断の一覧** を開く。一覧の項目を選ぶと、その位置に移る。この一覧は開いているファイルの LSP の診断だけを出すもので、check、lint、preflight の結果を出す左のサイドバーの診断のパネル（[ADR 0015](0015-diagnostics-and-search.md)）とは別である。

### 色付け

- `.gm` と `.emet` の色付けは、サーバーの semantic tokens（`textDocument/semanticTokens/full`）を使う。Golem の機能を Aleph で作り直さないためである。
- サーバーが応えるまでのあいだと、サーバーが使えないときは、Aleph の簡単な字句の読み方で色を付ける（[ADR 0006](0006-horizontal-editor.md)）。
- 命令と式を等幅にするための区別（[ADR 0006](0006-horizontal-editor.md)）も semantic tokens の型から決める。型の対応は Golem の `tools/editors/README.md` の表に合わせる。型だけで区別できないもの（式の中身と散文スロット）があれば、Golem に型か修飾子を足すよう依頼する。

### ホバーと補完

- ホバーは、サーバーの返す文言を出す。
- 補完は、`[` と空白で始め、サーバーの返す候補を出す。

### 整形

- 整形は、サーバーの `textDocument/formatting` の結果を、一回の変更としてエディタに当てる。⌘Z で一度に戻せる。
- 整形は、⌥⇧F と、ツールバーのメニューから行う。
- ⌘S は、整形してから保存する。設定で切れる（既定はオン）。自動保存（[ADR 0011](0011-saving-and-git.md)）では整形しない。書いている途中の文が動かないようにするためである。
- 整形して何も変わらなかったときと、変わったときで、別の通知を出す（「整形しました」「変更はありません」）。効いたかどうかがわかるようにする。
- サーバーが使えないときは、保存したファイルに `golem fmt` を実行し、結果をエディタに読み直す。

## 実装しないこと

- 定義、参照、名前の変更、アウトライン。サーバーは持っているが、最初の版では使わない。アウトラインは原稿の見出しから作る（[ADR 0012](0012-sheet-goals-and-notes.md)）。
- 縦書きのエディタの中での LSP の表示（波線、溝の印、ホバー、補完）と整形（[ADR 0007](0007-vertical-editor.md)）。縦書きでも、開く、変える、保存するをサーバーに伝え続け、ステータスバーの数と左のサイドバーの診断のパネルは使えるようにする。

## テスト設計

- 中継：`Content-Length` の見出しが分かれて届く場合、複数のメッセージが一度に届く場合、本文に日本語を含む場合に、メッセージを正しく切り出すことを `cargo test` で確かめる。
- URI：日本語と空白を含むパスから作った URI を確かめる。
- 整形の当て方：サーバーの返す編集の列（複数の範囲、文書の末尾を越える範囲、全文の置き換え）を、エディタの文書に当てた結果を `node --test` で確かめる。
- semantic tokens：サーバーの返す数の列（相対の位置と長さ、型、修飾子）を、エディタの範囲と分類に直す関数を確かめる（行をまたぐ相対の位置、日本語を含む行）。
- 結合の確かめ方：見本のプロジェクトの章に未知の命令を書き、波線、溝の印、ステータスバーの数、エディタの診断の一覧が出ること。ルビの区切りに空白のない章で ⌥⇧F と ⌘S を押し、整形され、⌘Z で戻ること。縦書きに切り替えても、ステータスバーの数が変わり続けること。

## トレードオフ

- プロジェクトごとにサーバーを一つ起動するので、短いあいだに多くのプロジェクトを開くとプロセスが増える。閉じて 10 分たてば止まるので、増えたままにはならない。
- ⌘S で整形すると、保存のたびに原稿が整う。その代わり、整形で行が変わると、カーソルの近くの文字が動くことがある。設定で切れる。
