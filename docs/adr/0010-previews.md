# ADR 0010: プレビュー

ステータス: 採択

## 文脈

メンテナーは、原稿を書きながら、組んだページと、命令と式を除いた本文を横に見たいと述べた。
ラスタライズしたプレビューは横に出し、別のウィンドウにもできるようにする（2026-11-07）。
本文のプレビューについては、「命令と式は記号としては消すが、結果はプレビューに反映する」ようにと求めた。

プロトタイプで次のことを試し、わかった。

- 本文のプレビューは、最初は原稿から命令と式の記号を取り除いて作った。これでは式の値やルビが出ない。`golem build --target html` の章の XHTML を使うと、記号は消え、式の値、ルビ、関数の出力が反映された。組むのにかかる時間は、見本の原稿で 0.2 秒ほどだった。
- ページのプレビューは、`golem build --target pdf` のあと `shem render` で PNG にして並べた。解像度を 110 dpi に決め打ちしたところ、A6 のページで幅がおよそ 450 画素にしかならず、Retina の枠では粗かった。見本の原稿の 17 ページの PDF で shem の時間を測ると、110 dpi で 0.02 秒、300 dpi で 0.05 秒、500 dpi で 0.1 秒だった（2026-11-07、Apple Silicon の Mac、shem 0.1.0-rc3）。解像度を枠に合わせて上げても、待ち時間はほとんど増えない。
- 「ページ」を選んだまま章を開くと、ボタンを押すまで何も出なかった。
- プレビューの枠のクラスを描く処理が上書きし、スクロールが効かなくなった。

## 実装すること

### 切り替え

- ツールバーの右に「原稿のみ」「本文」「ページ」を置き、エディタの右に出すプレビューを選ぶ（[ADR 0005](0005-layout-and-appearance.md)）。
- 形式ごとに出せるものを決める：`.gm` は本文とページ、`.md` はプレビュー、`.svg` と Mermaid は図、`.pdf` と画像はエディタの代わりに表示する。

### 本文のプレビュー

- `.gm` を保存したら、`golem build --target html` を実行し、その章の XHTML の本文を出す。記号は消え、命令と式の結果は反映される。
- XHTML から出すのは `body` の中身だけとし、`script`、`style`、`link` の要素を除く。スタイルは Aleph の本文のプレビューのものを使う。
- 組んでいるあいだと、組めなかったときは、前の結果を出したまま、そのことを小さく示す。前の結果がないときは、記号を取り除いただけの本文を出す。
- 縦と横の切り替え（[ADR 0007](0007-vertical-editor.md)）に従って、本文も縦書きと横書きを切り替える。
- 複数の章をまとめて開いたとき（[ADR 0006](0006-horizontal-editor.md)）は、選んだ章の本文を並べる。

### ページのプレビュー

- `golem build --target pdf` のあと、`shem render --dpi N` で各ページを PNG にし、縦に並べる。
- 「ページ」を選んでいて、まだ組んでいなければ、開いたときにすぐ組む。保存したあとは、設定（既定はオン）に従って組み直す。
- 解像度は既定で自動にする。枠の幅、画面の倍率、拡大率、`style.toml` の判型（`size` の名前か、幅の寸法）から、枠をちょうど埋める dpi を求める。拡大や枠の広がりで足りなくなったら、PDF を組み直さず、同じ PDF を shem で描き直す。設定で dpi を決めたときは、その値を使う。
- 拡大縮小は、枠の見出しのボタン、ピンチ、⌘ を押しながらのスクロールで行う。100% は枠の幅とする。
- 描く処理は、スクロールする枠そのものではなく、その中の要素に描く。

### ほかの形式

- **Markdown**：自前の字句の読み方で HTML にする（[ADR 0003](0003-application-architecture.md)、[ADR 0016](0016-markdown-to-gm.md)）。
- **SVG**：画像として出す。スクリプトは動かさない。
- **Mermaid**：Mermaid で描く。誤りは文言で出す。
- **PDF**：shem で描く。shem が描けない PDF（Golem の出す部分集合の外のもの）は、WebView の表示に任せる。
- **画像**：そのまま出す。

### 別ウィンドウ

- ページと本文は、別のウィンドウに出せる。ページのウィンドウは、組んで描いた結果をメインのウィンドウからイベントで受け取る。自分の幅と拡大率で足りなくなったら、自分に合う dpi で描き直すようメインのウィンドウに依頼する。

## 実装しないこと

- ページと原稿の対応による移動（ページを押すと原稿のその位置に移るなど）。Golem からページと原稿の対応を受け取れるようになってから決める（[ADR 0006](0006-horizontal-editor.md)）。
- EPUB のプレビュー。

## テスト設計

- 自動の dpi：枠の幅、倍率、拡大率、判型の組から求める値を `node --test` で確かめる（A6、A5、寸法で書いた判型、判型の書かれていない場合、上限と下限）。
- 判型の読み方：`size = "A6"`、`size = { width = "105mm", ... }`、書かれていない場合を確かめる。
- 本文の取り出し：Golem の XHTML（見出しの番号、ルビ、表、図版を含む）から本文を取り出し、スクリプトと外部の参照を除くことを確かめる。
- 画面の確かめ方：「ページ」を選んだまま章を開くとすぐ組まれること。拡大してもページが粗くならないこと。ページの枠と本文の枠がスクロールすること。保存のあと本文とページが組み直されること。

## トレードオフ

- 本文のプレビューを Golem の HTML から作ると、命令と式の結果が正確に出る。その代わり、保存するまで反映されない（自動保存は 10 秒ごと、[ADR 0011](0011-saving-and-git.md)）。
- ページを PNG で並べると、PDF のビューアーに頼らず、どの環境でも同じ見た目になる。その代わり、文字の選択や検索はできない。
