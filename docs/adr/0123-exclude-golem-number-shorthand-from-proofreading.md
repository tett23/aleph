# ADR 0123: Golem の数の糖衣構文を文章の検査から除く

Status: proposed

## 文脈

Golem の `.gm` で `##1##` と書くと、組版時に数として扱われる。元の記号や数字は組版の指定なので、Aleph の文章の検査では一つの範囲として除く。

## 調査した事項

`##N##` は `[number-text N]` の糖衣構文である。`N` は `0` または先頭が `0` でない ASCII の数字列とする。地の文と散文スロットで使え、エスケープすれば本文として書ける。
[Golem golem-parser ADR 0011](https://github.com/tett23/golem/blob/dc8bf92ec33549ae2cd3b1cbf43487d451b1071a/docs/golem-parser/adr/0011-number-shorthand.md)

Aleph は `.gm` の行を字句に分け、既存のコマンドや式などを除いた本文範囲を文章の検査と英語の綴り検査に渡す。数の糖衣構文を専用の範囲として除く処理はない。
[文章の検査範囲](https://github.com/tett23/aleph/blob/4682b5c2b3fa88581941d26d9a82e86d07e1257f/app/proofread.ts#L98-L120)

## 実装すること

`.gm` の地の文で Golem の数の糖衣構文として認識した範囲を、両端の `##` を含めて校正範囲から引く。段落、見出し、リスト、表、散文スロットのいずれでも同じ規則を使う。前後の文章は今の UTF-16 位置のまま検査する。

エスケープした表記と糖衣構文として成立しない形は、この規則の対象外とする。数の構文や値について Golem が出す診断は、そのまま問題の一覧に表示する。
Golem の構文と校正範囲の判定は Rust 側に置き、既存の範囲抽出に組み込む。 [ADR 0116](0116-own-domain-logic-in-rust.md)

## 実装しないこと

数の見た目の変更、書き換え、Markdown やプレーンテキストへの Golem の構文の追加。

## 不変条件

- I1: 認識した数の糖衣構文の両端を含む範囲は、文章の検査と英語の綴り検査に渡さない。
- I2: 前後の地の文を元の UTF-16 位置で検査し、エスケープした表記はこの規則で除かない。
- I3: この規則が校正範囲から引くのは、`.gm` の有効な数の糖衣構文だけである。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| `.gm` の `##0##`、`## 第##1##節`、`[strong: 第##10##回]` | 認識した数の範囲を除く | I1 |
| `.gm` の `見れる##1##食べれる` | 両側を検査し、数で位置をずらさない | I1, I2 |
| `.gm` の `\##1##`、`##007##`、`##１２##`、閉じがない `##1` | 数の糖衣構文として校正範囲から除かない | I2, I3 |
| `.md` または `.txt` の `##1##` | その形式の本文として扱う | I3 |

## 受けいれ条件

- A1: `.gm` の文中で糖衣構文の範囲を除いても、前後の校正診断の位置が正しい。

## テスト設計

範囲抽出と診断のテストで、段落の先頭、見出し、散文スロット、エスケープ、閉じ忘れ、全角数字を比べる。直前にサロゲートペアを置き、前後の診断位置を確かめる（A1）。

## トレードオフ

既存の範囲抽出で糖衣構文を認識するため、Golem 側で数字やエスケープの規則が変わったときはテストを更新する。
