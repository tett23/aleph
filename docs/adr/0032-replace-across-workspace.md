# ADR 0032: ワークスペースをまたいで置換する

ステータス: 採択

## 文脈

左のサイドバーの「検索」（⌘⇧F）は、このプロジェクト、このワークスペース、すべてのワークスペースを範囲に、ファイルを横断して探す（[ADR 0015](0015-diagnostics-and-search.md)）。
置換は、エディタの中の検索のパネル（⌘F）にしかなく、開いている一つのシートの中だけで行える（[ADR 0019](0019-one-editor-for-both-writing-modes.md)）。
登場人物の名前や用語を作品全体で直すときは、シートを一つずつ開いて置換することになる。

Obsidian には、検索の結果をまとめて置換するプラグインがある。
メンテナーから、Obsidian と Ulysses にあって Aleph にない機能を比べたうえで、ワークスペース全体の置換の ADR を作るよう求められた（2026-11-07）。

検索は Rust の側で行い、`regex` の正規表現で、`.gitignore` に従って、Aleph がテキストとして開く形式のファイルを読み、2000 件で打ち切る（[src-tauri/src/search.rs](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/src-tauri/src/search.rs#L30-L36)、[app/searchpanel.ts](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/searchpanel.ts#L86-L92)）。
検索はディスクの上のファイルを読むので、開いているシートの保存していない変更は、検索の結果に入らない。
エディタの置換は、JavaScript の正規表現で行っている。

## 実装すること

### 画面

- 検索のパネルに、置換の欄と、「選んだものを置換」「すべて置換」のボタンを足す。置換の欄が空でないあいだは、各一致の行に、置換の後の行を並べて出す（前の文字に取り消し線、後の文字を強調）。
- 一致ごとと、ファイルごとに、置換するかを選ぶ印を付ける。初めはすべて選んだ状態とする。

### 置換の規則

- 置換は、検索と同じ Rust の `regex` で行う。正規表現の検索では、置換の欄の `$1`、`${1}`、`$name`、`${name}` を捕獲した文字で置き換え、`$$` を `$` とする（`regex` の `Regex::replace` の規則）。`$1a` は名前が `1a` の捕獲と読まれるので、続けて文字を書くときは `${1}a` と書く。正規表現でない検索では、置換の欄を `NoExpand` で文字のまま使う。
- 開いているシートも、ディスクの上のファイルも、同じ Rust の処理で置換の後の文字を作る。正規表現の方言が二つに分かれないようにするためである。

### 当て方

- 置換を始める前に、範囲の中の開いているシートを保存し、ディスクとエディタの文字をそろえる。そのあと、検索をし直して一致を確かめる。
- 「すべて置換」は、検索の打ち切り（2000 件）によらず、範囲の中のすべての一致を置換する。「選んだものを置換」は、選んだ一致だけを置換する。一致は、ファイル、行、列と、一致した文字で指す。検索のあとでファイルが変わり、その位置の文字が違うときは、その一致を飛ばし、飛ばした数を知らせる。
- 開いているシートは、エディタの文書に一回の変更として当てる（⌘Z で一度に戻せる）。
- 開いていないファイルは、Rust の側で読み、置換して書き戻す。
- 置換したあとは、開いているシートの変更の印、ツリー、診断（lint と preflight）を、保存したときと同じように更新する。

### 確かめと戻し方

- 置換の前に、置換するファイルの数と一致の数を示して、確かめる。
- ワークスペースが Git のリポジトリでなければ、確かめの文に「ディスクの上のファイルの置換は元に戻せません」と添える。
- Git のリポジトリなら、確かめの文に「Git の変更から戻せます」と添え、置換のあとは Git のパネルの変更の一覧に出る（[ADR 0011](0011-saving-and-git.md)）。
- 置換の結果として、置換したファイルの数、一致の数、飛ばした数を通知で知らせる。

## 実装しないこと

- 置換の取り消しの一括の操作（開いていないファイルの置換は、Git で戻す）。
- ファイルの名前の置換。
- 大文字と小文字を保ったままの置換（`Foo` を `Bar` に、`foo` を `bar` に）。
- 置換の前の自動のコミット（Git の操作は書き手が選ぶ）。
- 正規表現の方言を JavaScript にそろえること。

## テスト設計

DOM に触れない部分は `node --test` で、Rust の部分は `cargo test` で、先に書いて失敗させてから実装する。

- Rust の置換の関数（文字と問い合わせと置換の欄と、置換する一致の位置の集合から、置換の後の文字と数を返す）：
  - 文字のままの置換、`$` を含む文字のままの置換が展開されないこと。
  - 正規表現の `$1`、`${1}`、`${name}`、`$$`。
  - 大文字と小文字の区別のありなし。
  - 選んだ一致だけを置換すること、選んでいない一致が残ること。
  - 位置の文字が一致しないときに飛ばして数えること。
  - 日本語とサロゲートペアを含む行での列の数え方（検索の `column` と同じく文字の数）。
- Rust のファイルの置換：一時のディレクトリのファイルを置換して書き戻すこと、`.gitignore` に従うこと、2000 件を超える一致もすべて置換すること。
- 画面の側：置換の前後の行の表示を作る関数（取り消し線と強調の範囲）、確かめの文を作る関数（Git かどうか、数）。
- 画面の確かめ方：見本のワークスペースで、登場人物の名前を全体で置換する。開いている章（保存していない変更があるもの）とそうでない章の両方が変わり、開いている章は ⌘Z で一度に戻り、ほかの章は Git のパネルに変更として出ること。一部の一致を選ばずに置換すると、それが残ること。

## トレードオフ

- 置換の正規表現を Rust の `regex` にそろえるので、エディタの中の置換（JavaScript）と、置換の欄の書き方が少し違う（名前の付いた捕獲の参照など）。検索との一致を優先した。
- 開いていないファイルの置換は、Aleph の中では戻せない。Git のリポジトリなら Git で戻せるので、確かめの文で戻し方を示す。Git でないワークスペースでは、確かめるだけで守る。
- 置換の前に開いているシートを保存するので、保存したくない変更も保存される。ディスクと画面の文字が違うまま置換すると、どちらかの変更が失われるため、保存を優先した。
