# ADR 0063: 外部で変わったファイルに追従する

ステータス: 採択（未実装）

## 文脈

Aleph は、シートを開いたときにファイルを読み、その後はエディタの中身を正とする。
開いているシートは、エディタの中身（`text`）と、最後に読むか書いた中身（`saved`）を持ち、二つが違えば変更ありとする（[app/store.ts](https://github.com/tett23/aleph/blob/b234f59/app/store.ts#L368)）。
保存は、`text` が `saved` と違うシートを書く。
書く前に、ディスクの中身を確かめない（[app/main.ts](https://github.com/tett23/aleph/blob/b234f59/app/main.ts#L110)）。
自動保存は、変更のあるシートを設定の間隔（既定 10 秒）ごとに保存する（[ADR 0011](0011-saving-and-git.md)）。

ファイルは Aleph の外からも変わる。
ほかのエディタで直す、`git pull` や `git checkout` をターミナルで行う、同期のサービスがほかの機械の変更を持ってくる、`golem fmt` をターミナルで走らせる、といった場合である。
今の Aleph は、これに気付かない。

- 開いているシートは、古い中身のまま表示される。
- そのシートに変更があると、自動保存が外部の変更を黙って上書きする。変更がなくても、⌘S は書く（明示の保存は、変わっていなくても整形して書くため）。
- ツリーは、ファイルを足す、消すなどの Aleph の操作のときにしか読み直さない（[app/ui/tree.ts](https://github.com/tett23/aleph/blob/b234f59/app/ui/tree.ts#L46)）。外で足されたファイルは、ワークスペースを開きなおすまで出ない。

黙って上書きすることは、原稿を失うことになるので、最も避けたい。

Aleph の書き手には、Git に慣れていない人もいる。
同じファイルを Aleph と外の両方で直したときに、「マージ」「コンフリクト」「ours と theirs」のような Git の言葉や、`<<<<<<<` の印を原稿に書き込むやり方では、何が起きていて何を選べばよいかが伝わらない。

## 実装すること

### 保存の前の確かめ

- シートを書く前に、そのファイルをディスクから読み、`saved` と比べる。
  - 同じなら、これまでどおり書く。
  - 違えば（外部で変わった）、書かずに、下の「外部で変わったときの振る舞い」に回す。
  - ファイルがなければ（外部で消えた）、書かずに、下の「消えたシート」に回す。
- 自動保存も、明示の保存も、整形してからの保存も、この確かめを通す。比べるのは中身であり、更新の時刻ではない。Aleph が書いた直後の時刻の揺れや、同じ中身での書き直しを、変更と取り違えないためである。
- この確かめは、下の見張りが動かないとき（見張りを始められなかったときなど）にも、上書きを防ぐ。

### 変更の見張り（FSEvents）

- macOS の FSEvents で、登録したワークスペースと共有ライブラリのフォルダを見張る。外部のライブラリ（`notify` など）は使わず、FSEvents の C の API を Rust から呼ぶ小さなモジュール（`src-tauri/src/fsevents.rs`）を自前で書く。
  - `FSEventStreamCreate` に、見張るフォルダの並び（`CFArray`）、ファイルごとの通知（`kFSEventStreamCreateFlagFileEvents`）、遅れなしの通知（`kFSEventStreamCreateFlagNoDefer`）、見張るフォルダ自身の移動と削除の通知（`kFSEventStreamCreateFlagWatchRoot`）を渡す。届いたパスは C の文字列の配列で受け取る（`kFSEventStreamCreateFlagUseCFTypes` を付けない）。
  - 通知は、`FSEventStreamSetDispatchQueue` で専用のディスパッチキューに届け、メインスレッドを使わない（[ADR 0062](0062-run-programs-off-the-main-thread.md)）。
  - 通知の遅れ（latency）は 0.1 秒とし、0.2 秒のあいだに届いたパスを一つにまとめてから、画面の側にイベント（`aleph:fs`）で送る。
  - ワークスペースの登録が変わったら、見張りを作りなおす。アプリを閉じるときに、`FSEventStreamStop`、`FSEventStreamInvalidate`、`FSEventStreamRelease` で片付ける。
- 次のパスは、画面の側に送らない。Aleph が書く組版の出力で、書き手のファイルではないためである。
  - プロジェクトの `build/` の下。
  - `.git/` の下。ただし `.git/HEAD`、`.git/index`、`.git/refs/` の下が変わったときは、「Git の状態が変わった」として一度だけ送る。
- 通知に「下のフォルダを調べなおせ」（`kFSEventStreamEventFlagMustScanSubDirs`）が付いたときは、そのフォルダの下の開いているシートをすべて確かめる。
- 画面の側は、届いたパスのうち、開いているシート（テキストの形式に加え、PDF、画像、SVG のプレビューのファイル）を読み、中身を `saved` と比べる。同じなら何もしない（Aleph 自身の保存の通知も、ここで無視される）。
- 見張りを始められなかったときは、ステータスバーの通知（[ADR 0064](0064-unified-notifications.md) の時間で消える通知）で知らせ、ウィンドウが前面に戻ったときに開いているシートを確かめるだけにする。

### 外部で変わったときの振る舞い

ディスクの中身を「ほかのアプリでの変更」、エディタの中身を「Aleph での変更」、`saved` を「元の内容」と呼ぶ。画面の文言には、マージ、コンフリクトなどの Git の言葉を使わない。

- **Aleph での変更がないシート**：ディスクの中身を読み込み、`text` と `saved` をそれにする。カーソルは同じ行と列（行が減っていれば最後の行）に置き、スクロールの位置を保つ。「ほかのアプリで変更されたので読み込みなおしました：ファイル名」を、時間で消える通知で出す（[ADR 0064](0064-unified-notifications.md)）。LSP と変更の印と字数は、編集のときと同じく新しい中身に追従する。PDF、画像、SVG のプレビューは描きなおす。
- **Aleph での変更があるシート**：元の内容、Aleph での変更、ほかのアプリでの変更の三つから、行ごとに合わせる（三方向のマージ）。
  - 合わせ方は diff3 の手続きとし、自前で書く。元の内容との差を、Aleph での変更とほかのアプリでの変更のそれぞれについて行ごとに求め、片方だけが変えた箇所はその変更を取り、両方が同じに変えた箇所はそれを取る。両方が違うように変えた箇所を「食い違い」とする。
  - **食い違いがない**：合わせた内容をエディタに入れる（一つの編集として入れ、⌘Z で入れる前に戻せる）。`saved` はディスクの中身にする。合わせた内容は、次の保存で書く。「ほかのアプリでの変更を取り込みました。Aleph での変更も残っています」を、「元に戻す」のボタン付きの、時間で消える通知で出す。
  - **食い違いがある**：エディタの中身は変えず、自動保存はそのシートを書かない。明示的に消すまで消えない通知（[ADR 0064](0064-unified-notifications.md)）で、「霧笛.gm がほかのアプリで変更され、Aleph での変更と 2 か所で食い違っています」と出し、次のボタンを置く。
    - 「食い違いを直す」：下の「食い違いを直す画面」を開く。
    - 「ほかのアプリの内容にする」：Aleph での変更を捨てて読み込む（⌘Z で戻せる）。
    - 「Aleph の内容で上書きする」：確かめのダイアログを経て、エディタの中身を書く。
  - 通知が出ているあいだに ⌘S を押すと、同じ三つの選び方のダイアログを出す。
- **消えたシート**：エディタは閉じない。明示的に消すまで消えない通知で「霧笛.gm がディスクにありません（ほかのアプリで消されたか、名前が変えられました）」と出し、「閉じる」と「この内容で作りなおす」のボタンを置く。通知が出ているあいだは、自動保存がそのシートを書かない。

### 食い違いを直す画面

- ダイアログで、食い違いの箇所を上から順に一つずつ並べる。各箇所は、前後の 2 行を薄く添え、「ほかのアプリでの変更」と「Aleph での変更」を左右に並べる。左右の行の中で、元の内容から変わった字に色を付ける（行の中の差は、字を単位に求める。見せるためだけで、合わせ方は行を単位とする）。
- 各箇所に、「こちらを使う」（左）、「こちらを使う」（右）、「両方残す」（Aleph での変更、ほかのアプリでの変更の順）の三つの選び方を置く。初めは「Aleph での変更」を選んである。
- 下に、合わせた結果の全文を出し、選び方を変えるとすぐに描きなおす。
- 「これで決める」で、合わせた結果をエディタに入れ（⌘Z で戻せる）、`saved` をディスクの中身にし、通知を消す。結果は次の保存で書く。「やめる」では何も変えず、通知は残る。

### ツリーと周りの表示

- 見張りの通知でワークスペースのファイルが増えたか減ったか名前が変わったときは、ツリーを読み直す（0.5 秒のあいだの通知をまとめて一度）。ウィキリンクの索引は、今のツリーの読み直しのときと同じく追従する。
- 「Git の状態が変わった」の通知で、Git のパネルの状態（`git status`）とブランチを読み直し、開いているシートの変更の印を HEAD と比べなおす。
- 開いているシートが外部で変わったときは、そのプロジェクトのページのプレビューを、保存のときと同じく、入力が止まってから組みなおす（[ADR 0056](0056-wait-before-building-pages.md)）。

### 仕様書

- 仕様書の保存の節に、保存の前の確かめ、見張り、外部で変わったときの振る舞い、食い違いを直す画面を書く。

## 実装しないこと

- `notify` などの外部のライブラリを依存に足すこと。
- 行より細かい単位（文字や語）で合わせること。行（`.gm` では段落）を単位とする。一つの段落を両方で直したときは、食い違いを直す画面で選ぶ。
- 開いていないファイルの中身の変化を、ツリーの読み直しのほかに追うこと（検索の結果、問題のパネルの診断の読み直しなど）。それぞれの機能を次に動かしたときに追いつく。
- `config.json` と `.aleph/` の下のファイル（ブックマークなど）が外部で変わったときに読み直すこと。
- macOS のほかの OS での見張り。Aleph は macOS を対象とする（[ADR 0002](0002-purpose-scope-and-name.md)）。

## テスト設計

`node --test` と `cargo test` で、テストを先に書いて失敗させてから実装する。

- TypeScript：三方向のマージの関数（`merge3(base, ours, theirs)`）が、次を返すこと。
  - 片方だけが変えた行はその変更、両方が同じに変えた行はその変更。
  - 両方が違うように変えた行は食い違い（元、Aleph、ほかのアプリの三つの行の並びを持つ）。
  - 片方が足し、片方が消した場合、両方が隣り合う行を変えた場合、ファイルの先頭と末尾の変更、空のファイル、末尾の改行の有無。
  - 食い違いのそれぞれに選び方を与えると、決まった全文を返すこと（「両方残す」は Aleph、ほかのアプリの順）。
  - 乱択の入力（種を固定した 1 万組）で、食い違いがないとき、Aleph だけが変えた行とほかのアプリだけが変えた行がすべて結果に入ること。base と ours が同じなら結果は theirs、base と theirs が同じなら結果は ours であること。
- TypeScript：外部の変更を分ける関数が、中身が `saved` と同じなら何もしない、違って変更がなければ読み込む、変更があれば合わせる、ファイルがなければ消えた、を返すこと。
- TypeScript：保存の前の確かめの関数が、ディスクの中身が `saved` と同じなら書く、違えば書かない、なければ書かない、を返すこと。自動保存が、食い違いと消えたシートを書かないこと。
- TypeScript：読み込みのあとのカーソルの位置を決める関数が、同じ行と列に、行が減っていれば最後の行に、列が短ければ行末に置くこと。
- TypeScript：見張りのパスを選ぶ関数が、`build/` の下と `.git/` の下を送らず、`.git/HEAD`、`.git/index`、`.git/refs/` を「Git の状態が変わった」にすること。
- Rust：FSEvents のモジュールが、一時のフォルダを見張り、その中でファイルを作る、書き換える、消す、名前を変えると、2 秒以内にそのパスを届けること。見張りを止めたあとは届けないこと。
- Rust：届いたパスをまとめる関数が、同じパスを一つにし、順を保つこと。
- 画面の確かめ方：試験のプロジェクトの章を開き、ターミナルから次を行う。
  - Aleph で変更していないシートの末尾に一行足す：1 秒ほどで読み込みなおし、時間で消える通知が出て、カーソルが保たれること。
  - Aleph で一行目を直してから、ターミナルで末尾に一行足す：両方が入り、通知の「元に戻す」で取り込む前に戻ること。
  - Aleph で一行目を直してから、ターミナルで同じ一行目を違うように直す：消えない通知が出て、10 秒待っても自動保存が上書きしないこと。「食い違いを直す」で左右の選び方と「両方残す」ができ、「これで決める」の後に ⌘Z で戻ること。
  - 開いているシートを消す：消えない通知が出て、「この内容で作りなおす」で戻ること。
  - 外で新しいファイルを作る：ツリーに出ること。ターミナルでコミットする：Git のパネルの変更が消えること。

## トレードオフ

- FSEvents の C の API を自前で呼ぶので、`unsafe` のコードと、CoreFoundation の型の作り方と片付けを、Aleph が持つことになる。外部のライブラリを足すより、依存とその更新を追う手間がない。
- 保存のたびに、ファイルを一度読む。シートは文書の大きさで、待ち時間は短い。
- 行を単位に合わせるので、`.gm` で一つの段落を両方で直すと、たとえ違う文を直していても食い違いになる。原稿で段落の途中を両方で同時に直すことはまれで、そのときは画面で選ぶ。
- 食い違いを直すまで、そのシートは保存されない。Aleph が落ちると、そのあいだの変更は失われうる。消えない通知で、直すことを促す。
- FSEvents は、ネットワークのボリュームなど一部の場所では通知が届かないことがある。保存の前の確かめで、上書きだけは防ぐ。
