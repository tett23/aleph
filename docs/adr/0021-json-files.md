# ADR 0021: JSON、JSONC、JSON5、JSON Lines のファイルを扱う

ステータス: 採択（未実装）

## 文脈

Aleph が開ける形式は、`.gm`、`.emet`、`.md`、`.txt`、`.toml`、`.csv`、`.tsv`、`.svg`、Mermaid、PDF、画像である（[ADR 0004](0004-workspaces-and-projects.md)）。
JSON の仲間のファイルはツリーに出ず、開けず、検索もされない。

Golem は、参考文献のデータを CSL-JSON の形式のファイルで読む。
`manifest.toml` の `bibliography` に、そのファイルを並べる（[tett23/golem のマニュアル 4 章](https://github.com/tett23/golem/blob/5285c2965f1a46f7af1e71da57f4802c076c0eb9/manual/chapters/04-manifest.gm)）。
CSL-JSON は Zotero などの文献管理のソフトウェアが書き出す形式で、書き手が手で直すこともある。
JSON を扱えないと、プロジェクトの入力の一部を Aleph の外で直すことになる。

メンテナーから、JSON も扱いたいと求められた（2026-11-07）。
下書きのレビューでは、JSONC、JSON Lines、JSON5 もひととおり扱うこと、⌘S でも整形することを求められた。
整形されていない JSON（1 行に詰めたものなど）を読むのは苦痛だ、という理由である。

四つの形式は、次のように違う。

- **JSON**：RFC 8259 と ECMA-404 が定める。
- **JSONC**（JSON with Comments）：JSON に `//` と `/* */` のコメントを足したもの。VS Code の設定ファイルなどで使われ、VS Code は末尾のカンマも受けるが警告を出す。拡張子は `.jsonc` が使われる。
- **JSON5**：JSON5 1.0.0 が定める。コメント、末尾のカンマ、引用符のないキー（ECMAScript 5.1 の識別子名）、単一引用符の文字列、行末の `\` による文字列の継続、`\x` などのエスケープ、16 進数、`.8` や `8.` の数、`+` の符号、`Infinity` と `NaN`、追加の空白文字を許す。
- **JSON Lines**：1 行に一つの JSON の値を書く。行は `\n`（`\r\n` も可）で終え、空の行は許さない。最後の改行は推奨。拡張子は `.jsonl`。

エディタは [ADR 0019](0019-one-editor-for-both-writing-modes.md) の一つのエディタで、形式ごとの字句の読み方と、診断の層（波線、溝の印、診断の一覧）を持つ。

## 実装すること

### 開く

- 拡張子 `.json`、`.jsonc`、`.json5`、`.jsonl` のファイルを、Aleph がテキストとして開く形式に足す。ツリーに出し、エディタで開き、検索（[ADR 0015](0015-diagnostics-and-search.md)）の対象にする。形式は拡張子で決める。
- エディタではコードとして扱う。等幅で書き、1 行の字数はほかのコードと同じ 110 字とし、縦書きにはしない。

### 色付け

- 形式ごとに字句の読み方を足す。キーの文字列、値の文字列、数、`true`・`false`・`null`（JSON5 では `Infinity`・`NaN` も）、記号、コメントを分けて色を付ける。JSON5 の引用符のないキーはキーの色にする。
- JSONC と JSON5 は、行をまたぐ `/* */` のコメントを、JSON5 は `\` で継続する文字列を、行の状態として次の行へ引き継ぐ。

### 文法の検査

- 検査を形式ごとに自前で書く。文書を読み、最初の誤りの位置（UTF-16 の位置）と理由を、エラーの診断としてエディタの診断の層に出す。
  - JSON：RFC 8259 に従う。誤りの例は、閉じていない文字列、末尾のカンマ、コロンの抜け、許されないエスケープ、文字列の中の制御文字、先頭に 0 が続く数、値の後の余計な文字、空の文書。
  - JSONC：JSON にコメントを許す。末尾のカンマは誤りにせず、警告にする。
  - JSON5：JSON5 1.0.0 に従う。
  - JSON Lines：行ごとに JSON として読み、行ごとに最初の誤りを出す（一つの行の誤りで、ほかの行の検査を止めない）。空の行は誤りとする。ただし、ファイルの末尾の改行の後は空の行と数えない。
- 同じオブジェクトの中でキーが重なるときは、四つの形式とも、警告の診断を二つ目のキーに出す（RFC 8259 はキーが重ならないことを「SHOULD」とする）。
- 検査は、文書が変わって入力が 300 ミリ秒止まったときに行う。ステータスバーの LSP の位置には何も出さない（これらの形式には LSP をつながない）。

### 整形

- 整形を自前で書く。字句の並びを読み直して、空白と改行だけを組み直す。字句そのもの（数、文字列とその引用符の種類、引用符のないキー、コメント、JSONC と JSON5 の末尾のカンマ）は書かれた文字のまま残し、キーの順も変えない。
  - JSON、JSONC、JSON5：空白 2 つの字下げで、オブジェクトと配列の要素を 1 行に一つずつ置く。空のオブジェクトと配列は `{}` と `[]` にする。キーとコロンのあいだには空白を置かず、コロンの後に空白を一つ置く。
  - コメント：自分の行にあったコメントは、自分の行に、その位置の字下げで残す。字句の後ろの同じ行にあったコメントは、その字句（とカンマ）の後ろの同じ行に残す。
  - 要素のあいだにあった空の行は、一つの空の行として残す（設定ファイルの項目のまとまりを保つため）。
  - JSON Lines：行ごとに、改行を含まない 1 行の形に組み直す（`{"a": 1, "b": [1, 2]}` のように、コロンとカンマの後に空白を一つ置く）。行の順は変えない。
  - 文書の末尾には改行を一つ置く。
- 整形は、⌥⇧F、ツールバーのメニューの「整形（⌥⇧F）」、⌘S で行い、一回の変更として当てる（⌘Z で一度に戻せる）。
  - ⌘S での整形は、[ADR 0009](0009-lsp-and-formatting.md) の設定「⌘S で整形する」（既定はオン）に従う。設定の説明を、golem lsp の形式と JSON の仲間の両方に効くものに書き換える。自動保存では整形しない。
  - 文法の誤りがあるときは整形せず、「JSON に誤りがあるため整形しません」と知らせる。⌘S では、整形せずに保存する。
  - 変わったときは「整形しました」、変わらなかったときは「変更はありません」と知らせる（[ADR 0009](0009-lsp-and-formatting.md) と同じ文言）。

### Golem との関わり

- プロジェクトの中の `.json` を保存したときは、`.toml` と同じく、2.5 秒たってから lint と preflight を裏で実行する（[ADR 0015](0015-diagnostics-and-search.md)）。参考文献のデータの誤りを、Golem の側の診断でも拾うためである。Golem が読むのは `.json` だけなので、ほかの三つの形式では実行しない。

## 実装しないこと

- 開いたときの自動の整形（書き手が保存しないかぎりファイルを変えない）。開いたあとに ⌥⇧F で整形できる。
- 形式のあいだの変換（JSON5 から JSON へ、など）。
- JSON Schema による検査と、CSL-JSON の項目の検査（CSL-JSON の中身の誤りは Golem の check に任せる）。
- 木の形で見る表示と、折りたたみ。
- `.ndjson`、`.geojson` などのほかの拡張子と、圧縮した JSON Lines（`.jsonl.gz`）。
- `.aleph/` のような隠しディレクトリの JSON をツリーに出すこと（ツリーの今の規則のまま、`.` で始まるものは出さない）。

## テスト設計

DOM に触れない部分を関数に分け、`node --test` で確かめる。テストを先に書いて失敗させてから実装する。

- 形式の判定：四つの拡張子がテキストとして開く形式に入り、ツリーに出て、検索の対象の拡張子に入ること。
- 字句の読み方：
  - JSON：キーと値の文字列の見分け（コロンの前か後か、配列の中の文字列は値）、エスケープを含む文字列、負の数と指数、`true`・`false`・`null`、記号、閉じていない文字列は行末までを文字列とすること。
  - JSONC：行のコメント、行をまたぐブロックのコメントの状態の引き継ぎ。
  - JSON5：引用符のないキー、単一引用符の文字列、`\` で継続する文字列の状態の引き継ぎ、16 進数、`Infinity`・`NaN`、`.8` と `8.`。
  - JSON Lines：行ごとに JSON として色が付くこと。
- 文法の検査：
  - JSON：正しい文書（スカラー一つだけ、入れ子、空の文字列、サロゲートペアと `😀` のエスケープ）が誤りを出さないこと。各誤りについて、位置（UTF-16）と理由を確かめる。例は JSONTestSuite（MIT）の `y_` と `n_` から、範囲を代表するものを取る。
  - JSONC：コメントを受けること、末尾のカンマが警告になること、閉じていないブロックのコメントが誤りになること。
  - JSON5：json5-tests（MIT）の正しい例と誤った例から、各機能を代表するものを取る。
  - JSON Lines：正しい複数の行、途中の空の行の誤り、末尾の改行が誤りにならないこと、二つの行の誤りがそれぞれの行に出ること。
  - キーの重なりの警告が、二つ目のキーの位置に出ること（四つの形式とも）。
- 整形：
  - 入れ子の字下げ、空のオブジェクトと配列、数と文字列が書かれたまま残ること、キーの順が変わらないこと、二度当てても変わらないこと、末尾の改行、誤りのある文書では整形しない（null を返す）こと。
  - JSONC と JSON5：自分の行のコメントと行末のコメントの置き場所、末尾のカンマが残ること、単一引用符と引用符のないキーが残ること、`\` で継続する文字列が崩れないこと、要素のあいだの空の行が一つにまとまって残ること。
  - JSON Lines：1 行に詰めた形になり、行の順と数が変わらないこと。
- ⌘S での整形：設定がオンなら整形してから保存し、オフなら整形せずに保存すること、誤りがあれば整形せずに保存すること、自動保存では整形しないことを、整形と保存の手順を表す関数で確かめる。
- 画面の確かめ方：見本のプロジェクトに、1 行に詰めた CSL-JSON のファイルと、JSONC、JSON5、JSON Lines のファイルを置く。ツリーに出ること、色が付くこと、末尾のカンマを書くとその位置に波線と溝の印が出て診断の一覧から移れること、⌥⇧F と ⌘S で整形され ⌘Z で一度に戻ること、誤りがあるときは整形しないことを確かめる。

## トレードオフ

- 検査と整形を自前で書くので、依存は増えないが、四つの形式の細部（数の書き方、エスケープ、制御文字、JSON5 の識別子名と空白）を自分で抱える。JSONTestSuite と json5-tests の例で確かめることで補う。
- `JSON.parse` と `JSON.stringify` を使えば JSON だけは短く書けるが、誤りの位置の示し方が WebView ごとに違い、整形で数の書き方（`1.0` や大きな整数）とエスケープが変わり、コメントも消えるので使わない。
- ⌘S で整形するので、Zotero などの道具が書き出したファイルを ⌘S で保存すると、字下げが変わって差分が大きくなることがある。読みやすさを優先し、困るときは設定の「⌘S で整形する」を切れるようにする。この設定は golem lsp の形式とも共通で、JSON の仲間だけを切ることはできない。
