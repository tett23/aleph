# ADR 0036: ⌘W はタブを閉じるキーとし、割り当てられないキーから外す

ステータス: 採択

## 文脈

[ADR 0034](0034-key-bindings.md) は、アプリのメニューが持つキーを割り当ての対象にしないと決め、その例に ⌘W を挙げた。
トレードオフの節でも、「⌘W などを別の操作に使うことはできない」と書いた。

一方、[ADR 0024](0024-tabs-and-split.md) は、⌘W で選んでいるタブを閉じ、ウインドウのメニューの「ウインドウを閉じる」のキーを ⇧⌘W に変えると決めた。
実装はこちらに従う。
メニューの「ウインドウを閉じる」は ⇧⌘W を持ち（[src-tauri/src/lib.rs](https://github.com/tett23/aleph/blob/4e0248c/src-tauri/src/lib.rs#L425-L432)）、⌘W はコマンド `file.closeTab` の既定のキーである。
割り当てられないキーの一覧は、⌘W ではなく ⇧⌘W を持つ（[app/keymap.ts](https://github.com/tett23/aleph/blob/4e0248c/app/keymap.ts#L77-L78)）。

二つの ADR は、⌘W がメニューのキーかどうかで食い違う。
[ADR 0021](0021-json-files.md)〜0035 を実装と照らしたレビューで、この食い違いが見つかった。
メンテナーは、今の実装を追認する ADR を書くよう求めた（2026-11-08）。

## 実装すること

- [ADR 0034](0034-key-bindings.md) の「アプリのメニューが持つキー」の一覧を、⌘Q、⇧⌘W、⌘C、⌘V、⌘X、⌘M、⌘H、⌥⌘H、⌃⌘F とする。⌘W はこの一覧に入れない。
- ⌘W は、コマンド `file.closeTab` の既定のキーとする（[ADR 0024](0024-tabs-and-split.md)）。ほかのコマンドの既定のキーと同じく、割り当ての設定で変えられ、外せる。
- ⌘W を `file.closeTab` から外したときは、⌘W で何も起きない。メニューの「ウインドウを閉じる」は ⇧⌘W のままで、⌘W に戻らない。
- [ADR 0034](0034-key-bindings.md) のステータスを「採択→アプリのメニューのキーの一覧はADR 0036」とする。

コードは、すでにこのとおりに振る舞う。この ADR で足すのは、下のテストと仕様書の記述である。

## 実装しないこと

- 「ウインドウを閉じる」のキーを、割り当ての設定で変えられるようにすること（アプリのメニューのキーは変えない、という [ADR 0034](0034-key-bindings.md) の決めごとは保つ）。
- ⌘W でタブがないときに、ウインドウを閉じること。

## テスト設計

DOM に触れない部分を `node --test` で確かめる。

- 割り当てられないキーの判定：⇧⌘W が割り当てられず、⌘W が割り当てられること（app/keymap.test.ts）。
- 既定の割り当て：`file.closeTab` の既定のキーが ⌘W であり、それを外した設定では ⌘W がどのコマンドにも当たらないこと（`effectiveBindings` と `press` で確かめる、app/keymap.test.ts）。
- 画面の確かめ方：設定の「キーの割り当て」で ⌘W を記録すると「このキーは使えません」と出ずに受け付けられ、⇧⌘W を記録すると出ること。

## トレードオフ

- ⌘W をタブに使うので、macOS のほかのアプリでウインドウを閉じる手癖が、Aleph ではタブを閉じる操作になる。Safari などのタブを持つアプリと同じ割り当てなので、こちらを優先した（[ADR 0024](0024-tabs-and-split.md) と同じ判断）。
- ⌘W を外せるので、外した書き手には、タブを閉じるキーがなくなる。タブの × とコマンドパレットで閉じられる。
