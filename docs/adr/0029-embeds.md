# ADR 0029: Markdown のプレビューでのシートの埋め込み

ステータス: 採択

## 文脈

Obsidian は、`![[名前]]` と書くと、別のノートの全体や見出しの下の部分を、その場に表示する（埋め込み）。
設定のメモの一部を別のメモに集めたり、章の構成を書いたメモに各章の冒頭を並べたりするのに使う。

メンテナーは、Obsidian と Ulysses にあって Aleph にない機能を比べ、埋め込みの ADR を求めた（2026-11-07）。
ウィキリンクは Markdown のシートにだけ入れる（[ADR 0027](0027-wikilinks-in-markdown.md)）ので、埋め込みも Markdown のシートの中だけとする。

今の Aleph の関わる部分は次のとおりである。

- Markdown のプレビュー（[ADR 0010](0010-previews.md)）は、自前の読み方 [`app/md.ts`](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/md.ts) の `markdownHtml` で、一つの文字列から HTML を作る。ファイルを読む処理は持たない。
- `.gm` のプレビューで Golem の HTML がまだないときは、記号を取り除いた本文を出す（[`app/preview/render.ts`](https://github.com/tett23/aleph/blob/556db161917fdf32808b5b5153fdce0a99c65c71/app/preview/render.ts) の `plainHtml`）。
- 画像は、ファイルのバイトから作った URL で出す（同じファイルの `fileUrl`）。

## 実装すること

### 書き方

- `.md` のシートの中で、行の全体が次の形のものを埋め込みとする。
  - `![[行き先]]`：シートの全体。
  - `![[行き先#見出し]]`：その見出しの行から、同じかより上の階層の次の見出しの前まで。
  - `![[画像のパス]]`：PNG、JPEG、GIF、WebP、SVG の画像。
- 行き先の決め方は [ADR 0027](0027-wikilinks-in-markdown.md) のウィキリンクと同じとする。
- 行の途中の `![[…]]` は、埋め込みにせず、ウィキリンクとして扱う（Markdown の段落の中に、ブロックを入れないため）。

### プレビュー

- プレビューを描く前に、埋め込みの行き先を集めて読み（開いているシートはエディタの今の文字、ほかはファイル）、その中身で埋め込みの行を置き換えて描く。
  - `.md`：Markdown として読み、その中の埋め込みも同じように置き換える。
  - `.gm`：`plainHtml` で、記号を取り除いた本文にする（埋め込みのために Golem を実行しない）。
  - そのほかのテキストの形式：`<pre>` の中に文字として出す。
  - 画像：画像として出す。
- 埋め込みは、枠で囲み、見出しに行き先の名前（`#見出し` があれば `名前 > 見出し`）を出す。見出しを押すと行き先を開く。
- 入れ子は 3 段までとする。それより深いものと、自分の祖先を埋め込むもの（循環）は、中身を出さず、「（循環のため埋め込みません）」か「（入れ子が深すぎるため埋め込みません）」とだけ出す。
- 一つのプレビューで埋め込む中身の合計は 20 万字までとし、超えた分は「（長すぎるため省きました）」と出す。
- 行き先が見つからないときと見出しが見つからないときは、その旨を枠の中に出す。
- 埋め込んだシートを保存したときは、それを埋め込んでいる開いたプレビューを描き直す。

### エディタと変換

- エディタでは、埋め込みの行をウィキリンクと同じ字句の色で出し、先頭の `!` を記号の色にする。⌘ を押しながらの押下で行き先を開くのも、ウィキリンクと同じとする。
- gm への変換（[ADR 0016](0016-markdown-to-gm.md)）では、画像の埋め込みは Markdown の画像と同じく `@figure` にし、シートの埋め込みは行き先の名前だけの段落にする（中身は写さない）。

## 実装しないこと

- `.gm` の中の埋め込みと、`.gm` のプレビューへの埋め込み。
- エディタの中での埋め込みの中身の表示と、その場での編集。
- ブロックへの参照（`![[名前#^id]]`）と、PDF のページの埋め込み。
- 埋め込みの中身の字数を、埋め込んだシートの字数に数えること。

## テスト設計

DOM に触れない部分を関数に分け、`node --test` で確かめる。テストを先に書いて失敗させてから実装する。

- 書き方の読み取り：行の全体の `![[…]]` だけが埋め込みになり、行の途中のものがウィキリンクになること。見出しつき、画像のパス。
- 見出しの範囲：見出しの行から、同じかより上の階層の次の見出しの前まで。最後の見出し、見つからない見出し、コードブロックの中の `#` を見出しと読まないこと。
- 展開：`.md` の入れ子の置き換え、3 段の限り、循環（自分自身、二つのシートのあいだ）、合計の字数の限り、見つからない行き先。読み出しは関数として渡し、ファイルを読まずに確かめる。
- 形式ごとの出し方：`.gm` が `plainHtml` を通ること、ほかのテキストが `<pre>` になること、画像が画像になること。
- gm への変換：画像の埋め込みが `@figure` に、シートの埋め込みが名前だけの段落になること。
- 画面の確かめ方：見本のワークスペースに、章の冒頭と人物のメモを埋め込んだ `.md` を置き、プレビューに枠と中身が出ること、見出しを押すと開くこと、循環の知らせ、埋め込んだシートを保存したときに描き直されることを確かめる。

## トレードオフ

- プレビューを描くたびに埋め込みの行き先を読むので、埋め込みの多いシートではプレビューが遅くなる。合計の字数の限りで抑える。
- `.gm` を埋め込むときに Golem を実行しないので、命令の結果（ルビ、図版など）は出ない。プレビューの速さを優先する。
- 埋め込みを行の全体に限るので、文の途中に別のシートの文を差し込むことはできない。Markdown の段落の構造を崩さないためである。
