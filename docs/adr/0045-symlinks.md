# ADR 0045: シンボリックリンクを辿らない

ステータス: 採択（未実装）

## 文脈

ツリーを読む `fsops::tree` は、`is_dir`（リンク先を見る）で再帰し、ループの検出も深さの上限もない（[src-tauri/src/fsops.rs](https://github.com/tett23/aleph/blob/b4ee3c4/src-tauri/src/fsops.rs#L22-L42)）。
書き込みの `write_text` は `std::fs::write` を使い、書き先がリンクならリンク先を上書きする（同じファイルの 44〜49 行目）。
2026-11-08 のセキュリティ監査（[docs/audit/2026-11-08-security.md](../audit/2026-11-08-security.md) の所見 4）は、共有されたリポジトリのリンクで、次のことが起きると指摘した。

- `a -> .` のようなループで、ツリーの読み込みが止まらない。
- `docs -> ../../..` のようなリンクで、ワークスペースの外のファイルがツリーに出て、ウィキリンクの埋め込みでプレビューに出せる。
- `memo.md -> ~/.zshrc` のようなリンクを編集して保存すると、リンク先が上書きされる。

メンテナーは、監査の修正をすべて ADR にするよう求めた（2026-11-08）。

## 実装すること

- `tree` と `list_dir` は `symlink_metadata` で種類を見て、シンボリックリンクはディレクトリとしてもファイルとしても辿らない。ツリーには出さない。
- `tree` に深さの上限（64 段）を置く。
- 書き込み（`write_text`、`write_bytes`、`copy_file` の書き先、`move_path` と `rename_path` の行き先）は、書き先がシンボリックリンクなら拒む。
- 読み込み（`read_text`、`read_bytes`）は、パスの途中かその先にシンボリックリンクがあり、`canonicalize` した結果が許す範囲（[ADR 0042](0042-ipc-trust-boundary.md)）の外なら拒む。
- 検索と置換は、今までどおりリンクを辿らない（`ignore` の既定）。

## 実装しないこと

- ワークスペースの中を指すリンクを、ツリーに出して辿ること。手間に比べて使う場面が少ない。
- リンクを Aleph から作ること。

## テスト設計

`cargo test` で、テストを先に書いて失敗させてから実装する。一時のディレクトリにリンクを作って確かめる。

- ループするリンク（`a -> .`）があっても `tree` がすぐ終わり、リンクがツリーに出ないこと。
- ワークスペースの外を指すディレクトリのリンクとファイルのリンクが、ツリーに出ないこと。
- 深さの上限で止まること。
- 書き先がリンクの `write_text`、`write_bytes`、`copy_file`、`move_path` が拒まれ、リンク先が変わらないこと。
- 外を指すリンクを通る `read_text` が拒まれること。

## トレードオフ

- リンクで別の場所の原稿をワークスペースに取り込む使い方はできなくなる。原稿はワークスペースの中に置く前提とする。
