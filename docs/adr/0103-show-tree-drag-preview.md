# ADR 0103: ツリーでドラッグする項目をポインターに追従表示する

Status: proposed

## 文脈

指示者から、シートをドラッグしてもシートの表示が動かず、操作している感触が乏しいとの指摘があった。
シートとフォルダに共通して、名前とアイコンの半透明なコピーをポインターに追従させたい。
このコピーを、以降「ドラッグ表示」と呼ぶ。

[ADR 0100](0100-move-tree-files-and-folders.md) の移動先の強調に、ドラッグ元を見失わないための表示を補う。
ファイルを実際に移す時点と移動の規則は、同 ADR のままとする。

## 調査した事項

基準版は `006c66ce4a871991073934a4393ebb5129d8f381` である。
`app/dragout.ts` の `mountDragOut` は、押下位置から 4 CSS px 以上動くと内部のドラッグとして扱う。
移動先の要素に `tree-move-target` または `tree-move-refuse` を付けるが、ドラッグ元を追従表示する要素は作らない。
ポインターがウィンドウ外へ出ると内部の操作を終了し、`api.dragOut` でネイティブのドラッグに渡す。
終了処理は移動先の印とイベントリスナーを除き、Esc、ポインターの取消、ウィンドウのフォーカス喪失でも呼ばれる。

`app/ui/tree.ts` の行は、種類のアイコン、表示名、必要に応じたファイル名を別の要素にしている。
内部移動の対象はファイルとフォルダの行から取得する。
プロジェクトの行もフォルダとして扱う。
画像のドラッグは `app/imagedrag.ts` に別の処理があり、ファイル名の追従表示と、Golem の章への挿入位置の印を作る。
根拠は末尾の固定した版のソースに示す。

## 実装すること

### 表示する内容と位置

シート、その他のファイル、通常のフォルダ、プロジェクトフォルダの内部ドラッグに、共通のドラッグ表示を付ける。
既存の開始判定を満たした時点で一つ表示し、ポインターの移動に追従させる。
クリックだけの場合は表示しない。
移動できない項目や行き先でも、ドラッグ表示そのものは残し、移動不可の印を添える。

ドラッグ表示には、押下したツリー行と同じ種類のアイコンと表示名を使う。
ツリー行にファイル名を併記している場合は、それも含める。
文字はテキストとして扱い、名前に含まれる HTML を解釈しない。
表示全体の不透明度を 0.65 とし、明暗の各テーマに合わせた背景と枠を付ける。
名前が長い場合は一行で末尾を省略し、表示幅は 240 CSS px 以下とする。

ドラッグ表示は、ポインターの右下からそれぞれ 12 CSS px 離して置く。
右端か下端に収まらない場合は、対応する軸でポインターの反対側へ置く。
反対側にも収まらない場合は、表示の幅や高さを表示領域以内に制限し、領域内へ位置を補正する。
通常時は表示領域の端から 4 CSS px の余白を取り、表示領域がその余白を取れない大きさなら余白を縮める。
ウィンドウのサイズや表示倍率が変わった場合は、現在の表示領域から位置を計算し直す。

### 移動先の判定と元の行

ドラッグ表示はツリーの配置から独立した表示面に置き、ポインターイベントを受け取らない。
移動先はドラッグ表示の背後にある要素から判定する。
ツリーのスクロールで行き先が変わった場合も、最後に受け取ったポインター位置で判定と印を更新する。
表示の更新を理由にツリーをスクロールさせたり、行を並べ替えたりしない。

元の行は、その位置と寸法を保って表示する。
ドラッグ表示のために元の行を取り除いたり、空き行に置き換えたりしない。
移動成功後のツリー更新は [ADR 0100](0100-move-tree-files-and-folders.md) に従う。

移動先の強調と不可表示は、移動元と移動先を合わせた内部移動の判定結果に従う。
有効な行き先では移動先の行を強調し、ツリーの空白が行き先ならツリー全体を強調する。
この場合、ドラッグ表示には不可の印を出さない。
移動元の保護規則に反しない同じ親へのドロップは、従来どおり何もせず、不可とは表示しない。
移動元が保護されている場合と、禁止された行き先ではドラッグ表示に不可の印を出す。
ツリー以外の場所も不可とするが、画像を挿入できるエディタは、次の規則で扱う。
ファイルシステムの競合など、実行時にしか判定できない失敗は、既存の通知で扱う。

ツリーからの画像ドラッグの追従表示は、この共通のドラッグ表示に統一する。
既存の画像用の追従表示を重ねて出さない。
挿入できるエディタ上では、既存の画像挿入の判定と挿入位置の印を使い、不可の印は出さない。
挿入できないエディタでは不可の印を出す。
ツリー上では内部移動、エディタ上では画像挿入を判定し、一度のドロップで両方を実行しない。

### 終了と外部への受け渡し

ボタンを離したときは、確認ダイアログやファイル処理を待たず、ドラッグ表示を消す。
Esc、ポインターの取消、フォーカス喪失、ワークスペースの切り替えでも、表示と内部の操作状態を片付ける。
後から届く移動イベントで、終了した操作の表示を復活させない。

ウィンドウ外へ出たときは、ネイティブのドラッグを始める前にドラッグ表示を消す。
以後の表示は OS に任せ、内部移動を重ねて実行しない。
ネイティブのドラッグ開始に失敗しても、内部の表示を残さない。
同じ操作でポインターがウィンドウ内へ戻っても、内部のドラッグ表示を作り直さない。

[ADR 0077](0077-hand-sidebar-files-outside.md) の複数選択の外部への受け渡しと、[ADR 0078](0078-accept-drops-on-the-tree.md) の外部からのコピーは、対象と処理を変えない。
内部のドラッグ表示は押下した一項目を表す。
外部への受け渡しで複数選択が対象になる場合の表示は OS に任せる。
ツリーからエディタへの画像の挿入も維持する。

## 実装しないこと

複数項目の内部移動、ドラッグによる表示順の変更、フォルダの自動展開、端での自動スクロールは追加しない。
本文内の画像から始めるドラッグ、プレビュー、タブのドラッグ表示は対象外とする。
Golem の移動計画の契約は変更しない。

## 不変条件

- I1: 内部ドラッグが成立してから終了するまで、押下した一項目を表すドラッグ表示が一つあり、成立前と終了後には存在しない。
- I2: ドラッグ表示の有無と位置だけが異なる状態では、同じポインター位置での移動先判定、ツリー行の矩形、ツリーのスクロール位置が等しい。
- I3: ドラッグ表示の更新後、その矩形は現在の表示領域に収まり、表示幅は 240 CSS px 以下である。
- I4: 不可の印は、ツリー上では移動元と移動先から得た内部移動の判定が禁止の場合だけ表示し、ツリー外では有効な画像挿入先を除いて表示する。
- I5: 取消と外部への受け渡しの後は、同じ操作のイベントで内部移動とドラッグ表示を再開しない。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| クリック、移動距離が 4 CSS px 未満 | ドラッグ表示なし | I1 |
| 移動距離がちょうど 4 CSS px、シート一つ | 表示が一つ現れて追従 | I1, I2 |
| 資料、空フォルダ、子孫を持つフォルダ、プロジェクト | 押下した行の名前とアイコンを表示 | I1 |
| 長い名前、HTML に見える名前 | 幅を制限し、文字として表示 | I3 |
| 右下端、左上端、小さい表示領域、倍率変更 | 表示領域内へ補正 | I3 |
| 有効な行、同じ親、自分自身、子孫、同名衝突、ツリー外 | 判定に合う行き先の印と不可の印 | I2, I4 |
| ツリーの空白への有効な移動 | ツリー全体を強調し、不可の印なし | I2, I4 |
| 移動が禁止された設定ファイルを、通常なら有効な行き先へ | 移動元の保護規則に従って不可の印 | I4 |
| ポインターを動かさずツリーをスクロール | 背後の行から行き先を再判定 | I2, I4 |
| 画像をツリーから有効なエディタへ、または無効なエディタへ | 追従表示は一つ、挿入の可否に合う印 | I1, I4 |
| ドロップ後の確認待ち、Esc、取消、フォーカス喪失、ワークスペース切り替え | 表示を消し、古いイベントを無視 | I1, I5 |
| ウィンドウ外への受け渡し、開始失敗、再入場 | 内部表示なし、内部移動の再開なし | I1, I5 |

## 受けいれ条件

- A1: macOS の Tauri でシートとフォルダをドラッグすると、明暗両テーマで名前とアイコンが半透明でポインターに追従する。
- A2: ドラッグ表示に行き先が重なっていても、同じ行へのドロップ結果が変わらず、有効と不可を見分けられる。
- A3: 取消、内部ドロップ、ウィンドウ外への受け渡しの後に表示が残らず、次のドラッグを通常どおり始められる。

## テスト設計

I1 と I5 は、開始から終了までのイベント列のテストを先に失敗させる。
ポインターイベントとマウスの互換イベントが両方届いても、表示と操作が二重にならないことを含める。
Esc 後のボタン解放、外部への受け渡し後の再入場、非同期処理の失敗を与え、表示数と内部移動の呼び出し回数を比較する。

I2 と I4 は、WebKit でドラッグ表示を行に重ね、表示前後の移動先と行の矩形とスクロール位置を比較する。
ドラッグ表示を一度除いた場合と同じ要素を移動先として得ることも確かめる。
I3 は位置を計算する処理に境界の表の入力を渡し、WebKit でも実際の表示矩形を照合する。
テスト名には、この ADR と対応する不変条件の番号を付ける。

A1〜A3 は試験用ワークスペースで、実際のマウスを押したまま移動して確認する。
シート、資料、空フォルダ、子孫を持つフォルダ、プロジェクトの各行を扱う。
押下中の静止、ツリーのスクロール、画面端、Esc、Finder への受け渡しと取消を確かめる。
画像をエディタへ落とす操作と、Finder からツリーへコピーする操作が一度だけ動くことも確認する。
画像をツリーからエディタへ往復させ、追従表示が常に一つであり、不可の印と挿入位置の印が行き先に合うことを確かめる。

## トレードオフ

ドラッグ表示があれば、元の行から離れた場所でも、操作中の項目を識別できる。
移動先を覆うことがあるため、半透明にし、表示とは独立して移動先を判定する。
OS のドラッグ表示と独自の表示を切り替える処理は増えるが、表示の寿命を内部操作とそろえて残留を防ぐ。
