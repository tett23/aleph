# ADR 0087: プレビューを、エディタの右の領域からタブに移す

Status: superseded [{"part":"不変条件 I7","by":["docs/adr/0088-diff-tab-and-commit-before-applying.md"]},{"part":"プレビュー更新後のスクロール位置","by":["docs/adr/0097-restore-preview-scroll-on-refresh.md"],"kind":"supplement"},{"part":"保存の後の組みなおしと不変条件 I10","by":["docs/adr/0113-refresh-previews-on-project-input-changes.md"],"kind":"supplement"}]

## 文脈

Aleph のプレビューは、エディタの枠の右に固定の幅で置く一つの領域である ([ADR 0005](0005-layout-and-appearance.md)、[ADR 0010](0010-previews.md)、[ADR 0024](0024-tabs-and-split.md))。
メンテナーは、タブの中身として、シートのほかのもの (差分の一覧など) を出したいと考えている (2026-11-18)。
その最初の段として、プレビューをタブの中身に移し、ファイルでないタブの形を試すよう求めた。

メンテナーは、同じ日に次のことを決めた。

- プレビューのタブは、今のプレビューの領域と同じく、書き手が選んだシートに従う。開いたときのシートには固定しない。
- 今のプレビューの領域はなくし、プレビューはタブだけで出す。
- タブの中身を別のウィンドウに移せる作りになることは許す。ただし、タブを別のウィンドウに移すことと、そのウィンドウを全画面にして書くこと (いわゆる zen モード) は、この ADR では作らない。後者は、メンテナーが価値を感じておらず、余計な機能になりうるためである。
- [画面のモック](../research/2026-11-18-preview-tab-mock.svg) を見て、形はこれでよいとした。

## 調査した事項

この節には、コードを読んで確かめたことだけを書く。
コードは、main のコミット [d45d840](https://github.com/tett23/aleph/tree/d45d84097175daf8ed7faf4d2d1424787448fff2) のものである。
以下、ファイルの名前だけを書くときは、このコミットのものを指す。

### プレビューの領域

- 画面の骨組みは、`.split` の中に、エディタの領域 (`.editor-area`) とプレビューの領域 (`.preview-area`) を左右に並べる ([`app/ui/shell.ts`](https://github.com/tett23/aleph/blob/d45d84097175daf8ed7faf4d2d1424787448fff2/app/ui/shell.ts) の 62 行から 65 行)。ペインは、エディタの領域の中に作る。そのため、今は二つのペインとプレビューの三つを並べられる。
- プレビューの領域の幅は、固定の 42% で、境目は動かせない (`app/style.css` の `.preview-area { flex: 0 0 42%; … }`)。
- 何を出すかは、画面の状態の最上位の `previewMode` (`"none"`、`"plain"`、`"pages"`) で決める (`app/store.ts` の 19 行と 33 行)。`previewMode` は保存して、次に起動したときに戻す (`app/main.ts` の `KEPT`)。古い鍵 `side` の値も読む (`app/legacy-names.ts`)。
- 出すシートは、選んでいるペインの選んでいるタブの、焦点のあるシートである (`app/store.ts` の `focused`)。`.gm` の本文は、選んでいるタブの `.gm` のシートをすべて並べる (`app/preview/mount.ts` の `chaptersShown`)。プロットのタブを選んでいるときは、領域を隠す (同じファイルの `drawSide`)。
- 本文の縦と横は、選んでいるタブのシートで決める (`app/toolbar.ts` の `verticalOn`)。
- 形式ごとに選べるモードは、`.gm` が原稿のみ、本文、ページ、`.md`、`.svg`、Mermaid が原稿のみと本文で、ほかの形式にはプレビューが無い (`app/toolbar.ts` の `previewsFor`)。
- 切り替えは、ツールバーの右の「原稿のみ」「本文」「ページ」と、コマンド `preview.none`、`preview.plain`、`preview.pages` で行う (`app/ui/shell.ts`、`app/palette.ts`)。
- プレビューの領域の見出しには、組みなおすボタン、拡大率、別のウィンドウのボタン、組んでいるときの知らせを出す (`app/preview/mount.ts`)。
- 保存の後にページを組みなおすのは、設定「保存したらページを組みなおす」がオンで、そのプロジェクトに前のページの結果があるか、保存したシートの形式で「ページ」を選んでいるときである (`app/preview/mount.ts` の保存の処理の `ctx.config.rebuildOnSave && (pages.has(project) || effectivePreviewMode(before.kind, s.previewMode) === "pages")`、[ADR 0072](0072-refresh-pages-on-explicit-save.md))。
- ページの解像度は、`.preview-area .pbody` の幅から計算し、見つからないか幅が 0 なら、幅を 500 px として計算する (`app/preview/mount.ts` の `wantedDpi`)。拡大率と描いた結果の覚え (`zoom`、`lastKey` など) は、モジュールの変数で、一つの領域を前提にしている。
- プレビューの中のウィキリンクは、`focused(s)` のシートを起点にして解決する。埋め込みの見出しは、要素が持つパスを開く。埋め込みを含む Markdown は、`focused(s)` が `.md` のときに保存の後で描きなおす (`app/wikilinkmount.ts`)。

### タブとペイン

- タブは、`{ id, open, focus, plot }` の形で、シートの並び、焦点、プロットのプロジェクトを持つ (`app/store.ts` の `Tab`)。ファイルでないタブは、プロットのタブだけである。
- プロットのタブは、`plot` が `null` でないことで見分け、`app/editor/panes.ts` の `build` で `ctx.kindViews.plot` に描かせる。題は「プロット」である。
- ペインの中を押すと、そのペインが選ばれる (`app/editor/panes.ts` の mousedown)。
- シートを開くと、選んでいるタブの中身を入れ替える ([ADR 0024](0024-tabs-and-split.md)、`app/store.ts` の `replaceActive`)。
- タブの並びは、ワークスペースごとに `{ paths, focus }` か `{ plot }` の並びで保存し、無くなったシートを落として戻す (`app/store.ts` の `writeTabs`、`readTabs`、`dropMissing`、`app/tabsui.ts`)。
- ペインは一つか二つで、二つのときに一方が空になれば分割をやめる。ペインが一つのときに最後のタブを閉じると、空のペインが残る ([ADR 0037](0037-split-conditions.md))。

### 名前、コマンドの一覧、テスト

- 用語集の名前の列は、[ADR 0082](0082-ui-names-and-glossary.md) の表と同じでなければならない (`app/glossary.test.ts` の `ADR 0082 A1`)。用語集は「プレビューの領域」(`.preview-area`、`ctx.view.previewArea`) を持つ。
- `preview.none` は、[ADR 0023](0023-command-palette.md) のコマンドの一覧 (`app/commands.test.ts` の `INITIAL`) と、アシスタントの計測の道具の `bench/assistant/commands.json` にある。`app/toolbar.test.ts` は `previewsFor` の `"none"` を確かめる。
- README.md と README.ja.md は、プレビューの領域と「原稿のみ」を書いていない。

## 実装すること

### データ構造

- `Tab` に `preview: boolean` を足す。`preview` が `true` のタブを**プレビューのタブ**と呼ぶ。プレビューのタブは、シートを持たない (`open` は空、`plot` は `null`)。
- 画面の状態に `followed: number | null` を足す。これは**映すタブ**の `id` である。映すタブは、プレビューのタブでもプロットのタブでもない、シートを持つタブとする。
- **映すシート**は、映すタブの焦点のあるシートとする。
- 保存するタブの形に `{ "preview": true }` を足す。`followed` は保存しない。
- 以下で、ペインの中のタブの**番号**は、左から 0 で数えた位置とする。タブの並びの**最初**は、左のペインから、ペインの中では左から数えた最初とする。

### 映すタブの決め方

- 選んでいるペインの選んでいるタブが、シートを持つタブになったとき (開く、選ぶ、切り替える、移す、閉じた後に繰り上がる、戻すのどれでも)、`followed` をそのタブの `id` にする。
- 選んでいるタブがプレビューのタブか、別に開いてあったプロットのタブになっても、`followed` は変えない。
- 映すタブが無くなったとき (閉じたとき、`view.plot` などで中身ごと置き換えられたとき) は、`followed` を、次の順で最初に見つかるタブにする。どれも無ければ `null` にする。
  1. その後に選んでいるタブが、シートを持つタブなら、そのタブ。
  2. 映すタブがあったペインの、その後の並びで、シートを持つタブのうち、映すタブの番号に最も近い番号のもの。距離が同じなら番号の大きいもの。
  3. もう一方のペインの、シートを持つタブのうち、そのペインの選んでいるタブの番号に最も近い番号のもの。距離が同じなら番号の大きいもの。
- タブの並びを戻した後は、選んでいるペイン、もう一方のペインの順に、そのペインのシートを持つタブのうち、そのペインの選んでいるタブの番号に最も近い番号のもの (距離が同じなら番号の大きいもの) を `followed` にする。
- ワークスペースを切り替えたときは、`null` にする。

### 映すタブに従うもの

- 関数 `shown(s)` を足す。`shown(s)` は、選んでいるタブがシートを持つタブならそのタブの `open` と `focus` を、そうでなければ映すタブの `open` と `focus` を返す。映すタブも無ければ、空の `open` を返す。
- 次のものは、`focused(s)` と選んでいるタブの `open` の代わりに、`shown(s)` を読む。
  - ツールバーの題、「ほか N 章」、縦と横、ビルドのボタン
  - 右サイドバー
  - ステータスバー
  - 本文の縦と横
  - `.gm` の本文に並べる章と、別のウィンドウに送る本文
  - `preview.window` を使える条件
  - プレビューの中のウィキリンクを解決する起点と、埋め込みを含む Markdown を保存の後に描きなおす判定
- 次のものは、今のとおり `focused(s)` を読む。そのため、プレビューのタブを選んでいるあいだは、使えないか、何もしない。
  - エディタのコマンド (取り消し、検索、整形など) と、タブを切り替えた後にキャレットを置く先
  - 保存、ブックマーク、ゴミ箱、Markdown から `.gm` への変換
  - 起動のときに最後のシートを開くかの判定
- そのため、プレビューのタブの中のウィキリンクを押してプレビューのペインが選ばれても、リンクは映すシートを起点にして解決する。埋め込みの見出しは、今のとおり、要素が持つパスを開く。

### プレビューのタブを選んでいるときに開くこと

- プレビューのタブを選んでいるときにシートかプロットを開くと、次のとおりにする。どの場合も、プレビューのタブの中身は入れ替えない。
  - すでに開いているシートなら、今のとおり、そのタブを選ぶ。
  - 選んでいるタブの中身を入れ替える開き方なら、映すタブがあれば、映すタブのペインを選び、映すタブを選んで、その中身を入れ替える。映すタブが無ければ、新しいタブとして開く。
  - 新しいタブとして開く開き方なら、映すタブがあれば、映すタブのペインの、映すタブの次に開いて選ぶ。
  - 映すタブが無いときに新しいタブとして開くのは、ペインが二つならプレビューのタブの無い側のペインの末尾、ペインが一つならプレビューのタブの次とする。
- これは、[ADR 0024](0024-tabs-and-split.md) の「選んでいるタブの中身を入れ替える」への補足である。

### プレビューのタブの中身

- 映すシートのプレビューを出す。本文とページの描き方、組みなおす時、拡大率は、今のプレビューの領域のとおりとする ([ADR 0010](0010-previews.md)、[ADR 0056](0056-wait-before-building-pages.md)、[ADR 0072](0072-refresh-pages-on-explicit-save.md))。
- 何を出すかは、映すシートの形式と `previewMode` を受ける純粋な関数で決める。
  - `.gm` は、`previewMode` が `"plain"` なら本文、`"pages"` ならページ。
  - `.md` は本文、`.svg` と Mermaid は図で、`previewMode` によらない。
  - ほかの形式は「このシートにはプレビューがありません」、映すシートが無いときは「シートを選ぶと、ここにプレビューが出ます」の一行。
- 中身の上の見出しに、映すシートの名前、モードの切り替え、今の見出しのもの (組みなおすボタン、拡大率、別のウィンドウのボタン、組んでいるときの知らせ) を出す。映すタブが章をまとめて持つときは、焦点のある章の名前に「ほか N 章」を添える。
- モードの切り替えは、映すシートが `.gm` なら「本文」と「ページ」を出し、ほかの形式では出さない。
- ページの解像度は、プレビューのタブの中身の幅で決める。その幅が取れないとき (プレビューのタブが無いか隠れているときに、別のウィンドウの求めで組むとき) は、今のとおり幅を 500 px として計算する。
- プレビューのタブがそのペインで選ばれていないあいだは、プレビューのタブを描くことで始まる処理 (本文とページの最初のビルド、幅による描きなおし) を行わない。選ばれたときに、今の映すシートで描きなおす。保存の後の組みなおしと、別のウィンドウの求めで組むことは、下の条件のとおりに行う。
- 画面の部品の名前を次のとおり変える。`ctx.view.previewArea` は `ctx.view.previewTab`、`ctx.refresh` の鍵 `"previewArea"` は `"previewTab"` にする。`shell` の `previewAreaEl`、`previewHead`、`previewBody` はなくす。

### 開くことと閉じること

- コマンド `preview.plain` と、ツールバーの「プレビュー」のボタンは、タブが一つ以上あるときに使える。`preview.pages` は、それに加えて、`shown(s)` の焦点のあるシートが `.gm` のときだけ使える。
- `previewMode` の初めの値は `"plain"` とする。`preview.plain` は `previewMode` を `"plain"` に、`preview.pages` は `"pages"` にする。ボタンは `previewMode` を変えない。
- そのうえで、どれも次のとおりにプレビューのタブを出す。選んでいるペインは、どの場合も変えない。
  - プレビューのタブがあれば、それを持つペインの選んでいるタブにする。
  - プレビューのタブが無く、ペインが一つなら、右に新しいペインを作ってプレビューのタブを開く。これは、[ADR 0037](0037-split-conditions.md) の分割を始める条件に足す、もう一つの条件である。
  - プレビューのタブが無く、ペインが二つなら、選んでいないペインの末尾に開き、そのペインの選んでいるタブにする。
- プレビューのタブを閉じると、プレビューは出なくなる。閉じ方は、ほかのタブと同じ (⌘W、タブの閉じるボタン) とする。
- プレビューのタブは、ほかのタブと同じく、ドラッグでもう一方のペインに移せる。
- コマンド `preview.none` と、ツールバーの「原稿のみ」「本文」「ページ」をなくす。ツールバーの右には「プレビュー」のボタンを一つ置く。
- `previewMode` の値から `"none"` をなくす。保存した `previewMode` と古い鍵 `side` の値が `"plain"` でも `"pages"` でもなければ (`"none"` を含む)、`"plain"` として読む。読みかえは、`app/store.ts` の純粋な関数で行う。

### 保存の後の組みなおし

- 保存の後にページを組みなおすのは、設定「保存したらページを組みなおす」がオンで、保存したシートが `.gm` で、次のどちらかのときとする。
  - そのプロジェクトに前のページの結果がある (今のとおり)。
  - プレビューのタブがあり、`previewMode` が `"pages"` である。
- これは、今の条件の「保存したシートの形式で「ページ」を選んでいる」を、「プレビューのタブがあり、`previewMode` が `"pages"`」に置き換えるものである ([ADR 0072](0072-refresh-pages-on-explicit-save.md) の組みなおす対象の条件)。
- この条件は、プレビューのタブの有無、`previewMode`、設定、保存したシートの形式、前の結果の有無を受ける純粋な関数で決める。

### タブの並びを戻すこと

- `{ "preview": true }` が二つ以上あれば、最初のものだけを戻す。
- 無くなったシートのタブを落とした後も、プレビューのタブと残ったタブの順は保つ。一方のペインが空になれば、[ADR 0037](0037-split-conditions.md) のとおり分割をやめる。空のペインを落とすのは、今のとおり、並びを読む側 (`dropMissing` と `restoreTabs`) で行う。

### なくすもの

- プレビューの領域 (`.preview-area`) と、それを出し入れする処理をなくす。

## 実装しないこと

- プレビューのタブを、開いたときのシートに固定すること。
- プレビューのタブを二つ以上開くこと。
- タブを別のウィンドウに移すこと、ウィンドウを全画面にして書くこと (zen モード)。
- エディタとプレビューのスクロールを合わせること。
- `preview.window` (別のウィンドウのプレビュー) の振る舞いを変えること。使える条件と送る本文が `shown(s)` に従うことだけを変える。
- プレビューのタブを選んでいるあいだに、エディタのコマンドを映すタブに効かせること。
- 差分の一覧のタブ。プレビューのタブの後に、別の ADR で決める。

## 不変条件

- I1: どの画面の状態でも、プレビューのタブは、すべてのペインを通して多くとも一つである。
- I2: `followed` は、`null` か、どれかのペインにあるシートを持つタブの `id` である。選んでいるタブがシートを持つタブなら、`followed` はその `id` に等しい。どれかのペインにシートを持つタブがあれば、`followed` は `null` でない。
- I3: `preview.plain`、`preview.pages`、「プレビュー」のボタンの後には、タブが一つ以上あればプレビューのタブがちょうど一つあり、それを持つペインで選ばれている。選んでいるペインは、実行の前と同じである。
- I4: ペインが二つのとき、どちらも一つ以上のタブを持つ (タブの並びを戻すときは、並びを読む側が空のペインを落とした後)。
- I5: プレビューのタブを選んでいるあいだ、`shown(s)` は映すタブの `open` と `focus` に等しく、映すタブが無ければ空の `open` である。`focused(s)` は `null` である。
- I6: プレビューのタブを選んでいるときに、シートかプロットを、どの開き方で開いても、プレビューのタブは残る。
- I7: 用語集の名前の列は、[ADR 0082](0082-ui-names-and-glossary.md) の表から「プレビューの領域」を除き、「プレビューのタブ」と「映すタブ」を足したものに等しい。
- I8: 保存した `previewMode` か `side` が `"plain"` でも `"pages"` でもなければ、`"plain"` として読む。保存したタブの並びに `{ "preview": true }` が二つ以上あれば、最初のものだけを戻す。
- I9: プレビューのタブに出すものは、映すシートの形式と `previewMode` だけで決まり、上の「プレビューのタブの中身」の対応に等しい。

## 受けいれ条件

- A1: `.gm` の章を開き、`previewMode` が `"plain"` のときに、ツールバーの「プレビュー」を押すと、右のペインにプレビューのタブが開き、本文が出る。プレビューのタブの「ページ」に切り替えるとページが出る。
- A2: プレビューのタブの中のウィキリンクを押すと、映すタブの中身が行き先のシートに入れ替わり、プレビューのタブは残る。
- A3: プレビューのタブを ⌘W で閉じると、一つのペインに戻る。
- A4: アプリを閉じて開きなおすと、プレビューのタブが同じペインに戻り、閉じる前に映していたシートを映す。
- A5: プレビューのタブを、そのペインのほかのタブの後ろに隠し、映すシートを変えてからプレビューのタブを選ぶと、変えた後のシートが出る。ページのモードでは、ペインの境目を動かすと、ページの解像度が中身の幅に合わせて変わる。

## トレードオフ

プレビューをタブにすると、プレビューの幅は、ペインの境目で書き手が決められる (今は 42% の固定)。
しかし、ペインが一つのときにプレビューを開くと、必ず分割になり、プレビューのタブがペインの一つを使う。
ペインは二つまでなので、二つのシートとプレビューの三つは、もう並べられない。
この ADR は、タブの中身の形を試すことを重く見て、この並べ方を手放す。

プレビューのタブが映すタブに従うと、プレビューは一つで足りる。
シートに固定する形なら、プレビューを二つ並べられ、後でウィンドウに移すときも映すものが決まっている。
メンテナーは、今の領域と同じ振る舞いを選んだ。
固定する形が要るときは、別の ADR で足す。

プレビューのタブを選んでいるあいだ、ツールバーや右サイドバーは、選んでいるタブではなく映すタブに従う (`shown(s)`)。
「選んでいるタブに従う」という今の決まりに、例外が一つ増える。
しかし、そうしないと、プレビューを押してスクロールしただけで、ツールバーと右サイドバーが空になり、ウィキリンクも開けなくなる。

`previewMode` が `"plain"` か `"pages"` で保存されていても、更新の後の最初の起動では、プレビューのタブが無いので、プレビューは出ない。
書き手は、一度「プレビュー」を押せばよい。
その後は、タブの並びとして保存され、戻る。

ページのプレビューの拡大率と描いた結果の覚えは、今は一つの領域を前提にしたモジュールの変数である。
プレビューのタブは一つだけなので、この前提はそのまま使える。
タブを別のウィンドウに移す作りに進むときは、これを要素ごとの状態に移す必要がある (推測)。
