# ADR 0109: ファイルツリーの右クリックのメニューで切り取りと貼り付けをする

Status: accepted-pending

## 文脈

サイドバーのファイルツリー (以下、ツリー) の右クリックのメニューには、「コピー」がある ([ADR 0077](0077-hand-sidebar-files-outside.md))。
「コピー」は、ファイルの URL を macOS の一般のペーストボードに書く。
書いたものは Finder で貼り付けられるが、Aleph のツリーには貼り付ける項目が無い。
そのため、ツリーの中で項目を複製するには、Finder を経由するしかない。

ツリーの中で項目を移す手段は、行のドラッグだけである ([ADR 0100](0100-move-tree-files-and-folders.md))。
長いツリーでは、移す先の行が画面の外にあり、ドラッグしながらスクロールすることになる。
書き手は、移したい項目を切り取り、移す先のフォルダを開いてから貼り付けたい。
切り取った項目は、貼り付けるまで元の場所にそのまま残っていてほしい。

この ADR は、ツリーの右クリックのメニューに「切り取り」と「貼り付け」を足し、貼り付けがコピーと移動のどちらになるかを決める。

## 調査した事項

この節には、ソースで確かめたことだけを書く。
ソースは main のコミット `97e8eef` で読んだ。

ツリーの右クリックのメニューの「コピー」は、押した行と選択から渡すパスを決め、`copy_files` を呼ぶ ([tree.ts:129-137](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/ui/tree.ts#L129-L137)、[tree.ts:452-456](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/ui/tree.ts#L452-L456))。
Rust の側は、一般のペーストボードを空にしてから、ファイルの URL を書く ([handout.rs:63-72](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/src-tauri/src/handout.rs#L63-L72))。
ペーストボードを読むコマンドは、今は無い。

Finder などからツリーに落としたものは、`copy_dropped` が落とした先のフォルダにコピーする ([lib.rs:426-451](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/src-tauri/src/lib.rs#L426-L451)、[ADR 0078](0078-accept-drops-on-the-tree.md))。
コピーは `dropcopy::copy_into` が行い、次のように振る舞う。

- 同じ名前があれば、名前の後ろに `-2`、`-3` と付け、上書きしない。
- シンボリックリンクと `.DS_Store` はコピーしない。
- フォルダを、それ自身やその子孫へはコピーしない。

これらは `dropcopy.rs` のテスト (`adr0078_i2_i3_a_taken_folder_name_gets_dash_2_but_not_the_names_inside`、`adr0078_i5_i6_a_folder_into_itself_or_its_descendant_changes_nothing` など) が確かめている。
TypeScript の側の `copyWithProgress` は、コピーが 500 ミリ秒を超えたら進み具合を通知に出し、終わったら結果を一つの通知にまとめる ([dropin.ts:57-90](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/dropin.ts#L57-L90))。

ワークスペースの外のパスは、Rust の側の読める範囲 ([ADR 0050](0050-paths-the-writer-chooses.md)) に入っていないと読めない。
落としたパスは、ドロップの事象を Rust の側が受けて、アプリケーションが動いているあいだだけ読める範囲に足す ([lib.rs:1738-1744](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/src-tauri/src/lib.rs#L1738-L1744))。
WebView の側から渡したパスを、読める範囲に足す経路は無い。

ツリーでの移動は `moveTreeItem` が行う ([tree-move-flow.ts:22](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/tree-move-flow.ts#L22))。
移せるかどうかは `treeDrop` が決め、同じワークスペースの外、ワークスペースとプロジェクト直下の設定ファイル、項目自身やその子孫、プロジェクトの入れ子を拒み、同じ親へは何もしない ([tree-move.ts:11-21](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/tree-move.ts#L11-L21))。
`moveTreeItem` は、プロジェクトの外とのあいだで章やシートを移すときに確認のダイアログを出し、取り消されると何もせずに戻る。プロジェクトそのものを移すときは確認を出さない ([tree-move-flow.ts:120](https://github.com/tett23/aleph/blob/97e8eef9eb8cf8c3fd2bc4090d2fc035cf1bf122/app/tree-move-flow.ts#L120))。
`moveTreeItem` は、呼んだ側が使える結果の値を返さない。そのため、呼んだ側は、移動が終わったかどうかを知れない。
`treeDrop` が移せる項目として認めるのは、改名できる項目 (`canRenameTreeItem` が真の項目) だけである。プロジェクト直下の `manifest.toml`、`style.toml`、`plot.csv` と、ワークスペースは移せない。
移す先は、同じワークスペースの中に限る。
[ADR 0100](0100-move-tree-files-and-folders.md) は、複数項目の一括移動を含めないと決めている。

macOS の一般のペーストボードの `changeCount` は、JavaScript for Automation から `$.NSPasteboard.generalPasteboard.changeCount` で読め、整数 (確かめたときは `712`) を返した。
Apple の文書によれば、この値は、ペーストボードの持ち主が変わるたび (`clearContents` を含む) に増える。
コピーで値が増えることは、クリップボードを書き換えないために、実際には確かめていない (未確認)。
そのため、この ADR は、Aleph の「コピー」で切り取りを消すことを、`changeCount` に頼らずに決める。

## 実装すること

### 切り取り

- ツリーの右クリックのメニューに「切り取り」を足す。「名前を変える」と同じく、`canRenameTreeItem` が真の行 (移せる項目の行) にだけ出す。
- 「切り取り」は、押した行の一つの項目だけを切り取る。選択している行がほかにあっても、押した行だけを対象にする。
- 切り取っても、ディスクのファイルは変えない。ファイルは、貼り付けるまで元の場所にそのまま残る。開いているタブも、そのまま編集できる。
- 切り取った項目は、ツリーで薄く描き、切り取ったことが分かるようにする。
- 切り取りは、アプリケーションのメモリにだけ持つ。設定には書かず、Aleph を終えると消える。
- 切り取りは、一度に一つだけ持つ。別の項目を切り取ると、前の切り取りは消える。
- 切り取った項目の行のメニューには、「切り取り」の代わりに「切り取りをやめる」を出す。選ぶと切り取りを消す。
- ツリーの「コピー」を選ぶと、切り取りを消す。
- 開いているワークスペースを切り替えると、切り取りを消す。ワークスペースをまたぐ移動はできないためである。
- 切り取ったときの一般のペーストボードの `changeCount` を、切り取りと一緒に控える。ほかのアプリケーションでのコピーを見分けるためである。

### 貼り付け

- ツリーの右クリックのメニューに「貼り付け」を足す。フォルダとプロジェクトの行に出し、その行のフォルダを貼り付け先にする。ファイルの行と、ワークスペースの直下には出さない。
- 貼り付けは、次の順で、移動、コピー、何もしないのどれかに決める。
  1. 切り取りがあり、ペーストボードの `changeCount` が切り取ったときと同じとき。
     - 切り取った項目がディスクにあれば、切り取った項目を貼り付け先へ移す。ペーストボードは読まない。
     - 切り取った項目がディスクに無ければ、「<パス> が見つかりません」と通知し、切り取りを消す。移動もコピーもしない。切り取った後の改名や外での移動は追わない。
  2. 切り取りがあり、`changeCount` が変わっていれば、切り取りを消してから、3 に進む。切り取りの後に、ほかのアプリケーションでコピーしたものを優先するためである。
  3. ペーストボードにファイルの URL があれば、それを貼り付け先にコピーする。
  4. どれでもなければ、移動もコピーもせず、「貼り付けるものがありません」と通知する。
- 移動は、[ADR 0100](0100-move-tree-files-and-folders.md) のドラッグでの移動と同じ `moveTreeItem` で行う。移せるかどうかの検査、Golem LSP の移動計画、参照とノートの付け替え、プロジェクトの外とのあいだで移すときの確認、失敗したときの巻き戻しは、ドラッグと同じである。
- `moveTreeItem` は、ディスクの移動を終えたときに真を、それ以外 (移せない行き先、同じ親、別の移動の実行中、確認の取り消し、事前の保存の失敗、移動の失敗) で偽を返すようにする。ドラッグの側は、この値を使わない。
- 移動が真で終わったら、切り取りを消す。偽で終わったら、切り取りを残し、書き手が別の貼り付け先を選び直せるようにする。
- コピーは、新しいコマンド `paste_files` で行う。`paste_files` は、貼り付け先のフォルダと、進み具合の事象 (`aleph:copy-progress`) を結び付ける番号だけを、WebView の側から受け取る。
  - Rust の側が、一般のペーストボードからファイルの URL (`public.file-url`) だけを読む。ファイルでない URL と文字列は読まない。
  - 読んだパスを、アプリケーションが動いているあいだだけ読める範囲に足す。落としたパスと同じ扱いである。
  - 読んだパスを、`dropcopy::copy_into` で貼り付け先にコピーする。同じ名前、シンボリックリンク、`.DS_Store`、フォルダ自身やその子孫への扱いは、[ADR 0078](0078-accept-drops-on-the-tree.md) のドロップと同じである。
  - 進み具合と結果の通知は、ドロップと同じ `copyWithProgress` で出す。
- `paste_files` とは別に、ペーストボードの `changeCount` を返すコマンドを足す。切り取りのときと貼り付けのときに呼ぶ。
- 貼り付けの後は、ツリーを読み直す。

## 実装しないこと

- 二つ以上の項目の切り取り。貼り付けが一括移動になり、[ADR 0100](0100-move-tree-files-and-folders.md) が含めないと決めたものに当たるためである。
- ⌘X、⌘C、⌘V などのキーでの切り取り、コピー、貼り付け。
- 切り取りを一般のペーストボードに書くこと。Finder で、Aleph で切り取ったものを貼り付けることはできない。
- Finder で切り取ったもの (⌘C の後の ⌥⌘V) を、Aleph で移動として貼り付けること。Aleph はコピーとして貼り付ける。
- 切り取った後の改名や、外での移動 ([ADR 0108](0108-follow-moves-made-outside.md)) に、切り取りを付いていかせること。
- 切り取りを、Aleph を終えた後まで残すこと。
- ファイルの行と、ワークスペースの直下への貼り付け。ワークスペースの直下へは、ドラッグで移せる。
- 同じ名前のものを上書きするか、名前を変えるかを、書き手に選ばせること。
- macOS のほかの OS での切り取りと貼り付け。

## 不変条件

- I1: 切り取りは、ディスクのファイル、タブ、文書を変えない。切り取りの前と後で、ファイルの一覧と中身、開いている文書は同じである。
- I2: 切り取りは、多くとも一つである。切り取りがあるときに別の項目を切り取ると、切り取りは後の項目だけになる。「切り取りをやめる」、ツリーの「コピー」、ワークスペースの切り替えの後は、切り取りは無い。
- I3: 貼り付けの決め方は、切り取りの有無、切り取ったときと今の `changeCount` が同じか、切り取った項目がディスクにあるか、ペーストボードにファイルの URL があるかだけで決まる。切り取りがあり `changeCount` が同じで項目があれば移動、切り取りが無いか `changeCount` が違い、ファイルの URL があればコピー、ほかは移動もコピーもせずに通知する。
- I4: `changeCount` が切り取ったときと違うときの貼り付けは、移動をせず、切り取りを消す。
- I5: 移動での貼り付けの後、切り取りは、`moveTreeItem` が真を返したときだけ消え、偽を返したときは残る。
- I6: `paste_files` がコピーするパスは、Rust の側がペーストボードから読んだファイルの URL のパスだけである。ファイルでない URL は読み飛ばす。
- I7: 切り取りがあり `changeCount` が同じで、切り取った項目がディスクに無いときの貼り付けは、移動もコピーもせず、切り取りを消す。

境界の入力は次のとおりである。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 切り取りなし、ファイルの URL なし | 移動もコピーもせず、「貼り付けるものがありません」 | I3 |
| 切り取りなし、ファイルの URL が一つ | コピー | I3 |
| 切り取りあり、`changeCount` が同じ、項目あり、ファイルの URL なし | 移動 | I3 |
| 切り取りあり、`changeCount` が同じ、項目あり、ファイルの URL あり | 移動 (ペーストボードは読まない) | I3 |
| 切り取りあり、`changeCount` が一つ増えた、ファイルの URL あり | 切り取りを消してコピー | I3, I4 |
| 切り取りあり、`changeCount` が一つ増えた、ファイルの URL なし | 切り取りを消し、「貼り付けるものがありません」 | I3, I4 |
| 切り取りあり、`changeCount` が同じ、項目なし、ファイルの URL あり | 移動もコピーもせず、切り取りが消える | I3, I7 |
| 切り取りの後に別の項目を切り取る | 切り取りは後の項目だけ | I2 |
| 切り取りの後に「切り取りをやめる」、ツリーの「コピー」、ワークスペースの切り替えのどれか | 切り取りが無い | I2 |
| `moveTreeItem` が真を返す | 切り取りが消える | I5 |
| `moveTreeItem` が偽を返す (同じ親、確認の取り消し、移せない行き先、移動の失敗) | 切り取りが残る | I5 |
| ペーストボードの URL が `file://` のものと `https://` のもの | `file://` のものだけを読む | I6 |
| ペーストボードの URL が空 | 何も読まない | I6 |

## 受けいれ条件

- A1: ツリーでシートを切り取ると、そのシートは元の場所に残り、薄く描かれる。開いていたタブはそのまま編集できる。別のフォルダに貼り付けると、シートが移り、章の登録と参照が新しい場所に変わる。
- A2: 子孫を持つフォルダを切り取り、別のフォルダに貼り付けると、子孫ごと移る。
- A3: ツリーで「コピー」したファイルとフォルダを、別のフォルダに貼り付けると、コピーされる。同じ名前があれば `-2` が付く。
- A4: Finder でコピーしたファイルを、ツリーのフォルダに貼り付けると、コピーされる。
- A5: 切り取った後に別の項目を「コピー」してから貼り付けると、コピーが貼り付けられ、切り取った項目は移らず、薄い描き方が消える。
- A6: 切り取ったシートを、別のプロジェクトのフォルダに貼り付け、確認のダイアログで取り消すと、シートは移らず、切り取りが残る。
- A7: 切り取った後に、ほかのアプリケーションで文字をコピーしてから貼り付けると、切り取った項目は移らず、薄い描き方が消える。

## テスト設計

- I1〜I5、I7 は、TypeScript で、切り取りと貼り付けの決め方を、ディスクとペーストボードと移動を差しかえて確かめる。決め方は、DOM と Tauri から離した関数にする。
  - I1 は、切り取りのあいだに、ディスクと文書を変える API が一度も呼ばれないことで確かめる。
  - I3 と I4 は、境界の表の各行を入力にする。
  - I2 は、切り取り、別の項目の切り取り、「切り取りをやめる」、ツリーの「コピー」、ワークスペースの切り替えを順に与える。
  - I5 は、移動を差しかえて真と偽を返させる。
  - I7 は、`exists` が偽を返すようにする。
- `moveTreeItem` が、ディスクの移動を終えたときだけ真を返すことは、今の移動のテストに、返り値の確かめを足して確かめる。
- I6 は、Rust で、ペーストボードから読んだ URL の一覧からパスを取り出す関数を、ペーストボードから離して確かめる。
- テストの名前には、この ADR と不変条件の番号を入れる。
- A1〜A7 は、macOS の使い捨てのワークスペースで、`planFileMove` に応じる Golem を設定して、右クリックのメニューで確かめる。A4 は Finder で ⌘C したファイルを使う。A3、A4、A7 はクリップボードを書き換えるので、メンテナーの許しを得てから確かめる。
- A7 は、ほかのアプリケーションでのコピーで `changeCount` が増えるという Apple の文書の記述を確かめる。増えなかったときは、この ADR の決め方が成り立たないので、新しい ADR で決め直す。

## トレードオフ

- 切り取りを Aleph のメモリにだけ持つので、Finder とのあいだで切り取りの貼り付けはできない。代わりに、ペーストボードの書式を Finder に合わせる必要がなく、切り取っても他のアプリケーションのコピーを消さない。
- `changeCount` で切り取りとコピーの新しさを比べるので、切り取りの後にほかのアプリケーションで文字をコピーしただけでも、切り取りは消える。どちらが新しいかを一つの規則で決められることを優先した。
- 貼り付けの決め方で `changeCount` を読んだ後、`paste_files` がペーストボードを読むまでのあいだに、ほかのアプリケーションがペーストボードを変えると、変えた後の中身をコピーする。このあいだは短く、変えた後の中身も書き手がコピーしたものなので、受けいれる。
- 切り取りを一つの項目に限るので、複数の項目を移すには、一つずつ切り取りと貼り付けを繰りかえす。[ADR 0100](0100-move-tree-files-and-folders.md) の一括移動の除外を変えずに済む。
- 切り取りの後の改名や外での移動を追わないので、その後の貼り付けは「見つかりません」になる。もう一度切り取ればよく、追うしくみを足すより単純である。
