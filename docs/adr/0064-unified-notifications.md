# ADR 0064: 通知を一つの仕組みにまとめる

ステータス: 採択（未実装）

## 文脈

Aleph が書き手に知らせる手段は、画面の下の中央に出る一行の通知（`toast`）だけである（[app/ui/dom.ts](https://github.com/tett23/aleph/blob/b234f59/app/ui/dom.ts#L5)）。
通知は 3.5 秒で消え、文字のほかには何も持たない。
65 か所から呼ばれており、保存、ビルド、Git、ツリーの操作の成否などを知らせている。

この通知には、次の不足がある。

- 重大さの区別がない。失敗の知らせも、成功の知らせと同じ見た目で、3.5 秒で消える。読み終える前に消えた失敗は、もう読めない。
- ボタンを持てない。知らせたうえで次の操作を選ばせることができず、そうした場面では別にダイアログを出している。
- 閉じられず、消えるまで残す方法もない。
- 二つ以上が同時に出ると、同じ位置に重なって読めない。

[ADR 0063](0063-watch-files-changed-outside.md) は、外部で変わったファイルについて、時間で消えてよい知らせ（読み込みなおした）と、書き手が選ぶまで残すべき知らせ（食い違いがある、ファイルが消えた）の両方を必要とする。
後者のためにエディタの上に帯を出すことも考えたが、画面の下と上に別々の知らせの形を持つと、どこを見ればよいかが分かれる。

## 実装すること

### 通知の形

- 通知は、ウィンドウの右下、ステータスバーの上に、下から上へ積む（VSCode の通知と同じ置き方）。幅は 360 ピクセルとし、狭いウィンドウではウィンドウの幅から余白を引いた幅にする。
- 一つの通知は、次のものを持つ。
  - 重大さ：情報、警告、エラーの三つ。左に、重大さの色のアイコン（lucide の `info`、`triangle-alert`、`circle-x`）を出す。
  - 文：複数行でよい。選んでコピーできる。
  - ボタン：0 個から 3 個。一つを主のボタンにできる。押すと、その操作を行い、通知を閉じる（閉じない指定もできる）。
  - 閉じるボタン（×）：いつも右上に置く。
- 通知は二種類とする。
  - **時間で消える通知**：既定は 5 秒で消える。ポインタが上にあるあいだは数えるのを止め、離れてから数えなおす。
  - **消えない通知**：× を押すか、ボタンで閉じるか、それを出した機能が閉じるまで残る。
- 同じ「鍵」を持つ通知を出すと、前のものを置き換える（同じファイルの食い違いの通知が二つ並ばないため）。機能は、鍵で通知を閉じられる（食い違いが直ったら、その通知を閉じる）。
- 一度に見せるのは 4 つまでとする。超えたときは、古い時間で消える通知から閉じる。消えない通知は、数を超えても閉じず、いちばん下に「ほか n 件の通知」の行を出して、押すと全部を見せる。

### 書き方

- 画面の側の関数を一つにする：`notify({ message, level, sticky, actions, key })`。返り値で、出した通知を閉じたり、文を変えたりできる。
- これまでの `ctx.toast(message)` は、情報の時間で消える通知を出す近道として残す。
- 失敗を知らせている今の呼び出し（「〜に失敗しました」「〜できませんでした」「〜が見つかりません」など）は、エラーの消えない通知に変える。ほかは、情報の時間で消える通知のままとする。どの呼び出しを変えたかは、実装のプルリクエストに一覧で書く。
- ページのプレビューとプロットの別のウィンドウでも、同じ通知を使う。
- エディタの上やパネルの中に、通知のための帯を新しく作らない。知らせは、この通知に集める。

### 通知の履歴

- 出した通知は、消えたものも閉じたものも含めて、履歴に残す。見る場所は、画面の下の問題のパネル（[ADR 0055](0055-problems-panel.md)）とする。
- 問題のパネルの見出しに、「問題」と「通知」の二つのタブを置く。最後に選んだタブを設定の `ui` に残し、パネルを開いたときにそれを出す。
- 「通知」のタブは、新しいものを上に、一つの通知を一行で並べる。各行は、重大さのアイコン、出した時刻（時と分と秒）、文を持つ。文は選んでコピーできる。表示中か閉じたかは、ボタンの有無で分かるので、文字では出さない。
  - 表示中の消えない通知の行には、その通知と同じボタンを出し、ここからも選べるようにする。閉じた通知の行には、ボタンを出さない（その操作が、もう意味を持たないことがあるため）。
  - 同じ鍵で置き換えられた通知は、置き換えた通知の行の中にまとめ、行の右に回数を出す。
- タブの名前の横に、そのタブを最後に見てから出た通知の数を出す。エラーの通知があれば、数をエラーの色にする。「通知」のタブを見たら、数を消す。
- 「通知」のタブの見出しに、「履歴を消す」のボタンを置く。表示中の通知は消さない。
- 履歴は、起動のあいだだけ持ち、500 件を超えたら古いものから捨てる。
- コマンドに「通知の履歴を表示」（`view.notifications`）を足す。問題のパネルを開き、「通知」のタブを選ぶ。
- ページのプレビューとプロットの別のウィンドウで出した通知も、メインのウィンドウの履歴に入れる（イベントで送る）。

### 仕様書

- 仕様書の画面の節に、通知の置き方、二種類の通知、重大さ、鍵による置き換え、数の上限、通知の履歴を書く。問題のパネルの節に、二つのタブを書く。

## 実装しないこと

- 通知の履歴を、アプリを閉じた後まで残すこと。
- macOS の通知センターに出すこと。
- 確かめのダイアログ（`confirmDialog`）と、一行の問い（`ask`）を通知に置き換えること。答えるまで操作を止めるべき場面では、これまでどおりダイアログを使う。
- 問題のパネル（[ADR 0055](0055-problems-panel.md)）の診断を、通知に出すこと。

## テスト設計

`node --test` で、テストを先に書いて失敗させてから実装する。通知の並びと時計は、DOM と切り離した関数で持ち、時計は差し替えられるようにする。

- 時間で消える通知が 5 秒で消え、消えない通知が残ること。
- ポインタが上にあるあいだは数えるのを止め、離れてから数えなおすこと。
- 同じ鍵の通知が前のものを置き換え、鍵で閉じられること。
- 見せる数が 4 を超えたとき、古い時間で消える通知から閉じ、消えない通知は残して「ほか n 件」の数が正しいこと。
- ボタンを押すと、その操作が一度だけ呼ばれ、通知が閉じること（閉じない指定のボタンでは閉じないこと）。
- `ctx.toast` の近道が、情報の時間で消える通知を出すこと。
- 履歴が、消えた通知と閉じた通知を新しい順に持ち、表示中かどうかが正しいこと（ボタンを出すかを決める）。同じ鍵の置き換えが一行にまとまり、回数が正しいこと。500 件を超えると古いものから捨てること。「履歴を消す」が表示中の通知を残すこと。
- 最後に見てからの数が、通知を出すと増え、タブを見ると 0 になること。エラーの通知があるかを返すこと。
- 画面の確かめ方：情報、警告、エラーの通知と、ボタン付きの消えない通知を続けて出し、右下に重ならずに積まれること、× で閉じること、時間で消える通知の上にポインタを置くと消えないこと、文を選んでコピーできること、ページのプレビューの別のウィンドウでも出ることを確かめる。ダークのテーマでも読めることを確かめる。問題のパネルの「通知」のタブに、消えた通知も含めて新しい順に並び、表示中の消えない通知のボタンをそこから押せること、タブの数が見ると消えること、別のウィンドウの通知も入ることを確かめる。

## トレードオフ

- 通知が右下に移るので、これまでの中央の位置に慣れた書き手には変化になる。そのかわり、エディタの本文に重なりにくい。
- 失敗の通知が消えない通知になるので、閉じる手間が増える。そのかわり、読み終える前に消えることがない。
- 消えない通知を出す機能は、直ったときに鍵で閉じる責任を持つ。閉じ忘れると、直った後も残る。
- 問題のパネルが、診断と通知の二つの役を持つ。診断を見ているときに通知の数が増えても、タブの数で気付ける。
