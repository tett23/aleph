# ADR 0097: プレビュー更新後にスクロール位置を復元する

Status: proposed

## 文脈

指示者は、プレビューを更新したときにスクロール位置を復元することを求めた（2026-11-22）。
保存や組み直しの後も、読んでいた位置から確認を続けたい。

## 調査した事項

調査したコミットは `8a102bdfa38df9fb2fa7a0852a5ca7da39d186af` である。
[`surface`](https://github.com/tett23/aleph/blob/8a102bdfa38df9fb2fa7a0852a5ca7da39d186af/app/preview/render.ts#L18) はスクロール枠を保ち、その子要素を描画先にする。
同ファイルの `renderPlain` と `renderPageImages` は子要素の `innerHTML` を置き換える。
`rg -n 'scrollTop|scrollLeft|scrollTo' app/preview` では一致がなく、明示的な位置復元は見つからなかった。
枠が保たれることだけでは、内容の縮小や画像読み込みに伴う位置変化を防げるとは確認できない。

## 実装すること

同じ対象と表示モードを更新するとき、スクロール位置を記録し、描画後に復元する。
プレビューのタブと別ウィンドウの本文およびページを対象にする。
**対象キー**は、ワークスペース、プロジェクト、表示するシートの順序付きパス一覧、表示モード、組み方向で作る。
本文とページを別ウィンドウへ送る通知に、ワークスペース、プロジェクト、順序付きシートパス一覧、表示モード、組み方向と更新世代を付ける。
別ウィンドウは通知の対象キーと自分の表示対象を照合する。
ページはプロジェクトの章一覧を使い、本文は通知で送る本文に対応するシート一覧を使う。
内容の版とズーム率は対象キーに含めない。
異なる対象キーに切り替えたときは、以前の対象の位置を復元しない。

位置は論理的な読み始めからの水平距離と垂直距離を CSS px で記録する。
縦書きの右端を起点とするスクロールは、WebKit の負の `scrollLeft` を読み始めからの距離に正規化する。
保存するのはピクセル位置であり、段落やページ番号を追跡する位置ではない。
新しい内容が短いときは、新しいスクロール可能範囲の末端に制限する。

更新要求には世代番号を付け、最新の世代だけが描画と復元を行う。
非同期処理の開始時だけでなく、DOM の置き換え直前の位置を取得する。
更新中の書き手のスクロールを巻き戻さないためである。
画像とフォントの読み込み後にも寸法を確認するが、置き換え後に書き手がスクロールした場合は、その世代の追加の復元をやめる。
取得や画像のデコードは表示中の内容を残したまま行い、成功した結果をまとめて置き換える。
失敗時は表示中の内容を置き換えず、その時点の位置を残し、更新失敗を知らせる。
まだ一度も表示に成功していない場合はエラーを表示する。
閉じたタブやウィンドウには復元せず、監視を解除する。

[ADR 0010](0010-previews.md) と [ADR 0087](0087-preview-in-a-tab.md) を補足する。
実装時に仕様書と README に位置復元の範囲を書く。

## 実装しないこと

エディタとのスクロール同期、アプリ再起動後の位置復元、段落やページ番号による追跡、PDF の iframe 内のスクロール操作。

## 不変条件

- I1: 同じ対象キーの更新後、追加の利用者操作がなければ、位置は置き換え直前の距離を新しい可動範囲に制限した値に等しい。
- I2: 更新要求の世代が最新でない、要求の対象キーが現在の表示対象キーと異なる、表示先が破棄済みのいずれかなら、その結果の描画も位置復元も行わない。
- I3: 置き換え後の利用者のスクロールを、遅れて完了した画像読み込み等による復元で上書きしない。
- I4: 更新失敗では表示中の内容とその時点の位置を保持し、成功した内容がまだ無いときだけエラー表示にする。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| スクロールのない短い内容 | 距離0 | I1 |
| 本文の途中、ページの途中で更新 | 同じピクセル位置 | I1 |
| 内容が位置より短くなる | 新しい末端まで | I1 |
| 縦書きの右端、左へ移動済み | 正規化した距離を復元 | I1 |
| 二つの更新が逆順に完了、対象切替、閉じる | 古い結果を適用しない | I2 |
| 更新中と画像読み込み中にスクロール | 最新の操作を維持 | I1, I3 |
| 組版または画像取得が失敗 | 前の内容と位置を維持 | I4 |

## 受けいれ条件

- A1: タブと別ウィンドウで、本文とページを途中まで読んで保存または組み直しをしても、同じ位置が見える。
- A2: 横書きと縦書き、ズーム後、画像を含む本文で同じ復元規則を満たす。

## テスト設計

位置の正規化、制限、対象キー、世代の判定を `ADR 0097 I1: …` の形で先にテストする。
DOM の置き換えと遅延読み込みを制御するテストで、置き換え前後のスクロール操作を挟み I2 と I3 を確かめる。
I4 は組版と画像取得の失敗を注入して確かめる。
A1 と A2 は Tauri で行い、縦書きの負の `scrollLeft` と画面上の復元位置を確認する。

## トレードオフ

ピクセル位置の復元なら本文の要素と組版ページの対応付けは不要になる。
ただし、前方の文章を大きく増減した場合は同じ文やページが見えるとは限らない。
