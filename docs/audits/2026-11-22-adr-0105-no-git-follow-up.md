# [ADR 0105](../adr/0105-use-libgit2-without-git-executable.md) の Git 起動拒否下での追試

2026-11-22 に、[実装検証](2026-11-22-adr-0105-validation.md) で残っていた、Git の起動を OS で拒否した状態での配布用 Tauri の確認を行った。
対象のコミットは `7af411f8ee7638e338b03b588ec73c23c500a227` である。
実装と試験には Sol を使った。

## 環境

独立した識別子 `dev.tett23.aleph.adr0105strict` のリリースビルドを使った。
一時ディレクトリの設定とリポジトリを使い、SSH エージェントと HTTPS の試験用 CA も検証用に限った。
アプリの PATH には、呼び出されると印を書いて失敗する偽の Git だけを置いた。
試験版プロセスに読み込んだライブラリで、ファイル名が `git` のプロセスの起動を macOS のサンドボックスで拒否した。
同じプロセスから `/usr/bin/git --version` を `posix_spawn` で起動しようとすると `EPERM` が返った。

試験用コードは、隔離した設定、試験用 CA、Git の起動拒否、アシスタントの固定応答、および WebView での操作と検査を受け持った。
Git の IPC、コミットと通信、エディタ、差分、置換の確認は製品コードを使った。
試験用コードは製品のコミットに含めていない。

## 結果

設定のないリポジトリを初期化し、グローバルの著者情報を保存した。
ローカルの名前だけを上書きでき、メールアドレスはグローバル設定から継承された。
ローカル値を消して両項目を継承に戻した後、手動コミット `26570a9` ができた。
別のワークスペースでは、起動時に自動コミット `94b424b Autosave 2026-11-22` ができた。
状態と履歴を読み、HEAD の本文と作業ツリーの差分を確かめた。

SSH エージェントによる pull でサーバーの変更を読み、追記をコミットして push した。
HTTPS の pull と push では、試験用のユーザー名とトークンで認証した。
クライアントが送ったコミット ID とサーバーの HEAD は、SSH では `195b591a8cc5726bb0e2885f3bc7a0365b5e36ce`、HTTPS では `49d00a606090e1372e02ad1c90cd6ae9e4d3a939` で一致した。
どちらも、サーバー側の章に試験用の追記があった。

アシスタントの変更前コミット `de9edf2` には、書き手が先に追加したファイルと、適用前の「初稿」が入った。
適用後の作業ツリーでは章が「アシスタントの改稿」になった。
エディタの変更マーカー、差分のタブの追加表示、検索パネルの Git に対応した置換確認も確かめた。
全 18 項目が成功し、偽の Git の起動を示すファイルは作られなかった。
