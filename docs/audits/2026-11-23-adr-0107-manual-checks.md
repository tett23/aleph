# [ADR 0107](../adr/0107-scroll-overflowing-tab-bar.md) の手の確かめ (2026-11-23)

## 対象と環境

- 対象は [ADR 0107](../adr/0107-scroll-overflowing-tab-bar.md) の A1 から A4 である。
- ブランチ `impl/adr-0107-tabbar` から `npx tauri build --debug` で作ったデバッグ版で確かめた。A3 の確かめで見つけた誤りを直した後のデバッグ版で、A3 を確かめ直した。
- 確かめには、使い捨てのワークスペースに、名前の長さの違う 30 個のシートを置き、設定の `ui.tabs` で 30 個のタブを開いた状態から起こした。ペインは一つで、タブはペインの幅を越えた。
- 書き手の `config.json` と `window.json` は、確かめの前に控え、後で戻した。戻した後の `config.json` の SHA-1 は、控えと同じだった。
- 操作は、画面を借りない背景の操作 (クリック、ホイール、ドラッグ、キー、ウィンドウごとの画面の取り込み) で行った。

## 結果

- A1：先頭を表示しているとき、右端に影が出て、左端には出なかった。「＋」は右端に見えた。並びの上で縦のホイールを回すと、並びが横に動き、左右の両端に影が出た。トラックパッドの横のスワイプは確かめていない。
- A2：ツリーで、右に隠れていた末尾のタブを選ぶと、そのタブが右端にちょうど見える位置までスクロールし、右端の影が消えた。ツリーで先頭のタブを選ぶと、並びは先頭に戻った。末尾のタブで ⌃Tab を押すと先頭のタブに移り、並びは先頭までスクロールした。起動して残したタブを開き直したときも、選んでいたタブが見える位置までスクロールした。⌘ と数字、⌘P での選び直しと、ウインドウを狭めたときは確かめていない。
- A3：先頭のタブを並びの右端までドラッグすると、端の近くにあるあいだに並びがスクロールし、隠れていた第18章の後ろに置けた。
- A3：「＋」の上で離すと、初めのデバッグ版では、末尾ではなく、右に隠れていた最初のタブの手前に入った。落とし先を、ポインターの位置とタブの中央を比べて決めていたためである。「＋」の上では末尾にするように直した後のデバッグ版で、「＋」の上で離したタブが末尾 (第30章の後ろ) に入ることを確かめた。
- A4：分割したペインでの確かめは、していない。

## 残ったこと

- A1 のトラックパッドの横のスワイプ。
- A2 の ⌘ と数字、⌘P での選び直しと、ウインドウを狭めたとき。
- A4。
