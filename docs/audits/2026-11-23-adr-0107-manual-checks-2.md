# [ADR 0107](../adr/0107-scroll-overflowing-tab-bar.md) の手の確かめの続き (2026-11-23)

## 対象と環境

- 対象は、[前の記録](2026-11-23-adr-0107-manual-checks.md) で残った [ADR 0107](../adr/0107-scroll-overflowing-tab-bar.md) の A1 から A4 である。
- main の `95e94da` から `npx tauri build` で作ったリリース版で確かめた。macOS は 27.0 である。
- 確かめには、前の記録と同じ使い捨てのワークスペースを使い、設定の `ui.tabs` で 30 個のタブを開いた状態から起こした。ペインは一つで、タブはペインの幅を越えた。
- 書き手の `config.json` と `window.json` は、確かめの前に控え、後で戻した。戻した後の二つのファイルの SHA-1 は、控えと同じだった。
- 操作は、画面を借りない背景の操作 (クリック、キー、ウィンドウごとの画面の取り込み) で行った。

## 結果

- A2：⌘P で、右に隠れていた末尾のタブ (第30章) を選ぶと、そのタブが右端にちょうど見える位置までスクロールし、左端に影が出た。
- A2：末尾を表示しているときに ⌘3 を押すと、左に隠れていた 3 番目のタブ (手紙) が左端に来る位置までスクロールした。
- A2：右端で一部が隠れていたタブ (第18章) をクリックすると、そのタブの全体が見える位置までスクロールした。
- A2：右のサイドバーを閉じてペインを広げても、スクロールの位置は変わらず、選んでいるタブは見えたままだった。サイドバーを開き直してペインを狭めると、選んでいるタブは右端に寄せられ、見え続けた。ウインドウそのものの大きさは変えていない。ペインの幅の変化は、ウインドウの大きさを変えたときと同じく、並びの `ResizeObserver` で受けるので、この確かめで代えた。
- A4：「右に分ける」で第19章を選んだまま分割すると、狭くなった左のペインでも、選んでいる第19章は見えたままだった。右のペインには第18章だけが入った。
- A4：左のペインで ⌘P から左に隠れていたタブ (帰り道) を選ぶと、そのタブが左端に来る位置までスクロールした。
- A4：右のペインで「右に分ける」を実行して、右のペインのただ一つのタブを左のペインに移すと、分割がやめになり、末尾に入った第18章が右端に見える位置までスクロールした。

## 残ったこと

- A1 のトラックパッドの横のスワイプ。背景の操作では横のホイールのイベントを送れないため、確かめていない。並びは、横の量が縦の量以上のホイールを、既定の処理に任せる ([ADR 0107](../adr/0107-scroll-overflowing-tab-bar.md) の I3)。
